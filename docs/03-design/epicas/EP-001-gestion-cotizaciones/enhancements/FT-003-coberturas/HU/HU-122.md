## 1. Identificación General
**Feature:** Gestión de Cotizaciones  
**Capability:** CAP-122 - Gestión de Coberturas por Ubicación  
**Actor:** Usuario (Agente de Ventas / Configurador de Producto)  
**Bounded Context:** Cotizaciones de Seguros  
**Story Points:** 3

## 2. Enabled Capability
**CAP-122:** Gestión de Coberturas por Ubicación  
**Business Value:** Permite personalizar la protección ofrecida según las necesidades específicas de cada cliente y ubicación de riesgo, lo que mejora la flexibilidad del producto y la satisfacción del cliente.  
**Requires:** CAP-121 (Visualización de Catálogo de Coberturas), CAP-116 (Edición de Detalles de Ubicación de Riesgo)  
**Enables:** CAP-XXX (Cálculo de Prima de Cotización), CAP-XXX (Generación de Documento de Cotización)  
**Orchestrates:** API de Cotizaciones (Backend)

## 3. User Story
Como usuario,  
Quiero poder seleccionar o deseleccionar coberturas específicas para cada ubicación de riesgo,  
Para personalizar la protección ofrecida según las necesidades del cliente.

## 4. Functional Description
**Description:** Esta historia de usuario permite al actor (Agente de Ventas o Configurador de Producto) gestionar las coberturas asociadas a una ubicación de riesgo dentro de una cotización. El usuario podrá visualizar un catálogo de coberturas disponibles y, para una ubicación específica, activar o desactivar estas coberturas mediante una interfaz intuitiva (e.g., checkboxes o toggles). Los cambios realizados en la selección de coberturas se persistirán en el sistema al guardar la cotización, asegurando que la configuración de la protección sea la deseada.  
**Flow:** HU-121 (Visualizar Catálogo de Coberturas) → HU-116 (Editar Detalles de Ubicación de Riesgo) → HU-122 (Seleccionar y Deseleccionar Coberturas por Ubicación) → HU-153 (Guardar Cotización)

## 6. Acceptance Criteria
### AC-001: Selección de Coberturas
**Description:** Valida que el usuario puede activar una o varias coberturas para una ubicación de riesgo.

```gherkin
Scenario: El usuario selecciona una o varias coberturas para una ubicación
  Given que visualizo el catálogo de coberturas disponibles para la "Ubicación A"
  When selecciono las coberturas "Robo" y "Daños por Agua"
  Then las coberturas "Robo" y "Daños por Agua" se marcan visualmente como activas para la "Ubicación A"
```

### AC-002: Deselección de Coberturas
**Description:** Valida que el usuario puede desactivar una cobertura previamente seleccionada para una ubicación de riesgo.

```gherkin
Scenario: El usuario deselecciona una cobertura activa para una ubicación
  Given que la cobertura "Incendio" está marcada como activa para la "Ubicación B"
  When deselecciono la cobertura "Incendio"
  Then la cobertura "Incendio" deja de estar marcada como activa para la "Ubicación B"
```

### AC-003: Persistencia de Cambios al Guardar Cotización
**Description:** Valida que los cambios de selección/deselección de coberturas se guardan correctamente cuando se persiste la cotización.

```gherkin
Scenario: Los cambios en las coberturas se guardan correctamente en el sistema
  Given que he seleccionado/deseleccionado coberturas para la "Ubicación C"
  And los cambios se reflejan visualmente en la interfaz
  When guardo la cotización
  Then las coberturas seleccionadas se asocian correctamente a la "Ubicación C" en la base de datos
  And las coberturas deseleccionadas se desasocian o marcan como inactivas para la "Ubicación C" en la base de datos
```

**BR-001:** Asociación Única de Cobertura por Ubicación
- Description: Una cobertura específica solo puede tener un estado (activa/inactiva) para una ubicación de riesgo determinada dentro de una cotización. No se permiten duplicados.

- Logic: La combinación (`ubicacion_id`, `cobertura_id`) debe ser única en la tabla de asociaciones.

## 10. UX and Navigation Flow
**UX Flow:** Pantalla de Detalles de Cotización → Sección "Ubicaciones de Riesgo" → Seleccionar Ubicación Específica → Pantalla de Configuración de Ubicación (con lista de coberturas y sus checkboxes/toggles) → Seleccionar/Deseleccionar Coberturas → Botón "Aplicar cambios a Ubicación" (o similar) → Retorno a Pantalla de Detalles de Cotización (con indicador de cambios pendientes de guardar) → Botón "Guardar Cotización".  
**Messages/Modals:**
- Mensaje de Éxito: "Coberturas actualizadas para la ubicación '[Nombre de Ubicación]'."
- Mensaje de Error: "Error al actualizar las coberturas. Intente nuevamente."
- Mensaje de Advertencia: "Hay cambios en las coberturas no guardados. ¿Desea descartarlos?" (al intentar salir sin guardar la cotización completa).  
**Stepper/Breadcrumbs:** Detalles de Cotización > [ID Cotización] > Ubicación [Nombre Ubicación] > Configuración de Coberturas.

## 11. Architecture and Technical Dependencies
- **Frontend (Controles de Selección de Coberturas):** Componente de UI responsable de renderizar el listado de coberturas y gestionar las interacciones de selección/deselección (ej. React/Angular/Vue).
- **Backend (API de Cotizaciones):** Un endpoint RESTful (ej. `PATCH /api/cotizaciones/{idCotizacion}/ubicaciones/{idUbicacion}/coberturas`) que recibe el estado de las coberturas para una ubicación y las persiste en la base de datos.
- **Base de Datos:** Tablas `cotizaciones`, `ubicaciones_riesgo`, `catalogo_coberturas` y una tabla de relación `ubicaciones_coberturas`.

## 13. Edge Cases and Exceptions
### Case 1: No hay coberturas disponibles para la ubicación
```gherkin
Scenario: El catálogo de coberturas para una ubicación está vacío
  Given que visualizo la pantalla de configuración de coberturas para la "Ubicación D"
  And el catálogo de coberturas para esa ubicación está vacío o no se pudo cargar
  When intento seleccionar una cobertura
  Then se muestra un mensaje "No hay coberturas disponibles para seleccionar para esta ubicación."
  And los controles de selección de coberturas están deshabilitados
```

### Case 2: Error de conexión o comunicación con el Backend al guardar
```gherkin
Scenario: Falla la comunicación con el backend al guardar las coberturas
  Given que he seleccionado/deseleccionado coberturas para la "Ubicación E"
  When intento guardar la cotización
  And se produce un error de red o de comunicación con la API de Cotizaciones
  Then se muestra un mensaje de error "No se pudieron guardar los cambios. Verifique su conexión o intente nuevamente."
  And los cambios en las coberturas no se persisten
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad en la Interfaz de Usuario (UI):**
    - Description: Si el número de coberturas es muy grande o existen reglas complejas de dependencia entre ellas (ej. seleccionar A implica seleccionar B), la interfaz de selección podría volverse confusa o difícil de usar.
    - Impact: Mala experiencia de usuario, errores en la configuración de la cotización, mayor tiempo de desarrollo.
    - Probability: Media.
    - Mitigation: Diseñar la UI de forma modular, considerar filtros o búsqueda, implementar validaciones en el frontend para reglas de dependencia básicas, explorar componentes de selección avanzados.
2.  **Integridad de Datos en el Backend:**
    - Description: Asegurar que los datos de las coberturas seleccionadas se persistan correctamente y mantengan la integridad, evitando duplicados o inconsistencias en la base de datos (ej. una misma cobertura activa dos veces para la misma ubicación).
    - Impact: Cotizaciones erróneas, cálculos de prima incorrectos, problemas en reportes.
    - Probability: Baja (si se aplican restricciones de DB y validaciones de API).
    - Mitigation: Implementar restricciones de unicidad a nivel de base de datos, validaciones exhaustivas en la capa de servicio del backend.

## 17. Criticality
**Criticality Level:** Alta  
**Justification:** Esta historia es fundamental para la propuesta de valor del producto, ya que permite la personalización y adaptación de las pólizas de seguro a las necesidades específicas del cliente. Sin esta funcionalidad, las cotizaciones serían genéricas y menos competitivas.  
**Feature Impact:** La no implementación o el fallo de esta historia impactaría directamente la capacidad de ofrecer productos de seguro flexibles y a medida, limitando severamente la funcionalidad central de "Gestión de Cotizaciones".  
**Critical Dependencies:** El cálculo de la prima final y la generación del documento de la póliza dependen directamente de la configuración de coberturas definida en esta historia.  
**Recommended Priority:** Sprint actual.
