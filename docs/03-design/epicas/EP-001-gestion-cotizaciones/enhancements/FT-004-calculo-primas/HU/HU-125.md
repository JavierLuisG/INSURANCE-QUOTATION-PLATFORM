## 2. Enabled Capability
**CAP-001:** Gestión del Proceso de Cálculo de Prima
**Business Value:** Permite a los usuarios obtener los resultados financieros de las ubicaciones válidas de su cotización, lo cual es un paso crítico para la finalización y emisión de pólizas.
**Requires:** CAP-XXX (Validación de Ubicaciones)
**Enables:** CAP-XXX (Visualización de Resultados de Cálculo de Prima), CAP-XXX (Emisión de Póliza)
**Orchestrates:** Servicio de Cálculo de Primas (interno o externo)

## 3. User Story
Como usuario,
Quiero solicitar el cálculo de la prima de mi cotización,
Para obtener los resultados financieros de las ubicaciones válidas.

## 4. Functional Description
**Description:** El usuario inicia el proceso de cálculo de prima para una cotización existente. El sistema debe identificar las ubicaciones dentro de la cotización que tienen un `estadoValidacion` de `COMPLETA` y proceder con su cálculo. Las ubicaciones con `estadoValidacion` de `INCOMPLETA` o `INACTIVA` serán excluidas del cálculo, y el sistema informará al usuario sobre estas exclusiones mediante alertas, sin detener el proceso para las ubicaciones válidas. Si no hay ubicaciones con `estadoValidacion: COMPLETA` en la cotización, el sistema debe prevenir el inicio del cálculo y notificar al usuario. Durante el proceso de inicio del cálculo, la interfaz de usuario mostrará un indicador de carga.
**Flow:** HU-XXX (Validación de Ubicaciones) → HU-125 (Iniciar Proceso de Cálculo de Prima) → HU-XXX (Mostrar Resultados de Cálculo de Prima)

## 6. Acceptance Criteria
### AC-001: Inicio de cálculo para ubicaciones válidas
**Description:** Valida que el sistema inicia el proceso de cálculo para las ubicaciones que cumplen con el criterio de `estadoValidacion: COMPLETA`.

```gherkin
Scenario: Inicio de cálculo con al menos una ubicación completa
  Given una cotización con al menos una ubicación con estadoValidacion: COMPLETA
  When el usuario hace clic en el botón "Calcular Prima"
  Then el sistema inicia el proceso de cálculo para las ubicaciones con estadoValidacion: COMPLETA
  And el botón "Calcular Prima" se deshabilita
  And la interfaz muestra un indicador de carga
```

### AC-002: Cálculo parcial y notificación de ubicaciones inválidas
**Description:** Valida que el sistema continúa el cálculo para las ubicaciones válidas, incluso si existen ubicaciones inválidas, y notifica al usuario sobre las exclusiones.

```gherkin
Scenario: Cálculo parcial ignorando ubicaciones inválidas
  Given una cotización con ubicaciones con estadoValidacion: COMPLETA y otras con estadoValidacion: INCOMPLETA o INACTIVA
  When el usuario inicia el cálculo
  Then el sistema inicia el cálculo para las ubicaciones con estadoValidacion: COMPLETA
  And el sistema excluye del cálculo las ubicaciones con estadoValidacion: INCOMPLETA o INACTIVA
  And el sistema muestra alertas informativas para las ubicaciones excluidas sin detener el proceso general
```

### AC-003: Bloqueo de cálculo sin ubicaciones válidas
**Description:** Valida que el sistema previene el inicio del cálculo si no hay ninguna ubicación elegible y notifica al usuario.

```gherkin
Scenario: Bloqueo de cálculo sin ubicaciones válidas
  Given una cotización donde todas las ubicaciones tienen estadoValidacion: INCOMPLETA o INACTIVA
  When el usuario visualiza la pantalla de cotización
  Then el botón "Calcular Prima" está deshabilitado
  And el sistema puede mostrar una notificación informativa sobre la ausencia de ubicaciones calculables
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| folio | string | yes | N/A | Formato UUID v4 | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| ubicacion.id | string | yes | N/A | Formato UUID v4 | N/A | x1y2z3a4-b5c6-7890-1234-567890ghijkl |
| ubicacion.estadoValidacion | string | yes | PENDIENTE | Debe ser uno de los valores del catálogo | COMPLETA, INCOMPLETA, INACTIVA, PENDIENTE | COMPLETA |
| ubicacion.estadoCalculo | string | yes | PENDIENTE | Debe ser uno de los valores del catálogo | PENDIENTE, EN_PROGRESO, CALCULADO, ERROR | PENDIENTE |


**BR-001:** Inclusión en Cálculo de Prima
- Description: Solo las ubicaciones con `estadoValidacion: COMPLETA` son elegibles para ser incluidas en el proceso de cálculo de prima.
- Trigger: Al iniciar el cálculo de prima para una cotización.
- Logic: `IF ubicacion.estadoValidacion == "COMPLETA" THEN INCLUIR_EN_CALCULO`.
- Implementation: Servicio de Cálculo de Primas (Backend).
- Exception: Ninguna.

**BR-002:** Exclusión y Notificación de Ubicaciones Inválidas
- Description: Las ubicaciones con `estadoValidacion: INCOMPLETA` o `INACTIVA` deben ser excluidas del cálculo de prima y el usuario debe ser notificado de esta exclusión sin interrumpir el cálculo de las ubicaciones válidas.
- Trigger: Al iniciar el cálculo de prima y detectar ubicaciones no válidas.
- Logic: `IF ubicacion.estadoValidacion == "INCOMPLETA" OR ubicacion.estadoValidacion == "INACTIVA" THEN EXCLUIR_DEL_CALCULO AND GENERAR_ALERTA_USUARIO`.
- Implementation: Servicio de Cálculo de Primas (Backend) y Frontend (UI para alertas).
- Exception: Ninguna.

**BR-003:** Prevención de Cálculo sin Ubicaciones Válidas
- Description: El proceso de cálculo no puede ser iniciado si no hay ninguna ubicación con `estadoValidacion: COMPLETA` en la cotización.
- Trigger: Intento de iniciar el cálculo.
- Logic: `IF NOT EXISTS (ubicacion WHERE ubicacion.estadoValidacion == "COMPLETA") THEN PREVENIR_INICIO_CALCULO AND NOTIFICAR_USUARIO`.
- Implementation: Frontend (deshabilitar botón) y Backend (validación en el endpoint).
- Exception: Ninguna.

## 16. Technical Notes and Risks
**Notas de Implementación (del usuario):**
- El botón "Calcular Prima" solo se deshabilita completamente cuando no existe ninguna ubicación calculable (`estadoValidacion: COMPLETA`).
- Las ubicaciones incompletas se excluyen del cálculo individualmente, no bloquean el proceso general.

**Risks:**
1.  **Consistencia de Datos del Estado de Ubicación**:
    - Descripción: Existe el riesgo de que el `estadoValidacion` de una ubicación cambie entre el momento en que la UI lo muestra y el momento en que el backend lo procesa para el cálculo.
    - Impacto: Cálculos incorrectos, incoherencias de datos o errores en el proceso.
    - Probabilidad: Media.
    - Mitigación: Implementar un mecanismo de bloqueo (optimista o pesimista) en la cotización o las ubicaciones durante el inicio del cálculo, o asegurar que el `estadoValidacion` sea inmutable una vez que la cotización alcanza cierto punto.
2.  **Rendimiento y Escalabilidad del Servicio de Cálculo**:
    - Descripción: Si el servicio de cálculo de primas es una operación pesada, su rendimiento y capacidad de escalado podrían afectar la experiencia del usuario y la estabilidad del sistema.
    - Impacto: Demoras en el inicio del cálculo, timeouts, sobrecarga del sistema.
    - Probabilidad: Media.
    - Mitigación: Implementar Circuit Breakers y retries con backoff exponencial. Asegurar que el servicio de cálculo sea asíncrono y escalable horizontalmente. Monitoreo robusto del rendimiento.
3.  **Manejo de Errores Asíncronos**:
    - Descripción: Si el proceso de cálculo es asíncrono y falla después de que el endpoint de inicio haya respondido con éxito, el usuario necesita ser notificado.
    - Impacto: El usuario no es consciente de que su cálculo falló, lo que lleva a confusión y frustración.
    - Probabilidad: Baja (si se planifica bien).
    - Mitigación: Implementar un sistema de notificaciones asíncronas (ej. webhooks, notificaciones push, emails) para informar al usuario sobre el estado final del cálculo (éxito/fallo).

## 18. Identified Assumptions
1.  **Cálculo Asíncrono**:
    - Description: Se asume que el proceso de cálculo de prima es una operación potencialmente de larga duración que se ejecuta de forma asíncrona en el backend, y el endpoint `POST /v1/quotes/{folio}/calculate` solo inicia este proceso, respondiendo rápidamente con una confirmación de inicio, sin esperar su finalización.
    - Impact if false: Si el cálculo fuera síncrono, la interfaz de usuario se bloquearía durante un tiempo prolongado o el endpoint sufriría timeouts, resultando en una mala experiencia de usuario.
    - Requires validation from: Equipo Técnico / Arquitectura.
2.  **Visibilidad y Actualización del Estado de Ubicación**:
    - Description: Se asume que el `estadoValidacion` de cada ubicación es visible y se actualiza en la interfaz de usuario de manera oportuna, permitiendo al usuario tomar decisiones informadas sobre cuándo iniciar el cálculo.
    - Impact if false: El usuario podría intentar iniciar un cálculo sin conocer el estado real de sus ubicaciones, llevando a confusión y errores.
    - Requires validation from: UX / Equipo de Frontend.
3.  **Persistencia del Estado de Cálculo**:
    - Description: Se asume que el sistema persiste el `estadoCalculo` de la cotización y/o de las ubicaciones (`EN_PROGRESO`, `CALCULADO`, `ERROR`) en la base de datos, lo que permite al usuario navegar fuera de la pantalla y luego regresar para verificar el progreso o los resultados.
    - Impact if false: El usuario perdería el contexto del cálculo si abandona la pantalla, lo que podría generar frustración o duplicidad de esfuerzos.
    - Requires validation from: Equipo Técnico / Backend.
