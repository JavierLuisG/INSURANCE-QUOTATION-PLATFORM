## 2. Enabled Capability
**CAP-005:** Ajuste de Prima por Riesgos Específicos
**Business Value:** Proporcionar una prima técnica más precisa y completa al considerar riesgos geográficos y específicos, mejorando la evaluación de riesgos y la rentabilidad del seguro.
**Requires:** CAP-004 (Cálculo de Prima Neta - implícito por HU-054)
**Enables:** CAP-006 (Cálculo de Prima Final - implícito)
**Orchestrates:** N/A

## 3. User Story
Como un **usuario**,
Quiero que el sistema **aplique los factores de Catástrofe (CAT) y FHM según la zona y condiciones de la ubicación**,
Para **ajustar la prima neta por estos riesgos específicos y obtener una prima técnica más completa**.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema ajusta la prima neta calculada previamente, incorporando factores de Catástrofe (CAT) y FHM (Fenómenos Hidrometeorológicos) basados en la ubicación geográfica y condiciones específicas de la póliza. El sistema debe identificar correctamente la zona CAT y las condiciones FHM para aplicar los factores o cuotas correspondientes, resultando en una prima técnica más robusta.
**Flow:** HU-054 (Cálculo de Prima Neta) → **HU-055 (Aplicación de Factores CAT y FHM)** → HU-056 (Cálculo de Prima Comercial Total de la Póliza)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Aplicación del factor CAT por zona
**Description:** Valida que si una ubicación pertenece a una zona CAT específica, el sistema aplica correctamente el factor CAT correspondiente a esa zona en el cálculo de la prima.

```gherkin
Scenario: Aplicación exitosa del factor CAT para una ubicación en zona de riesgo
  Given una ubicación con ID "LOC-001" que está en la Zona CAT "A"
  And la Zona CAT "A" tiene un factor CAT de 1.15
  And la prima neta calculada es de 1000
  When se calcula la prima técnica
  Then la prima técnica resultante es de 1150 (1000 * 1.15)
  And el factor CAT aplicado es 1.15
```

### AC-002: Aplicación de la cuota FHM por condiciones
**Description:** Valida que si una ubicación cumple con las condiciones para la tarifa FHM, el sistema aplica la cuota FHM definida en el cálculo de la prima.

```gherkin
Scenario: Aplicación exitosa de la cuota FHM para una ubicación con condiciones de riesgo
  Given una ubicación con ID "LOC-002" que cumple con las condiciones FHM
  And la cuota FHM definida es de 50
  And la prima neta calculada (después de CAT si aplica) es de 1150
  When se calcula la prima técnica
  Then la prima técnica resultante es de 1200 (1150 + 50)
  And la cuota FHM aplicada es 50
```

### AC-003: Manejo de factores no aplicables (valores neutros)
**Description:** Valida que si los factores CAT o FHM no aplican a una ubicación, el sistema no los incluye en el cálculo o utiliza valores neutros que no alteran la prima base.

```gherkin
Scenario: No aplicación de factores CAT o FHM cuando no corresponden
  Given una ubicación con ID "LOC-003" que no está en ninguna Zona CAT
  And la ubicación "LOC-003" no cumple con las condiciones FHM
  And la prima neta calculada es de 900
  When se calcula la prima técnica
  Then la prima técnica resultante es de 900
  And el factor CAT aplicado es 1 (o no se aplica)
  And la cuota FHM aplicada es 0 (o no se aplica)
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| id_ubicacion | UUID | yes | N/A | Formato UUID válido | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| zona_cat | String | no | N/A | Debe coincidir con una zona CAT definida en el catálogo | CatalogoZonasCAT | A, B, C |
| factor_cat_aplicado | Decimal | yes | 1.0 | Mayor o igual a 1.0 | N/A | 1.15 |
| cumple_condiciones_fhm | Boolean | yes | false | True o False | N/A | true |
| cuota_fhm_aplicada | Decimal | yes | 0.0 | Mayor o igual a 0.0 | N/A | 50.0 |
| prima_neta_base | Decimal | yes | N/A | Mayor que 0.0 | N/A | 1000.0 |
| prima_tecnica | Decimal | yes | N/A | Mayor que 0.0 | N/A | 1200.0 |


**BR-001:** Aplicación del Factor CAT
- Description: Si una ubicación se identifica dentro de una zona CAT, se debe aplicar el factor CAT correspondiente a esa zona como un multiplicador sobre la prima neta.
- Trigger: Durante el cálculo de la prima técnica, después de obtener la prima neta.
- Logic: `IF ubicacion.zona_cat IS NOT NULL THEN prima_intermedia = prima_neta_base * obtenerFactorCAT(ubicacion.zona_cat) ELSE prima_intermedia = prima_neta_base`
- Implementation: Servicio de aplicación de factores.
- Exception: Si la zona CAT no está definida o no se encuentra el factor.

**BR-002:** Aplicación de la Cuota FHM
- Description: Si una ubicación cumple con las condiciones predefinidas para FHM, se debe sumar una cuota fija FHM a la prima (después de aplicar el factor CAT).
- Trigger: Durante el cálculo de la prima técnica, después de aplicar el factor CAT.
- Logic: `IF ubicacion.cumple_condiciones_fhm IS TRUE THEN prima_tecnica = prima_intermedia + obtenerCuotaFHM() ELSE prima_tecnica = prima_intermedia`
- Implementation: Servicio de aplicación de factores.
- Exception: Si no se puede determinar si cumple las condiciones FHM.

## 13. Edge Cases and Exceptions
### Case 1: Ubicación sin datos de zona CAT o FHM
```gherkin
Scenario: Cálculo de prima para ubicación con información incompleta de riesgo
  Given una ubicación con ID "LOC-004" para la cual no se puede determinar la Zona CAT
  And la ubicación "LOC-004" no cumple con las condiciones FHM
  And la prima neta calculada es de 1200
  When se calcula la prima técnica
  Then la prima técnica resultante es de 1200
  And se registra un warning sobre la imposibilidad de determinar la Zona CAT
```

### Case 2: Factor CAT o Cuota FHM con valor cero o indefinido
```gherkin
Scenario: Manejo de factores con valores no válidos o cero
  Given una ubicación en Zona CAT "Z" con un factor CAT de 0.0 (inválido)
  And la prima neta calculada es de 1000
  When se calcula la prima técnica
  Then el sistema usa el factor neutro de 1.0 para CAT
  And se registra un error o warning sobre el factor CAT inválido
  And la prima técnica resultante es 1000 (si solo CAT es 0)
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Identificación incorrecta de zona CAT/condiciones FHM**:
    -   Description: Un error en la lógica o en los datos de entrada para identificar la zona CAT o si cumple las condiciones FHM podría llevar a un cálculo de prima técnica incorrecto.
    -   Impact: Prima incorrecta, riesgo de suscripción, pérdida de ingresos o competitividad.
    -   Probability: Media
    -   Mitigation: Implementar pruebas unitarias robustas, pruebas de integración con los servicios de geolocalización/condiciones, validación de datos de entrada, y auditoría de los factores aplicados.
2.  **Rendimiento del servicio de cálculo**:
    -   Description: Si la lógica de aplicación de factores es compleja o depende de múltiples consultas a servicios externos, podría impactar la latencia del cálculo.
    -   Impact: Mala experiencia de usuario, retrasos en la emisión de pólizas.
    -   Probability: Baja
    -   Mitigation: Optimización del algoritmo, caching de factores y tarifas, monitoreo de rendimiento.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** El cálculo de la prima técnica es fundamental para la correcta evaluación del riesgo y la viabilidad financiera de cada póliza. Un error aquí puede tener un impacto significativo en la rentabilidad y el cumplimiento normativo.
**Feature Impact:** Sin esta historia, la funcionalidad de "Cálculo de Prima de Seguro" sería incompleta y las primas calculadas no reflejarían los riesgos específicos de catástrofe y fenómenos hidrometeorológicos, llevando a suscripciones sub-optimizadas.
**Critical Dependencies:** Todas las historias que dependen de una prima técnica correcta (ej. cálculo de prima final, emisión de póliza, reportes de riesgo).
**Recommended Priority:** Sprint actual o siguiente.
