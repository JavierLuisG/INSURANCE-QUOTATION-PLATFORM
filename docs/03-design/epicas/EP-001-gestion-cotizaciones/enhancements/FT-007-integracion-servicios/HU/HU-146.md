## 3. User Story
Como sistema,
Quiero obtener los catálogos de clasificación de riesgo y garantías desde `Plataforma-core-ohs` (o su simulación),
Para permitir la configuración detallada de coberturas y la evaluación de riesgo.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad del sistema para consumir catálogos de clasificación de riesgo y garantías desde un servicio externo (`Plataforma-core-ohs`). El objetivo es integrar estos datos en el cotizador para facilitar la configuración de productos de seguros y la evaluación de riesgo asociada. Los catálogos son menos voluminosos y de actualización menos frecuente, lo que implica una estrategia de consumo adecuada para estas características.
**Flow:** HU-092 (Configurar Mock Server Base) → HU-146 (Consumir Catálogos) → HU-XXX (Configurar Coberturas) / HU-YYY (Evaluar Riesgo)

**BR-001:** Mapeo de Catálogos Externos
- Description: Esta regla asegura que la estructura de datos de los catálogos de clasificación de riesgo y garantías recibidos de `Plataforma-core-ohs` se transforma y valida para ajustarse al modelo de datos interno del cotizador.
- Trigger: Ejecución de la consulta y recepción de respuesta del servicio `Plataforma-core-ohs`.
- Logic: Los datos JSON recibidos deben ser parseados y sus campos mapeados a los atributos correspondientes del modelo de datos de catálogos del cotizador. Se deben aplicar validaciones de tipo y formato.
- Implementation: Capa de Integración / Adaptador para `Plataforma-core-ohs`.
- Exception: Si los datos recibidos no cumplen con el esquema esperado o son inconsistentes, se debe registrar un error y posiblemente descartar la actualización.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Latencia de `Plataforma-core-ohs`**:
    *   Descripción: Si `Plataforma-core-ohs` no está disponible o tiene alta latencia, el cotizador no podrá obtener catálogos actualizados o sufrirá degradación de rendimiento.
    *   Impacto: Alto. Afecta la capacidad de configurar productos y evaluar riesgos con datos correctos.
    *   Probabilidad: Media.
    *   Mitigación: Implementación de Circuit Breaker, políticas de reintento, cacheo de la última versión válida de los catálogos en el cotizador.
2.  **Cambios en el Contrato de API de `Plataforma-core-ohs`**:
    *   Descripción: Cambios inesperados en el esquema de los catálogos de `Plataforma-core-ohs` sin previo aviso.
    *   Impacto: Medio. Podría romper la integración y el mapeo de datos.
    *   Probabilidad: Baja.
    *   Mitigación: Comunicación fluida con el equipo de `Plataforma-core-ohs`, versionado de APIs, pruebas de integración automatizadas.

## 17. Criticality
**Criticality Level:** Media
**Justification:** La historia es fundamental para permitir la configuración de coberturas y la evaluación de riesgo. Sin embargo, los catálogos suelen ser menos voluminosos y de actualización menos frecuente, lo que reduce la inmediatez de su criticidad en comparación con datos transaccionales.
**Feature Impact:** La no implementación o el fallo de esta historia impediría al cotizador operar con información actualizada para la configuración de productos y la evaluación de riesgo, lo que podría llevar a ofertas incorrectas o evaluaciones erróneas.
**Critical Dependencies:** Las funcionalidades de configuración de coberturas y evaluación de riesgo del cotizador.
**Recommended Priority:** Sprint actual o siguiente, dada su dependencia con funcionalidades clave.
