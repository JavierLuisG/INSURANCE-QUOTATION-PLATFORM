## 3. User Story
As a usuario,
I want ver claramente el estado actual de la cotización en la interfaz,
So that conocer su progreso en todo momento.

## 4. Functional Description
**Description:** Esta historia de usuario describe la necesidad de que el sistema muestre de manera prominente y consistente el estado actual de una cotización en la interfaz de usuario. Esto incluye asegurar que el estado se actualice dinámicamente cuando cambie y que se utilice una representación visual uniforme (por ejemplo, con colores o etiquetas) para los diferentes estados (como Borrador, Calculada, Aprobada). La visibilidad del estado debe ser constante en las pantallas de edición y consulta de la cotización.

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización prominente del estado al cargar
**Description:** Valida que, al cargar una cotización, su estado actual se muestre de forma clara y prominente en la interfaz.

```gherkin
Scenario: El estado se muestra de forma prominente al cargar una cotización
  Given una cotización existe con el estado "Borrador"
  When el usuario visualiza los datos de la cotización
  Then el estado "Borrador" se muestra de forma prominente en la interfaz
```

### AC-002: Actualización del estado en la interfaz
**Description:** Valida que, si el estado de la cotización cambia, la interfaz se actualice para reflejar este nuevo estado.

```gherkin
Scenario: El estado de la cotización se actualiza dinámicamente
  Given el usuario está visualizando una cotización con el estado "Calculada"
  And el estado de la cotización cambia a "Aprobada" en el sistema
  When la interfaz se actualiza
  Then el estado mostrado en la interfaz es "Aprobada"
```

### AC-003: Representación visual consistente del estado
**Description:** Valida que los diferentes estados de la cotización utilicen una representación visual uniforme (ej. color, etiqueta) en toda la aplicación.

```gherkin
Scenario: Representación visual consistente para los estados de la cotización
  Given una cotización con el estado "Borrador" se muestra con una etiqueta gris
  When otra cotización con el estado "Aprobada" se muestra
  Then la cotización "Aprobada" se muestra con una etiqueta verde (ejemplo de color consistente)
  And la representación visual es consistente con el patrón de diseño definido
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de datos:**
    -   Descripción: Riesgo de que el estado mostrado en el frontend no sea el estado real y actual en el backend debido a problemas de sincronización o caching.
    -   Impacto: Información errónea para el usuario, decisiones incorrectas.
    -   Probabilidad: Media
    -   Mitigación: Implementar un mecanismo de actualización en tiempo real (ej. WebSockets) o un refresco periódico, y asegurar la atomicidad de las operaciones de cambio de estado en el backend.
2.  **Complejidad del componente de estado:**
    -   Descripción: Si los estados son muy numerosos o tienen lógicas visuales complejas, el componente puede volverse difícil de mantener.
    -   Impacto: Mayor tiempo de desarrollo y mantenimiento, errores visuales.
    -   Probabilidad: Baja (dada la estimación de 1 punto de historia)
    -   Mitigación: Usar un patrón de diseño para estados (badges, etiquetas) y una configuración centralizada para la representación visual de cada estado.
