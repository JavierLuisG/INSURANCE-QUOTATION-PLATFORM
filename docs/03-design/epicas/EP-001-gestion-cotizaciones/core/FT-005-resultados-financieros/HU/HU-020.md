## 1. Identificación General / General Identification
**Feature:** FT-005: Visualización Detallada de Resultados Financieros
**Capability:** CAP-005: Gestión de Visualización de Resultados Financieros
**Actor:** Usuario
**Bounded Context:** Cotizaciones / Resultados Financieros
**Story Points:** 2

## 2. Enabled Capability
**CAP-005:** Gestión de Visualización de Resultados Financieros
**Business Value:** Proporcionar al usuario una visión global y clara del costo total de la cotización, facilitando la toma de decisiones informadas.
**Requires:** CAP-004: Cálculo y Persistencia de Primas (inferido de HU-016 y HU-018)
**Enables:** CAP-006: Análisis Detallado de Cotizaciones (ej. Comparación de cotizaciones, descarga de reportes)
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero ver un resumen claro de la prima neta y comercial total de la cotización,
para tener una visión global del costo.

## 4. Functional Description
**Description:** Esta historia de usuario permite al "Usuario" acceder a una sección específica de la cotización donde se visualizan los valores agregados de la prima neta total y la prima comercial total. Estos valores deben reflejar el último cálculo realizado y persistido para la cotización. Si la cotización aún no ha sido calculada, el sistema debe informar al usuario sobre esta situación. Los valores monetarios se presentarán con formato adecuado.
**Flow:** HU-018: Persistir resultados del cálculo de primas con la cotización → HU-020: Visualizar resumen de prima neta y comercial total → [Posiblemente, HU-XXX: Descargar reporte de cotización]

## 5. Expected Results


| element | description |
|---|---|
| Data | Se recuperan la 'Prima Neta Total' y la 'Prima Comercial Total' asociadas a la cotización. |
| States | El estado de la cotización se consulta para determinar si el cálculo de primas ha sido ejecutado. La interfaz pasa de un estado 'sin cálculo' a 'resultados mostrados'. |
| Notifications | Se muestra un mensaje modal o en línea indicando 'El cálculo de la cotización no ha sido ejecutado' si aplica. |
| Integrations | El frontend consume la API de cotizaciones del backend para obtener los resultados financieros. |
| Kafka | No aplica directamente para esta historia de visualización. |
| Logs | Se registran logs de nivel INFO para la consulta exitosa de resultados y logs de nivel WARN/ERROR si la consulta falla o si los datos no están disponibles. |
| UI | El 'Componente de resumen de primas totales' se renderiza mostrando los valores o el mensaje de estado. Los valores se muestran con formato de moneda y decimales. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización de primas tras cálculo
**Description:** Valida que, una vez que la cotización ha sido calculada, la sección de resultados financieros muestra correctamente la prima neta total y la prima comercial total.

```gherkin
Scenario: Mostrar primas totales después de un cálculo exitoso
  Given una cotización con resultados de cálculo de primas persistidos
  When el usuario accede a la sección de resultados financieros de la cotización
  Then se muestran la "Prima Neta Total" y la "Prima Comercial Total" con su formato monetario
```

### AC-002: Consistencia de los valores mostrados
**Description:** Asegura que los valores de prima neta y comercial mostrados corresponden al último cálculo realizado y persistido para la cotización.

```gherkin
Scenario: Los valores mostrados corresponden al último cálculo
  Given una cotización con múltiples cálculos, siendo el último el ID "CALC_ABC"
  And los resultados del cálculo "CALC_ABC" son Prima Neta = $1000 y Prima Comercial = $1200
  When el usuario consulta la sección de resultados financieros
  Then la "Prima Neta Total" mostrada es $1000
  And la "Prima Comercial Total" mostrada es $1200
```

### AC-003: Mensaje cuando no hay cálculo
**Description:** Verifica que, si la cotización no ha sido calculada previamente, se muestra un mensaje informativo al usuario.

```gherkin
Scenario: Mensaje cuando la cotización no ha sido calculada
  Given una cotización que aún no ha tenido un cálculo de primas ejecutado
  When el usuario accede a la sección de resultados financieros de la cotización
  Then se muestra un mensaje indicando "El cálculo de la cotización no ha sido ejecutado"
  And no se muestran valores de prima neta o comercial
```

### AC-004: Formato de valores monetarios
**Description:** Valida que los valores de las primas se presentan con el formato de moneda y decimales apropiados.

```gherkin
Scenario: Formato correcto de valores monetarios
  Given una cotización con Prima Neta Total = 123456.78 y Prima Comercial Total = 987654.321
  When el usuario visualiza los resultados financieros
  Then la "Prima Neta Total" se muestra como "$123.456,78" (o formato local equivalente)
  And la "Prima Comercial Total" se muestra como "$987.654,32" (o formato local equivalente, redondeado a dos decimales)
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| cotizacionId | UUID | yes | N/A | Formato UUID válido | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| primaNetaTotal | Decimal | no | 0.00 | Mayor o igual a cero, hasta 2 decimales | N/A | 1500.75 |
| primaComercialTotal | Decimal | no | 0.00 | Mayor o igual a cero, hasta 2 decimales | N/A | 1800.90 |
| estadoCalculo | String | yes | PENDIENTE | Valores permitidos: PENDIENTE, CALCULADO, ERROR | ESTADOS_CALCULO_COTIZACION | CALCULADO |


**BR-001:** Valores del Último Cálculo
- Description: Los valores de prima neta y comercial total mostrados deben corresponder siempre al resultado del último cálculo exitoso y persistido para la cotización.
- Trigger: Al cargar la sección de resultados financieros de una cotización.
- Logic: `SELECT primaNetaTotal, primaComercialTotal FROM resultados_calculo WHERE cotizacionId = :cotizacionId ORDER BY fechaCalculo DESC LIMIT 1`
- Implementation: Servicio de consulta de cotizaciones en el backend.
- Exception: Si no existen resultados de cálculo, se considera que la cotización no ha sido calculada.

**BR-002:** Formato de Moneda
- Description: Los valores de prima neta y comercial total deben presentarse con el formato de moneda local y dos decimales.
- Trigger: Al renderizar los valores en la interfaz de usuario.
- Logic: Aplicar el formateador de moneda configurado para la localidad del usuario (ej. `Intl.NumberFormat('es-ES', { style: 'currency', currency: 'EUR' })`).
- Implementation: Componente de frontend.
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:** El usuario navega a la ficha de una cotización específica → Selecciona la pestaña/sección "Resultados Financieros" → El sistema muestra el "Componente de resumen de primas totales" con los valores o el mensaje de estado.
**Messages/Modals:**
- **Éxito:** Valores de prima neta y comercial total mostrados claramente.
- **Advertencia:** "El cálculo de la cotización no ha sido ejecutado. Por favor, realice el cálculo para ver los resultados." (Si el estado es PENDIENTE o no hay resultados).
- **Error:** "No se pudieron cargar los resultados financieros de la cotización. Intente de nuevo más tarde." (Si hay un error en la comunicación con el backend).
**Stepper/Breadcrumbs:** La ubicación actual dentro de la navegación de la cotización debe ser visible (ej. "Cotizaciones > [ID Cotización] > Resultados Financieros").

## 11. Architecture and Technical Dependencies
- **Backend Service (API de Cotizaciones):**
    - `GET /api/cotizaciones/{cotizacionId}/resultados-financieros`: Endpoint para obtener la prima neta y comercial total, junto con el estado del cálculo.
    - Propósito: Proveer los datos necesarios al frontend.
    - Timeout: 5 segundos.
    - Retries: 1 reintento con backoff exponencial en caso de fallos de red.
- **Frontend Component (Componente de Resumen de Primas Totales):**
    - Propósito: Renderizar los datos de primas o mensajes de estado.
    - Debe ser reactivo a cambios en el estado de cálculo (ej. si el cálculo se ejecuta en segundo plano).

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de Datos:**
    -   Descripción: Los valores de prima neta y comercial mostrados podrían no coincidir con el último cálculo real si hay problemas de sincronización o caché.
    -   Impacto: Información incorrecta para el usuario, afectando la confianza y decisiones.
    -   Probabilidad: Media
    -   Mitigación: Implementar un mecanismo de invalidación de caché robusto; asegurar que la consulta siempre traiga el último registro; utilizar un identificador de versión para los resultados del cálculo.
2.  **Rendimiento de Carga:**
    -   Descripción: La consulta de resultados financieros podría ser lenta si la base de datos es grande o la API no está optimizada.
    -   Impacto: Mala experiencia de usuario, frustración, abandono.
    -   Probabilidad: Baja (para esta historia simple, pero puede escalar)
    -   Mitigación: Optimización de índices en la base de datos, caching a nivel de servicio, monitoreo de latencia.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para el valor principal de la feature FT-005, que es proporcionar una visión detallada de los resultados financieros. Sin ella, el usuario no puede obtener la información clave sobre el costo de la cotización.
**Feature Impact:** La no implementación o fallo de esta historia dejaría la feature FT-005 incompleta e inutilizable para su propósito principal, ya que no se cumpliría el objetivo de visualizar el costo global.
**Critical Dependencies:** HU-016 y HU-018 son dependencias críticas; sin el cálculo y la persistencia, esta historia no tiene datos para mostrar.
**Recommended Priority:** Sprint actual (dada su prioridad "Alta" y su papel fundamental).
