## 2. Enabled Capability
**CAP-003:** Gestión Manual de Estado de Cotizaciones
**Business Value:** Permite registrar la decisión final del cliente sobre una cotización, mejorando el seguimiento del proceso de ventas y facilitando la toma de decisiones posteriores (ej. generación de contrato, archivo de cotización).
**Requires:** CAP-002 - Cálculo y Actualización de Estado de Cotización (derivado de HU-025)
**Enables:** CAP-004 - Generación de Documentos Post-Aprobación, CAP-005 - Archivo de Cotizaciones
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero poder cambiar manualmente el estado de una cotización a "Aprobada" o "Rechazada",
para poder indicar la decisión del cliente.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario con los permisos adecuados actualizar manualmente el estado de una cotización existente. El usuario podrá seleccionar entre "Aprobada" o "Rechazada". Esta acción solo será permitida si el estado actual de la cotización es "Calculada". Si la cotización se encuentra en cualquier otro estado, el sistema impedirá el cambio o advertirá al usuario. Tras la actualización exitosa, el nuevo estado será visible en la consulta de la cotización. Opcionalmente, se podría requerir un campo de comentarios para justificar el cambio de estado.
**Flow:** HU-025 (Actualizar estado a "Calculada") → HU-026 (Cambiar estado a "Aprobada" o "Rechazada") → [US-XXX: Generar Contrato (si Aprobada)] / [US-XXX: Archivar Cotización (si Rechazada)]

## 6. Acceptance Criteria
### AC-001: Actualización de estado a "Aprobada" o "Rechazada" desde "Calculada"
**Description:** Valida que un usuario puede cambiar exitosamente el estado de una cotización de "Calculada" a "Aprobada" o "Rechazada".

```gherkin
Scenario: El usuario aprueba una cotización en estado 'Calculada'
  Given una cotización con ID "COT-001" en estado "Calculada"
  When el usuario selecciona la opción "Aprobar" para la cotización "COT-001"
  Then el estado de la cotización "COT-001" se actualiza a "Aprobada"
  And el nuevo estado es visible al consultar la cotización "COT-001"

Scenario: El usuario rechaza una cotización en estado 'Calculada'
  Given una cotización con ID "COT-002" en estado "Calculada"
  When el usuario selecciona la opción "Rechazar" para la cotización "COT-002"
  Then el estado de la cotización "COT-002" se actualiza a "Rechazada"
  And el nuevo estado es visible al consultar la cotización "COT-002"
```

### AC-002: Restricción de cambio de estado desde estados no "Calculada"
**Description:** Valida que el sistema impide o advierte al usuario al intentar cambiar el estado a "Aprobada" o "Rechazada" desde un estado diferente a "Calculada".

```gherkin
Scenario: Intento de aprobar una cotización en estado 'Pendiente'
  Given una cotización con ID "COT-003" en estado "Pendiente"
  When el usuario selecciona la opción "Aprobar" para la cotización "COT-003"
  Then el sistema impide la acción o muestra un mensaje de advertencia "No se puede aprobar una cotización en estado Pendiente."
  And el estado de la cotización "COT-003" permanece como "Pendiente"
```

### AC-003: Visibilidad del nuevo estado
**Description:** Valida que el estado actualizado de la cotización es correctamente reflejado y visible en la interfaz de usuario.

```gherkin
Scenario: Consulta de cotización con estado actualizado
  Given una cotización con ID "COT-004" cuyo estado ha sido actualizado a "Aprobada"
  When el usuario consulta la cotización "COT-004"
  Then la información de la cotización "COT-004" muestra el estado "Aprobada"
```

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Vista de Listado de Cotizaciones**: El usuario navega a la lista de cotizaciones.
2.  **Vista de Detalle de Cotización**: El usuario selecciona una cotización para ver sus detalles.
3.  **Acción de Cambio de Estado**: En la vista de detalle, si el estado es "Calculada", se habilitan botones o un menú desplegable con las opciones "Aprobar" y "Rechazar".
4.  **Confirmación (Opcional)**: Al hacer clic en "Aprobar" o "Rechazar", puede aparecer un modal de confirmación, posiblemente con un campo para añadir comentarios.
5.  **Procesamiento**: El sistema procesa la solicitud.
6.  **Actualización de UI**: Tras el éxito, se muestra un mensaje de confirmación (ej. "Cotización aprobada exitosamente") y el estado de la cotización en la UI se actualiza inmediatamente. Si hay un error o la acción no es permitida, se muestra un mensaje de error o advertencia.
**Messages/Modals:**
*   Mensaje de éxito: "Cotización [ID] actualizada a [Nuevo Estado] exitosamente."
*   Mensaje de error: "Error al actualizar la cotización [ID]. Por favor, intente de nuevo."
*   Mensaje de advertencia/restricción: "No se puede cambiar el estado de la cotización [ID] a [Nuevo Estado] porque su estado actual es [Estado Actual]."
*   Modal de confirmación: "¿Está seguro de que desea cambiar el estado de la cotización [ID] a [Nuevo Estado]?" (con campo de comentarios opcional).
**Stepper/Breadcrumbs:** N/A (no aplica directamente a esta historia, pero la navegación general de cotizaciones podría tener un breadcrumb: `Inicio > Cotizaciones > Detalle de Cotización [ID]`).

## 11. Architecture and Technical Dependencies
- **Backend - Servicio de Cotizaciones (`QuoteService`):** Contendrá la lógica de negocio para las transiciones de estado, validación de permisos y actualización en la base de datos. Expondrá un endpoint REST (ej. `PUT /api/quotes/{id}/status`) para actualizar el estado.
- **Base de Datos:** Almacenará el estado de la cotización, la fecha de actualización y el usuario que realizó el cambio.
- **Frontend - Componente de Detalle de Cotización (`QuoteDetailComponent`):** Implementará la interfaz de usuario (botones/menús) para la interacción del usuario y consumirá el endpoint del backend.
- **Máquina de Estados:** Se utilizará un patrón de diseño o librería de máquina de estados para gestionar las transiciones válidas y asegurar la integridad del flujo de estados de las cotizaciones.
- **FT-009: Implementación de Reglas de Negocio y Validaciones:** Esta funcionalidad dependerá de la correcta implementación de las reglas de negocio de transición de estado.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad de la Máquina de Estados:**
    -   Description: Si el sistema de cotizaciones tiene muchas transiciones de estado y reglas complejas, la implementación de la máquina de estados puede ser propensa a errores.
    -   Impact: Errores en las transiciones de estado, datos inconsistentes, bloqueos de procesos.
    -   Probability: Media
    -   Mitigation: Utilizar una librería probada para máquinas de estados, definir claramente todos los estados y transiciones en un diagrama, realizar pruebas exhaustivas de todas las transiciones posibles.
2.  **Manejo de Concurrencia:**
    -   Description: Múltiples usuarios intentando cambiar el estado de la misma cotización simultáneamente.
    -   Impact: Pérdida de actualizaciones, estados inconsistentes.
    -   Probability: Baja (depende del volumen de usuarios y cotizaciones)
    -   Mitigation: Implementar bloqueo optimista (versión de registro) o pesimista a nivel de base de datos para la entidad Cotización.
**Technical Debt:** [To be filled by operating team per scope and MVP]
- Considerar la implementación de un sistema de notificaciones genérico para eventos de cambio de estado, en lugar de notificaciones ad-hoc.
- La justificación del cambio de estado (campo `comments`) es opcional. Podría ser obligatorio para ciertos estados o roles en el futuro.

## 17. Criticality
**Criticality Level:** Medium
**Justification:** Permite cerrar el ciclo de vida de una cotización con la decisión del cliente, lo cual es fundamental para el seguimiento de ventas y la operatividad del negocio. Sin embargo, no bloquea otras funcionalidades críticas iniciales como el cálculo de cotizaciones.
**Feature Impact:** La no implementación o el fallo de esta historia impediría registrar la decisión final del cliente, dejando las cotizaciones en un estado "Calculada" indefinidamente y dificultando el avance en el proceso de ventas.
**Critical Dependencies:** Depende de la correcta definición de los estados de cotización y de la funcionalidad de cálculo (HU-025).
**Recommended Priority:** Sprint actual o siguiente, ya que es crucial para el flujo de trabajo post-cálculo.
