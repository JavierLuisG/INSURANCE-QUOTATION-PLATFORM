## 2. Enabled Capability
**CAP-067:** Recarga de Última Versión de Cotización
**Business Value:** Permite al usuario trabajar con la información actualizada de la cotización y reintentar sus cambios si es necesario después de un conflicto de concurrencia, mejorando la coherencia de los datos y la productividad.
**Requires:** CAP-066 (Notificación de conflicto de concurrencia)
**Enables:** Continuación del trabajo del usuario en la cotización y reintento de guardado después de un conflicto
**Orchestrates:** N/A

## 3. User Story
As a usuario,
I want poder recargar la versión más reciente de la cotización desde la base de datos después de un conflicto,
So that trabajar con la información actualizada y reintentar mis cambios si es necesario.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario actualizar la vista de una cotización a su versión más reciente almacenada en la base de datos. Esto ocurre específicamente después de que el usuario ha sido notificado de un conflicto de concurrencia. Al elegir recargar, el sistema recuperará la versión más actual de la cotización, reemplazando cualquier cambio no guardado que el usuario tuviera localmente. Es crucial que el sistema advierta al usuario sobre la pérdida de sus cambios no guardados antes de proceder con la recarga.
**Flow:** HU-066 (Notificación de conflicto) → Esta historia (Recarga de cotización) → [Visualización de la cotización actualizada con los cambios de otros usuarios y oportunidad para reintentar cambios propios].

**Description:** Asegura que la cotización recargada refleja los cambios que otros usuarios pudieron haber guardado previamente.

```gherkin

  When el sistema detecta mis cambios no guardados
```

**BR-001:** Pérdida de Cambios Locales al Recargar
- Description: Cualquier modificación realizada por el usuario en la cotización que no haya sido guardada explícitamente se perderá al ejecutar la acción de recarga, siendo reemplazada por la versión de la base de datos.
- Trigger: El usuario inicia la acción de "recargar" la cotización.
- Logic:
    ```
    IF (cotizacion.tieneCambiosNoGuardadosLocales) THEN
        MOSTRAR_ADVERTENCIA("Perderá sus cambios no guardados. ¿Desea continuar?")
        IF (usuario_confirma) THEN
            DESCARTAR_CAMBIOS_LOCALES()
            OBTENER_ULTIMA_VERSION_DB()
            ACTUALIZAR_UI()
        ELSE
            CANCELAR_OPERACION()
        END IF
    ELSE
        OBTENER_ULTIMA_VERSION_DB()
        ACTUALIZAR_UI()
    END IF
    ```

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Contexto:** El usuario está editando una cotización.
2.  **Notificación de Conflicto (HU-066):** El sistema notifica un conflicto de concurrencia (ej. a través de un modal o banner).
3.  **Acción del Usuario:** El usuario hace clic en una opción (ej. botón "Recargar" o "Descartar Cambios y Recargar").
4.  **Modal de Advertencia (AC-003):** Si hay cambios no guardados, se muestra un modal: "Al recargar, perderá los cambios no guardados en esta cotización. ¿Desea continuar?"
    *   Opciones: "Sí, Recargar" / "No, Cancelar".
5.  **Confirmación/Cancelación:**
    *   Si "Sí, Recargar": Se procede a la recarga.
    *   Si "No, Cancelar": El modal se cierra y la cotización permanece en su estado actual.
6.  **Recarga:** El sistema invoca el servicio de consulta de cotizaciones.
7.  **Visualización Actualizada:** La interfaz de usuario se refresca con la última versión de la cotización.
**Messages/Modals:**
*   Modal de advertencia: "Al recargar, perderá los cambios no guardados en esta cotización. ¿Desea continuar?" (Botones: "Sí, Recargar", "No, Cancelar").
*   Mensaje de error: "No se pudo recargar la cotización. Por favor, intente de nuevo más tarde."

## 16. Technical Notes and Risks
**Risks:**
1.  **Pérdida de datos del usuario por falta de claridad en la advertencia:**
    *   Description: Si el mensaje de advertencia es ambiguo o el usuario lo omite, podría perder trabajo importante.
    *   Impact: Frustración del usuario, posible pérdida de productividad y datos.
    *   Probability: Media.
    *   Mitigation: Diseñar un modal de advertencia claro con opciones de confirmación/cancelación explícitas y visualmente destacadas. Considerar un pequeño delay o animación para asegurar que el usuario lo vea.
2.  **Problemas de rendimiento al recargar cotizaciones grandes:**
    *   Description: Si las cotizaciones son muy extensas, la recarga y renderización en el frontend podría ser lenta.
    *   Impact: Mala experiencia de usuario, percepción de lentitud del sistema.
    *   Probability: Baja a Media (dependiendo del tamaño promedio de las cotizaciones).
    *   Mitigation: Optimizar el servicio de consulta para que sea eficiente. Implementar un indicador de carga (spinner) en la UI durante la recarga.
**Technical Debt:**
*   **Fusión automática de cambios:** La "Nota de Implementación" menciona "una opción para fusionar (si fuera más complejo)". Si esta funcionalidad no se aborda en esta historia, se podría registrar como deuda técnica para una futura mejora, ya que ofrecería una experiencia de usuario superior al evitar la pérdida de cambios locales.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta funcionalidad es crucial para la gestión de conflictos de concurrencia, asegurando que los usuarios puedan resolver situaciones donde sus datos están desactualizados. Su ausencia podría llevar a que los usuarios trabajen con información incorrecta o se vean forzados a descartar cambios manualmente de forma ineficiente.
**Feature Impact:** Sin esta historia, la funcionalidad de edición de cotizaciones sería propensa a errores de concurrencia, pudiendo llevar a la sobrescritura de datos o a que los usuarios no puedan guardar sus cambios si otro usuario ha modificado la misma cotización.
**Critical Dependencies:** HU-066 (Notificación de conflicto) es una dependencia crítica, ya que sin la notificación, el usuario no sabría cuándo utilizar esta funcionalidad.
**Recommended Priority:** Esta historia debe ser implementada en una de las próximas iteraciones, idealmente en conjunto con HU-066, para proporcionar una solución completa a los conflictos de concurrencia.

## 18. Identified Assumptions
1.  **Mecanismo de detección y notificación de conflicto de concurrencia ya existe y funciona.**
    *   Description: Se asume que el sistema ya detecta cuándo hay un conflicto de concurrencia (ej. al intentar guardar) y notifica al usuario (referencia a HU-066).
    *   Impact if false: El usuario nunca sabría cuándo necesita usar la funcionalidad de recarga, haciendo la historia inútil.
    *   Requires validation from: Equipo de Desarrollo Backend y Frontend.
2.  **La "cotización" es una entidad sobre la que múltiples usuarios pueden trabajar concurrentemente.**
    *   Description: Se asume que el escenario de negocio implica la edición compartida de cotizaciones.
    *   Impact if false: La necesidad de esta historia sería menor o inexistente si la edición es exclusivamente por un solo usuario a la vez.
    *   Requires validation from: Product Owner / Stakeholders de Negocio.
3.  **La recarga implica una sustitución completa de la vista actual, no una fusión automática.**
    *   Description: Basado en los criterios de aceptación y las notas de implementación, se asume que la recarga sobrescribe los cambios locales, en lugar de intentar una fusión inteligente de cambios, lo cual se considera una complejidad futura.
    *   Impact if false: Si los usuarios esperan una fusión, la implementación actual no cumpliría con sus expectativas y podría generar insatisfacción.
    *   Requires validation from: Product Owner, UX.
