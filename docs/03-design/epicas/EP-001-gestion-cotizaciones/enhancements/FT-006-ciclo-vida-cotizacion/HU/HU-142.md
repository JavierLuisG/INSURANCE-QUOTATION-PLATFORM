Como usuario,
Quiero ver claramente el estado actual de la cotización,
Para tener un seguimiento visual del progreso del proceso de venta.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario visualizar de forma clara y prominente el estado actual de una cotización abierta (e.g., Borrador, Calculada). El objetivo es proporcionar una indicación visual del progreso de la cotización en el proceso de venta. La interfaz debe reflejar automáticamente los cambios de estado cuando la cotización es consultada. La representación visual puede incluir colores o iconos para mejorar la claridad.
**Flow:** [Visualizar Listado de Cotizaciones] → [Visualizar Detalle de Cotización] → [Visualizar Estado Actual de la Cotización]

## 6. Acceptance Criteria
### AC-001: Visualización del estado inicial de la cotización
**Description:** Valida que, al visualizar una cotización abierta, su estado actual se muestra claramente.

```gherkin
Scenario: Visualizar una cotización abierta con su estado actual
  Given que tengo una cotización abierta con el estado "Borrador"
  When la visualizo en la interfaz
  Then se muestra una etiqueta o indicador con el texto "Borrador"
```

### AC-002: Reflejo del cambio de estado en la interfaz
**Description:** Valida que la interfaz se actualiza para mostrar el nuevo estado de la cotización si este ha cambiado.

```gherkin
Scenario: La interfaz refleja el nuevo estado de la cotización
  Given que tengo una cotización con el estado "Borrador"
  And el estado de la cotización cambia a "Calculada" en el sistema
  When consulto la cotización de nuevo
  Then la interfaz refleja el nuevo estado "Calculada"
```

### AC-003: Prominencia y facilidad de identificación del estado
**Description:** Valida que el indicador de estado sea visualmente destacado y fácil de identificar para el usuario.

```gherkin
Scenario: El estado de la cotización se muestra de forma prominente
  Given que se visualiza una cotización con su estado
  When el usuario observa la interfaz
  Then el indicador de estado es prominente, fácil de leer y de identificar (ej. con colores o iconos)
```

## 18. Identified Assumptions
1.  **Existencia de Estados de Cotización Predefinidos**
    *   Description: Se asume que existen un conjunto de estados de cotización predefinidos y que el backend los gestiona y proporciona de forma consistente.
    *   Impact if false: La UI no podrá mostrar estados significativos o correctos, o tendrá que manejar estados dinámicos no previstos.
    *   Requires validation from: Equipo de Backend y Diseño de Producto.
2.  **API de Cotizaciones Disponible y Fiable**
    *   Description: Se asume que existe una API que proporciona el estado actual de la cotización de manera fiable y con un rendimiento aceptable para ser consumido por el frontend.
    *   Impact if false: No se podrá obtener el estado para visualizar, o la visualización será lenta/errónea.
    *   Requires validation from: Equipo de Backend.
3.  **Guías de Diseño para Indicadores de Estado**
    *   Description: Se asume que existen o se definirán guías de diseño (ej. colores, iconos) para la representación visual de los diferentes estados de la cotización.
    *   Impact if false: La implementación de la visualización podría ser inconsistente o no seguir los estándares de UX del producto.
    *   Requires validation from: Equipo de Diseño UX/UI.
