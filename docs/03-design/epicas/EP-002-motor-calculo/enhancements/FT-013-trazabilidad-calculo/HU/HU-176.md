## 3. User Story
Como sistema,
Quiero persistir la prima neta, prima comercial y el desglose por ubicación como parte del documento de cotización en MongoDB,
Para que los resultados financieros sean intrínsecos a la cotización.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad del sistema para almacenar los resultados del cálculo de la prima (prima neta total, prima comercial total y el desglose por ubicación) directamente dentro del documento de cotización existente en la base de datos MongoDB. Esto asegura que toda la información financiera relevante esté consolidada con la cotización.
**Flow:** HU-172 (Calcular Prima Comercial Total) → HU-128 (Persistir Resultados del Cálculo de Prima) → HU-176 (Persistir Prima Neta y Comercial en Cotización)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Persistencia de Resultados de Prima
**Description:** Validar que los valores calculados de prima neta total, prima comercial total y el desglose por ubicación se añaden correctamente al documento de cotización tras el cálculo.

```gherkin
Scenario: El sistema persiste los valores de prima en la cotización
  Given se ha completado el cálculo de la prima neta, prima comercial y el desglose por ubicación
  When se guardan los resultados
  Then los valores de prima neta total, prima comercial total y el desglose por ubicación se añaden al documento de la cotización
```

### AC-002: Recuperación de Cotización con Resultados
**Description:** Verificar que al consultar el documento de cotización, este contiene todos los resultados del cálculo de prima persistidos.

```gherkin
Scenario: La cotización recuperada contiene todos los resultados del cálculo
  Given el documento de cotización con los resultados de prima persistidos se consulta
  When se recupera el documento de cotización
  Then contiene todos los resultados del cálculo de prima (neta total, comercial total, desglose por ubicación)
```

### AC-003: Validación de Tipos de Datos
**Description:** Asegurar que los datos de prima se persisten con los tipos de datos correctos en la base de datos.

```gherkin
Scenario: Los resultados se persisten con los tipos de datos correctos
  Given los resultados de prima están listos para ser persistidos
  When se guarda la cotización
  Then los valores de prima neta total y prima comercial total se aseguran como tipos numéricos/decimales
  And el desglose por ubicación se asegura como un tipo de datos estructurado (ej. array de objetos)
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| prima_neta_total | Decimal | yes | 0.00 | Debe ser un valor numérico positivo con hasta dos decimales. | N/A | 1250.75 |
| prima_comercial_total | Decimal | yes | 0.00 | Debe ser un valor numérico positivo con hasta dos decimales. | N/A | 1500.90 |
| desglose_por_ubicacion | Array de Objetos | yes | [] | Array de objetos, cada objeto debe contener 'ubicacion_id', 'prima_neta_ubicacion' (Decimal) y 'prima_comercial_ubicacion' (Decimal). | N/A | [{"ubicacion_id": "LOC001", "prima_neta_ubicacion": 600.50, "prima_comercial_ubicacion": 700.60}, {"ubicacion_id": "LOC002", "prima_neta_ubicacion": 650.25, "prima_comercial_ubicacion": 800.30}] |


**BR-001:** Validación de Tipos de Datos para Primas
- Description: Asegura que los valores de prima neta y comercial, tanto totales como por ubicación, se persisten como tipos numéricos (decimales) para mantener la precisión financiera.
- Trigger: Al intentar guardar el documento de cotización con los resultados de prima.
- Logic: Validar que `prima_neta_total`, `prima_comercial_total`, `prima_neta_ubicacion` y `prima_comercial_ubicacion` son valores numéricos y cumplen con el formato decimal esperado.
- Implementation: Servicio de Repositorio de Cotizaciones.
- Exception: Si los tipos de datos no son correctos, se debe lanzar una excepción de validación y la operación de guardado debe fallar.

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Impacto en el Esquema de MongoDB
    -   **Descripción:** La adición de nuevos campos al documento de cotización puede requerir una migración de esquema o un manejo cuidadoso de documentos existentes si no se usa un esquema flexible.
    -   **Impacto:** Fallos en la lectura/escritura de cotizaciones, inconsistencia de datos.
    -   **Probabilidad:** Media
    -   **Mitigación:** Diseñar el esquema de datos con flexibilidad desde el inicio (según las notas de implementación). Realizar pruebas exhaustivas con datos existentes. Considerar un enfoque de "schema-on-read" si la base de datos lo permite.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La historia es fundamental para que los resultados financieros (prima neta y comercial) sean una parte intrínseca y permanente del documento de cotización, lo cual es vital para la contabilidad, auditoría y análisis de negocio.
**Feature Impact:** Sin la implementación de esta historia, las cotizaciones carecerán de sus datos financieros clave, haciendo que la funcionalidad de "Cotización" sea incompleta y los resultados financieros no estén disponibles con la cotización.
**Critical Dependencies:** HU-128, HU-172, y cualquier historia que dependa de la disponibilidad de los datos de prima dentro del documento de cotización.
**Recommended Priority:** Sprint actual / Inmediata (dada la prioridad "Alta" y la dependencia de otras HUs).
