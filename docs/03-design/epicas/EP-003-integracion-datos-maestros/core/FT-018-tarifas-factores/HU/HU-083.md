## 2. Enabled Capability
**CAP-101:** Obtener Factores Técnicos para Cálculo de Coberturas
**Business Value:** Permite aplicar cálculos de prima precisos y específicos para coberturas de equipo electrónico, asegurando la valoración correcta del riesgo y la oferta competitiva.
**Requires:** CAP-090 (Ej. Selección de Equipo Electrónico para Cotización, derivado de HU-068)
**Enables:** CAP-102 (Ej. Aplicar Cálculos de Prima de Equipo Electrónico)
**Orchestrates:** Servicio externo `Plataforma-core-ohs`

## 3. User Story
Como un **sistema**,
Quiero **consultar los factores técnicos para equipo electrónico desde el servicio `Plataforma-core-ohs` (o su mock)**,
Para que **se puedan aplicar los cálculos específicos para este tipo de cobertura**.

## 4. Functional Description
**Description:** El sistema, durante el proceso de cotización de una póliza que incluye cobertura para equipo electrónico, necesita obtener factores técnicos específicos para dicho equipo. Estos factores son esenciales para realizar los cálculos de prima correctos. La historia describe la interacción con el servicio `Plataforma-core-ohs` para recuperar esta información, utilizando la clase y el nivel de zona del equipo como parámetros de consulta. En caso de no obtener factores específicos, el sistema debe tener un mecanismo de respaldo, ya sea un factor por defecto o la generación de una alerta.
**Flow:** HU-068 (Selección de Equipo Electrónico) → **HU-083 (Consultar Factores Técnicos)** → HU-XXX (Aplicar Cálculos de Prima)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Consulta de Factores Técnicos al Servicio Externo
**Description:** Valida que el sistema realiza la llamada al servicio `Plataforma-core-ohs` cuando se cotiza equipo electrónico y se requieren factores técnicos.

```gherkin
Scenario: El sistema consulta el servicio externo para obtener factores técnicos
  Given se está cotizando un equipo electrónico con 'clase_equipo' "TELEFONO_MOVIL" y 'nivel_zona' "A"
  When el sistema necesita los factores técnicos para este equipo
  Then el sistema debe consultar el servicio 'Plataforma-core-ohs' con los parámetros "TELEFONO_MOVIL" y "A"
```

### AC-002: Aplicación Exitosa de Factores Recibidos
**Description:** Valida que, si la consulta al servicio externo es exitosa y devuelve factores, estos son pasados al módulo de cálculo.

```gherkin
Scenario: Los factores técnicos recibidos se aplican correctamente
  Given la consulta al servicio 'Plataforma-core-ohs' para un equipo electrónico fue exitosa
  And el servicio devolvió los factores técnicos: {"factor_desgaste": 0.8, "factor_riesgo": 1.2}
  When los datos se reciben en el sistema
  Then el módulo de cálculo debe recibir y utilizar estos factores para la cobertura de equipo electrónico
```

### AC-003: Manejo de Factores No Encontrados
**Description:** Valida que el sistema maneja correctamente el escenario donde el servicio externo no devuelve factores específicos para una clase de equipo, utilizando un factor por defecto o generando una alerta.

```gherkin
Scenario: El sistema utiliza un factor por defecto si no se encuentran factores específicos
  Given la consulta al servicio 'Plataforma-core-ohs' para un equipo electrónico no devolvió factores específicos
  When el sistema procesa la respuesta
  Then se debe utilizar un factor por defecto para la clase de equipo en cuestión
  And se debe generar una alerta (ej. log de advertencia) informando el uso del factor por defecto
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| id_cotizacion | UUID | yes | N/A | UUID válido | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| clase_equipo | String | yes | N/A | No vacío, valor de catálogo | CLASES_EQUIPO_ELECTRONICO | TELEFONO_MOVIL |
| nivel_zona | String | yes | N/A | No vacío, valor de catálogo | NIVELES_ZONA | A |
| factores_tecnicos | JSON Object | no (retornado) | {} | Estructura JSON con claves y valores numéricos esperados | N/A | { 'factor_desgaste': 0.8, 'factor_riesgo': 1.2 } |
| factor_por_defecto | Decimal | no (interno) | 1.0 | Mayor que 0 | N/A | 1.0 |


**BR-001:** Determinación de Factores Técnicos por Clase y Zona
- Description: Los factores técnicos para el cálculo de la prima de equipo electrónico deben ser consultados en base a la `clase_equipo` y el `nivel_zona` del mismo.
- Trigger: Cuando se inicia el proceso de cálculo de prima para un equipo electrónico.
- Logic: `CALL Plataforma-core-ohs/factores?clase={clase_equipo}&zona={nivel_zona}`
- Implementation: Módulo de consulta de factores.
- Exception: Si el servicio no devuelve factores específicos, se aplica BR-002.

**BR-002:** Uso de Factor por Defecto
- Description: Si el servicio `Plataforma-core-ohs` no proporciona factores técnicos para una combinación específica de `clase_equipo` y `nivel_zona`, el sistema debe utilizar un factor por defecto preestablecido.
- Trigger: Después de una consulta fallida o sin resultados específicos al servicio de factores.
- Logic: `IF (factores_recibidos_es_vacio OR factores_recibidos_es_nulo) THEN usar factor_por_defecto ELSE usar factores_recibidos`
- Implementation: Módulo de consulta de factores / Módulo de cálculo.
- Exception: Si no hay factor por defecto definido, se debe generar un error crítico y detener el cálculo.

## 11. Architecture and Technical Dependencies
- **`Plataforma-core-ohs` (Servicio REST):**
    - **Propósito:** Proveer los factores técnicos específicos para equipo electrónico.
    - **Endpoint:** `/api/v1/factores-tecnicos/equipo-electronico`
    - **Timeout:** 5 segundos.
    - **Retries:** 2 reintentos con backoff exponencial.
- **Cliente API REST:** Componente interno para realizar las llamadas HTTP salientes.
- **Módulo de consulta de factores:** Lógica de negocio para construir la solicitud, manejar la respuesta y aplicar la lógica de factor por defecto.
- **Repositorio de factores (interno):** Podría ser necesario para almacenar el factor por defecto o para un caché local de factores frecuentemente consultados (no explícito en la historia, pero posible optimización).
- **Circuit Breaker:** Implementar un Circuit Breaker para `Plataforma-core-ohs` para manejar fallos del servicio externo de manera resiliente.

## 13. Edge Cases and Exceptions
### Case 1: Servicio `Plataforma-core-ohs` no disponible o con errores internos
```gherkin

  When el sistema intenta consultar los factores técnicos
  Then el sistema debe intentar reintentar la llamada un número predefinido de veces
  And si todos los reintentos fallan, el sistema debe utilizar el factor por defecto (BR-002)
  And se debe registrar un error crítico y activar el Circuit Breaker
```

### Case 2: Respuesta del servicio `Plataforma-core-ohs` con datos inválidos o formato inesperado
```gherkin
Scenario: El servicio externo devuelve datos con formato inválido
  Given la consulta al servicio 'Plataforma-core-ohs' es exitosa
  And el servicio devuelve una respuesta que no cumple con el contrato esperado (ej. factor no numérico)
  When el sistema intenta procesar los datos
  Then el sistema debe registrar un error de validación de datos
  And el sistema debe utilizar el factor por defecto (BR-002)
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Latencia de `Plataforma-core-ohs`:**
    *   Descripción: La alta dependencia de un servicio externo puede introducir puntos de fallo y latencia en el proceso de cotización.
    *   Impacto: Retrasos en la cotización, cálculos incorrectos si el servicio falla y no se aplica el fallback.
    *   Probabilidad: Media.
    *   Mitigación: Implementación de Circuit Breaker, reintentos, caché local (opcional), monitoreo proactivo del servicio externo.
2.  **Consistencia de Datos entre Sistemas:**
    *   Descripción: Posibles discrepancias en la definición de `clase_equipo` o `nivel_zona` entre el sistema de cotización y `Plataforma-core-ohs`.
    *   Impacto: Fallos en la consulta de factores, uso incorrecto de factores por defecto.
    *   Probabilidad: Media.
    *   Mitigación: Acuerdos claros de contrato de API, validación de catálogos compartidos, mapeo explícito de valores si es necesario.

**Technical Debt:**
- La utilización de un mock para `Plataforma-core-ohs` inicialmente puede generar deuda técnica si no se valida exhaustivamente contra el servicio real antes de producción.

## 17. Criticality
**Criticality Level:** Media
**Justification:** La historia es fundamental para el cálculo preciso de la prima del equipo electrónico. Sin embargo, su criticidad se modera por la existencia de un mecanismo de factor por defecto, que permite que el sistema continúe operando (aunque con menor precisión) incluso si los factores específicos no están disponibles.
**Feature Impact:** La no implementación o fallo de esta historia resultaría en cálculos de prima incorrectos o imposibilidad de cotizar equipo electrónico, afectando la competitividad y la gestión de riesgos.
**Critical Dependencies:** El servicio `Plataforma-core-ohs` y la disponibilidad de un factor por defecto.
**Recommended Priority:** Sprint actual (dado que está en Backlog y es de prioridad Media).

## 18. Identified Assumptions
1.  **Contrato de API Estable:**
    *   Description: Se asume que el contrato de la API de `Plataforma-core-ohs` para la consulta de factores técnicos es estable y bien documentado, y que no cambiará sin previo aviso y coordinación.
    *   Impact if false: Ruptura de la integración, errores en tiempo de ejecución, necesidad de refactorización constante.
    *   Requires validation from: Equipo de `Plataforma-core-ohs`.
2.  **Disponibilidad de Factor por Defecto:**
    *   Description: Se asume que siempre existirá un factor por defecto configurado y accesible en el sistema para ser utilizado como fallback.
    *   Impact if false: El sistema no podría continuar con el cálculo si los factores específicos no se encuentran, resultando en un fallo crítico.
    *   Requires validation from: Equipo de Producto / Negocio.
3.  **Coherencia de Catálogos:**
    *   Description: Se asume que los catálogos de `clase_equipo` y `nivel_zona` utilizados por el sistema de cotización son consistentes con los que maneja `Plataforma-core-ohs`.
    *   Impact if false: La consulta de factores podría devolver "no encontrado" frecuentemente, resultando en un uso excesivo del factor por defecto o errores.
    *   Requires validation from: Equipo de Producto / Arquitectura de Datos.
