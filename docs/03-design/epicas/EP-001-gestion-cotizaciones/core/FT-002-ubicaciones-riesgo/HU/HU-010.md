**Actor:** Usuario

## 2. Enabled Capability
**CAP-015:** Gestión de Alertas de Validación de Ubicaciones
**Business Value:** Reduce errores en los datos de ubicación, mejora la experiencia del usuario al guiarlo en la corrección de información, y acelera el proceso de completado de cotizaciones.
**Requires:** CAP-010 - Gestión de Ubicaciones, CAP-012 - Validación de Datos de Cotización (implícito por FT-009)
**Enables:** CAP-020 - Finalización y Guardado de Cotización
**Orchestrates:** N/A

## 3. User Story
Como un usuario,
Quiero ver alertas visuales si una ubicación tiene datos incompletos o inválidos,
Para saber qué información necesita ser corregida.

## 4. Functional Description
**Description:** Esta historia de usuario permite a los usuarios identificar rápidamente las ubicaciones dentro de una cotización que tienen datos incompletos o que no cumplen con las reglas de validación. El sistema mostrará un indicador visual claro en la interfaz de usuario para señalar estas ubicaciones. Si el usuario intenta guardar la cotización con errores de validación, el sistema lo guiará o resaltará las ubicaciones problemáticas. Una vez que todos los datos requeridos y válidos son completados, el indicador visual desaparecerá.
**Flow:** [US-XXX - Creación/Edición de Ubicación] → [HU-010 - Visualizar alertas por datos incompletos en ubicaciones] → [US-XXX - Guardar Cotización con Ubicaciones Válidas]

## 5. Expected Results


| element | description |
|---|---|

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Indicador visual para ubicaciones con datos incompletos
**Description:** Valida que si una ubicación tiene campos obligatorios sin completar, se muestra un indicador visual en su pestaña o sección correspondiente.

```gherkin
Scenario: Una ubicación con campos obligatorios incompletos muestra un indicador visual
  Given que existe una cotización con una ubicación que tiene campos obligatorios sin completar
  When el usuario está en la vista de la cotización
  Then se muestra un indicador visual (ej. icono de advertencia o color) en la pestaña o sección de esa ubicación
```

### AC-002: Redirección/Resaltado al intentar guardar con errores de validación
**Description:** Valida que si una ubicación tiene errores de validación al intentar guardar la cotización, el sistema redirige o resalta la ubicación con problemas.

```gherkin
Scenario: Intentar guardar una cotización con ubicaciones inválidas
  Given que existe una cotización con una o más ubicaciones que contienen errores de validación
  When el usuario intenta guardar la cotización
  Then el sistema redirige o resalta claramente la pestaña o sección de la primera ubicación con errores de validación
  And se muestran mensajes de error específicos para los campos inválidos
```

### AC-003: Eliminación del indicador al corregir datos
**Description:** Valida que una vez que todos los datos requeridos y válidos de una ubicación son completados y guardados, el indicador de alerta desaparece.

```gherkin
Scenario: El indicador de alerta desaparece al corregir los datos de la ubicación
  Given que una ubicación tiene un indicador visual de alerta debido a datos incompletos o inválidos
  When el usuario completa todos los campos obligatorios y corrige los errores de validación de esa ubicación
  And el usuario guarda los cambios de la ubicación
  Then el indicador visual de alerta en la pestaña o sección de esa ubicación desaparece
```

**BR-005:** Validación de Campos Obligatorios de Ubicación
- Description: Todos los campos definidos como obligatorios para una ubicación deben contener un valor.
- Trigger: Al cargar o editar una ubicación y al intentar guardar la cotización.
- Logic: `IF campo_obligatorio IS NULL OR IS_EMPTY THEN estado_validacion_ubicacion = 'INCOMPLETO'`
- Implementation: Servicio de validación de ubicaciones (parte de FT-009).
- Exception: N/A

**BR-006:** Validación de Formato de Datos de Ubicación
- Description: Los campos de la ubicación deben cumplir con formatos y rangos específicos (ej. código postal, números de teléfono, etc.).
- Trigger: Al cargar o editar una ubicación y al intentar guardar la cotización.
- Logic: `IF campo_dato_no_cumple_formato THEN estado_validacion_ubicacion = 'INVALIDO'`
- Implementation: Servicio de validación de ubicaciones (parte de FT-009).

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Vista de Cotización (Resumen):** El usuario ve un resumen de la cotización con sus secciones, incluyendo las ubicaciones.
2.  **Pestañas/Secciones de Ubicación:** Si una ubicación tiene datos incompletos/inválidos, su pestaña o sección correspondiente muestra un icono de advertencia o un color distintivo.
3.  **Selección de Ubicación:** Al hacer clic en una ubicación con alerta, el usuario es llevado a la vista de detalle de esa ubicación.
4.  **Campos Resaltados:** Dentro de la vista de detalle de la ubicación, los campos específicos con errores o incompletos están resaltados (ej. borde rojo) y muestran mensajes de error en línea.
5.  **Corrección y Guardado:** El usuario corrige los datos. Al guardar los cambios de la ubicación, si todo es válido, el indicador visual en la pestaña/sección desaparece.
6.  **Intento de Guardar Cotización Global:** Si el usuario intenta guardar la cotización completa y aún hay ubicaciones con errores, el sistema lo notifica (ej. modal de error) y lo redirige automáticamente a la primera ubicación con problemas, resaltando los campos.
**Messages/Modals:**
*   Mensajes de error en línea para campos específicos (ej. "Este campo es obligatorio", "Formato inválido").
*   Posible modal de advertencia al intentar guardar la cotización con errores.
**Stepper/Breadcrumbs:** Los indicadores visuales en las pestañas o un "stepper" de progreso de la cotización podrían mostrar el estado de validación de cada paso de ubicación.

## 11. Architecture and Technical Dependencies
- **API de Cotizaciones (Backend):** Debe proporcionar un endpoint para obtener el estado de validación de las ubicaciones y los detalles de los errores.
- **Servicio de Validación de Ubicaciones (Backend):** Responsable de aplicar las reglas de negocio (FT-009) y devolver el estado de validación.
- **Componentes UI (Frontend):** Desarrollo de componentes para mostrar iconos de alerta, resaltar campos, y manejar la navegación a las ubicaciones con errores.
- **FT-009: Implementación de Reglas de Negocio y Validaciones:** Esta historia depende de que las reglas de negocio y las validaciones para los campos de ubicación estén implementadas y funcionando correctamente en el backend.

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Consistencia de la validación entre Frontend y Backend
    - **Descripción:** Si las validaciones implementadas en el frontend para retroalimentación en tiempo real no coinciden perfectamente con las validaciones del backend (FT-009), podría haber una experiencia de usuario inconsistente (ej. el FE dice que es válido, pero el BE lo rechaza).
    - **Impacto:** Frustración del usuario, aumento de errores, necesidad de retrabajo.
    - **Probabilidad:** Media
    - **Mitigación:** Trabajar de cerca con el equipo de backend para asegurar que las reglas de validación sean las mismas y se comuniquen claramente. Considerar un enfoque de "validación en el backend y visualización en el frontend" para la fuente de verdad.
2.  **Nombre:** Rendimiento de la UI con múltiples alertas
    - **Descripción:** Si una cotización tiene muchas ubicaciones y varias de ellas tienen errores, la lógica de renderizado de alertas en el frontend podría afectar el rendimiento de la UI.
    - **Impacto:** Lentitud de la interfaz, mala experiencia de usuario.
    - **Probabilidad:** Baja (para un número típico de ubicaciones) a Media (para casos extremos).
    - **Mitigación:** Optimizar los componentes de UI, considerar la carga diferida o la virtualización de listas si el número de ubicaciones es muy alto.
**Technical Debt:** [To be filled by operating team per scope and MVP] (Por ejemplo: Uso de librerías de validación estándar, refactorización de componentes de formulario para reusabilidad.)

## 17. Criticality
**Criticality Level:** Medium
**Justification:** Aunque no impide la creación de una cotización, mejora significativamente la usabilidad y la calidad de los datos. Sin esta funcionalidad, los usuarios podrían guardar cotizaciones con datos incompletos o incorrectos, lo que llevaría a problemas posteriores en el proceso de negocio.
**Feature Impact:** La no implementación o el fallo de esta historia impactaría negativamente la experiencia del usuario en la gestión de ubicaciones, aumentando la frustración y la probabilidad de errores en los datos de las cotizaciones.
**Critical Dependencies:** FT-009 es una dependencia crítica; sin validaciones de backend, las alertas no tendrían una base.
**Recommended Priority:** Sprint actual o siguiente, ya que es una mejora de calidad de vida importante para la funcionalidad existente.

1.  **Existencia y Definición de Campos Obligatorios:**
    - Description: Se asume que ya existe una definición clara de cuáles son los "campos obligatorios" para una ubicación y cuáles son los "errores de validación" (tipos de datos, formatos, rangos).
    - Impact if false: Si no hay una definición clara, la implementación de las validaciones y las alertas visuales sería ambigua o incorrecta.
    - Requires validation from: Equipo de Producto/Negocio, Dueño de la Funcionalidad (FT-009).
2.  **API de Validación Disponible:**
    - Description: Se asume que la API de cotizaciones (o un servicio de validación específico) expondrá los resultados de las validaciones de las ubicaciones de manera granular para que el frontend pueda interpretar y mostrar las alertas correctamente.
    - Impact if false: El frontend no tendría la información necesaria para mostrar las alertas de manera precisa y en tiempo real.
    - Requires validation from: Equipo de Backend.
