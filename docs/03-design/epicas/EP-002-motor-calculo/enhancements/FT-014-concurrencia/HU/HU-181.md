## 3. User Story
Como un sistema,
Quiero que al intentar guardar una cotización, se compare la versión de la cotización en memoria con la versión en la base de datos,
Para que se detecten posibles conflictos de concurrencia.

## 4. Functional Description
**Description:** Esta historia de usuario describe el mecanismo interno mediante el cual el sistema previene conflictos de concurrencia al guardar una cotización. Cuando se inicia la operación de guardado de una cotización, el sistema primero recupera la versión actual de esa cotización directamente desde la base de datos. Posteriormente, compara esta versión recuperada con la versión de la cotización que se encuentra en la memoria del sistema (la que el usuario intentó guardar). Si ambas versiones coinciden, la operación de guardado procede. En caso contrario, si las versiones difieren, el sistema identifica un conflicto potencial, lo que implica que otro usuario o proceso ha modificado la cotización desde que fue cargada en memoria.
**Flow:** [HU-151 - Prevenir Sobrescritura con Versionado Optimista] → [HU-181 - Comparar Versiones de Cotización en Guardado] → [HU-151 - Guardar Cotización (si no hay conflicto) / HU-182 - Detectar Conflicto de Concurrencia (si hay conflicto)]

**BR-001:** Verificación de Concurrencia Optimista
- Description: Antes de persistir los cambios de una cotización, el sistema debe asegurar que la versión de la cotización en memoria es idéntica a la versión actual de la cotización en la base de datos.
- Trigger: Al intentar guardar una cotización.
- Logic:
  ```
  FUNCTION GuardarCotizacionConConcurrencia(cotizacionEnMemoria):
    cotizacionEnBD = LeerCotizacionDesdeBD(cotizacionEnMemoria.id)
    IF cotizacionEnMemoria.version == cotizacionEnBD.version THEN
      cotizacionEnMemoria.version = cotizacionEnMemoria.version + 1
      PersistirCotizacion(cotizacionEnMemoria)
      RETURN Exito
    ELSE
      LanzarExcepcionConflictoConcurrencia()
      RETURN Conflicto
  ```
- Implementation: Backend (Lógica de Control de Concurrencia en Persistencia).
- Exception: Se lanza una excepción de conflicto de concurrencia si las versiones no coinciden.

## 16. Technical Notes and Risks
**Risks:**
1.  **Rendimiento de Base de Datos:**
    - Descripción: La lectura adicional de la versión de la cotización desde la base de datos para cada operación de guardado podría introducir latencia, especialmente en entornos de alta concurrencia o con bases de datos poco optimizadas.
    - Impacto: Mayor tiempo de respuesta para el usuario, posible cuello de botella en el servicio de persistencia.
    - Probabilidad: Media.
    - Mitigación: Asegurar índices adecuados en el campo de versión y ID de cotización, optimizar la consulta de lectura, considerar estrategias de caching si el rendimiento es crítico (con cuidado de la consistencia).
2.  **Manejo de Transacciones:**
    - Descripción: Si la comparación y el guardado no se realizan dentro de la misma transacción atómica, podría haber una condición de carrera donde la versión de la BD cambie entre la lectura y la escritura.
    - Impacto: La detección de concurrencia sería ineficaz, llevando a sobreescrituras de datos.
    - Probabilidad: Alta si no se gestiona correctamente.
    - Mitigación: Asegurar que la lógica de comparación y actualización se realice en una única transacción de base de datos.
**Technical Debt:** N/A (a ser llenado por el equipo operativo según el alcance y MVP)

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es crucial para mantener la integridad y consistencia de los datos de las cotizaciones. Sin ella, múltiples usuarios podrían sobrescribir los cambios de otros sin aviso, llevando a la pérdida de información y a la frustración del usuario.
**Feature Impact:** La no implementación o el fallo de esta funcionalidad comprometería seriamente la fiabilidad de la funcionalidad de "Guardar Cotización", haciendo que el sistema sea propenso a errores de datos.
**Critical Dependencies:** HU-180 es una dependencia crítica, ya que el campo de versión es fundamental para que esta lógica funcione.
**Recommended Priority:** Sprint Actual / Inmediata.
