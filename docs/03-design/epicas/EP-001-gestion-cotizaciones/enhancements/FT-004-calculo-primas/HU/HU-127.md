## 2. Enabled Capability
**CAP-001:** Cálculo de Prima por Ubicación de Riesgo
**Business Value:** Permite la transparencia y precisión en la tarificación de pólizas al desglosar el costo por cada ubicación asegurada, facilitando la auditoría y la justificación de primas ante el cliente y los reguladores.
**Requires:** CAP-002 (Gestión de Parámetros de Cobertura), CAP-003 (Cálculo de Prima Neta Base)
**Enables:** CAP-004 (Persistencia de Primas Calculadas), CAP-005 (Visualización de Resumen de Póliza)
**Orchestrates:** Motor Central de Cálculo de Primas

## 3. User Story
Como usuario,
Quiero que el sistema calcule la prima para cada ubicación de riesgo calculable individualmente,
Para que pueda entender el desglose del costo por cada lugar asegurado.

## 4. Functional Description
**Description:** Esta historia detalla el proceso mediante el cual el sistema, específicamente el "Motor Central de Cálculo de Primas", determina la prima neta para cada ubicación de riesgo individual dentro de una póliza. El cálculo se ejecuta solo para aquellas ubicaciones cuyo `estadoValidacion` es `COMPLETA`. Durante este proceso, se aplican las tarifas base de las coberturas y los factores técnicos específicos (como los de incendio, CAT, FHM y equipo electrónico) previamente configurados para cada ubicación. El resultado final de la prima neta por ubicación debe ser almacenado y accesible para su posterior persistencia y visualización en la interfaz de usuario.
**Flow:** HU-123 (Configurar Parámetros Específicos de Cobertura) → HU-170 (Calcular Prima Neta por Ubicación) → **HU-127 (Calcular Prima por Ubicación de Riesgo)** → [US-XXX: Persistir Primas Calculadas por Ubicación] / [US-XXX: Visualizar Desglose de Primas]

**Description:** Valida que, una vez iniciado y finalizado el cálculo para una ubicación, la prima neta se determina correctamente y se confirma que la ubicación tiene el estado `COMPLETA`.

**Description:** Asegura que el cálculo de la prima por ubicación considera correctamente todas las tarifas y factores técnicos configurados, como los de incendio, CAT, FHM y equipo electrónico.

  And factores técnicos específicos (incendio, CAT, FHM, equipo electrónico) asociados a la ubicación

**BR-001: Validación de Elegibilidad de Ubicación para Cálculo**
- Description: El sistema solo debe proceder con el cálculo individual de la prima para ubicaciones de riesgo que tengan su `estadoValidacion` como `COMPLETA`.
- Trigger: Al iniciar el proceso de cálculo de prima por ubicación.
- Logic: `IF ubicacion.estadoValidacion == "COMPLETA" THEN IniciarCalculo(ubicacion) ELSE OmitirUbicacion(ubicacion) AND RegistrarAdvertencia()`
- Implementation: Motor Central de Cálculo de Primas.
- Exception: Si el estado no es `COMPLETA`, la ubicación se omite y se registra un evento de advertencia.

**BR-002: Aplicación de Tarifas Base y Factores Técnicos**
- Description: La prima neta de cada ubicación se determinará aplicando las tarifas base de las coberturas específicas y multiplicando por los factores técnicos configurados para esa ubicación.
- Trigger: Durante la ejecución del cálculo de prima para una ubicación elegible.
- Logic: `primaNetaUbicacion = Σ (cobertura.tasaBase * factoresTecnicosAplicados.incendio * factoresTecnicosAplicados.CAT * ...)`
- Implementation: Motor Central de Cálculo de Primas.

**BR-003: Persistencia y Acceso a Resultados de Cálculo**
- Description: El resultado de la prima neta calculada para cada ubicación debe ser persistido y estar disponible para consulta por otros servicios del sistema.
- Trigger: Finalización exitosa del cálculo de prima por ubicación.
- Logic: `AFTER CalculoExitoso(ubicacion, primaNeta) THEN PersistirResultado(ubicacion.id, primaNeta) AND NotificarDisponibilidad()`
- Implementation: Servicio de Persistencia de Pólizas, API de Consulta de Primas.

## 16. Technical Notes and Risks
**Technical Notes:**
- Los factores técnicos (incendio, CAT, FHM, equipo electrónico) deben ser aplicados de manera granular por cada ubicación, lo que implica que la estructura de datos para estos factores debe estar ligada directamente a la entidad `UbicacionRiesgo`.
- Se debe considerar la eficiencia del algoritmo de cálculo, especialmente si una póliza puede contener un gran número de ubicaciones de riesgo.

**Risks:**
1.  **Nombre:** Complejidad y Mantenibilidad del Motor de Cálculo
    -   **Descripción:** La lógica de cálculo de primas puede ser inherentemente compleja, incorporando múltiples factores y reglas de negocio, lo que podría dificultar su desarrollo, prueba y mantenimiento.
    -   **Impacto:** Cálculos incorrectos, errores en la tarificación, incumplimiento regulatorio, alto costo de mantenimiento.
    -   **Probabilidad:** Media
    -   **Mitigación:** Implementación de un diseño modular para el motor de cálculo, uso de un sistema de gestión de reglas de negocio (BRMS) si la complejidad lo justifica, revisión de código por expertos en seguros, extensas pruebas automatizadas (unitarias, de integración y funcionales).
2.  **Nombre:** Rendimiento en Carga de Datos y Cálculos
    -   **Descripción:** El procesamiento de un gran volumen de ubicaciones de riesgo o la recuperación de datos de configuración para cada cálculo individual podría generar cuellos de botella de rendimiento.
    -   **Impacto:** Retrasos en la emisión de pólizas, experiencia de usuario negativa, sobrecarga de recursos del sistema.
    -   **Probabilidad:** Media
    -   **Mitigación:** Optimización de consultas a la base de datos, implementación de caché para parámetros y factores, procesamiento asíncrono o en lotes para pólizas con muchas ubicaciones, pruebas de carga y estrés para identificar límites.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** El cálculo de la prima por ubicación es un componente fundamental para la correcta tarificación, emisión y gestión de pólizas de seguros. Un error o la falta de esta funcionalidad impactaría directamente la capacidad de la empresa para operar, cumplir con la regulación y generar ingresos precisos.
**Feature Impact:** Sin este cálculo detallado, la funcionalidad de "Cálculo de Primas" no puede ofrecer un desglose granular de costos, lo que impide una tarificación justa y transparente. Esto afectaría la capacidad de emitir pólizas complejas y satisfacer las expectativas del cliente.
**Critical Dependencies:** Todas las historias relacionadas con la emisión de pólizas, visualización de detalles de pólizas, auditoría de primas y cumplimiento regulatorio dependen críticamente de esta funcionalidad.
**Recommended Priority:** Sprint actual / Inmediata
