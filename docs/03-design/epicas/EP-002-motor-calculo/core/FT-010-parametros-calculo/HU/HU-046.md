## 2. Enabled Capability
**CAP-001:** Ingestión de Parámetros de Tarifa y Factores
**Business Value:** Asegurar cálculos precisos en coberturas específicas (FHM y Equipo Electrónico).
**Requires:** CAP-002 - Conectividad con Plataforma-core-ohs (o simulación)

## 3. User Story
Como administrador de parámetros,
quiero que el sistema ingeste o simule la consulta de la tarifa FHM y los factores de equipo electrónico desde `Plataforma-core-ohs`,
para asegurar cálculos precisos en estas coberturas específicas.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema obtiene (ingesta o simula la consulta) la tarifa FHM y los factores de equipo electrónico desde el servicio externo `Plataforma-core-ohs`. El propósito principal es garantizar que los datos necesarios para realizar cálculos precisos de coberturas específicas (FHM y equipo electrónico) estén disponibles y actualizados para el motor de cálculo. Se debe considerar el manejo de errores para factores nulos o inválidos, utilizando valores por defecto configurables si es necesario.
**Flow:** [Disponibilidad de Plataforma-core-ohs] → [HU-046: Ingestión de Tarifa FHM y Factores de Equipo Electrónico] → [HU-055: Aplicar Factores CAT y FHM al cálculo de primas]

### AC-001: Obtención de parámetros desde Plataforma-core-ohs

### AC-002: Disponibilidad de parámetros para el motor de cálculo
**Description:** Asegura que los parámetros cargados están disponibles y actualizados para el motor de cálculo cuando este los requiere.

```gherkin
Scenario: Los parámetros cargados están disponibles para el motor de cálculo

  When el motor de cálculo requiere estos parámetros
  Then los parámetros están disponibles y actualizados para su uso
```

### AC-003: Manejo de factores nulos o inválidos
**Description:** Confirma que el sistema maneja adecuadamente los casos en que un factor es nulo o inválido en la fuente, ya sea mediante manejo de error o el uso de un valor por defecto configurable.

```gherkin
Scenario: Manejo de factores nulos o inválidos durante la ingestión
  Given el servicio 'Plataforma-core-ohs' proporciona un factor nulo o inválido
  When el sistema ingesta dicho factor
  Then el sistema maneja el error (ej. registra un error) o utiliza un valor por defecto configurable para ese factor
```

## 7. Data and Business Rules

**BR-001:** Manejo de Factores Inválidos
- Description: Si un factor de tarifa FHM o de equipo electrónico recibido de `Plataforma-core-ohs` es nulo o inválido (ej. no numérico, menor o igual a cero), el sistema debe aplicar una estrategia de manejo.
- Trigger: Durante la ingestión de datos desde `Plataforma-core-ohs`.
- Logic: `IF factor IS NULL OR factor <= 0 THEN USE default_value_configurable ELSE USE received_factor`
- Implementation: Adaptador de integración `Plataforma-core-ohs` y Repositorio de parámetros de cálculo.
- Exception: Si no se puede obtener un valor por defecto o si el error es crítico, se debe registrar un error y posiblemente notificar.

## 16. Technical Notes and Risks
**Risks:**
1.  **Dependencia de `Plataforma-core-ohs`**:
    *   Descripción: La disponibilidad y el rendimiento de `Plataforma-core-ohs` impactan directamente en la precisión y actualización de los cálculos.
    *   Impacto: Cálculos incorrectos o desactualizados.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breaker, reintentos, cacheo de últimos valores válidos, y monitoreo de la integración.
2.  **Calidad de datos de `Plataforma-core-ohs`**:
    *   Descripción: `Plataforma-core-ohs` podría enviar datos nulos, inválidos o con formato incorrecto.
    *   Impacto: Errores en la ingestión, uso de valores incorrectos en los cálculos.
    *   Probabilidad: Media.
    *   Mitigación: Implementar validaciones robustas en el adaptador de integración y aplicar la regla de negocio BR-001 (manejo de valores por defecto).

**Technical Debt:**
- Definir cómo se manejan los valores predeterminados o los errores de datos para estos parámetros de manera centralizada y configurable (implica una HU de configuración aparte).

## 17. Criticality
**Criticality Level:** Media
**Justification:** La precisión de los cálculos de coberturas FHM y de equipo electrónico es fundamental para el negocio. Sin embargo, la ingestión puede tolerar cierta intermitencia si se utilizan valores por defecto o los últimos valores conocidos.
**Feature Impact:** Si esta historia no se implementa o falla, los cálculos para estas coberturas específicas serán incorrectos o imposibles de realizar, afectando directamente la validez de los resultados del motor de cálculo.
**Critical Dependencies:** Cualquier historia de usuario o servicio que dependa de la precisión de los cálculos de FHM y equipo electrónico.
**Recommended Priority:** Sprint actual o próximo, para no retrasar la implementación de las funcionalidades de cálculo.
