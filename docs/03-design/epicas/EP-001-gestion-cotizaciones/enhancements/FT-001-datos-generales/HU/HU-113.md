## 2. Enabled Capability
**CAP-113:** Selección de Catálogos Básicos
**Business Value:** Mejora la calidad y consistencia de los datos en la entrada de información, reduce errores manuales y acelera el proceso de creación/edición de cotizaciones, contribuyendo a una mayor eficiencia operativa.
**Requires:** CAP-144 (Consumo de Catálogos de Suscriptores, Agentes y Giros)
**Enables:** CAP-XXX (Creación y Edición de Cotizaciones), CAP-XXX (Validación de Datos de Cotización)
**Orchestrates:** Plataforma-core-ohs (o su simulación para la consulta de catálogos)

## 3. User Story
Como un **usuario**,
quiero **seleccionar opciones de catálogos básicos (Suscriptores, Agentes, Giros) en los campos correspondientes**,
para que **se asegure la consistencia de los datos y se agilice la entrada de información**.

## 4. Functional Description
**Description:** Esta historia de usuario permite a los usuarios interactuar con campos de selección en la interfaz de usuario para elegir valores de catálogos predefinidos. Al hacer clic en un campo de catálogo (como Suscriptor, Agente o Giro), el sistema consultará un servicio de referencia (`Plataforma-core-ohs`) para obtener una lista de opciones válidas. El usuario podrá seleccionar una de estas opciones, y al guardar la cotización, el ID o valor asociado se persistirá, garantizando la integridad y consistencia de los datos. Esta funcionalidad optimiza la experiencia de entrada de datos y minimiza errores.
**Flow:** HU-144 (Consumir Catálogos de Suscriptores, Agentes y Giros) → HU-113 (Seleccionar Opciones de Catálogos Básicos) → HU-XXX (Guardar/Enviar Cotización)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización de Opciones Válidas del Catálogo
**Description:** Validar que al hacer clic en un campo de selección de catálogo, el sistema muestre una lista de opciones válidas y actualizadas, obtenidas del servicio de referencia.

```gherkin
Scenario: Mostrar opciones válidas al interactuar con un campo de catálogo
  Given que estoy en el formulario de creación o edición de una cotización
  And el servicio de catálogos de 'Plataforma-core-ohs' está disponible y devuelve opciones válidas para 'Suscriptor'
  When hago clic en el campo de selección de 'Suscriptor'
  Then se muestra una lista desplegable con las opciones válidas para 'Suscriptor'
  And las opciones mostradas corresponden a los datos actuales del catálogo de referencia
```

### AC-002: Persistencia Correcta de la Selección del Catálogo
**Description:** Asegurar que el identificador o valor de la opción seleccionada del catálogo se persista correctamente en la base de datos o sistema de almacenamiento al guardar la cotización.

```gherkin
Scenario: Persistir la opción seleccionada del catálogo al guardar la cotización
  Given que estoy en el formulario de creación o edición de una cotización
  And he seleccionado la opción 'Cliente Ejemplo S.A.' (ID: 'a1b2c3d4-e5f6-7890-1234-567890abcdef') del catálogo de Suscriptores
  And he completado los demás campos requeridos de la cotización
  When guardo la cotización
  Then el campo 'id_suscriptor' de la cotización se persiste con el valor 'a1b2c3d4-e5f6-7890-1234-567890abcdef'
  And la cotización se guarda exitosamente con la referencia al catálogo
```

### AC-003: Manejo de Catálogo No Disponible o con Fallo
**Description:** Verificar que el sistema notifique al usuario de manera clara y evite la selección de valores inválidos si el servicio de catálogo no está disponible o falla al intentar cargar las opciones.

```gherkin
Scenario: Notificación y prevención de selección cuando el catálogo no está disponible
  Given que estoy en el formulario de creación o edición de una cotización
  And existe un campo de selección para 'Agente'
  And el servicio de catálogos de 'Plataforma-core-ohs' para 'Agente' no está disponible o responde con un error
  When intento hacer clic en el campo de selección de 'Agente'
  Then el sistema muestra un mensaje de notificación indicando 'No se pudieron cargar las opciones del catálogo de Agentes'
  And el campo de selección de 'Agente' no permite la entrada o selección de un valor
  And el campo 'Agente' permanece sin un valor seleccionado
```

**BR-001:** Validación de Opciones de Catálogo
- Description: Cualquier valor seleccionado para los campos de Suscriptor, Agente o Giro debe corresponder a una opción válida y actualmente activa en el catálogo de referencia (`Plataforma-core-ohs`) en el momento de la selección y al intentar guardar la cotización.
- Trigger: Al seleccionar una opción en un campo de catálogo y al intentar guardar la cotización.
- Logic:
    ```
    IF (ID_seleccionado existe y es válido en el CATÁLOGO_CORRESPONDIENTE) THEN
        PERMITIR selección y persistencia
    ELSE
        RECHAZAR selección y persistencia
        MOSTRAR mensaje de error al usuario
    END IF
    ```
- Implementation: Componentes frontend para pre-validación y servicio backend de cotizaciones para validación final.
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Inicio:** El usuario accede al formulario de "Creación/Edición de Cotización".
2.  **Interacción con Catálogo:** El usuario hace clic en un campo de selección (ej. "Suscriptor").
3.  **Carga de Opciones:** El sistema muestra un indicador de carga mientras consulta el servicio de catálogos.
4.  **Selección:** Se despliega una lista de opciones válidas. El usuario selecciona una opción.
5.  **Visualización:** La opción seleccionada se muestra en el campo.
6.  **Repetición:** El usuario repite el proceso para los campos de "Agente" y "Giro".
7.  **Continuación:** El usuario procede con la entrada de otros datos de la cotización y la guarda.
**Messages/Modals:**
*   **Mensaje de Error:** "No se pudieron cargar las opciones del catálogo de [nombre_catalogo]. Por favor, intente de nuevo más tarde." (en caso de fallo del servicio).
*   **Mensaje de Advertencia:** "No hay opciones disponibles en el catálogo de [nombre_catalogo]." (si el catálogo devuelve una lista vacía).
*   **Mensaje de Validación:** "El valor seleccionado para [nombre_campo] no es válido." (si se intenta guardar un valor no existente).
**Stepper/Breadcrumbs:** No aplica directamente a esta historia, ya que es una funcionalidad dentro de un formulario más amplio.

## 11. Architecture and Technical Dependencies
- **Plataforma-core-ohs (API de Catálogos):**
    - **Propósito:** Proporcionar los datos maestros de Suscriptores, Agentes y Giros.
    - **Timeout:** 5 segundos para la respuesta de la API.
    - **Retries:** 2 reintentos con estrategia de backoff exponencial en caso de fallos transitorios.
- **Servicio Backend de Cotizaciones:**
    - **Propósito:** Orquestar la consulta a la API de catálogos y validar/persistir los IDs seleccionados.
- **Frontend (Aplicación Web/Mobile):**
    - **Propósito:** Renderizar los componentes de selección de catálogos, manejar la interacción del usuario y mostrar los mensajes de carga/error.
- **Circuit Breaker:** Se implementará un Circuit Breaker en el servicio backend de cotizaciones para las llamadas a `Plataforma-core-ohs` para prevenir fallos en cascada debido a la indisponibilidad del servicio de catálogos.

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** **Disponibilidad y Rendimiento de `Plataforma-core-ohs`**
    -   Descripción: El servicio externo `Plataforma-core-ohs` podría experimentar interrupciones o alta latencia, lo que afectaría directamente la capacidad de los usuarios para seleccionar opciones de catálogo.
    -   Impacto: Degradación de la experiencia de usuario, imposibilidad de crear/editar cotizaciones, posible pérdida de datos si la cotización no puede ser completada.
    -   Probabilidad: Media.
    -   Mitigación: Implementar Circuit Breaker, estrategias de reintento con backoff, caching de catálogos con TTL adecuado (si los datos no son altamente volátiles), y mensajes de error claros en la UI.
2.  **Nombre:** **Consistencia de Datos entre Sistemas**
    -   Descripción: Si los datos en `Plataforma-core-ohs` cambian (ej. un Suscriptor es eliminado) mientras un usuario está creando una cotización, podría haber una inconsistencia al intentar guardar un ID obsoleto.
    -   Impacto: Errores al guardar la cotización, necesidad de reingreso de datos, frustración del usuario.
    -   Probabilidad: Baja a Media (dependiendo de la frecuencia de cambios en los catálogos).
    -   Mitigación: Validar el ID seleccionado contra el catálogo actualizado en el momento de guardar la cotización. Implementar mecanismos de notificación o refresco de caché si los catálogos son muy dinámicos.

**Technical Debt:**
*   **Simulación de Servicio Externo:** Si `Plataforma-core-ohs` no está disponible en las primeras etapas, se podría implementar una simulación temporal para permitir el desarrollo del frontend y backend de cotizaciones. Esto debería documentarse y planificarse su reemplazo.

## 17. Criticality
**Criticality Level:** High
**Justification:** Esta historia es fundamental para la usabilidad, la calidad de los datos y la eficiencia del proceso de creación/edición de cotizaciones. Sin ella, los usuarios se verían obligados a ingresar datos manualmente, lo que incrementaría drásticamente los errores, la inconsistencia de la información y el tiempo requerido para completar una cotización.
**Feature Impact:** La no implementación o un fallo crítico de esta historia paralizaría o degradaría severamente la funcionalidad principal de la gestión de cotizaciones, haciendo que el sistema sea ineficiente o inutilizable para tareas esenciales.
**Critical Dependencies:** La funcionalidad de creación y edición de cotizaciones depende directamente de la capacidad de seleccionar estos datos de forma consistente.
**Recommended Priority:** Sprint actual / Inmediata (dada su prioridad "Alta" y su impacto central en el negocio).

## 18. Identified Assumptions
1.  **Estructura y Contenido de los Catálogos**
    -   Description: Se asume que el servicio `Plataforma-core-ohs` proporcionará los catálogos (Suscriptores, Agentes, Giros) con una estructura de datos consistente (ej. un `ID` único y un campo de `nombre`/`descripción` para la visualización), y que estos datos serán relevantes y suficientes para las necesidades de la cotización.
    -   Impact if false: Se requerirán adaptaciones significativas en el frontend y backend para parsear y presentar los datos, o la funcionalidad podría no cumplir con las expectativas de negocio.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` y Arquitectos.
2.  **Volumen de Datos de Catálogo Manejable**
    -   Description: Se asume que el volumen de opciones en cada catálogo no será excesivamente grande (ej. no millones de entradas), lo que permitiría un rendimiento adecuado con componentes de selección estándar (dropdowns, autocompletados). Si el volumen es muy alto, se asume que `Plataforma-core-ohs` soportará mecanismos de paginación o búsqueda eficiente.
    -   Impact if false: Problemas de rendimiento en la UI (tiempos de carga lentos, UI no responsiva) y en el backend (consultas ineficientes).
    -   Requires validation from: Equipo de Negocio y Equipo de `Plataforma-core-ohs`.
3.  **Disponibilidad de la API de Catálogos de `Plataforma-core-ohs`**
    -   Description: Se asume que la API de `Plataforma-core-ohs` estará disponible y estable en un entorno de desarrollo/pruebas a tiempo para la implementación y pruebas de esta historia.
    -   Impact if false: Retrasos en el desarrollo y las pruebas, necesidad de implementar simulaciones temporales que luego deben ser reemplazadas.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` y Equipo de Operaciones/Infraestructura.
