## 2. Enabled Capability
**CAP-005:** Visualización y Navegación de Ubicaciones de Riesgo
**Business Value:** Proporciona una visión general clara de los riesgos asegurados en una cotización y facilita la navegación para su gestión, mejorando la eficiencia del usuario.
**Requires:** CAP-004 - Gestión de Ubicaciones de Riesgo (implícito por HU-115)
**Enables:** CAP-006 - Edición de Detalles de Ubicación de Riesgo (implícito por el segundo criterio de aceptación)
**Orchestrates:** N/A

## 3. User Story
Como un usuario,
Quiero ver un resumen de todas las ubicaciones de riesgo en mi cotización,
Para tener una visión general de los riesgos asegurados y navegar entre ellas fácilmente.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite al usuario visualizar de forma consolidada todas las ubicaciones de riesgo asociadas a una cotización. La interfaz debe presentar una lista o un sistema de pestañas que represente cada ubicación. Al seleccionar una ubicación de la lista o pestaña, el sistema debe mostrar sus detalles completos, permitiendo su posterior edición. Se debe indicar claramente si se ha alcanzado un límite máximo de ubicaciones permitidas.
**Flow:** HU-115 (Agregar Nueva Ubicación de Riesgo) → HU-118 (Visualizar Múltiples Ubicaciones de Riesgo) → HU-116 (Editar Ubicación de Riesgo)

## 6. Acceptance Criteria
### AC-001: Visualización de lista/pestañas de ubicaciones
**Description:** Valida que al abrir una cotización con múltiples ubicaciones, la interfaz las muestre de forma accesible.

```gherkin
Scenario: El usuario ve una lista o pestañas de ubicaciones de riesgo al abrir una cotización
  Given que una cotización tiene múltiples ubicaciones de riesgo
  When el usuario abre la cotización
  Then la interfaz muestra una lista o pestañas con cada ubicación de riesgo
```

### AC-002: Navegación a detalles de ubicación
**Description:** Valida que al seleccionar una ubicación, sus detalles completos se carguen para edición.

```gherkin
Scenario: El usuario navega a los detalles de una ubicación específica
  Given que la interfaz muestra una lista o pestañas con ubicaciones de riesgo
  And el usuario ha hecho clic en una ubicación específica en la lista o pestaña
  When la navegación se completa
  Then se muestran los detalles completos de esa ubicación para edición
```

### AC-003: Indicación de límite de ubicaciones
**Description:** Valida que la interfaz comunique claramente cuando se ha alcanzado el número máximo de ubicaciones permitidas.

```gherkin
Scenario: La interfaz indica que se ha alcanzado el límite de ubicaciones
  Given que la cotización ha alcanzado el límite máximo de ubicaciones de riesgo
  When el usuario intenta agregar una nueva ubicación o visualiza la sección de ubicaciones
  Then la interfaz indica claramente que el límite de ubicaciones ha sido alcanzado
```

## 10. UX and Navigation Flow
**UX Flow:** El usuario abre una cotización → La interfaz muestra una vista tipo "maestro" con una lista o conjunto de pestañas representando cada ubicación de riesgo → El usuario selecciona una ubicación (clic en lista/pestaña) → La interfaz actualiza la vista "detalle" para mostrar los campos editables de la ubicación seleccionada.
**Messages/Modals:**
*   Mensaje de advertencia/informativo cuando se alcanza el límite de ubicaciones: "Se ha alcanzado el límite máximo de X ubicaciones de riesgo para esta cotización."
**Stepper/Breadcrumbs:** Posiblemente un breadcrumb "Cotizaciones > [Nombre Cotización] > Ubicaciones de Riesgo".

## 11. Architecture and Technical Dependencies
- **Frontend:** Implementación de interfaz de usuario (UI) para patrón maestro-detalle con navegación tipo pestañas.
- **Backend (API de Cotizaciones):** Servicio para obtener la lista de ubicaciones de riesgo de una cotización y los detalles de una ubicación específica.
- **Base de Datos:** Almacenamiento de las ubicaciones de riesgo asociadas a las cotizaciones.

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Rendimiento de la interfaz con muchas ubicaciones.**
    -   Descripción: Si una cotización tiene un número muy elevado de ubicaciones, la carga y renderización de la lista/pestañas podría impactar el rendimiento de la UI.
    -   Impacto: Mala experiencia de usuario, lentitud, posibles bloqueos.
    -   Probabilidad: Media.
    -   Mitigación: Implementar paginación o virtualización de la lista si el número de ubicaciones supera un umbral; optimizar la carga de datos (solo lo necesario para el resumen inicial).
**Technical Debt:** La elección entre lista o pestañas y la complejidad del patrón maestro-detalle podría generar deuda técnica si no se usa un framework UI adecuado o si la implementación no es modular.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para la usabilidad y la gestión de cotizaciones complejas. Sin ella, los usuarios no podrían revisar eficientemente los riesgos asegurados ni acceder a sus detalles.
**Feature Impact:** La no implementación o el fallo de esta historia haría que la funcionalidad de "Gestión de Cotizaciones" sea muy limitada y difícil de usar para cotizaciones con múltiples ubicaciones, impactando directamente la capacidad del usuario de comprender y administrar sus pólizas.
**Critical Dependencies:** HU-115 (Agregar Nueva Ubicación de Riesgo) es una dependencia crítica, ya que no habría ubicaciones para visualizar.
**Recommended Priority:** Sprint actual / Próximo sprint (dada la prioridad 'Alta' y su dependencia de HU-115).

## 18. Identified Assumptions
1.  **Existencia de datos de ubicación:**
    -   Description: Se asume que existe un servicio backend o una base de datos que ya almacena la información de las ubicaciones de riesgo asociadas a una cotización.
    -   Impact if false: La interfaz no podría mostrar ninguna ubicación y la historia no se podría completar sin desarrollar primero la capa de datos y servicio.
    -   Requires validation from: Equipo de Backend, Arquitectura de Datos.
2.  **Límite de ubicaciones definido:**
    -   Description: Se asume que el "límite de ubicaciones" mencionado en los criterios de aceptación es un valor de negocio predefinido y conocido.
    -   Impact if false: La implementación no podría aplicar la regla de negocio y la indicación en la interfaz.
    -   Requires validation from: Product Owner, Equipo de Negocio.
