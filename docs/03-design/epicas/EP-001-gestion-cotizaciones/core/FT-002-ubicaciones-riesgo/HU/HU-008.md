## 2. Enabled Capability
**CAP-003:** Gestión de Ubicaciones de Riesgo
**Business Value:** Mantiene la cotización organizada y mejora la claridad para el usuario, permitiendo la exclusión de ubicaciones no relevantes sin perder el historial, lo que puede llevar a cálculos de primas más precisos.
**Requires:** CAP-002 - Creación de Ubicaciones de Riesgo (habilitada por HU-006)
**Enables:** CAP-004 - Cálculo de Prima (al excluir ubicaciones inactivas del proceso)
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero marcar una ubicación de riesgo como inactiva cuando ya no sea necesaria,
para mantener la cotización organizada sin perder el historial de la ubicación.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario marcar una ubicación de riesgo existente dentro de una cotización como inactiva. Al realizar esta acción, la ubicación dejará de ser considerada en los cálculos activos de la cotización, pero su registro histórico se conservará. Se implementará un diálogo de confirmación para prevenir acciones accidentales.
**Flow:** HU-006 (Agregar una nueva ubicación de riesgo) → HU-008 (Marcar una ubicación de riesgo como inactiva) → HU-015 (Cálculo de prima excluyendo ubicaciones inactivas) / HU-010 (Consulta de cotización mostrando ubicaciones inactivas con indicador).

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Cambio de estado y exclusión del flujo activo
**Description:** Valida que al confirmar la acción, el estado de la ubicación se actualiza correctamente y esta deja de ser considerada en el flujo principal de la cotización.

```gherkin
Scenario: Marcar una ubicación de riesgo como inactiva y actualizar visibilidad
  Given tengo una cotización con múltiples ubicaciones activas
  And he seleccionado una ubicación específica
  When confirmo la acción de "Marcar como inactiva"
  Then el campo `estadoValidacion` de la ubicación seleccionada cambia a `INACTIVA`
  And la ubicación deja de aparecer en el flujo activo de la cotización
```

### AC-002: Exclusión de ubicaciones inactivas en cálculo de prima
**Description:** Asegura que las ubicaciones marcadas como inactivas son excluidas del proceso de cálculo de primas sin generar errores.

```gherkin
Scenario: Exclusión de ubicación inactiva en el cálculo de prima
  Given una cotización que contiene al menos una ubicación marcada como `INACTIVA`
  When se ejecuta el cálculo de prima para esa cotización
  Then la ubicación marcada como `INACTIVA` es excluida del proceso de cálculo
  And el cálculo de prima se completa sin generar errores
```

### AC-003: Persistencia y visualización histórica con indicador
**Description:** Verifica que la ubicación inactiva se mantiene en el historial de la cotización y se presenta con una indicación visual clara de su estado.

```gherkin
Scenario: Visualización de ubicación inactiva en el historial de la cotización
  Given una cotización con una ubicación marcada como `INACTIVA`
  When consulto los detalles históricos de la cotización
  Then la ubicación marcada como `INACTIVA` es visible
  And la ubicación muestra un indicador visual claro de su estado de inactiva
```

**BR-001:** Conservación de Ubicaciones de Riesgo
- Description: Las ubicaciones de riesgo nunca deben ser eliminadas físicamente del sistema, solo marcadas como inactivas para asegurar la trazabilidad y el historial.
- Trigger: Intento de "eliminar" una ubicación de riesgo.
- Logic: En lugar de eliminar, actualizar el `estadoValidacion` a `INACTIVA`.
- Implementation: Servicio de gestión de ubicaciones en el Backend.
- Exception: N/A

**BR-002:** Confirmación de Inactivación
- Description: Se debe solicitar una confirmación explícita al usuario antes de marcar una ubicación de riesgo como inactiva.
- Trigger: El usuario selecciona la opción "Marcar como Inactiva".
- Logic: Mostrar un diálogo de confirmación con opciones "Sí" y "No". La acción se ejecuta solo si el usuario selecciona "Sí".
- Implementation: Frontend.
- Exception: N/A

## 11. Architecture and Technical Dependencies
- **Backend API de Cotizaciones:** Endpoint `PATCH /api/cotizaciones/{idCotizacion}/ubicaciones/{idUbicacion}` para actualizar el campo `estadoValidacion`.
- **Frontend:** Componente de UI para mostrar ubicaciones, la opción "Marcar como Inactiva" y el diálogo de confirmación.
- **Servicio de Cálculo de Prima:** Debe ser capaz de filtrar ubicaciones por su `estadoValidacion` para excluir las `INACTIVA`.
- **Base de Datos de Cotizaciones:** Persistencia de los cambios en el estado de la ubicación.

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de Datos:** Existe el riesgo de que el estado de la ubicación no se sincronice correctamente entre el frontend, el backend y la base de datos, lo que podría llevar a cálculos erróneos o una interfaz de usuario desactualizada.
    *   Impacto: Cálculos de prima incorrectos, mala experiencia de usuario, posibles problemas de negocio.
    *   Probabilidad: Media.
    *   Mitigación: Implementar validaciones robustas en el backend, manejo de errores y reintentos, y pruebas de integración exhaustivas.
2.  **Rendimiento del Cálculo de Prima:** Si la lógica para filtrar ubicaciones inactivas en el servicio de cálculo de prima no es eficiente, podría impactar negativamente el rendimiento en cotizaciones con un gran número de ubicaciones.
    *   Impacto: Degradación del tiempo de respuesta del sistema.
    *   Probabilidad: Baja a Media (dependiendo del volumen y la implementación).
    *   Mitigación: Asegurar índices adecuados en la base de datos y optimizar las consultas de filtrado.
