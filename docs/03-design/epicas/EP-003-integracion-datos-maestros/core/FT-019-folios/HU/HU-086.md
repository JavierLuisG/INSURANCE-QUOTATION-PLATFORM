## 3. User Story
Como sistema,
Quiero generar un folio alfanumérico único siguiendo el patrón 'PREFIJO-AAAA-NNNNNN' (ej. 'COT-2026-000001'),
Para identificar cada cotización de forma inequívoca y robusta.

## 4. Functional Description
**Description:** El sistema será responsable de generar un folio alfanumérico único para cada nueva cotización. Este folio seguirá un patrón estricto 'PREFIJO-AAAA-NNNNNN'. El 'PREFIJO' será configurable, 'AAAA' corresponderá al año actual (2026), y 'NNNNNN' será un número secuencial de 6 dígitos que se incrementará con cada generación para un prefijo y año dados. La secuencia numérica se reiniciará a '000001' al inicio de cada nuevo año o cuando se cambia el prefijo. Una vez generado, el folio será asociado y persistido con la cotización correspondiente.
**Flow:** Solicitud de Creación de Cotización → [HU-086: Generación de Folio] → Persistencia de Cotización con Folio.

**BR-001:** Patrón de Folio
- Description: El folio generado debe seguir estrictamente el patrón 'PREFIJO-AAAA-NNNNNN'.
- Trigger: Al generar un nuevo folio.
- Logic: Concatenar el prefijo configurado, el año actual y el número secuencial formateado a 6 dígitos, separados por guiones.
- Implementation: Servicio de generación de folios.
- Exception: Si algún componente es nulo o inválido, se debe lanzar una excepción.

**BR-002:** Incremento y Unicidad Secuencial
- Description: El componente numérico 'NNNNNN' debe ser único para cada combinación de prefijo y año, e incrementarse en 1 con cada nueva solicitud.
- Trigger: Al solicitar un nuevo folio.
- Logic: Obtener el último número de secuencia para el prefijo y año actual, incrementarlo en uno. Si no hay registro previo para el prefijo y año, iniciar la secuencia en 1.
- Implementation: Módulo de secuencia numérica.
- Exception: Si la secuencia alcanza '999999', se debe lanzar una excepción de secuencia agotada.

**BR-003:** Prefijo Configurable
- Description: El prefijo utilizado en el folio debe ser configurable por el sistema.
- Trigger: Inicialización del sistema o modificación de configuración.
- Logic: El prefijo se debe obtener de un almacén de configuración (ej. base de datos, archivo de propiedades).
- Implementation: Servicio de configuración, Módulo de generación de folios.

**BR-004:** Reinicio Anual de Secuencia
- Description: La secuencia numérica 'NNNNNN' debe reiniciarse a '000001' al cambiar el año para un prefijo dado.
- Trigger: Al solicitar un nuevo folio y el año actual es diferente al último año registrado para el prefijo.
- Logic: Si `año_actual` > `ultimo_año_registrado_para_prefijo`, entonces `secuencia_numerica` = 1.
- Implementation: Módulo de secuencia numérica.

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo de Duplicidad de Folios:**
    *   Description: Un fallo en el mecanismo de incremento secuencial o en el manejo de concurrencia podría llevar a la generación de folios duplicados, comprometiendo la unicidad.
    *   Impact: Pérdida de integridad de datos, confusión en la identificación de cotizaciones, posibles problemas legales o de auditoría.
    *   Probability: Media.
    *   Mitigation: Implementar mecanismos de bloqueo transaccional a nivel de base de datos, bloqueo optimista, pruebas de estrés de concurrencia, uso de generadores de UUID como fallback.
2.  **Riesgo de Inconsistencia en el Reinicio Anual:**
    *   Description: Errores en la lógica de detección de cambio de año o en la sincronización de relojes del sistema podrían causar que la secuencia se reinicie en un momento incorrecto.
    *   Impact: Folios con años incorrectos o secuencias reiniciadas prematuramente, llevando a duplicados o inconsistencias.
    *   Probability: Baja.
    *   Mitigation: Pruebas unitarias robustas para la lógica de reinicio anual, asegurar la sincronización de NTP en los servidores.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La capacidad de generar folios únicos es fundamental para la identificación y trazabilidad de las cotizaciones, un proceso central y crítico para el negocio. Sin folios únicos, la gestión de cotizaciones sería caótica, propensa a errores y no cumpliría con los requisitos básicos de identificación.
**Feature Impact:** La no implementación o el fallo de esta historia impactaría directamente en la creación de cotizaciones, haciendo que toda la característica de "Gestión de Cotizaciones" sea inviable o altamente defectuosa.
**Critical Dependencies:** Cualquier historia de usuario que implique la creación, persistencia o búsqueda de una cotización depende críticamente de esta funcionalidad.
**Recommended Priority:** Sprint actual.

## 18. Identified Assumptions
1.  **Asunción de Persistencia Atómica de Secuencia:**
    - Description: Se asume que el último número de secuencia por prefijo y año será persistido de forma atómica y fiable (ej. en una base de datos con transacciones) para garantizar la continuidad y unicidad incluso bajo alta concurrencia o fallos del sistema.
    - Impact if false: Folios duplicados, secuencias incorrectas, o pérdida de datos si la persistencia no es robusta.
    - Requires validation from: Equipo de Desarrollo, Arquitectura de Datos.
2.  **Asunción de Sincronización del Reloj del Sistema:**
    - Description: Se asume que la fecha (año) obtenida por el sistema es siempre correcta y consistente en todos los nodos o instancias del servicio de generación de folios.
    - Impact if false: Folios generados con años incorrectos, lo que podría llevar a reinicios de secuencia prematuros o tardíos, o inconsistencias entre instancias.
    - Requires validation from: Equipo de Operaciones/Infraestructura.
3.  **Asunción de Suficiencia de la Secuencia Numérica (999999):**
    - Description: Se asume que la capacidad de generar hasta 999.999 folios por prefijo y año es suficiente para cubrir las necesidades operativas del negocio a largo plazo.
    - Impact if false: El sistema podría quedarse sin folios válidos para un prefijo/año, deteniendo la creación de cotizaciones y requiriendo una intervención de emergencia.
    - Requires validation from: Product Owner, Negocio.
