**Business Value:** Proporciona al usuario un resumen rápido y claro de la protección configurada para cada ubicación de riesgo, facilitando la auditoría y comprensión de su póliza.
**Requires:** CAP-122 (Seleccionar y Deseleccionar Coberturas por Ubicación)
**Enables:** [No especificado]
**Orchestrates:** [No especificado]

## 3. User Story
Como un usuario,
Quiero ver claramente qué coberturas están activas para cada ubicación de riesgo,
Para tener un resumen rápido de la protección configurada.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario visualizar las coberturas activas asociadas a una ubicación de riesgo específica. La funcionalidad debe presentar una lista clara de las coberturas configuradas, incluyendo sus parámetros clave (como suma asegurada y deducible), y manejar el escenario donde no hay coberturas activas para una ubicación, mostrando un mensaje informativo. La presentación debe ser concisa y fácil de entender.
**Flow:** HU-122 (Seleccionar y Deseleccionar Coberturas por Ubicación) → HU-124 (Visualizar Coberturas Activas por Ubicación) → [Posiblemente, una historia de usuario para editar o eliminar coberturas]

## 6. Acceptance Criteria
### AC-001: Visualización de Coberturas Activas
**Description:** Este criterio valida que, al visualizar una ubicación para la cual se han seleccionado coberturas, el sistema muestra claramente las coberturas que están activas.

```gherkin
Scenario: El usuario visualiza coberturas activas para una ubicación
  Given que he seleccionado coberturas para la ubicación "Ubicación A"
  When visualizo los detalles de "Ubicación A"
  Then se muestra una indicación clara de las coberturas activas para "Ubicación A"
```

### AC-002: Visualización de Parámetros de Cobertura
**Description:** Este criterio asegura que, además de la cobertura, se muestran sus parámetros configurados (ej. suma asegurada, deducible) para proporcionar información completa al usuario.

```gherkin
Scenario: Los parámetros de las coberturas activas son visibles
  Given que he seleccionado la cobertura "Incendio" con una suma asegurada de $100,000 y un deducible de $1,000 para "Ubicación A"
  When visualizo los detalles de "Ubicación A"
  Then se muestra la cobertura "Incendio" con sus valores: "Suma Asegurada: $100,000" y "Deducible: $1,000"
```

### AC-003: Mensaje para Ubicaciones sin Coberturas Activas
**Description:** Este criterio verifica que el sistema informa adecuadamente al usuario cuando una ubicación no tiene coberturas activas configuradas.

```gherkin
Scenario: El usuario visualiza una ubicación sin coberturas activas
  Given que no hay coberturas activas configuradas para la "Ubicación B"
  When visualizo los detalles de "Ubicación B"
  Then se muestra un mensaje indicando la ausencia de coberturas activas para "Ubicación B"
```

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario navega a la sección de "Mis Ubicaciones de Riesgo".
2.  El usuario selecciona una ubicación específica de la lista (ej. "Ubicación A").
3.  El sistema muestra una pantalla de "Detalle de Ubicación", que incluye una sección dedicada a "Coberturas Activas".
4.  Dentro de esta sección, se listan las coberturas activas con sus parámetros.
5.  Si no hay coberturas activas, se muestra un mensaje informativo.
**Messages/Modals:**
-   Mensaje de éxito: N/A (es una visualización pasiva).
-   Mensaje de error: "No se pudieron cargar las coberturas. Inténtelo de nuevo más tarde." (si falla la carga de datos).
-   Mensaje de advertencia/informativo: "No hay coberturas activas configuradas para esta ubicación."
**Stepper/Breadcrumbs:**
-   "Inicio > Mis Ubicaciones > [Nombre de Ubicación]" (para indicar la ruta de navegación).

## 11. Architecture and Technical Dependencies
-   **Frontend (Elementos de Visualización de Coberturas Activas):** Componente de UI responsable de renderizar la lista de coberturas y sus parámetros, así como el mensaje de ausencia de coberturas.
-   **Servicio Backend (API de Coberturas):** Se requiere un endpoint que, dado un `ubicacion_id`, devuelva las coberturas activas y sus parámetros. Se espera que este servicio tenga un tiempo de respuesta bajo (ej. < 500ms).
-   **Base de Datos:** Almacenamiento de las configuraciones de coberturas, sus estados (activas/inactivas) y sus parámetros asociados a cada ubicación.

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Rendimiento de Carga de Datos.**
    -   Descripción: Si una ubicación tiene un gran número de coberturas con muchos parámetros, la carga y renderización de la información podría ser lenta, afectando la experiencia del usuario.
    -   Impacto: Mala experiencia de usuario, posibles timeouts.
    -   Probabilidad: Media.
    -   Mitigación: Implementar paginación o carga diferida (lazy loading) si el número de coberturas es muy alto. Optimizar las consultas al backend.
2.  **Riesgo: Consistencia de Datos.**
    -   Descripción: Discrepancias entre las coberturas activas seleccionadas (HU-122) y lo que el servicio de visualización muestra.
    -   Impacto: Información incorrecta para el usuario, pérdida de confianza.
    -   Probabilidad: Baja (si se implementa correctamente HU-122).
    -   Mitigación: Asegurar que el servicio de backend sea la única fuente de verdad y que la lógica de "activo" esté bien definida y probada.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es fundamental para que el usuario pueda verificar y entender la protección que ha configurado. Sin ella, la acción de "seleccionar coberturas" (HU-122) pierde gran parte de su valor, ya que no hay una forma fácil de confirmar el estado.
**Feature Impact:** La no implementación o fallo de esta historia dejaría la funcionalidad de "Gestión de Coberturas por Ubicación" incompleta y poco útil, ya que el usuario no podría validar sus configuraciones.
**Critical Dependencies:** Depende directamente de la correcta persistencia y disponibilidad de datos de coberturas activas por ubicación.
**Recommended Priority:** Sprint actual (dado que HU-122 es un prerrequisito, esta debería seguir de cerca para cerrar el ciclo de feedback al usuario).

## 18. Identified Assumptions
1.  **Existencia del Servicio de Coberturas**
    -   Description: Se asume que existe un servicio o API backend capaz de proporcionar la lista de coberturas activas para una ubicación específica, incluyendo todos sus parámetros configurados.
    -   Impact if false: La historia no podría implementarse ya que el frontend no tendría una fuente de datos.

2.  **Definición Clara de "Activa"**
    -   Description: Se asume que existe una lógica y un estado bien definidos en el sistema para determinar cuándo una cobertura se considera "activa" para una ubicación.

    -   Requires validation from: Producto / Equipo de Backend.
