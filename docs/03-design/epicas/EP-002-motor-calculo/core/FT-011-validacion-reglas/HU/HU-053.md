## 2. Enabled Capability
**CAP-053:** Bloqueo de Cálculo por Errores de Validación
**Business Value:** Asegurar la integridad de los datos de las primas calculadas, reduciendo la posibilidad de errores en los resultados finales y el retrabajo.
**Requires:** CAP-049 (Gestión de Errores de Validación de Cotización), CAP-050 (Validación de Datos de Ubicación), CAP-051 (Validación de Datos del Asegurado), CAP-052 (Validación de Coberturas).
**Enables:** CAP-054 (Cálculo de Prima con Datos Válidos).
**Orchestrates:** Módulo de Orquestación de Cálculo, Motor Central de Cálculo (previene su ejecución).

## 3. User Story
Como usuario,
Quiero que el sistema impida el cálculo de la prima si existen errores de validación activos en la cotización o en sus ubicaciones,
Para que solo se realicen cálculos con datos válidos y completos.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que impide que el sistema inicie el proceso de cálculo de la prima si la cotización actual o cualquiera de sus ubicaciones asociadas contienen errores de validación activos. El objetivo es garantizar que cualquier cálculo se realice únicamente con datos válidos y completos, evitando resultados erróneos. Cuando se detectan errores, el sistema aborta el cálculo, notifica al usuario y le guía para resolver los problemas pendientes.
**Flow:** [Modificación de Cotización (HU-XXX)] → [HU-053: Bloqueo de Cálculo por Errores de Validación] → [Cálculo de Prima (HU-XXX) / Resolución de Errores (HU-XXX)]

## 5. Expected Results


| element | description |
|---|---|
| Data | El estado de validación de la cotización o sus ubicaciones permanece inalterado. No se crean ni modifican datos de cálculo si se aborta el proceso. |
| States | Si hay errores: El estado del cálculo no transiciona a 'En Progreso' o 'Calculando', sino que puede permanecer en 'Pendiente' o transicionar a 'Bloqueado por Validación'. Si no hay errores: El estado del cálculo transiciona a 'En Progreso' o 'Calculando'. |
| Notifications | Se muestra un mensaje de error o un modal al usuario indicando que el cálculo ha sido abortado debido a errores de validación. El mensaje debe ser claro y orientar al usuario a la resolución de los errores. |
| Integrations | Si hay errores: El 'Motor Central de Cálculo' NO es invocado. Si no hay errores: El 'Motor Central de Cálculo' es invocado para proceder con el cálculo. |
| Kafka | No se publican eventos específicos de Kafka relacionados con el bloqueo del cálculo. Si el cálculo procede, se publicarán los eventos correspondientes al inicio del cálculo. |
| Logs | Se registran logs de nivel INFO o WARN si el cálculo es abortado por errores de validación, incluyendo el ID de la cotización y la razón del bloqueo. Se registran logs INFO al iniciar un cálculo exitoso. |
| UI | El botón o acción de 'Calcular Prima' puede deshabilitarse o mostrar un estado de advertencia si hay errores. Al intentar calcular con errores, se presenta un modal o banner con el mensaje de error y, posiblemente, un enlace o indicación para ir a la sección de validación. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Abortar cálculo por errores de validación
**Description:** Valida que el sistema impide el inicio del cálculo de la prima si existen errores de validación activos en la cotización o cualquiera de sus ubicaciones.

  And el Motor Central de Cálculo NO es invocado

**BR-001:** Bloqueo de Cálculo por Errores de Validación
- Description: El sistema debe impedir la ejecución del cálculo de la prima si la cotización o cualquiera de sus ubicaciones asociadas tienen errores de validación activos.
- Trigger: Al intentar iniciar el proceso de cálculo de la prima.
- Logic:
  ```
  FUNCTION PRE_CALCULATION_VALIDATION(cotizacion_id):
      cotizacion = GET_COTIZACION(cotizacion_id)
      IF cotizacion.has_validation_errors THEN
          RETURN FALSE // Bloquear cálculo
      END IF

      ubicaciones = GET_UBICACIONES_BY_COTIZACION(cotizacion_id)
      FOR EACH ubicacion IN ubicaciones:
          IF ubicacion.has_validation_errors THEN
              RETURN FALSE // Bloquear cálculo
          END IF
      END FOR

      RETURN TRUE // Permitir cálculo
  ```
- Implementation: Módulo de orquestación de cálculo / Componente de control de flujo.
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Página de Detalle de Cotización:** El usuario visualiza los datos de la cotización y sus ubicaciones.
2.  **Identificación de Errores:** Si hay errores de validación, estos deben ser visibles o indicados en la interfaz (e.g., campos resaltados, mensajes de error).
3.  **Intento de Cálculo:** El usuario hace clic en el botón "Calcular Prima".
4.  **Bloqueo y Notificación:** Si existen errores, se muestra un modal o un banner de notificación en la parte superior de la página, indicando que el cálculo no puede proceder y listando la razón (errores de validación).
5.  **Guía al Usuario:** El mensaje incluye una opción (e.g., un botón "Ver Errores" o un enlace) que redirige o desplaza al usuario a la sección o pestaña donde se encuentran los errores de validación para su corrección.
6.  **Resolución y Reintento:** El usuario corrige los errores y puede intentar el cálculo nuevamente.
**Messages/Modals:**
*   **Mensaje de Error:** "No se puede realizar el cálculo de la prima. Por favor, corrija los errores de validación en la cotización o sus ubicaciones antes de continuar. [Ver Errores]"
*   **Mensaje de Éxito (cuando procede):** "Iniciando cálculo de prima..."
**Stepper/Breadcrumbs:** No aplica directamente a esta funcionalidad, pero el flujo de navegación del usuario dentro de la cotización debe ser claro para identificar y corregir errores.

## 11. Architecture and Technical Dependencies
-   **Módulo de Orquestación de Cálculo:** Actúa como el punto de entrada principal para el cálculo, siendo responsable de invocar el componente de control de flujo para la pre-validación.
-   **Componente de Control de Flujo:** Implementa la lógica de la regla de negocio (BR-001) para verificar la existencia de errores de validación.
-   **Motor Central de Cálculo:** Es el servicio que será invocado *solo si* la pre-validación es exitosa.
-   **Servicio de Gestión de Cotizaciones/Ubicaciones:** Provee los datos de la cotización y sus ubicaciones, incluyendo su estado de validación.
-   **APIs de Validación (HU-049 a HU-052):** Se asume que existen APIs o mecanismos internos que permiten consultar el estado de validación de una cotización y sus ubicaciones.

## 16. Technical Notes and Risks
**Technical Notes:**
-   La lógica de bloqueo debe ser una pre-condición estricta para la ejecución del Motor Central de Cálculo, ejecutándose *antes* de cualquier llamada a dicho motor.
-   La verificación de errores debe ser eficiente para no añadir latencia significativa al intento de cálculo.
-   Se debe considerar cómo los errores de validación son almacenados o consultados para determinar el estado `has_validation_errors`.
**Risks:**
1.  **Riesgo de Falso Positivo/Negativo en la Detección de Errores:**
    -   **Descripción:** Si el mecanismo de las HUs dependientes para identificar "errores de validación activos" no es preciso, esta HU podría bloquear cálculos válidos (falso positivo) o permitir cálculos con datos inválidos (falso negativo).
    -   **Impacto:** Frustración del usuario, pérdida de tiempo, resultados de cálculo incorrectos, posibles implicaciones financieras.
    -   **Probabilidad:** Media.
    -   **Mitigación:** Pruebas unitarias y de integración exhaustivas de las reglas de validación en las HUs dependientes. Definición clara de "error de validación activo". Colaboración estrecha con el equipo que implementa las validaciones.
2.  **Riesgo de Impacto en el Rendimiento:**
    -   **Descripción:** La consulta del estado de validación de la cotización y todas sus ubicaciones podría ser lenta si el volumen de datos o las ubicaciones son muy grandes.
    -   **Impacto:** Retraso en la respuesta del sistema al usuario al intentar calcular.
    -   **Probabilidad:** Baja a Media (dependiendo del diseño de las HUs de validación).
    -   **Mitigación:** Optimizar las consultas de validación (ej. índices, caché de estado de validación), asegurar que el estado de validación sea fácilmente consultable y agregable.

**Technical Debt:** [To be filled by operating team per scope and MVP]

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es crucial para garantizar la integridad y fiabilidad del proceso de cálculo de primas. Previene la generación de datos financieros incorrectos, lo que podría tener graves consecuencias operativas y de cumplimiento.
**Feature Impact:** Sin esta funcionalidad, el proceso de cálculo de primas sería propenso a errores, lo que socavaría la confianza en el sistema y requeriría un retrabajo significativo para corregir cotizaciones inválidas. Afecta directamente la calidad de los datos de negocio.
**Critical Dependencies:** El Motor Central de Cálculo depende de esta historia para recibir únicamente datos válidos. El valor de negocio del cálculo de primas se reduce drásticamente sin este filtro.
**Recommended Priority:** Sprint actual.
