## 2. Enabled Capability
**CAP-005:** Mapeo y Transformación de Datos de Tarificación
**Business Value:** Asegura la correcta interpretación y aplicación de las tarifas y factores técnicos externos en el motor de cálculo de primas, garantizando la precisión de los cálculos y la integridad del negocio.
**Requires:** CAP-001 (Recepción de Datos de Tarificación), CAP-002 (Validación de Datos de Tarificación) - *Asunción: Estas capacidades son previas para recibir los datos.*
**Enables:** CAP-006 (Cálculo de Primas), CAP-007 (Generación de Cotizaciones)
**Orchestrates:** Módulo de Cálculo de Primas

## 3. User Story
Como sistema,
Quiero mapear las tarifas (incendio, CAT, FHM) y factores técnicos a mi modelo interno,
Para su correcta aplicación en la lógica de cálculo de primas.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso por el cual el sistema toma los datos de tarifas (como incendio, CAT, FHM) y factores técnicos recibidos de fuentes externas (o internas, pero en un formato no nativo) y los transforma a una estructura de datos estandarizada y compatible con el módulo interno de cálculo de primas. El objetivo es asegurar que todos los elementos necesarios para el cálculo estén disponibles en el formato y con los atributos esperados por el motor de cálculo.
**Flow:** [HU-083 Procesamiento Inicial de Datos de Tarificación] → [HU-084 Mapear Tarifas y Factores Técnicos] → [HU-054 Cálculo de Prima Neta por Ubicación]


### AC-002: Mapeo exitoso de datos de factores técnicos

### AC-003: Disponibilidad de datos mapeados para el cálculo
**Description:** Asegura que una vez que el mapeo es exitoso, el módulo de cálculo puede solicitar y recibir los objetos de tarifas y factores técnicos con los atributos correctos para su uso.

```gherkin

  Given que el mapeo de tarifas y factores técnicos ha sido exitoso
  When el módulo de cálculo solicita una tarifa o factor técnico específico
  Then el sistema retorna un objeto con los atributos correctos y en el formato esperado
  And los valores numéricos están en el tipo de dato adecuado para operaciones matemáticas.
```

### AC-004: Manejo de datos de tarifas incompletos o inválidos

**BR-001:** Mapeo de Tipos de Tarifa
- Description: Cada tipo de tarifa externa debe ser mapeado a un tipo de tarifa interno predefinido para asegurar consistencia en el cálculo.
- Trigger: Al procesar datos de tarifas.
- Logic: `IF tarifa_externa.tipo_tarifa IN ['INC', 'FUEGO'] THEN tarifa_interna.tipo = 'INCENDIO'`
- Implementation: Capa de mapeo de datos / Servicio de transformación de tarifas.
- Exception: Si un tipo de tarifa externo no tiene un mapeo definido, se debe generar un error.

**BR-002:** Conversión de Unidades de Medida
- Description: Si los valores de tarifas o factores técnicos vienen en diferentes unidades, deben ser convertidos a las unidades estándar internas (ej. porcentajes a decimales).
- Trigger: Durante el proceso de mapeo de valores numéricos.
- Logic: `IF valor_externo > 1 THEN valor_interno = valor_externo / 100` (para porcentajes).
- Implementation: Servicio de transformación de tarifas/factores.
- Exception: N/A.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad del Modelo Interno:**
    *   Descripción: La nota de implementación ya menciona que "La complejidad de las tarifas puede requerir un modelo de datos interno flexible". Si el modelo interno no es lo suficientemente flexible o extensible, podría generar deuda técnica y dificultad para integrar nuevas tarifas.
    *   Impacto: Retrasos en la integración de nuevas líneas de negocio o productos, errores en el cálculo de primas.
    *   Probabilidad: Media
    *   Mitigación: Diseño de un modelo de datos polimórfico o basado en configuración, revisión temprana del diseño con expertos de dominio.
2.  **Manejo de Versiones de Tarifas:**
    *   Descripción: Las tarifas y factores técnicos pueden cambiar con el tiempo. Un mapeo incorrecto de versiones puede llevar a cálculos erróneos.
    *   Impacto: Inconsistencia en las primas, reclamos de clientes, problemas regulatorios.
    *   Probabilidad: Media
    *   Mitigación: Incluir campos de vigencia (fecha_desde, fecha_hasta) en el modelo mapeado, asegurar que el módulo de cálculo siempre solicite la versión correcta de la tarifa según la fecha de la cotización.

**Technical Debt:** [To be filled by operating team per scope and MVP]
- Si se decide implementar un mapeo rígido y codificado en lugar de un motor de reglas o configuración, esto podría generar deuda técnica a largo plazo.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para la funcionalidad principal del sistema de cálculo de primas. Sin un mapeo correcto, el módulo de cálculo no puede operar, resultando en primas incorrectas o la imposibilidad de generar cotizaciones.
**Feature Impact:** La no implementación o el fallo de esta historia detendría o invalidaría completamente la funcionalidad de "Cálculo de Primas" y todas las features que dependen de ella (ej. cotizaciones, emisiones).
**Critical Dependencies:** El módulo de cálculo de primas es críticamente dependiente de esta historia.
**Recommended Priority:** Sprint actual / Próximo sprint (dada la prioridad Alta y las dependencias).

## 18. Identified Assumptions
1.  **Formato de Datos de Entrada Estructurado:**
    *   Description: Se asume que los datos de tarifas y factores técnicos recibidos (provenientes de HU-080 a HU-083) tienen una estructura predecible (ej. JSON, XML) que permite su parsing y mapeo.
    *   Impact if false: Si el formato es inconsistente o muy variable, el proceso de mapeo será mucho más complejo y propenso a errores, requiriendo lógica de validación y limpieza adicional.
    *   Requires validation from: Equipo de Integración / Proveedor de Datos de Tarificación.
2.  **Existencia de un Catálogo Interno de Conceptos:**
    *   Description: Se asume que existe un catálogo definido de tipos de tarifas y factores técnicos internos a los cuales se deben mapear los conceptos externos.
    *   Impact if false: El mapeo sería ad-hoc y no estandarizado, llevando a inconsistencias y dificultades en el mantenimiento y evolución del sistema de cálculo.
    *   Requires validation from: Arquitectos de Solución / Expertos de Dominio de Seguros.
3.  **Módulo de Cálculo Preparado para Consumir el Modelo Interno:**
    *   Description: Se asume que el "módulo de cálculo" (ya sea existente o a desarrollar) está diseñado o será diseñado para trabajar con el modelo interno de tarifas y factores que esta historia definirá.
    *   Impact if false: Si el formato mapeado no coincide con las expectativas del módulo de cálculo, el trabajo de esta historia será inútil o requerirá retrabajo significativo.
    *   Requires validation from: Equipo de Desarrollo del Módulo de Cálculo / Arquitectos.
