## 2. Enabled Capability
**CAP-057:** Generación de Desglose Detallado de Primas por Ubicación
**Business Value:** Permite al usuario entender la composición del costo de la prima por ubicación de riesgo y facilita procesos de auditoría.
**Requires:** HU-054 (Cálculo de Primas), HU-055 (Asignación de Primas por Ubicación)
**Enables:** Análisis Financiero de Pólizas, Reportes de Auditoría de Primas
**Orchestrates:** N/A

## 3. User Story
Como un **usuario**,
quiero que el sistema **genere el desglose detallado de primas por cada ubicación de riesgo**,
para **entender la composición del costo y para fines de auditoría**.

## 4. Functional Description
**Description:** Esta historia de usuario describe la capacidad del sistema para presentar un desglose pormenorizado de las primas asociadas a cada ubicación de riesgo. Una vez que las primas han sido calculadas y asignadas a las ubicaciones (como resultado de HU-054 y HU-055), el sistema debe procesar esta información para mostrar los componentes individuales de la prima (prima neta, CAT, FHM y cualquier otro factor) por cada ubicación de riesgo. El objetivo es proporcionar transparencia sobre cómo se compone el costo total de la prima para cada punto de riesgo, facilitando tanto el análisis interno como los requisitos de auditoría.
**Flow:** HU-055 (Asignación de Primas por Ubicación) → **HU-057 (Generación de Desglose de Primas por Ubicación)** → HU-021 (Visualizar Desglose de Prima por Ubicación de Riesgo)

## 6. Acceptance Criteria
### AC-001: Visualización del desglose de primas por ubicación
**Description:** Valida que, una vez calculadas las primas, el sistema muestra correctamente el desglose de componentes por cada ubicación de riesgo.

```gherkin
Scenario: El sistema muestra el desglose de prima por ubicación con todos sus componentes
  Given las primas han sido calculadas y asignadas para 'Ubicación A' y 'Ubicación B'
  And 'Ubicación A' tiene componentes 'Prima Neta', 'CAT', 'FHM'
  And 'Ubicación B' tiene componentes 'Prima Neta', 'FHM' pero no 'CAT'
  When el usuario solicita el desglose de primas por ubicación
  Then el sistema muestra el desglose para 'Ubicación A' incluyendo 'Prima Neta', 'CAT', 'FHM' con sus valores
  And el sistema muestra el desglose para 'Ubicación B' incluyendo 'Prima Neta', 'FHM' con sus valores
  And el componente 'CAT' para 'Ubicación B' se muestra como '0' o 'N/A'
```

### AC-002: Consistencia del desglose con el cálculo total
**Description:** Valida que la suma de los componentes desglosados para una ubicación coincide con la prima total calculada para esa ubicación.

```gherkin
Scenario: La suma de los componentes desglosados coincide con el total de la prima por ubicación
  Given el desglose de primas se ha generado para 'Ubicación C'
  And 'Ubicación C' tiene una 'Prima Neta' de 100, 'CAT' de 10 y 'FHM' de 5
  And la prima total calculada para 'Ubicación C' es 115
  When el desglose se compara con el cálculo total de 'Ubicación C'
  Then la suma de 'Prima Neta' + 'CAT' + 'FHM' (100+10+5) es igual a la prima total calculada (115)
```

### AC-003: Manejo de componentes no aplicables
**Description:** Valida que los componentes de prima que no aplican a una ubicación específica se manejan adecuadamente en el desglose (mostrándose como cero o no aplicables).

```gherkin
Scenario: Componentes no aplicables se muestran como cero o no aplicables
  Given las primas han sido calculadas para 'Ubicación D'
  And 'Ubicación D' no tiene el componente 'FHM' aplicado
  When el sistema genera el desglose de primas para 'Ubicación D'
  Then el componente 'FHM' en el desglose para 'Ubicación D' se muestra como '0' o 'N/A'
  And el resto de los componentes aplicables se muestran con sus valores correspondientes
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| ubicacion_id | UUID/String | yes | N/A | Formato de ID válido | Ubicaciones de Riesgo | loc-uuid-12345 |
| nombre_ubicacion | String | yes | N/A | Texto libre | N/A | Oficina Central Madrid |
| prima_neta | Decimal | yes | 0.00 | Número positivo con 2 decimales | N/A | 1250.75 |
| cat | Decimal | yes | 0.00 | Número positivo con 2 decimales | N/A | 50.20 |
| fhm | Decimal | yes | 0.00 | Número positivo con 2 decimales | N/A | 15.00 |
| otros_componentes | Array de Objetos | no | [] | Cada objeto debe tener 'nombre' (String) y 'valor' (Decimal) | Catálogo de Componentes de Prima | [{"nombre": "Gastos Administración", "valor": 25.00}] |
| prima_total_ubicacion | Decimal | yes | 0.00 | Número positivo con 2 decimales | N/A | 1340.95 |


**BR-001:** Consistencia del Total de Prima por Ubicación
- Description: La suma de todos los componentes individuales (Prima Neta, CAT, FHM, otros componentes) para una ubicación específica debe ser igual a la Prima Total de esa ubicación.
- Trigger: Al generar el desglose de primas por ubicación.
- Logic: `prima_total_ubicacion = prima_neta + cat + fhm + SUM(otros_componentes.valor)`
- Implementation: Servicio de desglose de primas.
- Exception: Si la suma no coincide, se debe registrar una advertencia/error y, si es posible, notificar la inconsistencia.

**BR-002:** Manejo de Componentes No Aplicables
- Description: Si un componente de prima (ej. CAT, FHM) no aplica para una ubicación de riesgo, su valor en el desglose debe ser presentado como cero (0.00) o como "N/A" (No Aplicable).
- Trigger: Al generar el desglose de primas por ubicación.
- Logic: Si el valor del componente es nulo o no existe en los datos de la ubicación, se asigna 0.00 o "N/A".
- Implementation: Servicio de desglose de primas, capa de presentación.
- Exception: N/A

- **Algoritmos de cálculo de prima (Servicio Interno):** Fuente de los valores de los componentes de prima para cada ubicación. Se requiere que este servicio sea accesible y que los datos estén pre-calculados o sean accesibles para la generación del desglose.
- **Estructura de datos de resultados (Base de Datos/Data Store):** Almacena los resultados de los cálculos de primas por ubicación, incluyendo todos los componentes. Debe ser consistente y estar optimizada para consultas.
- **Servicio de Desglose de Primas (Nuevo o Existente):** Un microservicio o módulo dentro de un servicio existente que orquesta la obtención de datos y la presentación del desglose.

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de Datos:**
    -   Descripción: Riesgo de que los datos de primas recuperados de los servicios de cálculo no sean consistentes o estén desactualizados.
    -   Impacto: Desglose incorrecto, problemas de auditoría, pérdida de confianza del usuario.
    -   Probabilidad: Media
    -   Mitigación: Implementar validaciones de datos, asegurar la atomicidad en la actualización de primas, usar mecanismos de versionado de datos si es necesario.
2.  **Complejidad del Desglose:**
    -   Descripción: Si el número de "otros componentes" es muy variable o complejo, la lógica de presentación y los algoritmos de suma pueden ser difíciles de mantener.
    -   Impacto: Mayor tiempo de desarrollo, bugs en la suma, dificultad para añadir nuevos componentes.
    -   Probabilidad: Media
    -   Mitigación: Diseñar una estructura de datos flexible para los componentes, utilizar un enfoque basado en configuración para nuevos componentes si es posible.

## 17. Criticality
**Criticality Level:** Media
**Justification:** La historia es importante para la transparencia y la auditoría, pero no bloquea el cálculo o la emisión básica de pólizas. Su ausencia dificultaría la comprensión y verificación de los costos, pero no detendría el flujo principal del negocio.
**Feature Impact:** Sin esta funcionalidad, la característica de "Gestión y Análisis de Primas" perdería gran parte de su valor analítico y de cumplimiento, haciendo que la composición de los costos sea opaca para el usuario.
**Critical Dependencies:** Depende críticamente de que HU-054 y HU-055 funcionen correctamente y proporcionen datos fiables.
**Recommended Priority:** Sprint actual o siguiente, después de que las historias de cálculo y asignación de primas estén estables.

## 18. Identified Assumptions
1.  **Datos de Prima Pre-calculados y Disponibles:**
    -   Description: Se asume que los resultados de los cálculos de prima (Prima Neta, CAT, FHM, otros componentes) para cada ubicación de riesgo ya están disponibles y almacenados de forma accesible para esta historia, provenientes de HU-054 y HU-055.
    -   Impact if false: Si los datos no están disponibles o son inconsistentes, la generación del desglose fallará o será incorrecta.
    -   Requires validation from: Equipo de Desarrollo de Cálculo de Primas, Arquitectura de Datos.
2.  **Definición de "Otros Componentes":**
    -   Description: Se asume que existe una definición clara y un catálogo de "otros componentes" de prima que pueden aplicarse a las ubicaciones, y que su estructura de almacenamiento es conocida.
    -   Impact if false: Dificultad para integrar y mostrar componentes adicionales, o errores en la suma total.
    -   Requires validation from: Product Owner, Equipo de Negocio, Equipo de Desarrollo.
