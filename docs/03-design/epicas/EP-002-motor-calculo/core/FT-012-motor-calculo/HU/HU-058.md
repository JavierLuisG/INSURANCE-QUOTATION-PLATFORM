**Feature:** Cálculo de Primas de Seguros
**Capability:** CAP-058 - Cálculo de Prima de Incendio
**Actor:** Usuario (del sistema de seguros)

## 2. Enabled Capability
**CAP-058:** Cálculo Preciso de Prima de Incendio
**Business Value:** Proporciona un valor preciso y fundamental del riesgo de incendio, esencial para la cotización y emisión de pólizas, reduciendo errores manuales y agilizando el proceso.
**Requires:** CAP-044 - Obtención de Tarifas de Incendio
**Enables:** CAP-054 - Cálculo de Prima Neta
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero que el sistema calcule la prima de incendio basándose en la suma asegurada y las tarifas correspondientes,
para obtener un valor preciso y fundamental del riesgo de incendio.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para calcular la prima de incendio. El sistema debe tomar la suma asegurada de una propiedad y aplicar la tarifa de incendio correspondiente para determinar el costo de la prima. La tarifa de incendio puede variar según factores como la zona geográfica o el tipo de construcción, por lo que el sistema debe ser capaz de seleccionar la tarifa correcta. En caso de que la suma asegurada sea cero, la prima de incendio calculada también debe ser cero.
**Flow:** HU-044 (Obtención de Tarifas de Incendio) → HU-058 (Cálculo de Prima de Incendio) → HU-054 (Cálculo de Prima Neta)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Cálculo Básico de Prima de Incendio
**Description:** Valida que la prima de incendio se calcula correctamente como el producto de la suma asegurada y la tarifa de incendio aplicable.

```gherkin
Scenario: Cálculo exitoso de prima de incendio con suma asegurada y tarifa válidas
  Given que la suma asegurada es 100000
  And la tarifa de incendio aplicable es 0.005
  When se invoca el cálculo de prima de incendio
  Then el resultado de la prima de incendio es 500
```

### AC-002: Selección de Tarifa por Criterios Variables
**Description:** Asegura que el sistema utiliza la tarifa de incendio correcta basándose en factores como la ubicación geográfica o el tipo de construcción.

```gherkin
Scenario: Aplicación de tarifa de incendio según zona geográfica
  Given que la suma asegurada es 200000
  And la ubicación del riesgo es "Zona Urbana A"
  And la tarifa para "Zona Urbana A" es 0.003
  When se invoca el cálculo de prima de incendio
  Then el sistema utiliza la tarifa 0.003
  And el resultado de la prima de incendio es 600
```

### AC-003: Cálculo de Prima con Suma Asegurada Cero
**Description:** Verifica que cuando la suma asegurada es cero, la prima de incendio resultante también es cero, sin importar la tarifa.

```gherkin
Scenario: Prima de incendio es cero cuando la suma asegurada es cero
  Given que la suma asegurada es 0
  And la tarifa de incendio aplicable es 0.007
  When se invoca el cálculo de prima de incendio
  Then el resultado de la prima de incendio es 0
```

### AC-004: Manejo de Tarifa de Incendio No Encontrada
**Description:** Asegura que el sistema maneja adecuadamente el escenario donde no se puede encontrar una tarifa de incendio aplicable.

```gherkin
Scenario: Notificación de error si la tarifa de incendio no se encuentra
  Given que la suma asegurada es 50000
  And no existe una tarifa de incendio aplicable para los criterios dados (ej. zona, tipo de construcción)
  When se invoca el cálculo de prima de incendio
  Then el sistema retorna un error o una notificación de tarifa no encontrada
  And la prima de incendio no se calcula
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| suma_asegurada | Decimal | yes | 0.00 | Mayor o igual a 0.00; máximo 2 decimales | N/A | 150000.75 |
| tarifa_incendio | Decimal | yes | 0.00 | Mayor o igual a 0.00; precisión de hasta 5 decimales | Obtenida de CAP-044 | 0.0045 |
| criterios_tarifa | JSON/Object | yes | {} | Contiene al menos 'zona_geografica' y/o 'tipo_construccion' | N/A | { "zona_geografica": "Urbana", "tipo_construccion": "Concreto" } |
| prima_incendio | Decimal | no | 0.00 | Mayor o igual a 0.00; máximo 2 decimales | N/A | 675.34 |


**BR-001:** Fórmula de Cálculo de Prima de Incendio
- Description: La prima de incendio se calcula multiplicando la suma asegurada por la tarifa de incendio aplicable.
- Trigger: Se invoca el cálculo de la prima de incendio.
- Logic: `prima_incendio = suma_asegurada * tarifa_incendio`
- Implementation: Servicio de Cálculo de Primas (módulo de incendio).
- Exception: Si `suma_asegurada` es 0, la `prima_incendio` es 0.

**BR-002:** Selección de Tarifa de Incendio
- Description: La tarifa de incendio a utilizar debe ser seleccionada basándose en los criterios del riesgo (ej. zona geográfica, tipo de construcción, uso del inmueble).
- Trigger: Antes de aplicar la fórmula de cálculo de prima de incendio.
- Logic: El sistema consultará el repositorio de tarifas (proveniente de HU-044) utilizando los `criterios_tarifa` proporcionados por el riesgo.
- Implementation: Servicio de Tarifas (integración con CAP-044).
- Exception: Si no se encuentra una tarifa, el cálculo no procede y se notifica un error.

**BR-003:** Suma Asegurada Cero
- Description: Si la suma asegurada es igual a cero, la prima de incendio debe ser cero, independientemente de la tarifa aplicable.
- Trigger: Al inicio del proceso de cálculo de prima de incendio.
- Logic: `IF suma_asegurada == 0 THEN prima_incendio = 0`.
- Implementation: Servicio de Cálculo de Primas (módulo de incendio).
- Exception: N/A

## 11. Architecture and Technical Dependencies
-   **Servicio de Cálculo de Primas (Microservicio):** Encargado de la lógica de cálculo.
-   **Servicio de Tarifas (Microservicio):** Dependencia para obtener las `tarifa_incendio` y `criterios_tarifa` (relacionado con HU-044).
-   **Base de Datos de Riesgos/Pólizas:** Para almacenar la `suma_asegurada` y la `prima_incendio` calculada.
-   **API Gateway:** Para la exposición del servicio de cálculo de primas.
-   **Timeout:** 500 ms para la llamada al servicio de tarifas.
-   **Retries:** 2 reintentos con backoff exponencial en caso de fallo transitorio en la obtención de tarifas.
-   **Circuit Breaker:** Implementar un Circuit Breaker para el servicio de tarifas para evitar cascadas de fallos.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad del Servicio de Tarifas:**
    -   Descripción: Si el servicio que proporciona las tarifas de incendio (CAP-044) está caído o lento, el cálculo de la prima de incendio no podrá completarse.
    -   Impacto: Bloqueo en la cotización de pólizas de incendio, frustración del usuario, impacto en ventas.
    -   Probabilidad: Media.
    -   Mitigación: Implementar Circuit Breaker, reintentos, cache de tarifas (si es posible), monitoreo proactivo del servicio de tarifas.
2.  **Complejidad de Criterios de Tarifa:**
    -   Descripción: La lógica para seleccionar la tarifa correcta puede volverse muy compleja si los criterios (zona, tipo de construcción, uso, antigüedad) se multiplican o se combinan de formas no previstas.
    -   Impacto: Errores en la aplicación de tarifas, primas incorrectas, riesgo financiero.
    -   Probabilidad: Media.
    -   Mitigación: Mantener la lógica de selección de tarifas en el servicio de tarifas (CAP-044), no en el de cálculo; asegurar un buen conjunto de pruebas para la selección de tarifas; documentar claramente las reglas de negocio para los criterios.
3.  **Precisión del Cálculo:**
    -   Descripción: Errores de redondeo o precisión en los cálculos de punto flotante pueden llevar a primas ligeramente incorrectas.
    -   Impacto: Discrepancias en los sistemas contables, insatisfacción del cliente.
    -   Probabilidad: Baja (con buena implementación).
    -   Mitigación: Utilizar tipos de datos `Decimal` o `BigDecimal` para cálculos monetarios, definir una política clara de redondeo y aplicarla consistentemente.

**Technical Debt:** La fórmula debe ser verificada y documentada. Esto implica asegurar que la ecuación implementada corresponde exactamente con la especificación de negocio y que esta se registre en una wiki o repositorio de conocimiento.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Este cálculo es fundamental para la cotización y emisión de cualquier póliza de incendio. Un cálculo incorrecto o la imposibilidad de realizarlo impacta directamente la capacidad de la empresa para vender seguros de incendio.
**Feature Impact:** Sin este componente, la funcionalidad de "Cálculo de Primas de Seguros" es incompleta para el ramo de incendio, impidiendo la determinación del costo del riesgo.
**Critical Dependencies:** CAP-054 (Cálculo de Prima Neta) depende directamente de este cálculo, y cualquier fallo o imprecisión se propagaría.
**Recommended Priority:** Sprint actual / Próximo sprint (dada la prioridad Alta y el impacto crítico).

## 18. Identified Assumptions
1.  **Disponibilidad y Precisión de Tarifas:**
    -   Description: Se asume que el servicio o componente responsable de HU-044 proporcionará las tarifas de incendio correctas y actualizadas, y que siempre habrá una tarifa aplicable para los criterios de riesgo definidos.
    -   Impact if false: Cálculos de prima incorrectos, imposibilidad de calcular la prima, necesidad de manejo de errores más robusto y posiblemente tarifas por defecto.
    -   Requires validation from: Equipo de Producto/Actuarial para las reglas de tarifas, Equipo de Desarrollo para la implementación de CAP-044.
2.  **Formato Consistente de Suma Asegurada y Tarifas:**
    -   Description: Se asume que la `suma_asegurada` y la `tarifa_incendio` se proporcionarán en un formato numérico válido (ej. `Decimal` o `BigDecimal`) sin problemas de conversión o precisión.
    -   Impact if false: Errores de tipo de dato, cálculos incorrectos o fallos en tiempo de ejecución.
    -   Requires validation from: Equipo de Desarrollo (contratos de API, validación de datos de entrada).
3.  **Definición de Criterios para Tarifa Única:**
    -   Description: Se asume que, para un conjunto dado de criterios de riesgo (zona, tipo de construcción, etc.), siempre habrá una única tarifa de incendio aplicable o una regla clara para resolver ambigüedades.
    -   Impact if false: El sistema podría seleccionar la tarifa incorrecta o no saber cuál aplicar, llevando a primas erróneas.
    -   Requires validation from: Equipo de Producto/Actuarial.
