## 2. Enabled Capability
**CAP-001:** Validación de Códigos Postales
**Business Value:** Reduce errores en la captura de información de ubicación, mejora la calidad de los datos para la generación de cotizaciones y optimiza la experiencia del usuario al evitar el avance con datos incorrectos.
**Requires:** CAP-XXX - Gestión de Catálogo de Códigos Postales (externo)
**Enables:** CAP-002 - Captura de Ubicación Completa / Cálculo de Cotización
**Orchestrates:** Servicio Externo de Catálogo de Códigos Postales

## 3. User Story
Como usuario,  
Quiero que el sistema valide el código postal ingresado,  
Para que asegure que es un código postal válido y existente en el catálogo, y evite errores en la cotización.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema valida el código postal ingresado por un usuario como parte de la captura de la ubicación. La validación se realiza en dos fases: primero, una verificación de formato básico en el frontend (ej. 5 dígitos numéricos), y luego, una validación de existencia contra un catálogo de códigos postales en el backend. El sistema informará al usuario con mensajes específicos si el formato es incorrecto o si el código postal no existe, o permitirá continuar con la siguiente fase de captura de ubicación si el código postal es válido y existente.
**Flow:** HU-074 (Ingreso de Código Postal) → HU-075 (Validación de Código Postal) → HU-XXX (Continuar con la Captura de Ubicación / Calcular Cotización)

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| codigo_postal | string | yes | null | Debe ser un valor de 5 dígitos numéricos. Regex: ^[0-9]{5}$ | N/A (el catálogo se consulta, no es una lista de valores para el campo) | 01000 |


**BR-001:** Formato de Código Postal
- Description: El código postal ingresado por el usuario debe consistir exactamente en 5 dígitos numéricos.
- Trigger: Al ingresar el código postal en el campo y al intentar continuar con el flujo.
- Logic: `SI (longitud(codigo_postal) == 5) Y (es_numerico(codigo_postal))`
- Implementation: Frontend (validación básica) y Backend (validación estricta antes de consultar el catálogo).
- Exception: N/A

**BR-002:** Existencia en Catálogo de Códigos Postales
- Description: El código postal, una vez validado su formato, debe existir en el catálogo oficial de códigos postales gestionado por un servicio externo.
- Trigger: Después de que el código postal pasa la validación de formato.
- Logic: `LLAMAR servicio_externo_catalogo_cp.validar(codigo_postal)`
- Implementation: Módulo de validación de CP (Backend).
- Exception: Error de comunicación con el servicio externo, código postal no encontrado en el catálogo.

## 11. Architecture and Technical Dependencies
- **Módulo de validación de CP (Backend Service):** Microservicio o componente dentro del backend principal encargado de orquestar las validaciones, incluyendo la llamada al servicio externo.
- **Cliente API REST (Backend):** Componente para realizar llamadas HTTP al servicio externo de catálogo de CP.
- **Servicio Externo de Catálogo de Códigos Postales:**
    - Propósito: Fuente de verdad para verificar la existencia y detalles de los códigos postales.
    - Timeout: Máximo 5 segundos para la respuesta.
    - Retries: 2 reintentos con backoff exponencial en caso de fallos transitorios.
- **Interfaz de usuario (Frontend):** Implementa la validación de formato básica y la lógica para mostrar los mensajes de error y controlar el flujo de navegación.
- **Circuit Breaker:** Implementado para proteger la integración con el servicio externo de catálogo de CP (ej. umbral de error del 50%, 10 segundos de apertura).

## 16. Technical Notes and Risks
**Risks:**
1.  **Dependencia de Servicio Externo de Catálogo de CP**:
    *   Descripción: La disponibilidad, rendimiento y exactitud del servicio externo de catálogo de CP son críticos. Fallos en este servicio impactarán directamente la capacidad del sistema para validar códigos postales.
    *   Impacto: Errores en la validación, lentitud del sistema, imposibilidad de generar cotizaciones precisas, mala experiencia de usuario.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breaker, políticas de reintentos y timeouts, monitoreo proactivo del servicio externo, mensajes de error amigables al usuario. Evaluar un acuerdo de nivel de servicio (SLA) con el proveedor.
2.  **Mantenimiento y Actualización del Catálogo**:
    *   Descripción: El catálogo de códigos postales puede cambiar con el tiempo (nuevos CP, eliminaciones, cambios de zona). Si el servicio externo no se actualiza regularmente, la validación podría ser incorrecta.
    *   Impacto: Rechazo de códigos postales válidos o aceptación de inválidos, afectando la precisión de las cotizaciones.
    *   Probabilidad: Media.
    *   Mitigación: Establecer un proceso claro de sincronización o actualización con la fuente del catálogo. Definir la frecuencia de actualización con el proveedor del servicio.
**Technical Debt:** Considerar la implementación de un caché local (ej. Redis) para códigos postales frecuentemente consultados, si la latencia del servicio externo es un problema o si hay restricciones de llamadas a la API. (Esto será evaluado por el equipo operativo según el alcance y el MVP).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La validación del código postal es un paso fundamental y crítico para asegurar la integridad y exactitud de los datos de ubicación, los cuales son la base para cualquier cálculo de cotización. Sin una validación adecuada, el sistema podría generar cotizaciones erróneas o imposibles de cumplir, afectando directamente la operación del negocio y la confianza del usuario.
**Feature Impact:** La no implementación o un fallo en esta historia impactaría severamente la funcionalidad principal de "Generación de Cotizaciones", haciéndola propensa a errores y poco confiable.
**Critical Dependencies:** Cualquier historia de usuario que dependa de una ubicación válida para procesar o calcular información (ej. cálculo de tarifas de envío, determinación de zonas de servicio).
**Recommended Priority:** Sprint Actual / Próximo Sprint (alineado con la prioridad 'Alta' indicada por el usuario).

## 18. Identified Assumptions
1.  **Existencia y Fiabilidad de Catálogo de CP Externo**
    *   Description: Se asume que existe un servicio o API externo confiable y estable que provee un catálogo actualizado y accesible de códigos postales para su validación.
    *   Impact if false: El sistema no podrá validar la existencia de los códigos postales, solo su formato, lo que llevaría a errores en la cotización y una experiencia de usuario frustrante.
    *   Requires validation from: Equipo de Arquitectura, Proveedor de Datos, Operaciones.
2.  **Formato de Código Postal Estandarizado**
    *   Description: Se asume que el formato de "5 dígitos numéricos" es el estándar único y aplicable para todos los códigos postales que el sistema necesitará validar.
    *   Impact if false: El sistema podría rechazar códigos postales válidos de otras regiones o formatos (si aplica) o aceptar inválidos si el estándar no es consistente.
    *   Requires validation from: Stakeholders de Negocio, Expertos en Datos Geográficos.
