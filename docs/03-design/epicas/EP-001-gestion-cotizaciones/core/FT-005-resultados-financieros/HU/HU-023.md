## 1. Identificación General / General Identification
**Feature:** Gestión de Cotizaciones
**Capability:** CAP-023 - Sincronización de Resultados Financieros
**Actor:** Usuario
**Bounded Context:** Cotizaciones / Cálculo de Primas

## 2. Enabled Capability
**CAP-023:** Sincronizar Resultados Financieros
**Business Value:** Garantizar que la información de los resultados financieros de una cotización sea siempre veraz y esté actualizada con el último cálculo exitoso, mejorando la confianza del usuario y la precisión en la toma de decisiones.
**Requires:** CAP-018: Persistencia de Resultados de Cálculo (derivado de HU-018)
**Enables:** CAP-024: Consulta de Cotizaciones Precisas
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero que la información de los resultados financieros siempre refleje el último cálculo exitoso de la cotización,
para garantizar la veracidad de los datos.

## 4. Functional Description
**Description:** Esta historia de usuario asegura que al consultar los resultados financieros de una cotización, la información presentada al usuario corresponda al cálculo de prima más reciente y exitoso. Además, el sistema debe informar claramente al usuario si no hay un cálculo válido disponible, si el último cálculo falló, o si los datos de la cotización han sido modificados desde el último cálculo, indicando que los resultados podrían estar desactualizados.
**Flow:** HU-018 (Persistir resultados de cálculo) → HU-023 (Sincronizar y mostrar resultados) → Consulta de Cotización

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Mostrar el último cálculo exitoso
**Description:** Valida que, si existe un cálculo exitoso, sus resultados son los que se presentan al usuario.

```gherkin
Scenario: Consulta de resultados con cálculo exitoso
  Given Se ha realizado un cálculo de la cotización exitosamente y sus resultados han sido persistidos
  When El usuario consulta los resultados financieros de la cotización
  Then Los valores mostrados corresponden a este último cálculo exitoso
  And No se muestra ningún mensaje de error o advertencia sobre el estado del cálculo
```

### AC-002: Indicar estado de cálculo no disponible o fallido
**Description:** Valida que el sistema informa al usuario si no hay resultados de cálculo válidos.

```gherkin
Scenario: Consulta de resultados sin cálculo válido
  Given No se ha realizado ningún cálculo previo para la cotización
    Or El último cálculo de la cotización resultó en un fallo
  When El usuario consulta los resultados financieros de la cotización
  Then Se muestra un mensaje que indica que no hay resultados disponibles
    Or Se muestra un mensaje que indica que el último cálculo falló y los resultados no están disponibles
  And No se muestran valores de resultados financieros
```

### AC-003: Advertir sobre cálculo desactualizado
**Description:** Valida que se notifica al usuario si los datos de la cotización han cambiado después del último cálculo.

```gherkin
Scenario: Consulta de resultados con datos de cotización modificados post-cálculo
  Given Se ha realizado un cálculo exitoso de la cotización y sus resultados han sido persistidos
  And Posteriormente, se han modificado datos de la cotización relevantes para el cálculo
  When El usuario consulta los resultados financieros de la cotización
  Then Se muestran los resultados del último cálculo exitoso
  And Se muestra un mensaje de advertencia que indica que el cálculo actual podría estar desactualizado
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| id_cotizacion | UUID | yes | N/A | Formato UUID v4 | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| fecha_ultimo_calculo | DateTime | no | null | Formato ISO 8601 | N/A | 2026-04-20T10:30:00Z |
| estado_calculo | String | yes | PENDIENTE | ENUM('EXITOSO', 'FALLIDO', 'PENDIENTE', 'DESACTUALIZADO') | Estados de Cálculo | EXITOSO |
| resultados_financieros | JSON/Object | no | {} | Estructura JSON válida con campos como 'prima_total', 'impuestos', etc. | N/A | { "prima_total": 1500.00, "impuestos": 200.00, "descuentos": 50.00 } |
| fecha_ultima_modificacion_cotizacion | DateTime | yes | Fecha de creación de la cotización | Formato ISO 8601 | N/A | 2026-04-20T11:00:00Z |


**BR-001:** Determinación del estado de "Cálculo Desactualizado"
- Description: El sistema debe determinar si los resultados financieros mostrados están potencialmente desactualizados comparando la fecha del último cálculo exitoso con la fecha de la última modificación relevante de la cotización.
- Trigger: Al consultar los resultados financieros de una cotización.
- Logic: `IF (fecha_ultimo_calculo < fecha_ultima_modificacion_cotizacion) THEN estado_calculo = 'DESACTUALIZADO' ELSE estado_calculo = 'EXITOSO'` (asumiendo que hay un cálculo exitoso previo).
- Implementation: Servicio de backend de Cotizaciones.
- Exception: Esta regla solo se aplica si existe un `fecha_ultimo_calculo` y el `estado_calculo` no es 'FALLIDO' o 'PENDIENTE'.

**BR-002:** Prioridad de visualización de estados
- Description: La interfaz de usuario debe priorizar la visualización de los estados de cálculo en el siguiente orden: Fallido > Pendiente > Desactualizado > Exitoso (implícito).
- Trigger: Al cargar la sección de resultados financieros en la UI.
- Logic:
    - Si `estado_calculo` es 'FALLIDO', mostrar mensaje de error y no resultados.
    - Si `estado_calculo` es 'PENDIENTE', mostrar mensaje de estado y no resultados.
    - Si `estado_calculo` es 'DESACTUALIZADO', mostrar resultados (si existen) y mensaje de advertencia.
    - Si `estado_calculo` es 'EXITOSO', mostrar resultados sin mensajes adicionales.
- Implementation: Lógica de frontend.
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario navega a la pantalla de "Detalle de Cotización".
2.  El sistema consulta la API de Cotizaciones para obtener el estado del cálculo (`estado_calculo`), la `fecha_ultimo_calculo` y la `fecha_ultima_modificacion_cotizacion`.
3.  La sección de "Resultados Financieros" en la UI se renderiza:
    *   Si `estado_calculo` es 'EXITOSO' y `fecha_ultimo_calculo` >= `fecha_ultima_modificacion_cotizacion`, se muestran los resultados financieros.
    *   Si `estado_calculo` es 'EXITOSO' pero `fecha_ultimo_calculo` < `fecha_ultima_modificacion_cotizacion`, se muestran los resultados financieros junto con un mensaje de advertencia.
    *   Si `estado_calculo` es 'FALLIDO' o 'PENDIENTE', se muestra el mensaje de estado correspondiente y no se muestran resultados financieros.
    *   Si no hay `fecha_ultimo_calculo` (cotización nueva), se muestra un mensaje de "Sin resultados de cálculo".
**Messages/Modals:**
*   **Mensaje de Advertencia (Cálculo desactualizado):** "¡Atención! La cotización ha sido modificada desde el último cálculo ([fecha_ultimo_calculo]). Los resultados mostrados podrían estar desactualizados. Por favor, considere recalcular."
*   **Mensaje de Error (Cálculo fallido):** "El último cálculo de la cotización falló. Los resultados financieros no están disponibles. Por favor, revise los datos e intente recalcular."
*   **Mensaje de Estado (Cálculo pendiente/no realizado):** "No se han realizado cálculos para esta cotización o el cálculo está pendiente. Los resultados financieros no están disponibles."
**Stepper/Breadcrumbs:** N/A.

## 11. Architecture and Technical Dependencies
-   **Backend: Servicio de Cotizaciones (API de Cotizaciones):** Responsable de gestionar el estado del cálculo, la fecha del último cálculo, la fecha de última modificación de la cotización y de exponer los resultados financieros.
-   **Frontend: Aplicación de UI:** Contiene la lógica para consumir la API de Cotizaciones, interpretar los estados y fechas, y renderizar la información y los mensajes correspondientes al usuario.
-   **Base de Datos:** Almacenará los datos de la cotización, incluyendo `estado_calculo`, `fecha_ultimo_calculo`, `resultados_financieros` y `fecha_ultima_modificacion_cotizacion`.
-   **FT-006: Gestión del Ciclo de Vida y Estados de la Cotización:** Este componente técnico es crítico ya que define y gestiona los estados de la cotización, incluyendo los estados de cálculo, los cuales son la base para esta historia.

## 13. Edge Cases and Exceptions
### Case 1: No hay cálculos previos para la cotización
```gherkin
Scenario: Consulta de cotización recién creada sin cálculos
  Given Una cotización recién creada sin ningún cálculo asociado en el sistema
  When El usuario consulta los resultados financieros de esa cotización
  Then Se muestra un mensaje indicando que no hay resultados de cálculo disponibles
  And Los campos de resultados financieros están vacíos o inhabilitados
```

### Case 2: El último cálculo de la cotización resultó en fallo
```gherkin
Scenario: Consulta de cotización con cálculo fallido
  Given Una cotización cuyo último intento de cálculo resultó en un estado de 'FALLIDO'
  When El usuario consulta los resultados financieros de esa cotización
  Then Se muestra un mensaje de error indicando que el último cálculo falló
  And Los resultados financieros no se muestran o se muestran como no disponibles
```

### Case 3: La cotización fue modificada pero los resultados mostrados son correctos (ej. cambios no relevantes para el cálculo)
```gherkin
Scenario: Consulta de cotización con cambios no relevantes para el cálculo
  Given Una cotización con un cálculo exitoso previo
  And Posteriormente se han modificado datos de la cotización que NO son relevantes para el cálculo de primas (ej. notas internas)
  When El usuario consulta los resultados financieros de la cotización
  Then Se muestran los resultados del último cálculo exitoso
  And NO se muestra ningún mensaje de advertencia de desactualización (asumiendo que la `fecha_ultima_modificacion_cotizacion` no se actualiza o hay una lógica de "cambios relevantes")
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de datos en `fecha_ultima_modificacion_cotizacion`:**
    -   Descripción: Si la `fecha_ultima_modificacion_cotizacion` no se actualiza de forma consistente y transaccional cada vez que se realizan cambios relevantes en la cotización, la lógica de detección de "desactualizado" será defectuosa.
    -   Impacto: Mostrar advertencias incorrectas (falsos positivos) o no mostrar advertencias cuando debería (falsos negativos), llevando a decisiones basadas en datos potencialmente erróneos.
    -   Probabilidad: Media.
    -   Mitigación: Asegurar que todos los servicios o endpoints que modifican datos de una cotización actualicen esta fecha de forma atómica y consistente. Definir claramente qué modificaciones son "relevantes".
2.  **Rendimiento de la consulta de estado:**
    -   Descripción: La recuperación del estado del cálculo y las fechas para la sincronización podría introducir latencia si la API de cotizaciones no está optimizada.
    -   Impacto: Retraso en la visualización de los resultados financieros, afectando la experiencia del usuario.
    -   Probabilidad: Baja (para una simple consulta de fechas y estado).
    -   Mitigación: Asegurar índices adecuados en la base de datos para los campos `id_cotizacion`, `fecha_ultimo_calculo`, `fecha_ultima_modificacion_cotizacion`. Optimizar la consulta en el servicio de backend.
**Technical Debt:** N/A (Será definido por el equipo operativo según el alcance y el MVP).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La veracidad y la actualización de los resultados financieros son cruciales para la toma de decisiones del usuario y la integridad del negocio. Mostrar datos incorrectos o desactualizados sin advertencia puede tener graves consecuencias comerciales y de confianza.
**Feature Impact:** La no implementación o el fallo de esta historia comprometería fundamentalmente la fiabilidad de la funcionalidad de "Gestión de Cotizaciones", haciendo que los resultados financieros sean poco confiables.
**Critical Dependencies:** HU-018 es una dependencia crítica, ya que sin la persistencia de los resultados, esta historia no tendría datos que sincronizar.
**Recommended Priority:** Sprint actual.

## 18. Identified Assumptions
1.  **Mecanismo de actualización de `fecha_ultima_modificacion_cotizacion`:**
    -   Description: Se asume que existe un mecanismo robusto y confiable que actualiza automáticamente el campo `fecha_ultima_modificacion_cotizacion` en la base de datos de la cotización cada vez que se realiza un cambio en los datos relevantes de la misma (ej. coberturas, sumas aseguradas, datos del cliente que afecten el cálculo).
    -   Impact if false: La lógica para detectar cálculos desactualizados no funcionará correctamente, llevando a advertencias erróneas o a la ausencia de advertencias necesarias.
    -   Requires validation from: Equipo de Backend / Dueño de FT-006.
2.  **Disponibilidad y estructura de la API de Cotizaciones:**
    -   Description: Se asume que la API de Cotizaciones ya expone o se modificará para exponer de manera eficiente el `estado_calculo`, `fecha_ultimo_calculo`, `resultados_financieros` y `fecha_ultima_modificacion_cotizacion` para una cotización dada.
    -   Impact if false: El frontend no podrá obtener la información necesaria para implementar la lógica de sincronización y visualización de forma correcta.
    -   Requires validation from: Equipo de Backend.
