**Feature:** Gestión de Cotizaciones
**Capability:** CAP-001 - Notificación de Conflictos de Concurrencia
**Actor:** Usuario
**Bounded Context:** Gestión de Cotizaciones
**Story Points:** 2

## 2. Enabled Capability
**CAP-001:** Notificación de Conflictos de Concurrencia
**Business Value:** Evitar la sobrescritura de cambios por parte del usuario, asegurar la integridad de los datos de la cotización y guiar al usuario a resolver la situación, minimizando la pérdida de trabajo.
**Requires:** CAP-002 - Detección de Conflictos de Concurrencia (asociado a HU-065)
**Enables:** CAP-003 - Resolución de Conflictos de Concurrencia (futura)
**Orchestrates:** N/A

## 3. User Story
Como un **usuario**,
quiero **ser notificado claramente si se detecta un conflicto de concurrencia al intentar guardar**,
para que **sepa que necesito revisar la situación antes de continuar**.

## 4. Functional Description
**Description:** Esta historia de usuario describe el comportamiento del sistema cuando un usuario intenta guardar una cotización que ha sido modificada por otro usuario concurrentemente. El sistema debe interceptar el intento de guardado, detectar el conflicto (previamente implementado en HU-065) y, en lugar de guardar los cambios del usuario actual, mostrar un mensaje de error específico y amigable. Este mensaje debe informar al usuario que sus cambios no han sido guardados debido a una versión más reciente de la cotización y que debe revisar la situación, sin perder el trabajo que tenía en curso.
**Flow:** [HU-065 Detección de Conflicto] → [HU-066 Notificación de Conflicto al Usuario] → [HU-067 Resolución de Conflicto de Concurrencia]

## 5. Expected Results


| element | description |
|---|---|
| Data | Los cambios del usuario actual no se persisten en la cotización. La cotización en la base de datos mantiene la versión más reciente (modificada por el otro usuario). El trabajo actual del usuario (sus cambios no guardados) debe permanecer disponible en la interfaz para su revisión. |
| States | El estado de la cotización en el servidor permanece como la versión más reciente. El estado de la interfaz de usuario para el usuario actual debe mostrar el mensaje de error y mantener los datos modificados por el usuario para una posible resolución. |
| Notifications | Se muestra un mensaje de error específico en la interfaz de usuario indicando el conflicto de concurrencia. No se requieren notificaciones por correo electrónico o a otros canales. |
| Integrations | Ninguna integración externa es directamente afectada por la notificación de conflicto. La detección del conflicto (parte de HU-065) podría involucrar la API de cotizaciones. |
| Kafka | No se espera la publicación o consumo de eventos Kafka directamente por esta historia (la notificación es en UI). La detección del conflicto podría generar eventos internos. |
| Logs | Se espera un registro de nivel 'WARNING' o 'INFO' cuando se detecta y se notifica un conflicto de concurrencia, con detalles sobre la cotización y los usuarios involucrados (sin exponer datos sensibles). |
| UI | Un modal o un banner de notificación de error visible en la pantalla de edición de la cotización, mostrando el mensaje de conflicto. Los campos de la cotización deben permanecer editables con los cambios del usuario. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Mensaje de error específico al detectar conflicto
**Description:** Validar que, al detectar un conflicto de concurrencia, el sistema rechaza el intento de guardado y presenta un mensaje de error claro y específico al usuario.

```gherkin
Scenario: El sistema notifica un conflicto de concurrencia al intentar guardar
  Given que la cotización 'XYZ-001' ha sido modificada y guardada por otro usuario
  And que el usuario actual ha realizado cambios en la cotización 'XYZ-001'
  When el usuario actual intenta guardar sus cambios en la cotización 'XYZ-001'
  Then el intento de guardar es rechazado
  And el usuario recibe un mensaje de error específico que indica: "La cotización ha sido modificada por otro usuario. Por favor, revisa los cambios antes de continuar."
```

### AC-002: Claridad del mensaje y comprensión del usuario
**Description:** Asegurar que el mensaje de conflicto es fácil de entender y comunica efectivamente que los cambios del usuario no fueron guardados y que existe una versión más reciente.

```gherkin
Scenario: El usuario comprende el mensaje de conflicto
  Given que el usuario ha recibido el mensaje de error "La cotización ha sido modificada por otro usuario. Por favor, revisa los cambios antes de continuar."
  When el usuario lee el mensaje
  Then el usuario entiende que sus cambios no han sido guardados
  And el usuario entiende que existe una versión más reciente de la cotización en el sistema
```

### AC-003: Preservación del trabajo del usuario
**Description:** Verificar que, a pesar del conflicto, el trabajo actual del usuario (sus cambios no guardados) no se pierde y se le ofrece una opción para resolver la situación.

```gherkin
Scenario: El trabajo actual del usuario no se pierde
  Given que se ha detectado un conflicto de concurrencia al guardar una cotización
  And el sistema ha notificado el conflicto al usuario
  When el usuario revisa la pantalla de edición de la cotización
  Then sus cambios no guardados permanecen visibles en la interfaz
  And el sistema ofrece una indicación o una opción para que el usuario pueda resolver el conflicto (ej. 'Ver diferencias', 'Descartar cambios', 'Recargar última versión').
```

**BR-001:** Mensaje de Conflicto de Concurrencia
- Description: Define el contenido y el formato del mensaje de error que se muestra al usuario cuando se detecta un conflicto de concurrencia.
- Trigger: Cuando la API de guardado de cotizaciones detecta que la versión de la cotización en la base de datos es diferente a la esperada por el usuario (indicando que otro usuario ha guardado cambios).
- Logic:
  ```
  IF (version_cotizacion_actual_en_BD != version_cotizacion_esperada_por_usuario_al_guardar) THEN
    Mostrar_Mensaje_Error("La cotización ha sido modificada por otro usuario. Por favor, revisa los cambios antes de continuar.")
    Mantener_Cambios_Usuario_En_UI()
    Rechazar_Guardado()
  END IF
  ```
- Implementation: Servicio de Gestión de Cotizaciones (backend) y Componente de UI para mensajes de error (frontend).

## 13. Edge Cases and Exceptions
### Case 1: Múltiples intentos de guardar con conflicto
```gherkin
Scenario: El usuario intenta guardar repetidamente con un conflicto activo
  Given que la cotización 'XYZ-001' tiene un conflicto de concurrencia activo
  And el usuario ya ha recibido el mensaje de conflicto
  When el usuario ignora el mensaje y vuelve a intentar guardar sus cambios sin resolver el conflicto
  Then el sistema vuelve a rechazar el intento de guardar
  And el sistema vuelve a mostrar el mismo mensaje de error específico
  And los cambios del usuario permanecen en la interfaz.
```

### Case 2: Error al mostrar la notificación
```gherkin
Scenario: Falla al mostrar la notificación de conflicto en el frontend
  Given que se ha detectado un conflicto de concurrencia en el backend
  And el backend ha enviado la señal de notificación al frontend
  When ocurre un error en el frontend que impide mostrar el mensaje de error (ej. componente UI falla)
  Then el intento de guardar es rechazado por el backend
  And se registra un error de tipo 'ERROR' en los logs del frontend y/o backend indicando la falla en la notificación al usuario.
  And la cotización en el servidor no se modifica.
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Pérdida del trabajo del usuario.**
    -   Descripción: Si la implementación no asegura que los cambios del usuario permanezcan en la UI tras la notificación del conflicto, el usuario podría perder su progreso.
    -   Impacto: Alto. Frustración del usuario, pérdida de productividad.
    -   Probabilidad: Media. Requiere manejo cuidadoso del estado del frontend.
    -   Mitigación: Implementar un mecanismo robusto en el frontend para mantener el estado de los formularios, posiblemente usando estados locales o guardado temporal. Asegurar que el mensaje de notificación no recargue la página o el componente sin guardar el estado.
2.  **Riesgo: Mensaje poco claro o confuso.**
    -   Descripción: Si el texto del mensaje de error no es amigable o no explica claramente la situación, el usuario no sabrá cómo proceder.
    -   Impacto: Medio. Aumento de tickets de soporte, frustración.
    -   Probabilidad: Baja. El mensaje está especificado en los AC.
    -   Mitigación: Revisión de UX/UI y pruebas con usuarios reales para validar la claridad del mensaje.

## 17. Criticality
**Criticality Level:** High
**Justification:** Esta historia aborda un escenario crítico de integridad de datos y experiencia del usuario. La falta de una notificación clara puede llevar a la sobrescritura accidental de información, frustración del usuario y pérdida de confianza en el sistema.
**Feature Impact:** Sin esta notificación, la funcionalidad de "Gestión de Cotizaciones" sería propensa a errores de concurrencia no gestionados, invalidando el valor de la HU-065 (detección de conflicto) al no comunicarlo al usuario.
**Critical Dependencies:** HU-065 es una dependencia crítica, ya que sin la detección de conflictos, no hay nada que notificar.
**Recommended Priority:** Sprint actual o próximo, dada su alta prioridad y el impacto en la integridad de los datos.
