**Feature:** Cálculo de Primas de Cotización
**Capability:** CAP-005 - Iniciar Cálculo de Prima
**Actor:** Usuario (Agente/Asegurador)
**Bounded Context:** Cotizaciones de Seguros
**Story Points:** 3

## 2. Enabled Capability
**CAP-005:** Iniciar Cálculo de Prima de la Cotización
**Business Value:** Permite obtener los resultados financieros de una cotización, que es el objetivo principal del proceso de cotización, facilitando la toma de decisiones y la emisión de pólizas.
**Requires:**
*   FT-001: Creación y Edición de Datos Generales de la Cotización
*   FT-002: Gestión Dinámica de Ubicaciones de Riesgo
*   FT-003: Configuración y Selección de Coberturas por Ubicación
*   FT-009: Implementación de Reglas de Negocio y Validaciones
**Enables:** CAP-006: Visualizar Resultados de Cálculo de Prima (futura), CAP-007: Emitir Póliza (futura).
**Orchestrates:** Servicio de Cálculo de Primas (Backend).

## 3. User Story
Como un **usuario**,
quiero **iniciar el proceso de cálculo de la prima de la cotización**,
para **obtener los resultados financieros**.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario solicitar el cálculo de la prima para una cotización existente. El sistema verificará que los datos esenciales de la cotización (datos generales completos y al menos una ubicación con coberturas configuradas) estén completos y válidos antes de permitir el inicio del cálculo. Durante el proceso de cálculo, se mostrará un indicador de carga en la interfaz para informar al usuario sobre el estado y prevenir acciones duplicadas. Si la cotización tiene datos incompletos o inválidos, el sistema impedirá el cálculo y mostrará mensajes de error claros al usuario.
**Flow:** FT-001 (Datos Generales) → FT-002 (Gestión Ubicaciones) → FT-003 (Configuración Coberturas) → **HU-015 (Iniciar Cálculo)** → Visualización de Resultados de Cálculo (futura historia)

## 5. Expected Results


| element | description |
|---|---|
| Data | El objeto 'Cotización' es actualizado con el estado 'CALCULANDO' o 'CALCULADA' y los resultados de la prima (total, por cobertura, etc.). Se registran los detalles del cálculo en la base de datos. |
| States | El estado de la cotización cambia de 'EN_EDICION' a 'CALCULANDO' (si es asíncrono) o 'CALCULADA' (si es síncrono). El botón 'Calcular Prima' cambia su estado a 'deshabilitado' durante el cálculo. |
| Notifications | Se muestra un indicador visual de carga (spinner o barra de progreso) en la interfaz de usuario. En caso de errores de validación, se muestran mensajes de error contextuales en la UI. |
| Integrations | Se realiza una llamada al endpoint de la API de backend para iniciar el cálculo de la prima. |
| Kafka | Si el cálculo es asíncrono, se publica un evento 'cotizacion.calculo.iniciado' y, al finalizar, 'cotizacion.calculo.completado' o 'cotizacion.calculo.fallido'. |
| Logs | Se registran eventos de inicio de cálculo, validaciones de entrada, resultados del cálculo (éxito/falla) y posibles errores en el servicio de cálculo. |
| UI | El botón 'Calcular Prima' se habilita/deshabilita según la validez de los datos. Se muestra un indicador de carga mientras el cálculo está en progreso. Se presentan mensajes de error de validación en los campos correspondientes. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Inicio Exitoso del Cálculo
**Description:** Valida que el sistema inicia el proceso de cálculo cuando todos los datos requeridos están presentes y son válidos.

```gherkin
Scenario: El sistema inicia el proceso de cálculo con datos completos y válidos
  Given que he completado los datos generales de la cotización
  And que he configurado al menos una ubicación con coberturas válidas
  When hago clic en el botón "Calcular Prima"
  Then el sistema inicia el proceso de cálculo de la prima
  And el botón "Calcular Prima" se deshabilita
  And se muestra un indicador de carga en la interfaz
```

### AC-002: Prevención de Cálculo con Datos Incompletos/Inválidos
**Description:** Valida que el sistema previene el inicio del cálculo si faltan datos críticos o si estos son inválidos.

```gherkin
Scenario: El sistema impide el cálculo con datos incompletos o inválidos
  Given que la cotización tiene datos generales incompletos o inválidos
  Or que la cotización no tiene ubicaciones configuradas con coberturas
  When intento calcular la prima haciendo clic en el botón "Calcular Prima"
  Then el sistema me impide el cálculo
  And se muestran mensajes de error indicando los datos faltantes o inválidos
  And el botón "Calcular Prima" permanece habilitado o deshabilitado según los errores
```

### AC-003: Indicador de Carga Durante el Cálculo
**Description:** Valida que se muestra un indicador visual al usuario mientras el cálculo está en progreso para mejorar la experiencia y evitar acciones duplicadas.

```gherkin
Scenario: Se muestra un indicador de carga durante el proceso de cálculo
  Given que la cotización tiene datos completos y válidos
  And que el proceso de cálculo de la prima se ha iniciado
  When el cálculo se está ejecutando en el backend
  Then se muestra un indicador de carga visible en la interfaz de usuario
  And el botón "Calcular Prima" está deshabilitado
  And el usuario no puede iniciar otro cálculo para la misma cotización
```

**BR-001:** Validación de Datos Críticos para el Cálculo
- Description: El sistema debe verificar que los datos generales de la cotización estén completos y que al menos una ubicación de riesgo tenga coberturas configuradas antes de permitir el inicio del cálculo de la prima.
- Trigger: Intento de iniciar el cálculo de la prima (clic en el botón "Calcular Prima").
- Logic:
  ```
  IF (cotizacion.datosGenerales.estaCompleto() AND cotizacion.ubicaciones.algunaTieneCoberturas()) THEN
      Permitir_Inicio_Calculo()
  ELSE
      Impedir_Inicio_Calculo()
      Mostrar_Errores_De_Validacion()
  ```
- Implementation: Servicio de validación de cotizaciones en el backend y lógica de habilitación/deshabilitación del botón en el frontend.
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Pantalla de Edición de Cotización:** El usuario ha completado los datos generales y al menos una ubicación con coberturas.
2.  **Clic en "Calcular Prima":** El usuario presiona el botón.
3.  **Validación Frontend:** Si hay errores, se muestran mensajes de error y se bloquea el envío.
4.  **Llamada a Backend:** Si es válido, se realiza la llamada a la API.
5.  **Indicador de Carga:** Se muestra un spinner o mensaje "Calculando..." en la UI. El botón "Calcular Prima" se deshabilita.
6.  **Respuesta del Backend:**
    *   **Éxito:** El indicador de carga desaparece. Si es síncrono, los resultados se muestran en la pantalla. Si es asíncrono, se indica que el cálculo se ha iniciado y se notificará al finalizar.
    *   **Error:** El indicador de carga desaparece. Se muestra un mensaje de error genérico o específico en la UI (ej. "Error al calcular la prima, intente nuevamente."). El botón "Calcular Prima" vuelve a su estado original (habilitado).
**Messages/Modals:**
*   **Mensaje de Éxito (síncrono):** "Cálculo de prima completado exitosamente."
*   **Mensaje de Éxito (asíncrono):** "El cálculo de la prima ha sido iniciado. Recibirá una notificación cuando esté disponible."
*   **Mensaje de Error de Validación:** "No se puede iniciar el cálculo. Por favor, complete los datos requeridos." (con detalles específicos de los campos).
*   **Mensaje de Error de Proceso:** "Ha ocurrido un error inesperado al calcular la prima. Por favor, intente de nuevo más tarde."
*   **Indicador de Carga:** Un spinner o una barra de progreso visible en la sección de la cotización o en el botón.
**Stepper/Breadcrumbs:** N/A para esta acción específica, pero la pantalla de edición de cotización podría ser parte de un stepper más grande para el proceso de cotización.

## 11. Architecture and Technical Dependencies
-   **Frontend:**
    -   Componente del botón "Calcular Prima" (deshabilitación, estado de carga).
    -   Componente de indicador de carga (spinner/loader).
    -   Servicio de validación de datos en el cliente.
-   **Backend (API de Cotizaciones):**
    -   Endpoint: `POST /api/v1/cotizaciones/{id}/calcularPrima`
    -   Propósito: Recibir la solicitud, realizar validaciones adicionales, orquestar el llamado al motor de cálculo de primas.
    -   Timeout: 60 segundos (si el proceso es síncrono).
    -   Retries: N/A (el backend gestionará reintentos internos si se integra con servicios externos).
-   **Servicio/Motor de Cálculo de Primas (interno o externo):**
    -   Propósito: Contiene la lógica de negocio para calcular las primas basadas en los datos de la cotización, ubicaciones y coberturas.
    -   Contrato de API: Definir claramente las entradas (datos de cotización) y salidas (resultados de prima).
-   **Kafka Topic (opcional, si es asíncrono):**
    -   `cotizaciones.calculo.iniciado`: Evento publicado al iniciar el cálculo.
    -   `cotizaciones.calculo.completado`: Evento publicado al finalizar exitosamente.
    -   `cotizaciones.calculo.fallido`: Evento publicado si el cálculo falla.
-   **Circuit Breaker:** Implementado para la comunicación entre la API de Cotizaciones y el Servicio/Motor de Cálculo de Primas para manejar fallos y latencias.

```gherkin
Scenario: El servicio de cálculo de primas externo falla o excede el tiempo de espera
  Given que he iniciado el cálculo de la prima con datos válidos
  And que el servicio de cálculo de primas externo no responde o devuelve un error
  When el backend intenta comunicarse con el servicio de cálculo
  Then el sistema responde con un error 500 Internal Server Error (o 504 Gateway Timeout)
  And el indicador de carga desaparece
  And se muestra un mensaje de error al usuario
  And el estado de la cotización no cambia a 'CALCULADA'
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Rendimiento del Motor de Cálculo:**
    -   Description: El motor de cálculo de primas puede ser complejo y lento, lo que podría afectar la experiencia de usuario (si es síncrono) o la capacidad de procesamiento (si es asíncrono).
    -   Impact: Tiempos de espera excesivos, timeouts, sobrecarga del sistema.
    -   Probability: Media.
    -   Mitigation: Implementar el cálculo de forma asíncrona, optimizar algoritmos del motor, monitoreo de rendimiento, escalabilidad de los servicios de cálculo.
2.  **Consistencia de Datos:**
    -   Description: Inconsistencias entre los datos de la cotización almacenados y los datos utilizados por el motor de cálculo, o errores en la actualización del estado de la cotización.
    -   Impact: Cálculos incorrectos, estados de cotización erróneos, frustración del usuario.
    -   Probability: Media.
    -   Mitigation: Validaciones robustas en frontend y backend, transacciones distribuidas (si aplica), logging detallado, mecanismos de reintento idempotentes.

**Technical Debt:**
*   (A ser completado por el equipo operativo según el alcance y el MVP)
    *   Si el cálculo se implementa inicialmente de forma síncrona, la refactorización a un modelo asíncrono (con eventos Kafka y notificaciones) podría ser deuda técnica futura si el rendimiento se convierte en un cuello de botella.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para el propósito de la aplicación de cotizaciones, ya que sin el cálculo de la prima, la cotización no tiene valor financiero. Es un paso indispensable para cualquier proceso posterior como la visualización de resultados o la emisión de la póliza.
**Feature Impact:** La no implementación o el fallo de esta funcionalidad haría que la característica completa de "Cotización de Seguros" sea inutilizable.
**Critical Dependencies:** Todas las historias de usuario relacionadas con la visualización de resultados, la comparación de primas y la emisión de pólizas dependen directamente de un cálculo exitoso.
**Recommended Priority:** Sprint actual (Inmediata)
