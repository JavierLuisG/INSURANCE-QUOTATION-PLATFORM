## 2. Enabled Capability
**CAP-076:** Mapeo de Información de Zonas de Código Postal
**Business Value:** Permite la utilización de datos geográficos (zona CAT, nivel técnico) en la lógica de cálculo de primas por ubicación, lo que mejora la precisión y la competitividad de las tarifas.
**Requires:** HU-074 (Obtención de respuesta de consulta de CP)
**Enables:** CAP-XXX (Cálculo de Primas por Ubicación)
**Orchestrates:** Servicio Externo de Códigos Postales (la respuesta, no la invocación)

## 3. User Story
Como sistema,
Quiero mapear la información de zonas (CAT, nivel técnico) obtenida de un código postal del servicio externo,
Para que esté disponible en el modelo de datos interno y pueda ser utilizada en la lógica de cálculo de primas por ubicación.

## 4. Functional Description
**Description:** Esta historia describe el proceso automático por el cual el sistema toma la respuesta de un servicio externo de códigos postales, extrae la información relevante de zonas (CAT y nivel técnico), y la transforma para que se ajuste al modelo de datos interno de ubicación. El objetivo es asegurar que estos datos estén disponibles y sean consistentes para su uso en cálculos posteriores, específicamente en la lógica de cálculo de primas basada en la ubicación. Incluye el manejo de casos donde la información de zona no es proporcionada por el servicio externo.
**Flow:** HU-074 (Obtención de respuesta de CP) → HU-076 (Mapeo de información de zonas) → HU-XXX (Cálculo de Primas por Ubicación)

**BR-001:** Asignación de Valores por Defecto para Zonas Faltantes
- Description: Si el servicio externo de códigos postales no proporciona la información de `zona_cat` o `nivel_tecnico`, el sistema debe asignar un valor predefinido para cada uno de estos campos antes de persistirlos.
- Trigger: Al procesar la respuesta del servicio externo y detectar la ausencia de datos en los campos de zona.
- Logic:
  ```
  IF external_response.zona_cat IS NULL OR external_response.zona_cat IS EMPTY THEN
      internal_model.zona_cat = CONFIG.DEFAULT_ZONA_CAT
  ELSE
      internal_model.zona_cat = external_response.zona_cat
  END IF

  IF external_response.nivel_tecnico IS NULL OR external_response.nivel_tecnico IS EMPTY THEN
      internal_model.nivel_tecnico = CONFIG.DEFAULT_NIVEL_TECNICO
  ELSE
      internal_model.nivel_tecnico = external_response.nivel_tecnico
  END IF
  ```
- Implementation: Capa de mapeo de datos.
- Exception: Se debe registrar una advertencia en los logs indicando que se utilizó un valor por defecto.

## 16. Technical Notes and Risks
**Risks:**
1.  **Incompatibilidad de tipos de datos o formatos**:
    - Description: Los tipos de datos o el formato de `zona_cat` y `nivel_tecnico` recibidos del servicio externo podrían no ser compatibles con los definidos en el modelo de datos interno.
    - Impact: Errores en tiempo de ejecución, corrupción de datos, cálculos de primas incorrectos.
    - Probability: Media.
    - Mitigation: Implementar validaciones robustas y mecanismos de conversión/transformación. Mantener comunicación con el proveedor del servicio externo y definir un contrato de datos claro.
2.  **Cambios en el contrato del servicio externo**:
    - Description: El servicio externo podría modificar el formato o los nombres de los campos `zona_cat` y `nivel_tecnico` sin previo aviso.
    - Impact: Fallos en el mapeo, datos incorrectos, interrupción del cálculo de primas.
    - Probability: Baja a Media (depende de la estabilidad del servicio externo y la comunicación).
    - Mitigation: Contar con pruebas de integración robustas, monitorización activa de la API externa y un mecanismo para detectar y alertar sobre cambios en el contrato.
**Technical Debt:** Considerar la creación de un motor de reglas de mapeo configurable si se prevén muchos mapeos de diferentes servicios o cambios frecuentes.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La historia es de alta prioridad porque la información de zona (CAT, nivel técnico) es un insumo crítico para la lógica de cálculo de primas por ubicación. Sin este mapeo, la funcionalidad principal de tarificación no puede operar correctamente.
**Feature Impact:** La no implementación o el fallo de esta historia haría que la funcionalidad de "Cálculo de Primas por Ubicación" sea inoperable o produzca resultados erróneos, afectando directamente la capacidad del negocio para cotizar y vender pólizas.
**Critical Dependencies:** La lógica de negocio que utiliza los datos de ubicación para el cálculo de primas es críticamente dependiente de esta historia.
**Recommended Priority:** Sprint Actual.

## 18. Identified Assumptions
1.  **Disponibilidad y Estabilidad del Servicio Externo**:
    - Description: Se asume que el servicio externo de códigos postales estará disponible y devolverá respuestas de manera estable cuando sea invocado por HU-074.
    - Impact if false: Si el servicio no está disponible o es inestable, el sistema no podrá obtener la información de zona, impactando directamente el mapeo y el cálculo de primas.
    - Requires validation from: Equipo de Integración/DevOps, Proveedor del servicio externo.
2.  **Definición de Valores por Defecto**:
    - Description: Se asume que existen valores por defecto predefinidos y acordados por el negocio para `zona_cat` y `nivel_tecnico` en caso de que la información falte en la respuesta del servicio externo.
    - Impact if false: Si no hay valores por defecto, el sistema podría fallar o persistir datos nulos, lo que afectaría la lógica de cálculo de primas.
    - Requires validation from: Product Owner, Expertos de Negocio.
3.  **Contrato del Servicio Externo Estable**:
    - Description: Se asume que el contrato (formato de respuesta, nombres de campos) del servicio externo para códigos postales es estable y no cambiará sin previo aviso significativo.
    - Impact if false: Cambios inesperados requerirían ajustes urgentes en la capa de mapeo, causando interrupciones.
    - Requires validation from: Equipo de Integración, Proveedor del servicio externo.
