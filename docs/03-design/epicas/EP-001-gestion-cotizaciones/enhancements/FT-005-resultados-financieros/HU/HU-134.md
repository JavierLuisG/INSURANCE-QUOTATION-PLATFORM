## 2. Enabled Capability
**CAP-001:** Visualización de Desglose Técnico de Prima
**Business Value:** Permite al usuario entender en detalle cómo se compuso cada valor de prima calculada, lo que mejora la transparencia y la confianza en el proceso de cotización.
**Requires:** CAP-002 (Persistencia de Resultados de Cálculo), CAP-003 (Visualización de Resumen de Prima) - *Asumo que HU-128 y HU-130 son parte de estas capacidades.*
**Enables:** Análisis Detallado de Cotizaciones, Soporte a Clientes
**Orchestrates:** N/A

## 3. User Story
Como usuario,
Quiero acceder a una vista detallada con el desglose técnico del cálculo de prima por ubicación y por componente,
Para entender en detalle cómo se compuso cada valor de prima calculada.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario autenticado visualizar una pantalla específica que muestra el desglose técnico completo de una cotización calculada. La vista presentará los valores aplicados para cada componente de cálculo activo (ej., Incendio edificios, CAT TEV) desglosados por ubicación. Además, si alguna ubicación fue excluida del cálculo, se mostrará un indicador de `alertasBloqueantes` junto con los motivos de exclusión. En caso de que la cotización no haya sido calculada previamente, el sistema informará al usuario sobre esta condición.
**Flow:** HU-128 (Persistir Resultados del Cálculo de Prima) → HU-130 (Visualizar Resumen de Prima Neta y Comercial) → **HU-134 (Pantalla de Información Técnica del Cálculo)**

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización del desglose técnico por ubicación y componente
**Description:** Valida que, una vez que una cotización ha sido calculada, el usuario puede acceder a una vista detallada que muestra el desglose técnico de cada componente de cálculo activo por ubicación.

```gherkin
Scenario: Acceder y ver el desglose técnico de una cotización calculada
  Given una cotización con folio "Q123" ha sido calculada y sus resultados persistidos
  When el usuario navega a la ruta "/quotes/Q123/technical-info"
  Then la interfaz muestra el desglose técnico detallado de cada componente de cálculo activo por ubicación
```

### AC-002: Visualización de valores de componentes técnicos activos
**Description:** Valida que el desglose técnico incluye los valores específicos aplicados para cada componente de cálculo activo.

```gherkin
Scenario: Mostrar valores aplicados para componentes técnicos activos
  Given el desglose técnico de una cotización se muestra en pantalla
  When el usuario visualiza el desglose
  Then puede ver los valores aplicados para componentes como 'Incendio edificios', 'Incendio contenidos', 'CAT TEV', 'CAT FHM' y otros activos
```

### AC-003: Indicación de ubicaciones excluidas y sus motivos
**Description:** Valida que las ubicaciones que fueron excluidas del cálculo son claramente identificadas con sus `alertasBloqueantes` y los motivos de exclusión.

```gherkin
Scenario: Identificar ubicaciones excluidas y sus motivos
  Given el desglose técnico de una cotización se muestra en pantalla
  And una ubicación específica fue excluida del cálculo
  When el usuario visualiza la información de esa ubicación
  Then se muestra un indicador de "alertasBloqueantes" y los motivos de exclusión para dicha ubicación
```

### AC-004: Mensaje para cotizaciones no calculadas
**Description:** Valida que el sistema informa al usuario si intenta acceder al desglose técnico de una cotización que aún no ha sido calculada.

```gherkin
Scenario: Intentar ver el desglose técnico de una cotización no calculada
  Given una cotización con folio "Q124" no ha sido calculada
  When el usuario navega a la ruta "/quotes/Q124/technical-info"
  Then el sistema muestra un mensaje indicando que la cotización debe ser calculada primero
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| folio_cotizacion | string | yes | N/A | Formato alfanumérico único para el folio de la cotización | N/A | Q-2026-001 |
| id_ubicacion | string | yes | N/A | Identificador único de la ubicación | N/A | LOC-001 |
| nombre_componente_tecnico | string | yes | N/A | N/A | Catálogo de Componentes Técnicos de Prima | Incendio edificios |
| valor_prima_aplicado | decimal | yes | 0.00 | Mayor o igual a cero | N/A | 1500.75 |
| es_ubicacion_excluida | boolean | yes | false | N/A | N/A | true |
| alertas_bloqueantes | array<string> | no | [] | N/A | Catálogo de Alertas Bloqueantes | ['Riesgo no asegurable', 'Ubicación en zona sísmica'] |
| motivos_exclusion | array<string> | no | [] | N/A | Catálogo de Motivos de Exclusión | ['Violación de política de suscripción', 'Datos incompletos'] |


**BR-001:** Validación de Estado del Cálculo de Cotización
- Description: Antes de mostrar el desglose técnico, el sistema debe verificar si la cotización asociada al `folio` ha sido calculada.
- Trigger: Acceso a la ruta `/quotes/{folio}/technical-info`.
- Logic: `IF cotizacion.estado == 'CALCULADA' THEN mostrar_desglose ELSE mostrar_mensaje_error`.
- Implementation: Servicio de consulta de cotizaciones (backend).
- Exception: Si la cotización no existe o no se puede acceder.

**BR-002:** Desglose por Componente Activo
- Description: Solo se deben mostrar los componentes técnicos que estuvieron activos y contribuyeron al cálculo de la prima para cada ubicación.
- Trigger: Renderización del desglose técnico.
- Logic: Filtrar los datos del snapshot de trazabilidad para incluir únicamente `componentes_tecnicos.estado == 'ACTIVO'`.
- Implementation: Lógica de negocio en el backend o en el componente de frontend.

**BR-003:** Indicador y Motivos de Exclusión
- Description: Para cualquier ubicación marcada como `es_ubicacion_excluida = true`, se deben recuperar y mostrar sus `alertas_bloqueantes` y `motivos_exclusion` asociados.
- Trigger: Renderización de la información de una ubicación.
- Logic: `IF ubicacion.es_ubicacion_excluida == true THEN mostrar(ubicacion.alertas_bloqueantes, ubicacion.motivos_exclusion)`.
- Implementation: Componente de frontend que procesa los datos recibidos del backend.

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario accede a la pantalla de resumen de una cotización (HU-130).
2.  Desde esta pantalla, el usuario selecciona una opción (ej., botón "Ver Desglose Técnico" o pestaña "Información Técnica").
3.  El sistema navega a la ruta `/quotes/{folio}/technical-info`.
4.  La pantalla carga y muestra la tabla con el desglose técnico por ubicación y componente.
5.  Si la cotización no está calculada, se muestra un mensaje informativo en lugar del desglose.
**Messages/Modals:**
*   Mensaje de error/información: "La cotización no ha sido calculada. Por favor, ejecute el cálculo primero." (en caso de cotización no calculada).
**Stepper/Breadcrumbs:**
*   Se podría integrar en un breadcrumb o navegación por pestañas dentro de la vista de detalle de la cotización: `Cotizaciones > [Folio de Cotización] > Información Técnica`.

## 11. Architecture and Technical Dependencies
- **Frontend:** Ruta `/quotes/{folio}/technical-info` que consume una API de backend. Componente de tabla o grid para mostrar el desglose.
- **Backend (API de Consulta de Cotizaciones):** Endpoint RESTful (ej., `GET /api/quotes/{folio}/technical-info`) que se encarga de:
    - Validar el estado de cálculo de la cotización.
    - Recuperar los datos del **snapshot de trazabilidad del cálculo (FT-013)**.
    - Formatear los datos para su visualización en el frontend.
- **Base de Datos/Almacenamiento:** El snapshot de trazabilidad del cálculo se almacena en una base de datos (ej., MongoDB, PostgreSQL con JSONB) o un sistema de almacenamiento de documentos donde se persisten los resultados detallados del cálculo (HU-128).

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Consistencia de Datos del Snapshot.**
    - Description: La información mostrada depende completamente de la integridad y completitud del "snapshot de trazabilidad". Si este snapshot no se genera correctamente o está corrupto, la pantalla mostrará datos incorrectos o incompletos.
    - Impact: Alta (información crítica para el negocio errónea).
    - Probability: Media (depende de la robustez del proceso de cálculo y persistencia).
    - Mitigation: Implementar validaciones exhaustivas al persistir el snapshot (HU-128, FT-013). Monitoreo de la integridad de los datos del snapshot.
2.  **Riesgo: Rendimiento para Cotizaciones Grandes.**
    - Description: Si una cotización tiene un número muy elevado de ubicaciones o componentes técnicos, la recuperación y renderización del desglose podría ser lenta.
    - Impact: Media (mala experiencia de usuario, posibles timeouts).
    - Probability: Baja a Media (depende del volumen de datos esperado).
    - Mitigation: Implementar paginación o virtualización en el frontend. Optimizar la consulta en el backend. Revisar la estructura del snapshot para facilitar la consulta.
**Technical Debt:** [To be filled by operating team per scope and MVP]
*   Considerar la implementación de un mecanismo de caché para el desglose técnico de cotizaciones calculadas frecuentemente consultadas.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta funcionalidad es fundamental para la transparencia y la validación de los cálculos de prima, permitiendo a los usuarios entender el "por qué" detrás de los números. Sin ella, la confianza en el sistema de cotización podría verse comprometida.
**Feature Impact:** La no implementación o el fallo de esta historia impactaría severamente la capacidad del usuario para validar y confiar en los resultados de la Feature FT-005 (Visualización Detallada de Resultados Financieros). Es un componente clave para la auditoría interna y el soporte al cliente.
**Critical Dependencies:** HU-128 (Persistir Resultados del Cálculo de Prima) y FT-013 (Generación y Persistencia del Snapshot de Trazabilidad) son críticas; sin ellas, esta historia no puede funcionar.
**Recommended Priority:** Sprint actual (dada la prioridad 'Alta').

## 18. Identified Assumptions
1.  **Asunción: Existencia y Accesibilidad del Snapshot de Trazabilidad.**
    - Description: Se asume que el "snapshot de trazabilidad del cálculo" (FT-013) se genera de manera consistente y contiene toda la información necesaria y detallada para el desglose técnico, y que es fácilmente accesible por la API de consulta de cotizaciones.
    - Impact if false: La pantalla no podrá mostrar el desglose o mostrará datos incompletos/incorrectos.
    - Requires validation from: Equipo de Backend / Arquitectura de Datos.
2.  **Asunción: Permisos de Usuario.**
    - Description: Se asume que los roles de usuario apropiados (ej. Cotizador, Suscriptor) tendrán los permisos necesarios para acceder a esta información sensible.
    - Impact if false: Los usuarios autorizados no podrán acceder a la funcionalidad, o usuarios no autorizados podrían hacerlo.
    - Requires validation from: Equipo de Seguridad / Product Owner.
3.  **Asunción: Folio Único y Válido.**
    - Description: Se asume que el `folio` de la cotización proporcionado en la URL es un identificador único y válido para una cotización existente en el sistema.
    - Impact if false: Errores al cargar la página o mostrar información incorrecta.
    - Requires validation from: Equipo de Backend.
