## 2. Enabled Capability
**CAP-005:** Resiliencia en la Generación de Folios
**Business Value:** Mejora la robustez y la continuidad de los procesos que dependen de la generación de folios, minimizando la intervención manual y optimizando la experiencia del usuario final al reducir fallos visibles.
**Requires:** CAP-004 (Generación de Folios - implícita en HU-086, HU-087)

**Orchestrates:** Servicio de Generación de Folios (interno)

## 3. User Story
Como sistema,
Quiero tener un mecanismo de reintentos automáticos configurable en caso de fallo en la generación de folios,
Para que se mejore la resiliencia del proceso y se reduzca la necesidad de intervención manual.

## 4. Functional Description
**Description:** El sistema implementará un mecanismo de reintentos automático para la generación de folios. Cuando el servicio de generación de folios falle, el sistema detectará el error y, si el tipo de error es reintentable, aplicará una estrategia de reintentos configurable (ej. Exponential Backoff). Este mecanismo permitirá un número máximo de reintentos definido. Si un reintento es exitoso, el proceso de generación de folio se completará y la ejecución normal continuará. Si se agotan los reintentos sin éxito, el sistema detendrá los intentos y registrará el fallo final para una posible intervención.
**Flow:** [Inicio Proceso] → [HU-086: Solicitud de Generación de Folio] → [HU-087: Generación de Folio] → **[HU-088: Manejo de Fallo con Reintentos]** → [Folio Generado Exitosamente / Fallo Final y Alerta]

## 5. Expected Results


| element | description |
|---|---|
| Data | El folio se genera y persiste en la base de datos (en caso de éxito en un reintento). Se actualizan los logs con el estado de cada intento y el resultado final. |
| States | El estado del proceso de generación de folio transita de 'Fallo Temporal' a 'Reintentando' y finalmente a 'Éxito' o 'Fallo Definitivo'. |
| Notifications | En caso de agotar los reintentos sin éxito, se generará una alerta a los equipos de operaciones o soporte técnico. No hay notificaciones al usuario final por cada reintento, solo por el éxito o el fallo final. |
| Integrations | El Servicio de Generación de Folios será invocado múltiples veces hasta lograr el éxito o agotar los reintentos. |
| Kafka | Si la generación de folio es exitosa (incluso después de reintentos), se publicará un evento 'FolioGenerado' en el topic 'folio.events'. Si falla definitivamente, se puede publicar un evento 'FalloGeneracionFolio' para auditoría o procesos de compensación. |
| Logs | Se registrarán los siguientes eventos: inicio de reintento, número de intento actual, tipo de error detectado, resultado de cada intento (éxito/fallo), y el resultado final del mecanismo de reintentos. |
| UI | No hay impacto directo en la UI durante los reintentos. Si el proceso fue iniciado por un usuario, la UI reflejará el éxito o el fallo final de la generación del folio una vez que el mecanismo de reintentos haya concluido. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Reintento automático ante fallo reintentable
**Description:** Valida que el sistema detecta fallos temporales y ejecuta un reintento automático tras un periodo de espera.

```gherkin
Scenario: El sistema reintenta automáticamente la generación de folio ante un fallo temporal
  Given la generación del folio falla inicialmente con un error reintentable (ej. conflicto de concurrencia)
  And el sistema está configurado para reintentar
  When el sistema detecta el fallo
  Then realiza un reintento automático de la generación del folio después de un breve periodo
```

### AC-002: Límite de reintentos configurado
**Description:** Valida que el sistema respeta el número máximo de reintentos configurado y detiene el proceso si se excede.

```gherkin
Scenario: El sistema detiene los reintentos al alcanzar el límite configurado
  Given la generación del folio ha fallado 3 veces consecutivas con errores reintentables
  And el sistema está configurado con un máximo de 3 reintentos
  When el sistema intenta el cuarto reintento
  Then el sistema detiene los reintentos y marca la generación del folio como fallida
  And no se realiza ningún reintento adicional
```

### AC-003: Reintento exitoso y continuación del proceso
**Description:** Valida que si un reintento es exitoso, el folio se genera y el flujo de negocio continúa normalmente.

```gherkin
Scenario: El sistema genera el folio y continúa el proceso cuando un reintento es exitoso
  Given la generación del folio falla inicialmente
  And el sistema ha realizado un reintento
  When el reintento resulta exitoso
  Then el folio se genera correctamente
  And el proceso de negocio que requiere el folio continúa su ejecución normal
```

### AC-004: Errores no reintentables
**Description:** Valida que el sistema no reintenta para tipos de errores que no justifican un reintento.

```gherkin
Scenario: El sistema no reintenta ante un error no reintentable
  Given la generación del folio falla con un error de lógica de negocio (ej. datos inválidos)
  And el sistema está configurado para no reintentar este tipo de error
  When el sistema detecta el fallo
  Then el sistema detiene el proceso de generación del folio inmediatamente
  And registra el fallo sin realizar reintentos
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| maxRetries | Integer | yes | 3 | >0 | N/A | 3 |
| initialBackoffMs | Integer | yes | 500 | >0 | N/A | 500 (ms) |
| backoffMultiplier | Decimal | yes | 2.0 | >=1.0 | N/A | 2.0 |
| retryableErrorCodes | List<String> | yes | ['409', '500', '503'] | Lista de códigos HTTP o de error | N/A | ['CONCURRENCY_ERROR', 'INTERNAL_SERVER_ERROR'] |


**BR-001:** Estrategia de Reintentos
- Description: El sistema debe utilizar una estrategia de reintentos con backoff exponencial para espaciar los intentos fallidos, evitando sobrecargar el servicio de generación de folios.
- Trigger: Cada vez que la generación de folio falla con un error reintentable.
- Logic: `delay = initialBackoffMs * (backoffMultiplier ^ (currentAttempt - 1))`
- Implementation: Módulo de Resiliencia / Servicio de Generación de Folios
- Exception: No aplica.

**BR-002:** Límite Máximo de Reintentos
- Description: El sistema debe respetar un número máximo configurable de reintentos. Una vez alcanzado este límite, no se realizarán más intentos y el fallo se considerará definitivo.
- Trigger: Antes de cada reintento.
- Logic: `if (currentAttempt > maxRetries) then stopRetrying()`
- Implementation: Módulo de Resiliencia
- Exception: No aplica.

**BR-003:** Clasificación de Errores para Reintento
- Description: Los reintentos solo se aplicarán a tipos de errores específicos que se consideran transitorios o reintentables (ej. conflictos de concurrencia, errores temporales de red, indisponibilidad del servicio). Los errores de lógica de negocio o de validación (ej. datos inválidos) no deben activar un reintento.
- Trigger: Tras detectar un fallo en la generación del folio.
- Logic: `if (errorType is in retryableErrorCodes) then retry() else failImmediately()`
- Implementation: Servicio de Generación de Folios / Módulo de Resiliencia
- Exception: Errores no clasificados por defecto se considerarán no reintentables a menos que se especifique lo contrario.

## 11. Architecture and Technical Dependencies
- **Servicio de Generación de Folios:** Componente principal que esta historia intenta proteger y hacer más resiliente. Se debe asegurar que este servicio es idempotente para las operaciones de generación de folios, para evitar la creación de folios duplicados en caso de reintentos.
- **Estrategia de reintentos (ej. Exponential Backoff):** Librería o patrón de diseño implementado para gestionar los tiempos de espera entre reintentos.
- **Circuit Breaker:** Se recomienda implementar un Circuit Breaker para proteger el Servicio de Generación de Folios de sobrecargas y para proporcionar un mecanismo de fallback rápido si el servicio está inoperativo por un período prolongado, evitando reintentos inútiles.
- **Mecanismo de Observabilidad:** Herramientas de logging y métricas para monitorear el comportamiento de los reintentos (éxitos, fallos, latencia).

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Sobrecarga del Servicio de Generación de Folios.**
    *   Descripción: Una configuración agresiva de reintentos o un gran volumen de fallos concurrentes podría sobrecargar el servicio de folios, empeorando la situación en lugar de mejorarla.
    *   Impacto: Indisponibilidad prolongada del servicio de folios, degradación del rendimiento.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breaker, configurar un backoff exponencial adecuado, limitar el número de reintentos, monitorear la carga del servicio de folios.
2.  **Riesgo: Lógica incompleta de clasificación de errores.**
    *   Descripción: Si no se clasifican correctamente los errores reintentables de los no reintentables, el sistema podría reintentar fallos permanentes o no reintentar fallos transitorios.
    *   Impacto: Reintentos inútiles, consumo de recursos, retrasos innecesarios, o fallos definitivos que podrían haberse recuperado.
    *   Probabilidad: Alta.
    *   Mitigación: Trabajar con el equipo del Servicio de Generación de Folios para definir una lista exhaustiva de códigos/tipos de error reintentables. Implementar pruebas robustas para diferentes escenarios de error.
3.  **Riesgo: Idempotencia del Servicio de Generación de Folios.**
    *   Descripción: Si el servicio de generación de folios no es idempotente, un reintento podría crear un folio duplicado si el fallo original ocurrió después de la creación pero antes de la confirmación.
    *   Impacto: Datos inconsistentes, folios duplicados, errores en procesos downstream.
    *   Probabilidad: Media.
    *   Mitigación: Validar y asegurar que el Servicio de Generación de Folios es idempotente para la operación de creación de folios, usando identificadores únicos de transacción.

**Technical Debt:** [To be filled by operating team per scope and MVP]
*   La configuración de los reintentos (maxRetries, backoff, etc.) inicialmente podría ser estática, con la deuda de hacerla dinámica vía configuración remota.
*   La lista de errores reintentables puede ser simple al inicio y requerir un refinamiento más granular en el futuro.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La generación de folios es un proceso fundamental para el negocio. La falta de un mecanismo de reintentos robusto implica que cualquier fallo transitorio en este proceso requeriría intervención manual, interrumpiendo el flujo de trabajo y afectando la disponibilidad del servicio. Esta historia mejora significativamente la resiliencia y la estabilidad del sistema.
**Feature Impact:** Sin esta historia, la funcionalidad de "Generación y Gestión de Folios" sería frágil y propensa a interrupciones, impactando negativamente a todas las funcionalidades dependientes de folios.
**Critical Dependencies:** HU-086 y HU-087 son críticamente dependientes de que los folios se generen de manera fiable.
**Recommended Priority:** Próximo Sprint (dada la prioridad 'Alta' y su impacto en la resiliencia).

## 18. Identified Assumptions
1.  **Tipos de Errores Definidos:**
    *   Description: Se asume que existe una clara distinción y clasificación de los tipos de errores que pueden ocurrir durante la generación del folio, permitiendo identificar cuáles son reintentables y cuáles no.
    *   Impact if false: El sistema podría reintentar errores permanentes o no reintentar errores transitorios, llevando a un comportamiento ineficiente o incorrecto.
    *   Requires validation from: Equipo de Desarrollo del Servicio de Generación de Folios.
2.  **Configuración de Reintentos Centralizada:**
    *   Description: Se asume que los parámetros de reintento (número máximo, tiempos de espera) serán configurables y accesibles de forma centralizada, sin necesidad de redeploy.
    *   Impact if false: Los cambios en la estrategia de reintentos requerirían modificaciones de código y redeploys, aumentando el tiempo de respuesta ante problemas.
    *   Requires validation from: Arquitectura / Equipo de DevOps.
3.  **Idempotencia del Servicio de Generación de Folios:**
    *   Description: Se asume que el Servicio de Generación de Folios es idempotente, es decir, que invocarlo múltiples veces con los mismos parámetros para una misma solicitud de folio no resultará en la creación de folios duplicados.
    *   Impact if false: Los reintentos podrían llevar a la creación de folios duplicados, causando inconsistencias en los datos y problemas en los procesos downstream.
    *   Requires validation from: Equipo de Desarrollo del Servicio de Generación de Folios.
