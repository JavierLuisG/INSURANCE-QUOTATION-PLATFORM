## 2. Enabled Capability
**CAP-050:** Validación de Códigos Postales y Zonas
**Business Value:** Asegurar la correcta clasificación geográfica del riesgo y la aplicación de factores específicos, lo que impacta directamente en la precisión de las evaluaciones de riesgo.
**Requires:** CAP-047 (Disponibilidad del `catalogo_cp_zonas`)
**Enables:** CAP-XXX (Cálculo de Factores de Riesgo por Zona), CAP-XXX (Asignación de Políticas por Ubicación)
**Orchestrates:** Servicio de consulta de catálogos (CP)

## 3. User Story
Como usuario,
Quiero que el sistema valide los códigos postales de las ubicaciones contra el `catalogo_cp_zonas`,
Para asegurar la correcta clasificación geográfica del riesgo y la aplicación de factores específicos.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema verificará la validez de los códigos postales introducidos por el usuario para las ubicaciones. La validación se realizará consultando un `catalogo_cp_zonas` centralizado. Si el código postal existe en el catálogo, se considerará válido y se asignará la zona geográfica asociada a la ubicación. En caso de que el código postal no se encuentre o el catálogo no esté disponible, el sistema gestionará estas situaciones reportando un error o aplicando una lógica de contingencia.
**Flow:** [HU-XXX: Ingreso/Modificación de Datos de Ubicación] → [HU-050: Validación de Código Postal y Zona] → [HU-XXX: Guardado de Ubicación con Zona Asignada / Reporte de Error]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Validación exitosa de código postal existente
**Description:** Valida que un código postal que se encuentra en el `catalogo_cp_zonas` sea reconocido como válido y su zona correspondiente sea asignada.

```gherkin
Scenario: Código postal válido y existente
  Given un usuario ha ingresado un código postal existente en el `catalogo_cp_zonas` para una ubicación
  When el sistema ejecuta la validación del código postal
  Then el código postal se considera válido y se asigna la zona correspondiente a la ubicación
```

### AC-002: Reporte de error por código postal no existente
**Description:** Valida que el sistema reporte un error claro cuando se ingresa un código postal que no se encuentra en el `catalogo_cp_zonas`.

```gherkin
Scenario: Código postal inválido o no existente
  Given un usuario ha ingresado un código postal no existente en el `catalogo_cp_zonas` para una ubicación
  When el sistema ejecuta la validación del código postal
  Then el sistema reporta un error indicando un código postal inválido
```

### AC-003: Manejo de catálogo no disponible
**Description:** Valida que el sistema reaccione adecuadamente (ej. error de sistema o validación predeterminada) si el `catalogo_cp_zonas` no está accesible.

```gherkin
Scenario: Fallo en la disponibilidad del catálogo de códigos postales
  Given el `catalogo_cp_zonas` no está disponible o el servicio de consulta falla
  When el sistema intenta validar un código postal
  Then el sistema maneja la situación (ej. reporta un error de sistema o aplica una validación predeterminada)
```

**BR-050-01:** Regla de Existencia en Catálogo de Código Postal
- Description: Un código postal ingresado por el usuario es válido si y solo si se encuentra en el `catalogo_cp_zonas`.
- Trigger: Al intentar guardar o actualizar una ubicación con un código postal.
- Logic: `SI codigo_postal EXISTE EN catalogo_cp_zonas ENTONCES VALIDAR_OK Y ASIGNAR_ZONA_CORRESPONDIENTE SINO INVALIDAR_CP`
- Implementation: Módulo de reglas de validación.
- Exception: Si el `catalogo_cp_zonas` no está disponible, se activa el manejo de errores del sistema.

## 11. Architecture and Technical Dependencies
- **Módulo de reglas de validación:** Componente encargado de orquestar la llamada al servicio de catálogos y aplicar la lógica de negocio para la validación del código postal.
- **Servicio de consulta de catálogos (CP):** Microservicio o API que expone la funcionalidad para consultar el `catalogo_cp_zonas`.
  - Propósito: Proporcionar acceso performante y fiable a los datos de códigos postales y sus zonas asociadas.
  - Timeout: 500ms
  - Retries: 2 (con backoff exponencial)
- **`catalogo_cp_zonas`:** Base de datos o fuente de datos donde se almacenan los códigos postales y sus zonas.
- **Componente de reporte de errores:** Módulo encargado de gestionar y presentar los mensajes de error al usuario y registrar los errores en el sistema de logs.

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Performance del Servicio de Catálogos.
    - Descripción: Si el `catalogo_cp_zonas` es muy extenso o el servicio de consulta no es performante, la validación podría ralentizar la experiencia del usuario y procesos posteriores. (Mencionado en "Notas de Implementación").
    - Impacto: Baja experiencia de usuario, cuellos de botella en la creación/actualización de ubicaciones.
    - Probabilidad: Media.
    - Mitigación: Implementar caché en el servicio de validación, optimizar la base de datos del catálogo (índices), monitorear la latencia del servicio.
2.  **Nombre:** Desactualización del `catalogo_cp_zonas`.
    - Descripción: Si el catálogo no se mantiene actualizado con los cambios geográficos o nuevos códigos postales, la validación puede ser incorrecta o fallar para ubicaciones válidas.
    - Impacto: Clasificación de riesgo errónea, aplicación incorrecta de factores específicos, datos inconsistentes.
    - Probabilidad: Baja (asumiendo que HU-047 aborda la actualización).
    - Mitigación: Establecer un proceso claro de sincronización y actualización del catálogo, monitoreo de la frescura de los datos.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La validación del código postal es fundamental para la correcta clasificación geográfica del riesgo, que es un pilar central del negocio. Un fallo o imprecisión en esta validación puede llevar a decisiones de negocio erróneas y potenciales pérdidas financieras.
**Feature Impact:** La no implementación o el fallo de esta historia invalidaría la fiabilidad de cualquier funcionalidad que dependa de la ubicación geográfica para el cálculo de riesgo o la aplicación de factores específicos.
**Critical Dependencies:** Todas las historias que impliquen el cálculo de riesgo o la aplicación de reglas basadas en la ubicación geográfica (zona).
**Recommended Priority:** Sprint actual (Dada la prioridad "Alta" y su impacto crítico).
