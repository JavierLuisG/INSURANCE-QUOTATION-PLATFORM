## 2. Enabled Capability
**CAP-001:** Obtener Catálogo de Suscriptores
**Business Value:** Garantiza que el formulario de cotización siempre disponga de una lista actualizada y precisa de suscriptores, mejorando la eficiencia y la calidad en la creación de cotizaciones.
**Requires:** CAP-XXX (asociada a HU-068, que podría ser "Inicializar Contexto de Cotización")
**Enables:** CAP-002 (Seleccionar Suscriptor en Cotización)
**Orchestrates:** Servicio externo `Plataforma-core-ohs` (o su mock)

## 3. User Story
Como sistema (cotizador),
Quiero recuperar el catálogo de suscriptores desde el servicio `Plataforma-core-ohs` (o su mock),
Para ofrecer una lista actualizada en el formulario de cotización.

## 4. Functional Description
**Description:** El sistema cotizador, al requerir la lista de suscriptores para la creación o edición de una cotización, realiza una solicitud al servicio `Plataforma-core-ohs`. La respuesta recibida es procesada por una capa de mapeo de datos que transforma la información al formato interno del cotizador, asegurando que los datos sean válidos. Finalmente, el catálogo de suscriptores, que contiene al menos el ID y el nombre, se pone a disposición de la interfaz de usuario para su selección en el formulario de cotización. En caso de errores en la comunicación, datos malformados o una lista vacía, el sistema gestiona estas situaciones de forma robusta, priorizando la estabilidad y la experiencia del usuario.
**Flow:** HU-068 (Preparar Formulario de Cotización) → HU-069 (Recuperar Catálogo de Suscriptores) → HU-XXX (Seleccionar Suscriptor en Formulario de Cotización)

**BR-001:** Mapeo Robusto de Datos de Suscriptores
- Description: La capa de mapeo de datos debe ser capaz de transformar la respuesta del servicio `Plataforma-core-ohs` a un formato interno de Suscriptor (ID, Nombre). Debe ser tolerante a campos adicionales en la respuesta y a la ausencia de campos no requeridos.
- Trigger: Después de recibir la respuesta del servicio `Plataforma-core-ohs`.
- Logic: Validar la estructura básica de cada elemento de la lista esperada (que contenga 'id' y 'nombre'). Si un elemento no cumple, se descarta o se intenta un mapeo parcial si es posible y seguro.
- Implementation: Servicio de Catálogos / Capa de Mapeo de Datos en el Cotizador.
- Exception: Si la respuesta global no es una lista o es nula, se considera un error crítico de mapeo.

**BR-002:** Paginación de Catálogo (Condicional)
- Description: Si el volumen de suscriptores excede un umbral predefinido (ej. 1000 elementos), se debe implementar un mecanismo de paginación para la recuperación de datos, tanto en la solicitud como en el procesamiento de la respuesta.
- Trigger: Al realizar la solicitud al servicio `Plataforma-core-ohs`.
- Logic: Determinar si el catálogo es grande. Si es así, realizar múltiples llamadas paginadas hasta obtener todos los resultados o hasta un límite configurado.
- Implementation: Cliente API REST / Repositorio de Catálogos.
- Exception: Si el servicio `Plataforma-core-ohs` no soporta paginación, se debe documentar como riesgo y considerar alternativas (ej. caché más grande, carga asíncrona).

## 11. Architecture and Technical Dependencies
- **`Plataforma-core-ohs`**: Servicio RESTful para la obtención del catálogo de suscriptores.
    - Propósito: Proveer una lista autorizada y actualizada de suscriptores.
    - Timeout: 5000 ms (configurable).
    - Retries: 2 reintentos con backoff exponencial.
- **Cliente API REST**: Módulo encargado de realizar las llamadas HTTP a `Plataforma-core-ohs`.
- **Capa de Mapeo de Datos**: Componente responsable de transformar la respuesta JSON del servicio a objetos de dominio del cotizador.
- **Repositorio de Catálogos**: Componente que abstrae la fuente de datos del catálogo (en este caso, la API externa y posiblemente una caché interna).
- **Circuit Breaker**: Implementar un patrón Circuit Breaker para la llamada a `Plataforma-core-ohs` para manejar fallos transitorios y evitar cascadas de errores.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad de `Plataforma-core-ohs`**:
    *   Descripción: Si el servicio `Plataforma-core-ohs` no está disponible o experimenta alta latencia, el cotizador no podrá obtener la lista de suscriptores.
    *   Impacto: El formulario de cotización no podrá funcionar correctamente, afectando la capacidad de los usuarios para crear cotizaciones.
    *   Probabilidad: Media.
    *   Mitigación: Implementación de Circuit Breaker, reintentos con backoff, caché local de suscriptores (si es aceptable que no sea 100% en tiempo real), monitoreo proactivo del servicio dependiente.
2.  **Cambios en el Contrato de la API de `Plataforma-core-ohs`**:
    *   Descripción: Un cambio en la estructura de la respuesta del servicio `Plataforma-core-ohs` sin previo aviso podría romper el mapeo de datos en el cotizador.
    *   Impacto: Errores de mapeo, catálogo vacío o incorrecto en la UI, interrupción del flujo de cotización.
    *   Probabilidad: Baja (con buena comunicación entre equipos) a Media (si la comunicación es deficiente).
    *   Mitigación: Pruebas de integración automatizadas, monitoreo de la API externa, comunicación proactiva con el equipo de `Plataforma-core-ohs`, mapeo robusto y tolerante a campos adicionales.
3.  **Rendimiento con Catálogos Muy Grandes**:
    *   Descripción: Si el catálogo de suscriptores crece a millones de registros, la recuperación completa en una sola llamada podría causar problemas de rendimiento o memoria.
    *   Impacto: Tiempos de carga lentos, consumo excesivo de recursos, timeouts.
    *   Probabilidad: Baja inicialmente, pero aumenta con el crecimiento del negocio.
    *   Mitigación: Implementar paginación (BR-002), caching distribuido, carga asíncrona o búsqueda progresiva en la UI.

**Technical Debt:**
- La implementación de paginación (BR-002) se considera deuda técnica si no se aborda en el MVP inicial y el volumen de datos actual no lo justifica. Deberá ser priorizado cuando el catálogo supere un umbral de tamaño.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para el funcionamiento básico del formulario de cotización. Sin la capacidad de recuperar el catálogo de suscriptores, los usuarios no pueden seleccionar a quién cotizar, haciendo que la funcionalidad principal del cotizador sea inutilizable.
**Feature Impact:** La no implementación o el fallo de esta historia impide completamente la creación de nuevas cotizaciones y la edición de cotizaciones existentes que requieran la selección de un suscriptor.
**Critical Dependencies:** Cualquier historia de usuario relacionada con la creación, edición o visualización de cotizaciones que requiera la selección de un suscriptor.
**Recommended Priority:** Sprint actual (dado que es de prioridad alta y una dependencia crítica).

    *   Description: Se asume que el volumen inicial del catálogo de suscriptores no será excesivamente grande (ej. menos de 10,000 registros) de manera que no se requiera paginación en la primera iteración.
    *   Impact if false: Problemas de rendimiento y memoria, necesidad de implementar paginación de forma urgente.
    *   Requires validation from: Product Owner / Equipo de Negocio.
