## 1. Identificación General / General Identification
**Feature:** Motor de Cálculo de Tarifas/Precios  
**Capability:** CAP-EP-002 - Consumir Catálogo de Códigos Postales y Zonas  
**Actor:** Sistema (Motor de Cálculo)  
**Bounded Context:** Geozonificación y Cálculo  
**Story Points:** 3

## 2. Enabled Capability
**CAP-EP-002:** Consumir Catálogo de Códigos Postales y Zonas  
**Business Value:** Permite al motor de cálculo obtener y utilizar la relación entre códigos postales y sus zonas (CAT, nivel técnico) para realizar cálculos precisos y basados en la ubicación geográfica.  
**Requires:** HU-092 (Configurar Mock Server Base, FT-020)  
**Enables:** Historias de usuario relacionadas con el cálculo de tarifas, precios o cualquier lógica de negocio que dependa de la geozonificación.  
**Orchestrates:** Servicio `Plataforma-core-ohs`

## 3. User Story
Como sistema (motor de cálculo),  
Quiero consumir o simular el `catalogo_cp_zonas` del servicio `Plataforma-core-ohs` y mapear las zonas,  
Para poder obtener la relación entre códigos postales y sus zonas CAT y nivel técnico para fines de cálculo.

## 4. Functional Description
**Description:** Esta historia describe el proceso mediante el cual el sistema del motor de cálculo adquiere la información de zonificación geográfica (zona CAT y nivel técnico) asociada a los códigos postales. El sistema realizará una consulta al servicio `Plataforma-core-ohs` para obtener el `catalogo_cp_zonas`. Para entornos de desarrollo o pruebas, se permitirá la simulación de esta consulta a través de un mock. Una vez obtenidos los datos, el sistema los procesará y mapeará internamente para establecer la relación correcta entre cada código postal y sus respectivas zonas. La implementación inicial no considerará la gestión de versionado o fechas de vigencia para estos parámetros, dejándolo como una mejora futura.  
**Flow:** HU-092 (Configurar Mock Server Base, FT-020) → [HU-163: Consumir Catálogo de Códigos Postales y Zonas] → [Cualquier historia de cálculo que requiera CP-Zonas]

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| codigo_postal | String | yes | N/A | Formato de código postal (ej. 5 dígitos numéricos) | N/A | 28001 |
| zona_cat | String | yes | N/A | Valores definidos por el catálogo de zonas CAT | CAT_ZONAS | CAT_A |
| nivel_tecnico | String | yes | N/A | Valores definidos por el catálogo de niveles técnicos | NIVEL_TECNICO_ZONAS | NIVEL_1 |


**BR-001:** Mapeo de Zonas por Código Postal
- Description: Cada `codigo_postal` recibido debe ser asociado con una única `zona_cat` y un único `nivel_tecnico` dentro del sistema.
- Trigger: Al procesar el `catalogo_cp_zonas` recibido.
- Logic: Para cada entrada válida en el catálogo, se actualizará o insertará la relación `(codigo_postal -> {zona_cat, nivel_tecnico})` en la estructura de datos interna del motor de cálculo.
- Implementation: Componente "Mapeador de Datos" dentro del Backend.
- Exception: Si un `codigo_postal` aparece con múltiples `zona_cat` o `nivel_tecnico` en el mismo catálogo, se debe registrar un error y el sistema debe seguir una regla de desambiguación (ej. tomar la primera ocurrencia, rechazar la entrada, o fallar la carga completa del catálogo).

## 11. Architecture and Technical Dependencies
- **`Plataforma-core-ohs` (Servicio Externo):** Propósito: Proporcionar el `catalogo_cp_zonas`. Se debe definir y configurar un `timeout` adecuado para la llamada HTTP (ej. 5 segundos) y una política de reintentos (ej. 3 reintentos con backoff exponencial).
- **Backend (Adaptador para `Plataforma-core-ohs`):** Componente encargado de realizar la llamada HTTP al servicio externo y manejar la autenticación.
- **Mapeador de Datos:** Componente encargado de procesar la respuesta del servicio, validar los datos y transformarlos al formato interno del motor de cálculo.
- **Circuit Breaker:** Se recomienda implementar un Circuit Breaker para la llamada a `Plataforma-core-ohs` para manejar fallos del servicio de manera resiliente, evitando cascadas de errores.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Rendimiento de `Plataforma-core-ohs`:**
    *   **Description:** Si el servicio `Plataforma-core-ohs` no está disponible o es inestable, el motor de cálculo no podrá obtener o actualizar los datos de CP-Zonas, afectando la precisión y operatividad de los cálculos.
    *   **Impact:** Alto
    *   **Probability:** Media
    *   **Mitigation:** Implementar Circuit Breaker, retries con backoff, definir un `timeout` estricto, logging y alertas de monitoreo. Considerar una estrategia de caché o persistencia de la última versión conocida del catálogo para contingencias.
2.  **Calidad y Consistencia de los Datos del Catálogo:**
    *   **Description:** Si el `catalogo_cp_zonas` recibido contiene datos inconsistentes, incompletos o incorrectos, los cálculos basados en ellos serán erróneos, lo que puede llevar a decisiones de negocio incorrectas.
    *   **Impact:** Alto
    *   **Probability:** Media
    *   **Mitigation:** Implementar validaciones robustas en el mapeador de datos, logging detallado de errores de validación, y establecer un canal de comunicación con el equipo propietario de `Plataforma-core-ohs` para asegurar la calidad de los datos.
**Technical Debt:** La gestión de versionado o fechas de vigencia para los parámetros del catálogo CP-Zonas se pospone para una mejora futura. Esto implica que la implementación inicial asumirá que siempre se consume la versión más reciente del catálogo sin un control explícito de versiones.

**Critical Dependencies:** Cualquier historia de usuario que implique cálculos o reglas de negocio basadas en la ubicación geográfica (códigos postales y sus zonas).

## 18. Identified Assumptions
1.  **Formato de Datos Consistente:**
    - Description: Se asume que el formato y la estructura del `catalogo_cp_zonas` proporcionado por `Plataforma-core-ohs` será consistente y predecible, conforme a la especificación acordada (ej. un contrato de API).
    - Impact if false: El mapeador de datos podría fallar al procesar el catálogo, llevando a errores en la carga de datos o a datos incorrectos en el motor de cálculo.
    - Requires validation from: Equipo de `Plataforma-core-ohs` y equipo de desarrollo del motor de cálculo.
2.  **Frecuencia de Actualización del Catálogo:**
    - Description: Se asume que la frecuencia con la que el `catalogo_cp_zonas` necesita ser consultado o actualizado por el motor de cálculo será definida (ej. una vez al día, bajo demanda, etc.). La implementación inicial no considerará un mecanismo de actualización en tiempo real a menos que se especifique.
    - Impact if false: Podrían usarse datos desactualizados en los cálculos o el sistema podría sobrecargar `Plataforma-core-ohs` con consultas excesivas.
    - Requires validation from: Propietario del Producto, equipo de negocio, y equipo de `Plataforma-core-ohs`.
3.  **Unicidad del Mapeo CP-Zona:**
    - Description: Se asume que cada código postal tendrá una única asociación con una `zona_cat` y un `nivel_tecnico` en el catálogo en un momento dado.
    - Impact if false: El mapeo podría ser ambiguo, resultando en cálculos inconsistentes o errores si el sistema no tiene una regla clara para resolver conflictos.
    - Requires validation from: Propietario del Producto y equipo de `Plataforma-core-ohs`.
