## 3. User Story
Como sistema,  
Quiero que cada edición de una cotización actualice el campo `fechaUltimaActualizacion`,  
Para tener un registro de cuándo fue la última modificación de la cotización.

## 4. Functional Description
**Description:** Esta historia de usuario detalla el comportamiento del sistema para garantizar que el campo `fechaUltimaActualizacion` de una cotización se mantenga actualizado. Cuando una cotización existente es modificada y guardada exitosamente, o cuando una nueva cotización se crea y guarda por primera vez, este campo debe reflejar la fecha y hora actual de la operación. En caso de que la operación de guardado falle, el campo `fechaUltimaActualizacion` no debe ser modificado.  
**Flow:** HU-149 (Incrementar Versión en Ediciones de Cotización) → [Esta historia] → [Falta información: ¿Qué sigue después de que la fecha de última actualización ha sido registrada?]

**BR-001:** Actualización automática de `fechaUltimaActualizacion`
- Description: El campo `fechaUltimaActualizacion` debe ser actualizado automáticamente por el sistema al guardar una cotización, ya sea en su creación inicial o en ediciones posteriores.
- Trigger: Operación de guardado (creación o modificación) de una cotización.
- Logic:
  ```
  IF (operacion_guardado_cotizacion_exitosa) THEN
    cotizacion.fechaUltimaActualizacion = fecha_y_hora_actual_del_sistema (en UTC)
  ELSE IF (operacion_guardado_cotizacion_falla) THEN
    // El campo fechaUltimaActualizacion no debe ser modificado.
    // Si era una nueva cotización, el campo podría quedar nulo o no crearse.
  END IF
  ```
- Implementation: Capa de Persistencia o Servicio de Gestión de Cotizaciones.
- Exception: Si la operación de guardado de la cotización falla, la fecha no se actualiza.

## 16. Technical Notes and Risks
**Notes:**
- La actualización de la fecha debe ser automática.
- Se recomienda usar UTC para todas las fechas para evitar problemas de zona horaria.

**Risks:**
1.  **Consistencia de la Fecha:**
    - Description: Riesgo de que la `fechaUltimaActualizacion` no refleje con precisión el momento real de la modificación debido a problemas de zona horaria, configuración del reloj del servidor o errores en la lógica de actualización.
    - Impact: Datos inconsistentes, dificultad para auditar o rastrear cambios, posibles problemas legales o de negocio.
    - Probability: Media
    - Mitigation: Usar UTC consistentemente, asegurar sincronización del reloj del servidor (NTP), pruebas unitarias exhaustivas para la lógica de actualización de fecha.
2.  **Impacto en el rendimiento:**
    - Description: Aunque la actualización de un solo campo de fecha es generalmente ligera, si la lógica de persistencia es ineficiente o se ejecuta en un contexto de alta concurrencia sin optimización, podría añadir latencia a la operación de guardado de cotizaciones.
    - Impact: Degradación del rendimiento de la API de guardado de cotizaciones.
    - Probability: Baja
    - Mitigation: Asegurar que la actualización se realice dentro de la misma transacción de persistencia, optimizar las consultas de base de datos.
