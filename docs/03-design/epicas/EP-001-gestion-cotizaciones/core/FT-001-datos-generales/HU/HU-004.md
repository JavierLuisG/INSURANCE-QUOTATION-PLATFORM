## 2. Enabled Capability
**CAP-004:** Selección de Parámetros de Cotización
**Business Value:** Estandarizar la información de la cotización, mejorando la calidad y consistencia de los datos, y facilitando procesos posteriores.
**Requires:** FT-007: Integración con Servicios de Referencia (Catálogos)
**Enables:** CAP-005: Creación de Cotización Estandarizada
**Orchestrates:** Integración con `Plataforma-core-ohs` para la obtención de catálogos.

## 3. User Story
As a usuario,
I want seleccionar el tipo de seguro, la moneda y el canal de venta de listas predefinidas,
So that estandarizar la información de la cotización.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario seleccionar opciones predefinidas para el tipo de seguro, la moneda y el canal de venta dentro de la sección de datos generales de una cotización. Los valores se obtienen de catálogos externos (`Plataforma-core-ohs`) y se persisten junto con la cotización. El sistema debe validar que estos campos obligatorios sean seleccionados antes de guardar.
**Flow:** Inicio de Creación de Cotización → **HU-004: Seleccionar tipo de seguro, moneda y canal de venta de catálogos** → Ingreso de Datos del Asegurado / Cálculo de Cotización

## 10. UX and Navigation Flow
**UX Flow:**
1. El usuario inicia el proceso de creación de cotización y llega a la "Sección de Datos Generales".
2. Los campos "Tipo de Seguro", "Moneda" y "Canal de Venta" se muestran como dropdowns/selectores.
3. Al hacer clic en un selector, se muestra un indicador de carga (spinner) mientras se obtienen las opciones del catálogo.
4. Una vez cargadas, se muestran las opciones y el usuario selecciona una.
5. El valor seleccionado se muestra en el campo.
6. El usuario continúa con otros campos o intenta guardar la cotización.
7. Si se intenta guardar sin seleccionar un campo obligatorio, se muestra un mensaje de validación.

**Messages/Modals:**
*   Mensaje de éxito: "Datos generales guardados correctamente." (o parte de un mensaje más grande de guardado de cotización)
*   Mensaje de error: "Por favor, seleccione un valor para [Campo Obligatorio]."
*   Mensaje de carga: "Cargando opciones..." (visible durante la recuperación de catálogos).
*   Mensaje de error de catálogo: "No se pudieron cargar las opciones de [Tipo de Seguro/Moneda/Canal de Venta]. Intente de nuevo más tarde."
**Stepper/Breadcrumbs:** Se espera que esta sección sea parte de un flujo mayor de creación de cotización, por ejemplo: "Creación de Cotización > **Datos Generales** > Datos del Asegurado > ...".

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Rendimiento del Servicio de Catálogos (`Plataforma-core-ohs`):**
    - Descripción: La disponibilidad y el rendimiento de `Plataforma-core-ohs` son críticos para esta historia. Un fallo o latencia excesiva podría impedir la creación de cotizaciones.
    - Impacto: Alto (bloqueo de la creación de cotizaciones, mala experiencia de usuario).
    - Probabilidad: Media.
    - Mitigación: Implementar Circuit Breaker y políticas de reintento. Considerar la implementación de un caché local para catálogos con TTL, si la consistencia en tiempo real no es estrictamente requerida. Monitoreo proactivo del servicio de catálogos.
2.  **Desincronización de Catálogos:**
    - Descripción: Posibilidad de que los datos en los catálogos cambien mientras un usuario está creando una cotización, invalidando una selección previa.
    - Impacto: Medio (errores al guardar, datos inconsistentes).
    - Probabilidad: Baja.
    - Mitigación: Validaciones en backend al momento de guardar para asegurar que el valor seleccionado sigue siendo válido. Notificación al usuario si un valor seleccionado se ha vuelto obsoleto.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es fundamental para la estandarización y la calidad de los datos de las cotizaciones. Aunque la creación de una cotización podría teóricamente avanzar con datos no estandarizados (si hubiera una alternativa manual), la falta de esta funcionalidad comprometería la eficiencia y la integridad de la información desde el inicio del proceso.
**Feature Impact:** Sin esta historia, la funcionalidad de creación de cotizaciones no cumpliría con los requisitos de estandarización, lo que llevaría a datos inconsistentes, errores en cálculos posteriores y dificultades en la generación de informes.
**Critical Dependencies:** La disponibilidad y correcto funcionamiento de la integración con `Plataforma-core-ohs` es una dependencia crítica.
**Recommended Priority:** Sprint actual o siguiente (dada su prioridad Media y su rol como habilitador de la creación de cotizaciones estandarizadas).
