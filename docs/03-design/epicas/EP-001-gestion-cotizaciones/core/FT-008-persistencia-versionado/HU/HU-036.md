## 2. Enabled Capability
**CAP-001:** Trazabilidad de Cambios en Cotizaciones
**Business Value:** Permite conocer la última vez que una cotización fue modificada, mejorando la auditoría, la trazabilidad de los cambios y facilitando la depuración y el análisis del historial.
**Requires:** CAP-002 - Creación y Edición de Cotizaciones
**Enables:** CAP-003 - Auditoría de Cotizaciones, CAP-004 - Reportes de Actividad de Cotizaciones
**Orchestrates:** N/A

## 3. User Story
Como un **desarrollador**,
quiero **que en cada edición de una cotización se actualice el campo `fechaUltimaActualizacion`**,
para **conocer cuándo fue el último cambio**.

## 4. Functional Description
**Description:** Esta historia de usuario implementa la lógica necesaria para que el campo `fechaUltimaActualizacion` de una cotización se actualice automáticamente con la fecha y hora actuales del sistema cada vez que una cotización es creada o modificada y persistida en la base de datos. Esto asegura que siempre se tenga un registro preciso del último cambio realizado.
**Flow:** [Cualquier historia de modificación de cotización (ej. US-001: Editar detalles de cotización)] → [Actualización automática de `fechaUltimaActualizacion`] → [US-002: Consultar detalles de cotización con metadatos actualizados]

## 6. Acceptance Criteria
### AC-001: Actualización del campo en edición
**Description:** Valida que el campo `fechaUltimaActualizacion` se actualice correctamente cuando una cotización existente es editada y guardada.

```gherkin
Scenario: Actualizar fechaUltimaActualizacion al editar una cotización
  Given una cotización existente con ID "COT-001" y una fechaUltimaActualizacion previa "2026-04-20T14:00:00Z"
  When un usuario edita la cotización "COT-001" y la guarda
  Then el campo fechaUltimaActualizacion de la cotización "COT-001" se actualiza con la fecha y hora actuales del sistema (ej. "2026-04-21T10:30:00Z")
```

### AC-002: Establecimiento del campo en creación
**Description:** Valida que el campo `fechaUltimaActualizacion` se establezca correctamente cuando una nueva cotización es creada y guardada por primera vez.

```gherkin
Scenario: Establecer fechaUltimaActualizacion al crear una cotización
  Given que se crea una nueva cotización con datos válidos
  When la cotización es guardada por primera vez
  Then el campo fechaUltimaActualizacion de la nueva cotización se establece con la fecha y hora de su creación (ej. "2026-04-21T10:35:00Z")
```

### AC-003: Consulta de metadatos refleja el último guardado
**Description:** Valida que al consultar una cotización, la `fechaUltimaActualizacion` mostrada sea la del último guardado.

```gherkin
Scenario: fechaUltimaActualizacion refleja el último guardado en la consulta
  Given una cotización con ID "COT-002" que fue editada y guardada por última vez el "2026-04-21T10:40:00Z"
  When un usuario consulta los detalles de la cotización "COT-002"
  Then la fechaUltimaActualizacion mostrada para "COT-002" es "2026-04-21T10:40:00Z"
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de la zona horaria:**
    *   Description: Riesgo de que la fecha y hora se guarden en diferentes zonas horarias o sin información de zona horaria, lo que puede llevar a inconsistencias.
    *   Impact: Datos de fecha erróneos o confusos, problemas en auditorías y reportes.
    *   Probability: Media
    *   Mitigation: Implementar de forma estricta el uso de UTC para el almacenamiento y convertir a la zona horaria local solo para la presentación en la UI. Validar con pruebas exhaustivas.
2.  **Impacto en el rendimiento de la base de datos:**
    *   Description: La actualización constante de un campo en cada operación de guardado podría tener un impacto marginal en el rendimiento, especialmente en sistemas con alta concurrencia.
    *   Impact: Aumento leve en la latencia de las operaciones de guardado de cotizaciones.
    *   Probability: Baja (para un solo campo simple)
    *   Mitigation: Monitorear el rendimiento después de la implementación. Asegurar que la actualización sea eficiente a nivel de base de datos (ej. evitar triggers complejos si no son necesarios).

## 17. Criticality
**Criticality Level:** Media
**Justification:** La funcionalidad es importante para la trazabilidad y la auditoría, proporcionando un valor significativo a los desarrolladores y equipos de soporte. Sin embargo, su ausencia no impide la funcionalidad central de creación o edición de cotizaciones, aunque dificulta el seguimiento de cambios.
**Feature Impact:** Sin esta funcionalidad, las features que modifican cotizaciones (FT-001 a FT-006) carecerían de un registro automático de su última actualización, lo que complicaría la depuración, el análisis de problemas y la generación de reportes de actividad.
**Critical Dependencies:** Todas las historias de usuario que implican la modificación de datos de cotizaciones dependen de esta historia para tener la funcionalidad de registro de la última actualización.
**Recommended Priority:** Sprint actual.
