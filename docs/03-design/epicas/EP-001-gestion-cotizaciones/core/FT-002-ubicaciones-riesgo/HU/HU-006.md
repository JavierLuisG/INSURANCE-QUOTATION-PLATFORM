## 1. Identificación General / General Identification
**Feature:** Gestión de Cotizaciones
**Capability:** CAP-006 - Gestión de Ubicaciones de Riesgo
**Actor:** Usuario (Agente de Seguros / Administrador de Cotizaciones)
**Bounded Context:** Cotizaciones
**Story Points:** 3

## 2. Enabled Capability
**CAP-006:** Gestión de Ubicaciones de Riesgo
**Business Value:** Permite la especificación detallada de los activos a asegurar, mejorando la precisión de la cotización y la evaluación del riesgo, lo que puede llevar a una mejor experiencia del cliente y una mayor conversión de ventas.
**Requires:** CAP-001: Iniciar nueva cotización con folio automático
**Enables:** CAP-007: Configurar detalles de la ubicación de riesgo, CAP-008: Calcular prima por ubicación
**Orchestrates:** N/A

## 3. User Story
As a usuario,
I want agregar una nueva ubicación de riesgo a la cotización,
So that detallar los diferentes lugares a asegurar.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario añadir múltiples ubicaciones de riesgo dentro de una cotización existente. El sistema debe proporcionar una interfaz clara para la gestión de estas ubicaciones (mediante secciones o pestañas) y debe aplicar un límite configurable (por defecto 10) al número total de ubicaciones que se pueden añadir a una cotización.
**Flow:** HU-001 (Iniciar nueva cotización con folio automático) → HU-006 (Agregar una nueva ubicación de riesgo) → HU-007 (Configurar detalles de la ubicación)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Creación de nueva sección o pestaña para ubicación
**Description:** Validar que al hacer clic en el botón "Agregar Ubicación", el sistema presente una nueva sección o pestaña en la interfaz de usuario, lista para que el usuario introduzca los detalles de la nueva ubicación.

```gherkin
Scenario: El usuario puede crear una nueva sección para la ubicación
  Given estoy editando una cotización existente
  When hago clic en el botón "Agregar Ubicación"
  Then se crea y se muestra una nueva sección o pestaña para una ubicación vacía
  And el foco de la interfaz se mueve a la nueva sección/pestaña
```

### AC-002: Asociación correcta de la ubicación a la cotización padre
**Description:** Validar que una ubicación recién creada, una vez guardada, se asocie correctamente a la cotización de la que forma parte y sea visible dentro de la lista de ubicaciones de esa cotización.

```gherkin
Scenario: La ubicación se asocia correctamente a la cotización
  Given he agregado una nueva ubicación a una cotización en edición
  And he completado los detalles requeridos para la ubicación (ej. dirección, ciudad)
  When hago clic en "Guardar Ubicación"
  Then la ubicación se guarda exitosamente
  And la ubicación aparece listada como parte de la cotización padre
  And se muestra un mensaje de éxito "Ubicación agregada exitosamente."
```

### AC-003: Notificación al alcanzar el límite de ubicaciones
**Description:** Validar que el sistema notifique al usuario de forma clara cuando intente agregar una ubicación más allá del límite configurado (por ejemplo, 10 ubicaciones).

```gherkin
Scenario: El sistema notifica al usuario al alcanzar el límite de ubicaciones
  Given estoy editando una cotización que ya tiene el número máximo de ubicaciones permitidas (ej. 10)
  When intento hacer clic en el botón "Agregar Ubicación"
  Then el botón "Agregar Ubicación" está deshabilitado o no visible
  And se muestra un mensaje de notificación indicando "Se ha alcanzado el límite máximo de 10 ubicaciones de riesgo para esta cotización."
```

**BR-001: Límite Máximo de Ubicaciones de Riesgo por Cotización**
- Description: Una cotización no puede tener más de un número máximo configurable de ubicaciones de riesgo asociadas. El valor por defecto es 10.
- Trigger: Intento de agregar una nueva ubicación de riesgo a una cotización.
- Logic:
    ```
    IF (cantidad_ubicaciones_actuales_en_cotizacion >= LIMITE_MAXIMO_UBICACIONES) THEN
        RECHAZAR_OPERACION("Límite de ubicaciones alcanzado")
    ELSE
        PERMITIR_OPERACION
    END IF
    ```
- Implementation: Servicio de Cotizaciones (Backend), Componente de UI (Frontend).
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:** `Pantalla de Edición de Cotización` → Clic en "Agregar Ubicación" → `Nueva Pestaña/Sección de Ubicación` (con campos de formulario vacíos) → Rellenar campos → Clic en "Guardar Ubicación" → `Pantalla de Edición de Cotización` (con la nueva ubicación listada y seleccionada, o con un indicador visual de su adición).
**Messages/Modals:**
- Mensaje de éxito: "Ubicación agregada y guardada exitosamente." (Toast o barra de notificación)
- Mensaje de error (límite): "Se ha alcanzado el límite máximo de 10 ubicaciones de riesgo para esta cotización. No se pueden añadir más." (Modal o Toast de error)
- Mensaje de error (validación): "Por favor, complete todos los campos obligatorios antes de guardar." (Mensajes de validación inline en el formulario)
**Stepper/Breadcrumbs:** Se utilizará un patrón de interfaz de usuario de tipo "maestro-detalle" o "pestañas" para navegar entre las diferentes ubicaciones de riesgo dentro de una cotización.

## 11. Architecture and Technical Dependencies
- **Frontend:** Componente de botón "Agregar Ubicación", Interfaz de gestión de ubicaciones (maestro-detalle/pestañas), Formularios para la entrada de datos de ubicación.


## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Complejidad en la Interfaz de Usuario para Múltiples Ubicaciones.**
    - Description: Si la interfaz para gestionar múltiples ubicaciones (pestañas o maestro-detalle) no está bien diseñada, puede volverse compleja y generar una mala experiencia de usuario, especialmente con muchos campos por ubicación.
    - Impact: Baja adopción, errores en la entrada de datos, frustración del usuario.
    - Probability: Media.
    - Mitigation: Realizar pruebas de usabilidad con prototipos. Considerar un diseño que permita colapsar/expandir secciones o una vista de tabla resumen para una navegación eficiente.
2.  **Riesgo: Configuración del Límite de Ubicaciones.**
    - Description: Aunque la historia menciona que el límite es configurable, existe el riesgo de que se implemente de forma rígida (hardcodeado), lo que dificultaría futuros cambios.
    - Impact: Retrabajo, falta de flexibilidad para el negocio.
    - Probability: Baja (dado que ya está identificado).
    - Mitigation: Asegurar que el límite se gestione a través de un parámetro de configuración externo (ej. variable de entorno, base de datos de configuración) desde el inicio.

**Technical Debt:** N/A (Para ser rellenado por el equipo operativo según el alcance y el MVP).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta funcionalidad es fundamental para la creación de cotizaciones precisas y detalladas. Sin la capacidad de especificar múltiples ubicaciones de riesgo, las cotizaciones serían genéricas y no cumplirían con las necesidades de muchos clientes, afectando directamente la propuesta de valor del producto.
**Feature Impact:** La no implementación o el fallo de esta historia impediría que los usuarios realicen cotizaciones complejas que requieren múltiples ubicaciones. Esto impactaría negativamente la capacidad de vender pólizas de seguro para activos distribuidos geográficamente.
**Critical Dependencies:** Depende de la creación inicial de una cotización (HU-001) y es un prerrequisito para cualquier cálculo de prima o gestión de activos a nivel de ubicación.
**Recommended Priority:** Sprint actual (dada su criticidad y dependencia para otras funcionalidades clave).

## 18. Identified Assumptions
1.  **Asunción: El "usuario" es un rol con permisos adecuados.**
    - Description: Se asume que el actor de la historia (Agente de Seguros, Administrador de Cotizaciones) tiene los conocimientos y los permisos necesarios para gestionar cotizaciones y sus ubicaciones de riesgo.
    - Impact if false: La interfaz o los flujos podrían no ser adecuados para el usuario real, o el usuario podría no tener los permisos necesarios, generando errores de autorización.
    - Requires validation from: Stakeholders de Negocio, Equipo de Producto.
2.  **Asunción: Existen datos básicos definidos para una "ubicación de riesgo".**
    - Description: La historia original no especifica qué datos componen una ubicación. Se asume que se necesitan campos básicos como dirección, ciudad, país, etc., para una ubicación de riesgo estándar.
    - Impact if false: La funcionalidad podría no ser útil o requerir un retrabajo significativo para capturar los datos necesarios para la evaluación de riesgos.
    - Requires validation from: Stakeholders de Negocio, Analistas de Datos, Equipo de Actuaría.
3.  **Asunción: El límite de 10 ubicaciones es un valor inicial y configurable.**
    - Description: Aunque se menciona en las notas, se asume que este límite no es un valor fijo e inmutable, sino que puede ajustarse por configuración en el futuro si las necesidades del negocio cambian.
    - Impact if false: Un cambio futuro en el límite requeriría un cambio de código, aumentando el esfuerzo de mantenimiento.
    - Requires validation from: Equipo de Producto, Arquitectura.
