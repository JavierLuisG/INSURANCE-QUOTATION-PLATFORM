## 2. Enabled Capability
**CAP-001:** Verificación de Datos Mínimos de Ubicación
**Business Value:** Garantiza la integridad de los datos necesarios para el cálculo de primas, evitando errores y resultados incompletos.
**Requires:** Modelo de datos de la cotización
**Enables:** CAP-XXX - Cálculo de Prima
**Orchestrates:** Módulo de reglas de validación

## 3. User Story
Como usuario,
Quiero que el sistema verifique que todas las ubicaciones tengan los datos mínimos requeridos para el cálculo de prima,
Para que el cálculo pueda proceder correctamente y evitar resultados incompletos.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para validar que cada ubicación dentro de una cotización contenga todos los datos obligatorios necesarios para realizar el cálculo de la prima. El sistema debe identificar cualquier campo faltante y reportarlo al usuario, impidiendo que se proceda con el cálculo hasta que los datos estén completos.
**Flow:** [Ingreso/Edición de Ubicación] → [HU-051: Verificación de Datos Mínimos por Ubicación] → [Cálculo de Prima (si es válido) / Reporte de Errores (si es inválido)]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Ubicación completa
**Description:** Valida que una ubicación se considera completa cuando todos sus campos obligatorios están llenos.

```gherkin
Scenario: Verificación de ubicación con datos mínimos completos

  When se ejecuta la validación
  Then la ubicación se considera completa
```

### AC-002: Campo obligatorio faltante
**Description:** Valida que el sistema reporta un error específico si falta un campo obligatorio.

```gherkin
Scenario: Verificación de ubicación con un campo obligatorio faltante
  Given falta un campo obligatorio en una ubicación
  When se ejecuta la validación
  Then el sistema reporta un error específico para el campo faltante
```

### AC-003: Bloqueo de cálculo por ubicación incompleta
**Description:** Valida que el cálculo de prima es bloqueado si la ubicación está incompleta y se muestran los errores.

```gherkin
Scenario: Intento de cálculo con una ubicación incompleta
  Given se intenta calcular con una ubicación incompleta
  When se ejecuta la validación
  Then el cálculo es bloqueado y se muestran los errores
```

**BR-001:** Verificación de Campos Obligatorios de Ubicación
- Description: Antes de permitir el cálculo de una prima, el sistema debe asegurar que todos los campos definidos como obligatorios para cada ubicación asociada a la cotización estén presentes y sean válidos.
- Trigger: Al intentar guardar una ubicación, al intentar iniciar el cálculo de una prima.
- Logic:
    ```pseudocode
    PARA CADA Ubicación EN Cotización:
      PARA CADA CampoObligatorio DEFINIDO PARA Ubicación:
        SI CampoObligatorio.valor ES NULO O VACÍO:
          AÑADIR_ERROR(Ubicación.ID, CampoObligatorio.nombre, "Campo obligatorio faltante")
      FIN PARA
    FIN PARA
    SI HAY_ERRORES_EN_ALGUNA_UBICACION:
      BLOQUEAR_CALCULO()
      MOSTRAR_ERRORES_AL_USUARIO()
    SINO:
      PERMITIR_CALCULO()
    ```
- Implementation: Módulo de reglas de validación
- Exception: N/A

## 10. UX and Navigation Flow
**UX Flow:** Pantalla de edición de Ubicación → Al intentar guardar o al intentar calcular la prima → Mensajes de error en línea o modal si hay campos faltantes → Pantalla de resumen de cotización con el estado de validación de las ubicaciones.
**Messages/Modals:**
- Mensaje de error en línea: "Este campo es obligatorio."

- Modal de bloqueo de cálculo: "No se puede proceder con el cálculo. Revise los errores de validación en las ubicaciones."

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad en la definición de "datos mínimos":** Si la lógica para determinar qué campos son obligatorios es muy compleja, variable por tipo de ubicación o por contexto, podría aumentar la dificultad de implementación y mantenimiento del módulo de reglas.
    *   Impacto: Mayor tiempo de desarrollo, errores en validación, dificultad en futuras modificaciones.
    *   Probabilidad: Media
    *   Mitigación: Documentar exhaustivamente los campos obligatorios en el modelo de dominio y considerar un motor de reglas de negocio configurable si la complejidad lo justifica.
2.  **Rendimiento en validaciones masivas:** Si una cotización puede contener un número muy elevado de ubicaciones, la ejecución de la validación puede afectar el rendimiento del sistema.
    *   Impacto: Lentitud en la interfaz de usuario, mala experiencia para el usuario.
    *   Probabilidad: Baja (a menos que el número de ubicaciones sea excepcionalmente alto).
    *   Mitigación: Optimizar el algoritmo de validación, considerar técnicas de validación asíncrona o por lotes si el volumen de datos lo requiere.
