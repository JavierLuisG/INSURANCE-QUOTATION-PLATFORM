## 2. Enabled Capability
**CAP-005:** Inicio de Cálculo de Prima
**Business Value:** Permite al usuario obtener los resultados financieros de las ubicaciones válidas de una cotización, lo cual es fundamental para generar propuestas y completar el proceso de venta.
**Requires:**

## 3. User Story
Como usuario,
Quiero iniciar el proceso de cálculo de la prima de la cotización,
Para poder obtener los resultados financieros de las ubicaciones válidas.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual un "usuario" inicia el cálculo de las primas para una cotización. El sistema validará cada ubicación de riesgo asociada a la cotización para determinar si cumple con los requisitos mínimos para el cálculo (código postal válido, clave de incendio y garantías tarifables). Las ubicaciones que cumplan serán incluidas en el cálculo, mientras que las que no cumplan serán excluidas y el usuario será notificado a través de una alerta sobre cuáles ubicaciones fueron excluidas y por qué. Durante el proceso de cálculo, se mostrará un indicador de carga para proporcionar feedback visual al usuario. Si no hay ninguna ubicación válida o activa para calcular, el sistema informará al usuario y no procederá con el cálculo.
**Flow:** FT-002: Gestión Dinámica de Ubicaciones de Riesgo → HU-015: Iniciar el cálculo de primas de la cotización → HU-XXX: Visualizar resultados del cálculo (Historia posterior)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Inicio de Cálculo para Ubicaciones Válidas
**Description:** Valida que el sistema inicia correctamente el proceso de cálculo para las ubicaciones que cumplen con los requisitos mínimos, tras la acción del usuario.

```gherkin
Scenario: Inicio de cálculo exitoso para ubicaciones válidas
  Given que he completado los datos generales y al menos una ubicación con los campos mínimos requeridos (codigoPostal válido, giro.claveIncendio y garantías tarifables)
  When hago clic en el botón "Calcular Prima"
  Then el sistema inicia el proceso de cálculo para las ubicaciones válidas
```

### AC-002: Cálculo Parcial con Exclusión de Ubicaciones Inválidas
**Description:** Valida que el sistema puede procesar un cálculo parcial, excluyendo ubicaciones con datos incompletos o inválidos y notificando al usuario.

```gherkin
Scenario: Cálculo parcial con exclusión de ubicaciones incompletas
  Given que alguna ubicación tiene datos incompletos (sin CP válido, sin giro.claveIncendio o sin garantías tarifables)
  When inicio el cálculo
  Then el sistema calcula las demás ubicaciones válidas
  And muestra una alerta indicando qué ubicaciones fueron excluidas y por qué
```

### AC-003: Bloqueo de Cálculo por Falta de Ubicaciones Válidas
**Description:** Valida que el sistema impide el inicio del cálculo si no hay ninguna ubicación que cumpla con los criterios para ser procesada.

```gherkin
Scenario: Bloqueo de cálculo por ausencia de ubicaciones válidas
  Given que todas las ubicaciones están incompletas o inactivas y no existe ninguna calculable
  When intento calcular
  Then el sistema informa que no hay ubicaciones válidas para calcular
  And no procede con el cálculo
```

### AC-004: Indicador de Carga Durante el Cálculo
**Description:** Valida la presencia de un feedback visual al usuario mientras el proceso de cálculo está en ejecución.

```gherkin
Scenario: Visualización de indicador de carga
  Given que el cálculo se está ejecutando
  When el usuario interactúa con la interfaz
  Then se muestra un indicador de carga
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| ubicacion.codigoPostal | String | yes (para ser válida) | N/A | Debe ser un código postal con formato y validez reconocidos. | N/A | 28001 |
| ubicacion.giro.claveIncendio | String | yes (para ser válida) | N/A | Debe existir en el catálogo de claves de incendio. | Catálogo de Claves de Incendio | G001 |
| ubicacion.garantiasTarifables | Array de Objetos | yes (al menos una para ser válida) | [] | Debe contener al menos un elemento que represente una garantía que afecta la prima. | N/A | [{"idGarantia": "C001", "valorAsegurado": 100000}] |
| ubicacion.estado | String | no | activa | Valores permitidos: 'activa', 'inactiva'. | N/A | activa |


**BR-001:** Requisitos Mínimos para Ubicación Calculable
- Description: Una ubicación se considera apta para el cálculo de prima si cumple con un conjunto específico de datos.
- Trigger: Al iniciar el proceso de cálculo de primas.
- Logic: `ubicacion.codigoPostal` es válido Y `ubicacion.giro.claveIncendio` está presente Y `ubicacion.garantiasTarifables` contiene al menos un elemento Y `ubicacion.estado` es 'activa'.
- Implementation: Servicio de backend de cotizaciones.
- Exception: Si no cumple, la ubicación es excluida del cálculo y se genera una alerta.

**BR-002:** Deshabilitación del Botón "Calcular Prima"
- Description: El botón para iniciar el cálculo de primas solo debe estar habilitado si existe al menos una ubicación que cumpla con los requisitos mínimos para ser calculada.
- Trigger: Al cargar la pantalla de la cotización o al modificar las ubicaciones de riesgo.
- Logic: `IF (COUNT(ubicaciones_que_cumplen_BR-001) > 0) THEN Habilitar Botón ELSE Deshabilitar Botón`.
- Implementation: Frontend.

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario se encuentra en la pantalla de edición de una cotización, con datos generales y ubicaciones de riesgo configuradas.
2.  Hace clic en el botón "Calcular Prima".
3.  Si hay ubicaciones válidas:
    *   Se muestra un indicador de carga (spinner o barra de progreso) en la interfaz.
    *   Si existen ubicaciones incompletas o inválidas, se muestra una alerta (ej. un modal o un mensaje tipo "toast") detallando cuáles ubicaciones fueron excluidas y por qué.
    *   Al finalizar el cálculo, el indicador de carga desaparece y se actualiza la interfaz para mostrar los resultados de las primas calculadas.
4.  Si no hay ubicaciones válidas para calcular:
    *   Se muestra una alerta informativa (ej. un modal) indicando "No hay ubicaciones válidas para calcular".
    *   El indicador de carga no se activa y el proceso de cálculo no se inicia.
**Messages/Modals:**
*   Mensaje de éxito (implícito, para la siguiente historia): "Cálculo de primas completado."
*   Mensaje de advertencia: "Algunas ubicaciones fueron excluidas del cálculo. Ver detalles."
*   Mensaje de error (funcional): "No hay ubicaciones válidas para calcular."
*   Mensaje de error (técnico): "Ocurrió un error inesperado al calcular las primas. Por favor, inténtelo de nuevo más tarde."
**Stepper/Breadcrumbs:** No aplica directamente a esta historia, pero se integra en el flujo general de creación de cotizaciones.

    *   Componente de indicador de carga.

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Rendimiento del Servicio de Cálculo de Primas**
    *   Description: El servicio de backend responsable del cálculo de primas podría ser lento o inestable, impactando directamente la experiencia del usuario.
    *   Impact: Alta latencia en la respuesta, posibles timeouts, frustración del usuario, interrupción del flujo de cotización.
    *   Probability: Media
    *   Mitigation: Implementar monitoreo robusto en el servicio de cálculo, optimizar algoritmos, considerar un enfoque asíncrono para cálculos muy complejos si el rendimiento síncrono no es viable.
2.  **Riesgo: Complejidad de la Lógica de Validación de Ubicaciones**
    *   Description: La lógica para determinar si una ubicación es "calculable" (validación de CP, clave de incendio, garantías tarifables) puede volverse compleja y propensa a errores.
    *   Impact: Ubicaciones válidas excluidas incorrectamente o ubicaciones inválidas incluidas, llevando a cálculos erróneos o confusión del usuario.
    *   Probability: Media
    *   Mitigation: Desarrollar pruebas unitarias y de integración exhaustivas para la lógica de validación, documentar claramente las reglas de negocio, y considerar el uso de un Motor de Reglas de Negocio (BRMS) si la complejidad aumenta.

## 18. Identified Assumptions
1.  **Asunción: Existencia y Disponibilidad del Servicio de Cálculo de Primas**
    *   Description: Se asume que existe un servicio de backend (interno o externo) que puede realizar el cálculo de primas y que estará disponible y responderá de manera confiable cuando sea invocado por la API de cotizaciones.
    *   Impact if false: El cálculo de primas fallará consistentemente, impidiendo el funcionamiento de la funcionalidad principal.
    *   Requires validation from: Equipo de Arquitectura, Equipo de Backend responsable del servicio de cálculo.
2.  **Asunción: Mecanismo de Validación de `codigoPostal`**
    *   Description: Se asume que existe un mecanismo o fuente de datos (ej. un catálogo geográfico, un servicio externo) para validar la existencia y el formato de un `codigoPostal`.
    *   Impact if false: Las validaciones de ubicaciones podrían ser incorrectas, llevando a exclusiones erróneas o a la inclusión de ubicaciones con datos inválidos.
    *   Requires validation from: Equipo de Backend, Dueño de Producto (para definir el alcance de la validación).
3.  **Asunción: Definición Clara de "Garantías Tarifables"**
    *   Description: Se asume que el sistema puede identificar inequívocamente qué garantías (coberturas) son consideradas "tarifables" y, por lo tanto, son un requisito para que una ubicación sea válida para el cálculo.
    *   Impact if false: La lógica de exclusión de ubicaciones podría ser defectuosa, afectando la precisión del cálculo.
    *   Requires validation from: Dueño de Producto, Equipo de Backend (para la lógica de negocio).
