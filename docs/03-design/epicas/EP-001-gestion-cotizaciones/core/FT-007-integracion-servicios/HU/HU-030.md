## 1. Identificación General
**Feature:** Gestión de Direcciones y Cálculo de Primas
**Capability:** CAP-005 - Validación de Códigos Postales y Zonas de Riesgo
**Actor:** Usuario (del sistema que requiere la validación)
**Bounded Context:** Catálogos de Referencia / Cálculo de Primas
**Story Points:** 4

## 2. Enabled Capability
**CAP-005:** Validación de Códigos Postales y Zonas de Riesgo
**Business Value:** Asegurar la precisión de las direcciones, permitir la aplicación correcta de factores de riesgo en el cálculo de primas, y reducir errores en la tarificación.
**Requires:** Acceso a Servicio Externo Plataforma-core-ohs
**Enables:** CAP-006 (Cálculo de Primas), CAP-007 (Generación de Pólizas)
**Orchestrates:** Plataforma-core-ohs (servicio de referencia de CP)

## 3. User Story
Como **usuario**,
quiero que el sistema **consulte y valide información de códigos postales y zonas de riesgo desde el servicio de referencia**,
para **validar direcciones y aplicar factores** (en el cálculo de primas).

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para que el sistema consulte y valide códigos postales introducidos por el usuario, utilizando un servicio de referencia externo (`Plataforma-core-ohs`). El objetivo es obtener detalles geográficos como municipio y estado, así como información crucial sobre zonas de riesgo asociada al código postal. Esta información es fundamental para la validación de direcciones y, posteriormente, para el cálculo de primas, donde la zona de riesgo actúa como un factor determinante. En caso de que el servicio externo no esté disponible, el sistema deberá manejar la situación de error y notificar al usuario.
**Flow:** HU-009 (Consultar y validar código postal de ubicación) → HU-030 (Consultar y validar información de códigos postales y zonas de riesgo) → HU-015 (Cálculo de prima con factor de riesgo)

## 6. Acceptance Criteria
### AC-001: Validación exitosa de código postal y recuperación de detalles
**Description:** Este criterio valida que, al introducir un código postal, el sistema lo valida correctamente y recupera sus detalles asociados, incluyendo municipio, estado y zona de riesgo, desde el servicio de referencia.

```gherkin
Scenario: Validación exitosa de código postal y recuperación de detalles
  Given que he introducido un código postal válido (ej. "28001")
  When el sistema lo valida
  Then consulta el catálogo de CP de `Plataforma-core-ohs`
  And obtiene los detalles correspondientes (municipio: "Madrid", estado: "Madrid", zona de riesgo: "Alta")
```

### AC-002: Disponibilidad de zona de riesgo para cálculo de primas
**Description:** Este criterio asegura que la información de la zona de riesgo recuperada del código postal esté disponible y pueda ser utilizada en procesos posteriores, como el cálculo de primas.

```gherkin
Scenario: Disponibilidad de zona de riesgo para cálculo de primas
  Given que un código postal ha sido validado exitosamente
  And está asociado a una zona de riesgo (ej. "Alta")
  When se recupera esa información
  Then la zona de riesgo está disponible para el cálculo de primas
```

### AC-003: Gestión de error por indisponibilidad del servicio de CP
**Description:** Este criterio verifica que el sistema maneje adecuadamente los escenarios donde el servicio de consulta de códigos postales (`Plataforma-core-ohs`) no está disponible, notificando al usuario.

```gherkin
Scenario: Gestión de error por indisponibilidad del servicio de CP
  Given que el servicio de CP de `Plataforma-core-ohs` no está disponible
  When intento validar un código postal
  Then el sistema gestiona el error
  And notifica al usuario con un mensaje apropiado (ej. "El servicio de validación de CP no está disponible. Intente más tarde.")
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| codigo_postal | String | yes | N/A | Regex de CP de 5 dígitos (ej. ^\d{5}$) | Plataforma-core-ohs | 28001 |
| municipio | String | no | N/A | N/A | Plataforma-core-ohs | Madrid |
| estado | String | no | N/A | N/A | Plataforma-core-ohs | Madrid |
| zona_riesgo | String | no | N/A | Catálogo de zonas de riesgo (ej. 'Baja', 'Media', 'Alta', 'Muy Alta') | Plataforma-core-ohs | Alta |


**BR-001:** Consulta de Código Postal
- Description: El sistema debe consultar el servicio `Plataforma-core-ohs` para obtener los detalles de un código postal.
- Trigger: Cuando un usuario introduce un código postal para validación.
- Logic: Llamada a API `/postal-codes/{codigo_postal}` de `Plataforma-core-ohs`.
- Implementation: Cliente API Backend.
- Exception: Fallo en la comunicación con el servicio externo.

**BR-002:** Disponibilidad de Datos de Riesgo
- Description: La información de zona de riesgo obtenida del servicio de CP debe ser accesible para el módulo de cálculo de primas.
- Trigger: Después de una validación exitosa de un código postal.
- Logic: Los datos de zona de riesgo son parte del objeto de respuesta del CP y se pasan al contexto del cálculo de primas.
- Implementation: Servicio de Cálculo de Primas.

## 11. Architecture and Technical Dependencies
- **Plataforma-core-ohs (Servicio externo)**: Servicio de referencia para el catálogo de códigos postales.
    - Propósito: Obtener detalles geográficos y zonas de riesgo asociadas a un CP.
    - Timeout: 5 segundos.
    - Retries: 2 reintentos con backoff exponencial.
- **Backend (Cliente API)**: Implementación de un cliente HTTP robusto para interactuar con `Plataforma-core-ohs`.
- **Circuit Breaker**: Implementar un Circuit Breaker para la integración con `Plataforma-core-ohs` para proteger el sistema de caídas del servicio externo.

## 13. Edge Cases and Exceptions
### Case 1: Código postal no encontrado en el catálogo
```gherkin
Scenario: Código postal no encontrado
  Given que he introducido un código postal que no existe en el catálogo (ej. "00000")
  When el sistema lo valida
  Then el sistema indica que el código postal no es válido
  And no recupera detalles geográficos ni zona de riesgo
```

### Case 2: Servicio de CP devuelve datos inconsistentes o incompletos
```gherkin
Scenario: Servicio de CP devuelve datos inconsistentes
  Given que he introducido un código postal válido
  And el servicio de CP responde, pero con datos incompletos (ej. falta la zona de riesgo)
  When el sistema procesa la respuesta
  Then el sistema utiliza los datos disponibles
  And registra una advertencia sobre los datos faltantes
  And podría aplicar una zona de riesgo por defecto o solicitar clarificación al usuario si es crítico
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Alta dependencia de servicio externo.
    -   Descripción: La funcionalidad es completamente dependiente de la disponibilidad y rendimiento de `Plataforma-core-ohs`.
    -   Impacto: Interrupción del flujo de validación de direcciones y cálculo de primas, afectando la experiencia del usuario y la capacidad de negocio.
    -   Probabilidad: Media.
    -   Mitigación: Implementar Circuit Breaker, reintentos, caché de CP válidos (si es viable), monitoreo proactivo del servicio externo, y mensajes de error claros al usuario.
2.  **Nombre:** Contrato de servicio externo cambiante.
    -   Descripción: Cambios inesperados en la API de `Plataforma-core-ohs` podrían romper la integración.
    -   Impacto: Fallos en la validación de CP y necesidad de refactorización urgente.
    -   Probabilidad: Baja a Media (dependiendo de la gobernanza de `Plataforma-core-ohs`).
    -   Mitigación: Mantener una comunicación fluida con el equipo de `Plataforma-core-ohs`, usar contratos de API bien definidos (OpenAPI/Swagger), y pruebas de integración automatizadas.

**Technical Debt:**
-   **No se especifican en la historia. Se llenará por el equipo operativo según el alcance y MVP.** (Ej: Implementación de caché local de códigos postales para reducir la dependencia en tiempo real del servicio externo, si la latencia es un problema recurrente).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta funcionalidad es fundamental para la validación de datos de dirección y un componente crítico para el cálculo de primas, impactando directamente la precisión y legalidad de los seguros. Un fallo aquí podría llevar a primas incorrectas o direcciones no válidas.
**Feature Impact:** Sin esta historia, la funcionalidad de "Gestión de Direcciones y Cálculo de Primas" no puede operar correctamente, ya que no se pueden validar direcciones ni aplicar factores de riesgo basados en la ubicación.
**Critical Dependencies:** El módulo de cálculo de primas depende directamente de la información de zona de riesgo proporcionada por esta historia.
**Recommended Priority:** Sprint actual / Próximo sprint (dada la prioridad 'Alta' y dependencia de otras HUs críticas).

1.  **Disponibilidad del servicio `Plataforma-core-ohs`**
    -   Description: Se asume que el servicio externo `Plataforma-core-ohs` estará disponible y responderá en un tiempo razonable la mayor parte del tiempo.

    -   Description: Se asume que el contrato de la API de `Plataforma-core-ohs` para la consulta de CP es estable y bien documentado, y no cambiará sin previo aviso.
    -   Impact if false: Ruptura de la integración y retrabajo significativo.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` / Equipo de Desarrollo.

    -   Impact if false: El cálculo de primas podría ser inexacto o incompleto, requiriendo información adicional o un servicio de riesgo más granular.
    -   Requires validation from: Product Owner / Equipo de Negocio / Actuarial.
