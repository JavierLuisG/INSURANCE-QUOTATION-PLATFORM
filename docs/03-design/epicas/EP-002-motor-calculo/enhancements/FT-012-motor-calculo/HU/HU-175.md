## 3. User Story
Como sistema,
Quiero calcular y aplicar cada uno de los 14 componentes técnicos de prima para las ubicaciones calculables,
Para determinar con precisión y trazabilidad cada parte del costo de la cobertura.

## 4. Functional Description
**Description:** El motor de cálculo procesará una ubicación individual, evaluando y aplicando cada uno de los 14 componentes técnicos de prima definidos. Para cada componente, se determinará su estado de actividad (si está en `opcionesCobertura` y tiene garantía tarifable). Si un componente está activo, se aplicará la lógica de cálculo correspondiente utilizando las sumas aseguradas y las tarifas o factores específicos obtenidos de los servicios de datos. Los componentes inactivos serán omitidos. Finalmente, los valores calculados de todos los componentes activos se sumarán para obtener la prima neta de la ubicación, y cada valor individual de componente se persistirá como parte de un snapshot para asegurar la trazabilidad y auditoría.
**Flow:** `HU-170 (Inicio del cálculo de prima por ubicación)` → `HU-175 (Cálculo y aplicación de componentes técnicos)` → `HU-170 (Consolidación de prima neta)`

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Cálculo y Aplicación de los 14 Componentes Activos
**Description:** Valida que el motor de cálculo evalúa y aplica correctamente los 14 componentes técnicos de prima para una ubicación calculable, utilizando las coberturas configuradas.
```gherkin
Scenario: El motor calcula y aplica los 14 componentes técnicos para una ubicación
  Given una ubicación calculable con coberturas configuradas (ej. Incendio Edificios, Robo)
  And el motor tiene acceso a las tarifas y factores necesarios para los 14 componentes
  When el motor procesa los componentes de la ubicación
  Then evalúa cada uno de los 14 componentes
  And aplica los componentes activos según las coberturas configuradas, calculando su prima individual
```
### AC-002: Omisión de Componentes Inactivos
**Description:** Verifica que los componentes que no están activos (no configurados en `opcionesCobertura` o sin garantía tarifable) son omitidos del cálculo y no afectan la prima final.
```gherkin
Scenario: Un componente inactivo es omitido del cálculo
  Given una ubicación calculable donde el componente "Robo" no está activo (ej. no está en opcionesCobertura)
  When el motor evalúa el componente "Robo"
  Then el componente "Robo" es omitido del cálculo
  And su valor de prima individual es cero
  And no impacta la prima neta consolidada
```
### AC-003: Consolidación de la Prima Neta
**Description:** Asegura que la prima neta final de la ubicación es la suma correcta de todos los componentes activos calculados.
```gherkin
Scenario: La prima neta de la ubicación se consolida correctamente
  Given el cálculo de todos los componentes activos para una ubicación ha sido completado
  And los valores de prima individual para cada componente activo han sido determinados
  When se consolida la prima neta de la ubicación
  Then la prima neta de la ubicación es la suma exacta de todos los componentes activos aplicados
```
### AC-004: Trazabilidad de los Resultados
**Description:** Valida que los resultados de cada componente individual se persisten para garantizar la trazabilidad del cálculo y facilitar auditorías.
```gherkin
Scenario: Los resultados de los componentes se persisten para trazabilidad
  Given el cálculo de todos los componentes activos para una ubicación ha sido completado
  And los valores de prima individual para cada componente activo han sido determinados
  When los resultados se persisten en el sistema
  Then el snapshot incluye el valor calculado de cada componente activo individualmente
```

**BR-001: Condición de Actividad de Componente**
- Description: Un componente técnico se considera activo si está presente en las `opcionesCobertura` de la ubicación y tiene una garantía tarifable asociada.
- Trigger: Antes de calcular cualquier componente.
- Logic: `isComponentActive = (component.isInOptionsCobertura && component.hasTarifiableGuarantee)`
- Implementation: Motor de cálculo de primas.
- Exception: Si no se puede determinar la actividad, el componente se asume inactivo.

**BR-002: Cálculo Incendio Edificios**
- Description: Calcula la prima del componente Incendio Edificios.
- Trigger: Cuando el componente Incendio Edificios está activo.
- Logic: `prima_incendio_edificios = suma_asegurada_edificio * tarifa_incendio_giro`
- Implementation: Módulo de cálculo de componente Incendio Edificios.

**BR-003: Cálculo Incendio Contenidos**
- Description: Calcula la prima del componente Incendio Contenidos.
- Trigger: Cuando el componente Incendio Contenidos está activo.
- Logic: `prima_incendio_contenidos = suma_asegurada_contenidos * tarifa_incendio_giro`
- Implementation: Módulo de cálculo de componente Incendio Contenidos.

**BR-004: Cálculo Extensión de Cobertura**
- Description: Calcula la prima de Extensión de Cobertura, aplicando un factor sobre la prima total de incendio.
- Trigger: Cuando el componente Extensión de Cobertura está activo.
- Logic: `prima_extension_cobertura = (prima_incendio_edificios + prima_incendio_contenidos) * factor_extension_cobertura`
- Implementation: Módulo de cálculo de componente Extensión de Cobertura.

**BR-005: Cálculo CAT TEV**
- Description: Calcula el factor de catástrofe por zona CAT aplicado a la prima de incendio.
- Trigger: Cuando el componente CAT TEV está activo.

**BR-006: Cálculo CAT FHM**

## 13. Edge Cases and Exceptions
### Case 1: Ubicación sin coberturas activas
```gherkin
Scenario: Ubicación sin coberturas configuradas para ningún componente
  Given una ubicación con opcionesCobertura vacías o sin garantías tarifables
  When el motor intenta calcular los componentes técnicos
  Then todos los componentes son omitidos
  And la prima neta de la ubicación es 0
  And se persiste un snapshot con todos los componentes en 0
```
### Case 2: Falta de tarifas/factores para un componente activo
```gherkin
Scenario: Un componente está activo pero su tarifa o factor requerido no está disponible
  Given una ubicación con el componente "Robo" activo
  And el servicio de tarifas de robo no responde o devuelve un error (ej. HTTP 404, 500)
  When el motor intenta calcular la prima de "Robo"
  Then la prima del componente "Robo" se asigna a 0
  And se registra un WARNING detallado sobre la tarifa faltante
  And la prima neta de la ubicación se calcula con los demás componentes activos
```
### Case 3: Suma asegurada en cero para un componente activo
```gherkin
Scenario: Un componente está activo, pero su suma asegurada es cero
  Given una ubicación con el componente "Vidrios" activo
  And la suma_asegurada_vidrios es 0
  When el motor intenta calcular la prima de "Vidrios"
  Then la prima del componente "Vidrios" se calcula como 0
  And se registra un log informativo sobre la suma asegurada en cero
  And la prima neta de la ubicación se calcula con los demás componentes activos
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad de Lógica de Negocio (Medio, Alto):** La implementación de 14 componentes con lógicas específicas y posibles interdependencias puede ser compleja.
    *   Impacto: Errores en cálculo, retrabajo, dificultad para mantener.
    *   Probabilidad: Media.
    *   Mitigación: Implementación modular con tests unitarios exhaustivos, revisión de código por expertos en dominio/cálculo, documentación clara de cada algoritmo.
2.  **Disponibilidad y Latencia de Servicios de Tarifas (Medio, Medio):** Dependencia de múltiples servicios para obtener datos críticos puede afectar la disponibilidad y el rendimiento del cálculo.
    *   Impacto: Fallos en cálculo, latencia elevada en la respuesta del motor.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breakers, reintentos con backoff exponencial, políticas de fallback (ej. valores por defecto si no disponibles), monitoreo proactivo de servicios dependientes, caching de tarifas.
3.  **Rendimiento del Cálculo (Medio, Medio):** Calcular 14 componentes para múltiples ubicaciones concurrentemente podría afectar el rendimiento general del motor.
    *   Impacto: Tiempos de respuesta lentos para el cálculo de primas.
    *   Probabilidad: Media.
    *   Mitigación: Optimización de algoritmos, pruebas de carga y rendimiento tempranas, procesamiento asíncrono si el contexto lo permite.

## 18. Identified Assumptions
1.  **Disponibilidad y Estructura de Datos de Entrada:**
    *   Description: Se asume que las sumas aseguradas, `opcionesCobertura`, tarifas y factores (incendio, catástrofe, FHM, equipo electrónico, etc.) están disponibles y tienen el formato esperado cuando el motor los solicita.
    *   Impact if false: Cálculos incorrectos, errores en tiempo de ejecución, necesidad de implementar lógica compleja de manejo de datos faltantes o incorrectos.
    *   Requires validation from: Equipo de Integración, Equipo de Datos, Dueño de Producto.
2.  **Definición de "Prima Base" para Pérdida de Rentas y BI:**
    *   Description: Se asume que "prima base" en los componentes de Pérdida de Rentas y BI se refiere a una tarifa o factor que se multiplica por la suma asegurada, siguiendo el patrón de otros componentes.
    *   Impact if false: Lógica de cálculo incorrecta para estos componentes.
    *   Requires validation from: Actuarial, Dueño de Producto.
3.  **Prioridad en Remoción de Escombros (Porcentaje vs. Suma Fija):**
    *   Description: Se asume que si el componente de Remoción de Escombros está activo y se especifica una `suma_fija_remocion_escombros`, esta tiene prioridad sobre el cálculo por porcentaje.
    *   Impact if false: Cálculo incorrecto del componente.
    *   Requires validation from: Actuarial, Dueño de Producto.
4.  **Manejo de Componente Activo con Datos Críticos Faltantes:**
    *   Description: Se asume que si un componente está activo pero le faltan datos críticos (ej., una tarifa obligatoria), se asigna una prima de 0 y se registra un WARNING para permitir que el cálculo global continúe, en lugar de fallar toda la operación de la ubicación.
    *   Impact if false: Fallo completo del cálculo de la ubicación, o cálculo incorrecto sin advertencia adecuada.
    *   Requires validation from: Dueño de Producto, Arquitectura.
