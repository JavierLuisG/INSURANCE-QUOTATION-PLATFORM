## 1. Identificación General
**Feature:** Cálculo de Prima
**Capability:** CAP-007 - Gestión de Cálculo de Prima
**Actor:** Sistema (internamente, el motor de cálculo)
**Bounded Context:** Cotización / Cálculo de Prima
**Story Points:** 3

## 2. Enabled Capability
**CAP-007:** Gestión de Cálculo de Prima
**Business Value:** Asegurar que el proceso de cálculo de prima solo se ejecute cuando existan riesgos válidos, optimizando recursos y evitando cálculos inconsistentes.
**Requires:** CAP-006 - Validación de Ubicaciones (implícito, ya que el estado de validación es un pre-requisito)
**Enables:** CAP-008 - Presentación de Resultados de Cotización

## 3. User Story
Como sistema,
Quiero que el cálculo de prima no se ejecute únicamente cuando no existe ninguna ubicación calculable,
Para evitar calcular cotizaciones sin ningún riesgo válido asegurado.

## 4. Functional Description
**Description:** Esta historia de usuario describe el comportamiento del sistema al iniciar el proceso de cálculo de prima, enfocándose en la validación previa del estado de las ubicaciones. Antes de proceder con el cálculo, el sistema evaluará el `estadoValidacion` de cada ubicación. Si todas las ubicaciones de la cotización tienen un `estadoValidacion` de `INCOMPLETA` o `INACTIVA`, el sistema impedirá el inicio del cálculo y notificará al usuario. Si al menos una ubicación tiene `estadoValidacion: COMPLETA`, el cálculo procederá solo para esas ubicaciones válidas, excluyendo aquellas `INCOMPLETA` o `INACTIVA`. Las ubicaciones excluidas individualmente incluirán sus `alertasBloqueantes` en el resultado del cálculo.
**Flow:** HU-125 (Iniciar Proceso de Cálculo de Prima) → **HU-169 (Prevenir Ejecución de Cálculo cuando No Existen Ubicaciones Válidas)** → HU-168 (Proporcionar Mensajes de Error Específicos de Validación) / Presentación de Resultado de Cálculo

## 5. Expected Results


| element | description |
|---|---|
| Data | El resultado del cálculo de prima (`primasPorUbicacion[]`) incluirá las primas de las ubicaciones válidas y, para las ubicaciones excluidas, incluirá sus `alertasBloqueantes` con `estado: EXCLUIDA`. |
| States | Si no hay ubicaciones calculables, el estado del cálculo de la cotización podría permanecer como 'PENDIENTE' o 'FALLIDO_POR_VALIDACION'. Si hay ubicaciones calculables, el estado del cálculo podría pasar a 'EN_PROCESO' o 'COMPLETADO_PARCIALMENTE'. |
| Notifications | En caso de que no existan ubicaciones calculables, se generará una notificación al usuario (ej. mensaje en UI, modal) indicando la imposibilidad de calcular la cotización y la razón. |
| Integrations | Si el cálculo no procede, no se invocarán servicios externos relacionados con el cálculo de prima. Si procede parcialmente, se invocarán solo para las ubicaciones válidas. |
| Kafka | Si el cálculo es impedido, no se publicarán eventos de 'Cálculo Iniciado' o 'Cálculo Completado'. Si procede parcialmente, se publicarán eventos de 'Cálculo Completado' con el estado de las ubicaciones. |
| Logs | Se registrarán mensajes de nivel 'INFO' cuando el cálculo procede, y 'WARN' o 'ERROR' cuando el cálculo es impedido o cuando ubicaciones individuales son excluidas, detallando las razones. |
| UI | La interfaz de usuario mostrará un mensaje de error o una alerta clara si el cálculo es impedido. Si el cálculo procede parcialmente, los resultados en la UI reflejarán las primas de las ubicaciones válidas y las alertas para las excluidas. |


## 6. Acceptance Criteria
### AC-001: Procesar cálculo con al menos una ubicación válida
**Description:** Valida que el sistema procede con el cálculo cuando existe al menos una ubicación con estado `COMPLETA`, ignorando las incompletas.

```gherkin
Scenario: El sistema procede con el cálculo cuando al menos una ubicación es válida
  Given una cotización con una ubicación A con estadoValidacion: COMPLETA
  And una ubicación B con estadoValidacion: INCOMPLETA
  When se inicia el cálculo de la cotización
  Then el sistema procede con el cálculo para la ubicación A
  And la ubicación B es excluida individualmente del cálculo
  And el resultado incluye las primas de la ubicación A y las alertas de la ubicación B
```

### AC-002: Excluir ubicaciones individuales incompletas
**Description:** Valida que las ubicaciones con `estadoValidacion: INCOMPLETA` son excluidas individualmente del cálculo, y sus alertas se incluyen en el resultado.

```gherkin
Scenario: Una ubicación incompleta es excluida individualmente con sus alertas
  Given una ubicación con estadoValidacion: INCOMPLETA
  And el motor de cálculo la evalúa
  Then esa ubicación se excluye individualmente del cálculo
  And sus alertasBloqueantes se incluyen en el resultado como parte de primasPorUbicacion[] con estado EXCLUIDA
```

### AC-003: Impedir cálculo si todas las ubicaciones son inválidas
**Description:** Valida que el sistema impide el cálculo cuando todas las ubicaciones de la cotización son `INCOMPLETA` o `INACTIVA`.

```gherkin
Scenario: El sistema impide el cálculo si todas las ubicaciones son inválidas
  Given una cotización donde todas las ubicaciones tienen estadoValidacion: INCOMPLETA o INACTIVA
  When se intenta calcular la cotización
  Then el sistema impide el cálculo
  And el sistema notifica que no hay ubicaciones calculables
```

### AC-004: Resultado de cálculo con ubicaciones parcialmente excluidas
**Description:** Valida que el resultado final del cálculo es coherente cuando hay ubicaciones válidas y excluidas.

```gherkin
Scenario: El resultado del cálculo incluye primas de ubicaciones válidas y alertas de excluidas
  Given el cálculo procede con ubicaciones parcialmente excluidas
  When el cálculo finaliza
  Then el resultado incluye las primas de las ubicaciones válidas
  And el resultado incluye las alertas de las ubicaciones excluidas
  And ambos elementos están en el mismo response
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |

**BR-001:** Determinación de Ubicación Calculable
- Description: Define los criterios mínimos para que una ubicación sea considerada `COMPLETA` y, por lo tanto, calculable.
- Trigger: Evaluación de cada ubicación por el motor de validación.
- Logic: Una ubicación es calculable (`estadoValidacion: COMPLETA`) si cumple con:
    - `codigoPostal` válido en el catálogo.
    - `giro.claveIncendio` presente.
    - Al menos una garantía tarifable asociada.
    - Si no cumple, su `estadoValidacion` será `INCOMPLETA` (o `INACTIVA` si aplica por otras reglas).
- Implementation: Motor de Validación de Reglas de Negocio.
- Exception: N/A

**BR-002:** Restricción de Cálculo por Ubicaciones Inválidas
- Description: Impide el inicio del cálculo de prima a nivel de cotización si no hay ubicaciones válidas para calcular.
- Trigger: Intento de iniciar el cálculo de prima (`POST /v1/quotes/{folio}/calculate`).
- Logic: Si para una cotización, `TODAS` sus ubicaciones tienen `estadoValidacion` igual a `INCOMPLETA` o `INACTIVA`, entonces el cálculo no procede.
- Implementation: Endpoint de Cálculo `POST /v1/quotes/{folio}/calculate`.
- Exception: N/A

2.  Usuario intenta iniciar el cálculo de prima.
3.  **Si no hay ubicaciones calculables**: El sistema muestra un modal o un mensaje de error en la pantalla indicando "No se puede calcular la cotización: No hay ubicaciones válidas para el cálculo."

## 11. Architecture and Technical Dependencies
- **Motor de Validación de Reglas de Negocio**: Componente backend responsable de determinar el `estadoValidacion` y las `alertasBloqueantes` de cada ubicación antes del cálculo.
- **Endpoint de Cálculo `POST /v1/quotes/{folio}/calculate`**: Servicio backend que invoca la lógica de esta historia, primero consultando el estado de validación de las ubicaciones y luego procediendo o impidiendo el cálculo.
- **Motor de Cálculo de Prima**: Servicio o módulo que realiza el cálculo efectivo de las primas para las ubicaciones válidas.
- **Servicio de Catálogos**: Para validar `codigoPostal` y `giro.claveIncendio`.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad en el manejo de estados y resultados parciales:**
    -   Description: La mezcla de primas calculadas y alertas de ubicaciones excluidas en un mismo response puede complicar el parseo y la presentación en el frontend.
    -   Impact: Mayor esfuerzo de desarrollo y posible introducción de errores en la UI.
    -   Probability: Media
    -   Mitigation: Definir un formato de respuesta claro y consistente, con campos explícitos para ubicaciones calculadas y excluidas. Realizar pruebas exhaustivas de integración con el frontend.
2.  **Rendimiento del Motor de Validación:**
    -   Description: Si la validación de `estadoValidacion` es muy lenta para una cotización con muchas ubicaciones, podría afectar la latencia del inicio del cálculo.
    -   Impact: Experiencia de usuario degradada.
    -   Probability: Baja (asumiendo que el motor de validación ya está optimizado)
    -   Mitigation: Monitorear el rendimiento del motor de validación. Optimizar consultas y lógica de validación si es necesario.
**Technical Debt:** N/A

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es crítica porque asegura la integridad del proceso de cálculo de primas, impidiendo la generación de cotizaciones inválidas o incompletas. Afecta directamente la calidad de los datos de negocio y la eficiencia operativa.
**Feature Impact:** Sin esta historia, la funcionalidad de "Cálculo de Prima" podría proceder con datos insuficientes o incorrectos, llevando a resultados erróneos y desperdicio de recursos de procesamiento.
**Critical Dependencies:** El correcto funcionamiento de HU-125 (Iniciar Proceso de Cálculo de Prima) y HU-168 (Proporcionar Mensajes de Error Específicos de Validación) depende de que esta historia defina cuándo y cómo se procede con el cálculo y se comunican los errores.
**Recommended Priority:** Sprint actual (dada su alta prioridad y dependencias).
