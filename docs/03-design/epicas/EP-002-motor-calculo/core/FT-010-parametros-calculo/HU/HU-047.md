**Feature:** Gestión de Catálogos de Ubicaciones de Riesgo
**Capability:** CAP-007 - Ingestión y Mapeo de Catálogos Externos
**Actor:** Administrador de parámetros
**Bounded Context:** Gestión de Riesgos / Catálogos

## 2. Enabled Capability
**CAP-007:** Ingestión y Mapeo de Catálogos Externos
**Business Value:** Asegurar la clasificación correcta de las ubicaciones de riesgo según su código postal, lo que permite una evaluación de riesgo precisa y consistente.
**Requires:** CAP-001 - Conectividad con Plataformas Externas (Plataforma-core-ohs)
**Enables:** CAP-008 - Evaluación de Riesgos por Ubicación
**Orchestrates:** Plataforma-core-ohs

## 3. User Story
Como administrador de parámetros,
Quiero que el sistema ingeste o simule la consulta del `catalogo_cp_zonas` desde `Plataforma-core-ohs` y realice el mapeo de zonas,
Para que las ubicaciones de riesgo se clasifiquen correctamente según su código postal.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para que el sistema obtenga y procese el catálogo de códigos postales y zonas desde una fuente externa (`Plataforma-core-ohs`). El objetivo principal es cargar estos datos en un repositorio local y realizar un mapeo que asocie cada código postal con una zona CAT y un nivel técnico de riesgo. Esta información es crucial para la correcta clasificación de las ubicaciones de riesgo dentro del sistema. Se debe contemplar la simulación de la consulta en caso de que el servicio externo no esté disponible.
**Flow:** [Inicio del Proceso de Configuración] → [HU-047: Ingestión y Mapeo de Catálogo de Códigos Postales y Zonas] → [Consulta de Ubicaciones de Riesgo]

## 6. Acceptance Criteria
### AC-001: Obtención de datos del catálogo CP-Zonas
**Description:** Este criterio valida que el sistema es capaz de obtener los datos del catálogo CP-Zonas desde `Plataforma-core-ohs` o su simulación.

```gherkin
Scenario: El sistema obtiene los datos del catálogo CP-Zonas
  Given el servicio "Plataforma-core-ohs" está disponible (o simulado)
  When se solicita la carga del catálogo CP-Zonas
  Then el sistema obtiene los datos del catálogo correctamente
```

### AC-002: Consulta exitosa de código postal y mapeo de zona
**Description:** Este criterio asegura que, una vez cargado el catálogo, el sistema puede consultar un código postal y devolver su zona CAT y nivel técnico asociado.

```gherkin
Scenario: Consulta de código postal existente
  Given el catálogo CP-Zonas ha sido cargado exitosamente
  And existe un código postal "28001" mapeado a "ZONA-A" y "NIVEL-ALTO"
  When se consulta el código postal "28001"
  Then el sistema devuelve "ZONA-A" como zona CAT y "NIVEL-ALTO" como nivel técnico
```

### AC-003: Manejo de código postal no encontrado
**Description:** Este criterio valida el comportamiento del sistema cuando se consulta un código postal que no se encuentra en el catálogo cargado.

```gherkin
Scenario: Consulta de código postal no encontrado
  Given el catálogo CP-Zonas ha sido cargado exitosamente
  And el código postal "99999" no se encuentra en el catálogo
  When se consulta el código postal "99999"
  Then el sistema devuelve un valor por defecto (ej. "ZONA-DESCONOCIDA", "NIVEL-BAJO")
  And/Or el sistema devuelve un error indicando la falta de mapeo
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| codigo_postal | string | yes | N/A | Regex para códigos postales (ej. ^\d{5}$ en España) | N/A | 28001 |
| zona_cat | string | yes | N/A | N/A | CAT_ZONAS_RIESGO | ZONA-A |
| nivel_tecnico | string | yes | N/A | N/A | NIVEL_RIESGO | ALTO |
| fecha_carga | datetime | yes | Fecha y hora actual | Fecha válida | N/A | 2026-04-21T10:30:00Z |


**BR-001:** Mapeo de Código Postal a Zona y Nivel Técnico
- Description: Cada código postal debe ser mapeado a una única `zona_cat` y un `nivel_tecnico` asociado, tal como se define en el `catalogo_cp_zonas` obtenido.
- Trigger: Durante la ingesta y al consultar un código postal.
- Logic: `(codigo_postal) -> {zona_cat, nivel_tecnico}`
- Implementation: Servicio de mapeo y repositorio de catálogos.
- Exception: Si el código postal no está en el catálogo, se aplica BR-002.

**BR-002:** Valor por Defecto para Códigos Postales No Mapeados
- Description: Si un código postal consultado no se encuentra en el catálogo cargado, el sistema debe devolver un valor por defecto predefinido para `zona_cat` y `nivel_tecnico`, o un error explícito.
- Trigger: Consulta de un código postal no existente en el catálogo.
- Logic: `IF codigo_postal NOT IN catalogo THEN RETURN {default_zona_cat, default_nivel_tecnico} OR ERROR`
- Implementation: Servicio de consulta de catálogo.
- Exception: N/A

## 11. Architecture and Technical Dependencies
- **Plataforma-core-ohs**:
    - **Propósito**: Fuente externa del `catalogo_cp_zonas`.
    - **Timeout**: 30 segundos (configurable).
    - **Retries**: 3 intentos con backoff exponencial.
- **Adaptador de integración Plataforma-core-ohs**: Componente encargado de la comunicación con el servicio externo, manejando la autenticación, reintentos y transformación de datos.
- **Repositorio de catálogos**: Componente de persistencia (ej. base de datos NoSQL o relacional) para almacenar el `catalogo_cp_zonas` de forma optimizada para consulta.
- **Mapeador de datos de CP a zonas**: Componente lógico que transforma los datos brutos del catálogo en la estructura interna requerida (ej. `codigo_postal`, `zona_cat`, `nivel_tecnico`).
- **Circuit Breaker**: Configurado para la integración con `Plataforma-core-ohs` para prevenir fallos en cascada.

## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Inestabilidad de `Plataforma-core-ohs`
    -   **Descripción:** `Plataforma-core-ohs` podría no estar disponible o devolver datos inconsistentes con frecuencia.
    -   **Impacto:** Fallos en la clasificación de ubicaciones de riesgo, datos desactualizados, impacto en la evaluación de riesgos.
    -   **Probabilidad:** Media.
    -   **Mitigación:** Implementar reintentos, circuit breaker, sistema de caché para el catálogo, y un modo de simulación robusto. Establecer un acuerdo de nivel de servicio (SLA) con el equipo de `Plataforma-core-ohs`.
2.  **Nombre:** Rendimiento de consulta del catálogo
    -   **Descripción:** Si el catálogo es muy grande y no está optimizado, las consultas frecuentes pueden ser lentas.
    -   **Impacto:** Latencia en la evaluación de riesgos, mala experiencia de usuario.
    -   **Probabilidad:** Media.
    -   **Mitigación:** Implementar indexación adecuada en el repositorio, considerar una base de datos optimizada para lectura (ej. caché en memoria distribuida), y realizar pruebas de carga.

**Technical Debt:** [To be filled by operating team per scope and MVP]
- Considerar la implementación de un mecanismo de "delta updates" en lugar de cargas completas del catálogo si el volumen de datos es muy alto y los cambios son incrementales.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La correcta clasificación de las ubicaciones de riesgo es fundamental para el negocio, ya que impacta directamente en la evaluación de riesgos, la tarificación y la toma de decisiones críticas. Sin este catálogo, el sistema no puede operar con precisión.
**Feature Impact:** La no implementación o el fallo de esta historia paralizaría o invalidaría la funcionalidad principal de clasificación de riesgos por ubicación.
**Critical Dependencies:** Todas las historias de usuario que dependan de la clasificación geográfica de riesgos.
**Recommended Priority:** Sprint actual / Próximo sprint (siempre que las dependencias estén resueltas).

## 18. Identified Assumptions
1.  **Formato y Contenido del Catálogo de `Plataforma-core-ohs`**
    -   Description: Se asume que el formato y el contenido del `catalogo_cp_zonas` proporcionado por `Plataforma-core-ohs` son estables, bien documentados y contienen los campos (`codigo_postal`, `zona_cat`, `nivel_tecnico`) necesarios para el mapeo.
    -   Impact if false: Si el formato cambia o faltan datos, el proceso de ingesta y mapeo fallará, impidiendo la clasificación de riesgos.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` y Arquitectura.
2.  **Volumen de Datos del Catálogo**
    -   Description: Se asume que el volumen del `catalogo_cp_zonas` es manejable por el sistema actual y no requerirá una infraestructura de almacenamiento o procesamiento masivamente escalable de inmediato.
    -   Impact if false: Si el catálogo es extremadamente grande, podría haber problemas de rendimiento, almacenamiento y tiempo de procesamiento durante la ingesta y consulta.
    -   Requires validation from: Arquitectura, Operaciones.
