## 2. Enabled Capability
**CAP-082:** Consulta de Tarifas FHM
**Business Value:** Permite el cálculo preciso de las primas por ubicación, asegurando la correcta valoración de los riesgos hidrometeorológicos y la generación de cotizaciones exactas.
**Requires:** HU-068 (Conectividad con `Plataforma-core-ohs` o su mock)
**Enables:** HU-055 (Aplicar Factores CAT y FHM al Cálculo de Primas)
**Orchestrates:** Plataforma-core-ohs (o su mock)

## 3. User Story
Como un sistema,
Quiero consultar las tarifas FHM (Fenómenos Hidrometeorológicos) desde el servicio `Plataforma-core-ohs` (o su mock),
Para realizar el cálculo preciso de las primas por ubicación.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad mediante la cual el módulo de cálculo de primas del sistema interactúa con el servicio `Plataforma-core-ohs` (o su mock) para obtener las tarifas de Fenómenos Hidrometeorológicos (FHM). El objetivo es recuperar las cuotas FHM organizadas por grupo, zona y condición, que son esenciales para determinar la prima adecuada para una ubicación específica. En caso de que el servicio `Plataforma-core-ohs` no esté disponible o se produzca un error durante la consulta, el sistema debe detectar esta situación, notificar al módulo de cálculo y registrar el incidente para su posterior análisis.
**Flow:** (Inicio del Cálculo de Prima FHM) → **HU-082: Consultar Tarifas FHM** → (Continuación del Cálculo de Prima FHM o Manejo de Error)

## 11. Architecture and Technical Dependencies
- **Plataforma-core-ohs (o su mock):** Servicio externo para la consulta de tarifas FHM. Se debe configurar un cliente REST robusto con manejo de timeouts (ej. 500ms), reintentos (ej. 3 reintentos con backoff exponencial) y circuit breaker.
- **Cliente API REST:** Componente encargado de realizar las llamadas HTTP al servicio `Plataforma-core-ohs`.
- **Módulo de consulta de tarifas:** Lógica de negocio dentro del sistema que orquesta la llamada al cliente API y procesa la respuesta.
- **Repositorio de tarifas:** Componente para almacenar y gestionar las tarifas FHM obtenidas (posiblemente un caché o una capa de abstracción de datos).
- **Circuit Breaker:** Implementado para el servicio `Plataforma-core-ohs` para prevenir fallos en cascada en caso de indisponibilidad.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad del mapeo de tarifas FHM:**
    -   Descripción: La estructura de las tarifas FHM (grupo, zona, condición) puede ser compleja y requerir un mapeo detallado y flexible en el sistema.
    -   Impacto: Errores en el mapeo pueden llevar a cálculos de primas incorrectos.
    -   Probabilidad: Media.
    -   Mitigación: Diseño cuidadoso del modelo de datos de tarifas, pruebas exhaustivas con diversos escenarios de tarifas, y validación con expertos de negocio.
2.  **Disponibilidad y rendimiento de `Plataforma-core-ohs`:**
    -   Descripción: La dependencia de un servicio externo introduce el riesgo de indisponibilidad o latencia elevada.
    -   Impacto: Retrasos o fallos en el cálculo de primas, afectando la experiencia del usuario o la operación del negocio.
    -   Probabilidad: Media.
    -   Mitigación: Implementación de Circuit Breakers, reintentos con backoff, monitoreo constante del servicio externo, y posible implementación de caché local para tarifas.
3.  **Cambios en la estructura de tarifas FHM:**
    -   Descripción: Si la estructura de las tarifas FHM cambia en `Plataforma-core-ohs`, el sistema podría requerir adaptaciones.
    -   Impacto: Desfase en el cálculo de primas, necesidad de refactorización.
    -   Probabilidad: Baja a Media.
    -   Mitigación: Contrato API claro y versionado con `Plataforma-core-ohs`, diseño de un módulo de tarifas flexible y desacoplado.

**Technical Debt:** [To be filled by operating team per scope and MVP]
*   Considerar la implementación de un caché para las tarifas FHM para reducir la dependencia en llamadas al servicio externo y mejorar el rendimiento.
*   Evaluar la necesidad de una estrategia de "fallback" más sofisticada en caso de indisponibilidad prolongada del servicio de tarifas FHM.

## 17. Criticality
**Criticality Level:** High
**Justification:** Esta historia es fundamental para la funcionalidad central del "Cálculo de Primas por ubicación". Sin la capacidad de consultar las tarifas FHM, el sistema no puede realizar uno de sus cálculos de negocio más críticos.
**Feature Impact:** La no implementación o falla de esta historia detendría completamente la capacidad del sistema para calcular primas FHM, haciendo que la funcionalidad de "Cálculo de Primas FHM" sea inoperable y afectando directamente la capacidad de cotización y emisión de pólizas relacionadas con Fenómenos Hidrometeorológicos.
**Critical Dependencies:** Todas las historias de usuario que implican el cálculo de primas FHM dependen críticamente de esta funcionalidad.
**Recommended Priority:** Sprint actual / Próximo sprint (dependiendo de la planificación, pero alta prioridad).
