## 3. User Story
Como desarrollador,
Quiero que el mock server simule fielmente los endpoints para tarifas (incendio, CAT, FHM) y factores técnicos,
Para poder probar la lógica de cálculo de primas en el cotizador con datos consistentes.

## 4. Functional Description
**Description:** Esta historia de usuario se centra en la implementación de un mock server que emulará el comportamiento de los sistemas de tarifas y factores técnicos. El mock server debe ser capaz de interceptar solicitudes HTTP del cotizador para tarifas de incendio, CAT (Catástrofes), FHM (Fenómenos Hidrometeorológicos) y factores técnicos específicos (como los de equipo electrónico). Deberá responder con datos predefinidos y consistentes, permitiendo al cotizador ejecutar su lógica de cálculo de primas sin depender de la disponibilidad o el estado de los servicios externos reales. También debe manejar el escenario de una tarifa no encontrada.
**Flow:** Desarrollo/Prueba del Cotizador → [HU-096: Simular Endpoints de Tarifas y Factores Técnicos] ← Solicitud de Tarifas/Factores del Cotizador

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Simulación de tarifas de Incendio
**Description:** Valida que el mock server puede responder correctamente a las solicitudes de tarifas de incendio con las tasas y factores predefinidos.

```gherkin
Scenario: El mock server devuelve tarifas de incendio esperadas
  Given el cotizador está configurado para usar el mock server
  And el mock server tiene configuradas tarifas de incendio específicas
  When el cotizador solicita tarifas de incendio
  Then el mock server devuelve las tasas y factores de incendio esperados (status 200 OK)
```

### AC-002: Simulación de tarifas CAT para una zona específica
**Description:** Valida que el mock server puede proporcionar el factor CAT correcto para una zona geográfica determinada.

```gherkin
Scenario: El mock server devuelve el factor CAT para una zona específica
  Given el cotizador está configurado para usar el mock server
  And el mock server tiene factores CAT configurados para "Zona Geográfica A"
  When el cotizador solicita tarifas CAT para la "Zona Geográfica A"
  Then el mock server devuelve el factor CAT correspondiente a la "Zona Geográfica A" (status 200 OK)
```

### AC-003: Simulación de factores técnicos de equipo electrónico
**Description:** Valida que el mock server puede devolver los factores técnicos por clase y nivel de zona para equipo electrónico.

```gherkin
Scenario: El mock server devuelve factores técnicos de equipo electrónico
  Given el cotizador está configurado para usar el mock server
  And el mock server tiene factores técnicos de equipo electrónico configurados para "Clase X" y "Nivel de Zona Z"
  When el cotizador solicita factores técnicos de equipo electrónico para "Clase X" y "Nivel de Zona Z"
  Then el mock server devuelve los factores por "Clase X" y "Nivel de Zona Z" (status 200 OK)
```

### AC-004: Manejo de tarifas no encontradas
**Description:** Valida que el mock server responde de manera apropiada cuando una tarifa o factor solicitado no ha sido configurado.

```gherkin
Scenario: El mock server indica cuando una tarifa no es encontrada
  Given el cotizador está configurado para usar el mock server
  And el mock server NO tiene configurada la "Tarifa Inexistente FHM"
  When el cotizador consulta la "Tarifa Inexistente FHM"
  Then el mock server devuelve una respuesta que indica la ausencia de la tarifa (ej. status 404 Not Found o un objeto vacío con un mensaje de error)
```

**BR-001:** Coincidencia de Solicitudes del Mock Server
- Description: El mock server debe ser capaz de identificar la respuesta configurada más apropiada basándose en el endpoint de la URL, el método HTTP, y los parámetros o el cuerpo de la solicitud entrante.
- Trigger: Cada vez que el mock server recibe una solicitud HTTP.
- Logic:
    1. Buscar una configuración de mock que coincida exactamente con el `endpoint_path` y `http_method`.
    2. Si hay múltiples coincidencias por ruta/método, aplicar `request_matcher` para encontrar la más específica.
    3. Si no se encuentra una coincidencia, aplicar la lógica de manejo de "tarifa no encontrada".
- Implementation: Motor de enrutamiento y coincidencia del framework de mock server.
- Exception: Si no se encuentra ninguna configuración de mock que coincida, se debe devolver una respuesta configurada por defecto (ej. 404 Not Found).

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad de los datos de tarifas:**
    - Description: Los datos de tarifas y factores técnicos pueden ser extremadamente complejos, con numerosas condiciones y variaciones (geográficas, tipo de bien, montos asegurados, etc.). Configurar mocks para cubrir todos estos escenarios puede ser muy laborioso.
    - Impact: Retrasos en la configuración del mock server, posibles inconsistencias o brechas en las pruebas si no se cubren todos los casos relevantes.
    - Probability: Media
    - Mitigation: Priorizar la simulación de los escenarios más críticos y de mayor impacto. Utilizar un framework de mock que permita la definición de lógica condicional en las respuestas. Realizar un descubrimiento incremental de los escenarios complejos.
2.  **Desfase con la API real:**
    - Description: Los mocks se configuran en base a un entendimiento inicial de las APIs de tarifas. Si las APIs reales evolucionan significativamente, los mocks podrían quedar desactualizados y llevar a pruebas erróneas.
    - Impact: Pruebas falsamente positivas o negativas, necesidad de retrabajo para actualizar los mocks, posibles fallos en integración real.
    - Probability: Baja a Media
    - Mitigation: Mantener una comunicación fluida con el equipo responsable de las APIs de tarifas reales. Documentar claramente la versión de la API que simula el mock. Establecer un proceso para la revisión y actualización periódica de los mocks.

**Technical Debt:** N/A (Este componente es una herramienta de apoyo al desarrollo y pruebas, no introduce deuda técnica en la funcionalidad de negocio).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es crítica porque su implementación es un habilitador fundamental para el desarrollo y las pruebas del cotizador. Sin un mock server funcional, los desarrolladores se verían bloqueados o severamente ralentizados al no poder probar la lógica de cálculo de primas de forma aislada y controlada, debido a la dependencia de sistemas externos que podrían no estar disponibles o estables.
**Feature Impact:** La no implementación, o una implementación deficiente, de este mock server detendría o ralentizaría drásticamente el progreso de la feature principal del cotizador (cálculo de primas), impactando directamente en el tiempo de salida al mercado.
**Critical Dependencies:** Todas las historias de usuario relacionadas con la funcionalidad de cálculo de primas del cotizador dependen críticamente de la disponibilidad de estos mocks para un desarrollo y pruebas eficientes.
