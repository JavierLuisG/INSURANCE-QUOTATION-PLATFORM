## 1. Identificación General / General Identification
**Feature:** Gestión de Ubicaciones de Riesgo en Cotizaciones
**Capability:** CAP-007 - Actualización de Detalles de Ubicación de Riesgo
**Actor:** Usuario (Agente de Seguros / Administrador de Cotizaciones)
**Bounded Context:** Cotizaciones de Seguros / Gestión de Riesgos
**Story Points:** 3

## 2. Enabled Capability
**CAP-007:** Actualización de Detalles de Ubicación de Riesgo
**Business Value:** Asegurar la precisión y actualidad de la información de las ubicaciones de riesgo en las cotizaciones, permitiendo corregir errores y adaptarse a cambios, lo cual es crítico para una tarificación y emisión de pólizas correctas.
**Requires:** CAP-006 - Agregar una nueva ubicación de riesgo a la cotización (La ubicación debe existir previamente).
**Enables:** CAP-008 - Generación de Cotización con Datos Actualizados (La cotización reflejará la información corregida).
**Orchestrates:** N/A

## 3. User Story
As a usuario,
I want modificar los datos de una ubicación de riesgo existente,
So that corregir o actualizar su información.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario seleccionar una ubicación de riesgo previamente asociada a una cotización y editar sus detalles específicos, tales como la dirección, el tipo de uso o las características de la propiedad. El sistema debe validar los datos ingresados y, si son válidos, persistir los cambios en la base de datos de cotizaciones. Es crucial que la actualización solo afecte a la ubicación seleccionada y que los datos corregidos se muestren correctamente al consultar la cotización.
**Flow:** HU-006 (Agregar nueva ubicación) → HU-007 (Editar ubicación existente) → HU-008 (Consultar/Generar Cotización con datos actualizados)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Actualización exitosa de los detalles de la ubicación
**Description:** Valida que, al modificar los campos de una ubicación existente y guardar, los cambios se persisten correctamente y se reflejan en la cotización.

```gherkin
Scenario: El usuario edita y guarda los detalles de una ubicación existente
  Given que el usuario ha seleccionado una "Ubicación de Riesgo A" con dirección "Calle Falsa 123"
  When el usuario edita la dirección a "Avenida Siempre Viva 742" y guarda los cambios
  Then los detalles de la "Ubicación de Riesgo A" se actualizan con la nueva dirección en el sistema
  And la cotización asociada muestra la dirección "Avenida Siempre Viva 742" para la "Ubicación de Riesgo A"
```

### AC-002: Manejo de campos obligatorios vacíos
**Description:** Valida que el sistema impide guardar cambios si un campo obligatorio se deja vacío y muestra un mensaje de validación.

```gherkin
Scenario: El usuario intenta guardar una ubicación con un campo obligatorio vacío
  Given que el usuario ha seleccionado una "Ubicación de Riesgo B"
  And el campo "Tipo de Uso de la Propiedad" es obligatorio
  When el usuario deja el campo "Tipo de Uso de la Propiedad" vacío e intenta guardar
  Then el sistema muestra el mensaje de validación "El campo 'Tipo de Uso de la Propiedad' es obligatorio."
  And los cambios no son guardados en el sistema
```

### AC-003: Visualización de datos actualizados en la cotización
**Description:** Valida que, una vez guardados los cambios de una ubicación, estos se reflejan correctamente al consultar la cotización.

```gherkin
Scenario: Los datos actualizados de la ubicación se reflejan en la consulta de la cotización
  Given que el usuario ha editado y guardado exitosamente la "Ubicación de Riesgo C"
  And el "Tipo de Construcción" de "Ubicación de Riesgo C" se ha cambiado a "Concreto Armado"
  When el usuario consulta los detalles de la cotización asociada
  Then la "Ubicación de Riesgo C" dentro de la cotización muestra el "Tipo de Construcción" como "Concreto Armado"
```

**BR-001:** Validación de Campos Obligatorios
- Description: Todos los campos de la ubicación marcados como obligatorios deben contener un valor válido antes de que se pueda guardar la actualización.
- Trigger: Intento de guardar los cambios de la ubicación.
- Logic: Si algún campo obligatorio está vacío o no cumple con su formato, se mostrará un mensaje de validación específico y se impedirá el guardado.
- Implementation: Lógica de validación en el frontend y el backend (API de Cotizaciones).
- Exception: N/A

**BR-002:** Actualización Parcial de Ubicación
- Description: La API debe permitir la actualización de campos específicos de una ubicación sin requerir el envío de todos los datos de la ubicación completa.
- Trigger: Solicitud de actualización de ubicación.
- Logic: Utilizar un método HTTP PATCH o una lógica de actualización que procese solo los campos proporcionados en el cuerpo de la solicitud, dejando los campos no especificados sin cambios.
- Implementation: Endpoint de la API de Cotizaciones.
- Exception: N/A

**BR-003:** Recálculo o Marca de Recálculo de Cotización
- Description: Al modificar datos de una ubicación que impactan la tarificación (ej. tipo de uso, características de seguridad), la cotización asociada debe ser recalculada o marcada para un recálculo posterior.
- Trigger: Guardado exitoso de los detalles de la ubicación.
- Logic: Identificar los campos que afectan la prima. Si uno de estos campos es modificado, disparar un evento o invocar un servicio para iniciar el proceso de recálculo de la cotización.
- Implementation: Backend (API de Cotizaciones, Servicio de Tarificación).
- Exception: N/A (puede ser un proceso asíncrono).

```gherkin

  And los cambios no son guardados
```

### Case 3: Error de concurrencia al editar
```gherkin
Scenario: Dos usuarios intentan editar la misma ubicación simultáneamente
  Given que 'Usuario A' está editando la 'Ubicación X'
  And 'Usuario B' también comienza a editar la 'Ubicación X'
  When 'Usuario A' guarda sus cambios exitosamente
  And luego 'Usuario B' intenta guardar sus cambios
  Then el sistema detecta un conflicto de concurrencia
  And muestra un mensaje a 'Usuario B' indicando "Los datos han sido modificados por otro usuario. Por favor, recargue y vuelva a intentar."
  And los cambios de 'Usuario B' no son guardados hasta que resuelva el conflicto
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Impacto en el Recálculo de la Cotización**
    *   Description: La modificación de ciertos campos de ubicación (ej. tipo de uso, características de seguridad) puede tener un impacto directo y significativo en el cálculo de la prima de la cotización, requiriendo un proceso de recálculo que debe ser eficiente y preciso.
    *   Impact: Cálculos de primas incorrectos, latencia en la UI, inconsistencia de datos si el recálculo no es automático o no se notifica al usuario.
    *   Probability: Media
    *   Mitigation: Definir claramente qué campos disparan un recálculo. Implementar un servicio de tarificación robusto y considerar si el recálculo debe ser síncrono o asíncrono. Comunicar al usuario si un recálculo es necesario.
2.  **Riesgo: Manejo de Concurrencia**
    *   Description: Si varios usuarios intentan editar la misma ubicación simultáneamente, podría haber sobrescritura de datos o inconsistencias.
    *   Impact: Pérdida de información, datos erróneos en la cotización.
    *   Probability: Baja (dependiendo del volumen de usuarios concurrentes)
    *   Mitigation: Implementar mecanismos de control de concurrencia a nivel de base de datos o aplicación (ej. bloqueo optimista con control de versión, uso de ETag en HTTP, timestamps de última modificación).

**Technical Debt:** N/A (Se determinará por el equipo operativo en función del alcance y el MVP).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La capacidad de editar los detalles de una ubicación de riesgo es fundamental para mantener la integridad y precisión de los datos de las cotizaciones. Sin esta funcionalidad, cualquier error o cambio en la información de una ubicación no podría ser corregido, llevando a cotizaciones incorrectas o inválidas, lo que impactaría directamente en la operación del negocio y la satisfacción del cliente.
**Feature Impact:** La no implementación o el fallo de esta historia dejaría la funcionalidad de "Gestión de Ubicaciones de Riesgo" incompleta y poco fiable, afectando la calidad general de las cotizaciones.
**Critical Dependencies:** Impacta directamente la validez de cualquier cotización que contenga ubicaciones con datos susceptibles de cambio o error.
**Recommended Priority:** Sprint actual / Inmediata.

## 18. Identified Assumptions
1.  **Asunción: Existencia previa de la ubicación**
    *   Description: Se asume que la ubicación de riesgo que se desea editar ya ha sido creada y está asociada a una cotización existente en el sistema.
    *   Impact if false: El usuario no podría seleccionar una ubicación para editar, o la operación de edición fallaría al intentar referenciar una entidad inexistente.
    *   Requires validation from: Equipo de Producto / UX.
2.  **Asunción: Disponibilidad de catálogos de datos**
    *   Description: Se asume que los catálogos para campos como "Tipo de Uso de la Propiedad", "Tipo de Construcción", "Estados", etc., ya están definidos y son accesibles por el frontend para la selección y por el backend para la validación.
    *   Impact if false: El usuario no podría seleccionar valores válidos, o la validación de datos fallaría.
    *   Requires validation from: Equipo de Datos / Backend.
3.  **Asunción: Permisos de usuario**
    *   Description: Se asume que el usuario que intenta editar la ubicación tiene los permisos de acceso y edición adecuados para la cotización y la ubicación específica.
    *   Impact if false: El usuario experimentaría errores de autorización o la funcionalidad de edición estaría deshabilitada.
    *   Requires validation from: Arquitectura de Seguridad / Equipo de Producto.
