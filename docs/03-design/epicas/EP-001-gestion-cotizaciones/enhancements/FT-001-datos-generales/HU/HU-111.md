## 2. Enabled Capability
**CAP-001:** Consulta y Gestión de Cotizaciones
**Business Value:** Permite a los usuarios revisar y continuar trabajando en cotizaciones previamente guardadas, mejorando la eficiencia operativa y la continuidad del proceso de ventas.
**Requires:** N/A
**Enables:** CAP-002 - Edición de Cotización, CAP-003 - Visualización de Detalles de Cotización
**Orchestrates:** API de Consulta de Cotizaciones (Backend)

## 3. User Story
Como usuario,
Quiero abrir una cotización existente utilizando su folio,
Para revisar o continuar editando la información previamente guardada.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario buscar y cargar los detalles de una cotización previamente guardada en el sistema. El usuario introducirá un folio único en un campo de búsqueda en la interfaz principal. Si el folio es válido y corresponde a una cotización existente, el sistema recuperará y mostrará la información completa de la cotización, incluyendo su estado actual. En caso de que el folio no sea válido o no exista en el sistema, el usuario recibirá un mensaje de error claro y la interfaz permanecerá sin cargar ninguna cotización.
**Flow:** [Interfaz Principal] → [HU-111: Cargar Cotización Existente] → [HU-XXX: Editar Cotización Existente / HU-YYY: Visualizar Detalles de Cotización]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Carga exitosa de cotización válida
**Description:** Valida que al introducir un folio existente y válido, el sistema carga y muestra correctamente todos los datos de la cotización asociada, incluyendo su estado.

```gherkin
Scenario: Cargar cotización existente con folio válido
  Given estoy en la interfaz principal del módulo de cotizaciones
  And existe una cotización con folio "COT-2026-001" y estado "Borrador"
  When introduzco el folio "COT-2026-001" en el campo de búsqueda y presiono "Cargar"
  Then se carga la cotización correspondiente a "COT-2026-001"
  And se muestran todos sus datos (cliente, productos, precios, etc.)
  And el estado de la cotización se muestra correctamente como "Borrador"
```



| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| folioCotizacion | String | yes | N/A | Formato alfanumérico, máximo 20 caracteres (ej. COT-YYYY-NNN). | N/A | COT-2026-001 |


**BR-001: Validación de Existencia de Folio**
- Description: El sistema debe verificar si el folio proporcionado por el usuario corresponde a una cotización existente y activa en la base de datos.
- Trigger: Al intentar cargar una cotización después de introducir el folio.
- Logic: `IF (folio_existe_en_db) THEN cargar_datos_cotizacion ELSE retornar_error_no_encontrado`
- Implementation: Servicio de Consulta de Cotizaciones (Backend).
- Exception: Folio no encontrado.

**BR-002: Búsqueda Tolerante a Mayúsculas/Minúsculas**
- Description: La búsqueda del folio debe ser insensible a mayúsculas y minúsculas para facilitar la experiencia del usuario.
- Trigger: Al procesar el folio introducido para la consulta en el backend.
- Logic: `Convertir folio_introducido a formato estandarizado (ej. mayúsculas) antes de la comparación con los folios almacenados.`
- Implementation: Servicio de Consulta de Cotizaciones (Backend).
- Exception: N/A.

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Rendimiento de la búsqueda.**
    - Description: Si el volumen de cotizaciones en la base de datos es muy alto, la consulta por folio podría volverse lenta, afectando la experiencia del usuario.
    - Impact: Tiempos de respuesta lentos, frustración del usuario.
    - Probability: Media (dependiendo del crecimiento de datos).
    - Mitigation: Asegurar la existencia de índices eficientes en la base de datos para el campo `folioCotizacion`. Evaluar estrategias de caching para cotizaciones recientemente accedidas.
2.  **Riesgo: Seguridad de acceso a datos.**
    - Description: Si las políticas de RBAC o las restricciones de acceso no se implementan correctamente, un usuario podría acceder a cotizaciones que no le corresponden.
    - Impact: Brecha de seguridad, exposición de información confidencial.
    - Probability: Baja (si los estándares de seguridad están bien definidos).
    - Mitigation: Realizar pruebas exhaustivas de seguridad y penetración en el endpoint de la API. Implementar validaciones de autorización en el backend para cada solicitud de carga.
