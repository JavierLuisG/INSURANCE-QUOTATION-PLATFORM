**Requires:** CAP-FT-010 (Acceso a Tarifas y Factores), CAP-FT-011 (Validación de Datos de Ubicación)

## 3. User Story
Como usuario,
Quiero que el sistema calcule la prima neta para cada ubicación de riesgo, utilizando las tarifas y factores técnicos correspondientes,
Para obtener el costo base del seguro para cada propiedad asegurada.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para calcular la prima neta de forma individual para cada ubicación de riesgo asociada a una póliza o cotización. El sistema consultará y aplicará las tarifas de incendio y factores técnicos (como el tipo de riesgo y la suma asegurada) para determinar el valor monetario de la prima neta. Cada cálculo se realizará de manera independiente, asegurando la precisión para las características específicas de cada ubicación.
**Flow:** [FT-011: Validación de Datos de Ubicación de Riesgo] → [HU-054: Cálculo de Prima Neta por Ubicación] → [HU-XXX: Consolidación de Prima Total de Póliza]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Cálculo de Prima Neta Individual
**Description:** Valida que el sistema calcula una prima neta individual para cada ubicación de riesgo cuando todos sus datos son válidos.

```gherkin
Scenario: Cálculo exitoso de prima neta para una ubicación con datos válidos
  Dado que una ubicación de riesgo (ID: "LOC-001") tiene todos los datos de cálculo válidos (ej. suma asegurada = 150000.00, tipo de riesgo = "INCENDIO")
  Y el servicio FT-010 provee una tarifa de incendio de 0.0015 y un factor técnico de 1.2
  Cuando se solicita el cálculo de la prima neta para la ubicación "LOC-001"
  Entonces el sistema calcula la prima neta como 270.00 (150000 * 0.0015 * 1.2)
  Y la prima neta individual se almacena y asocia a la ubicación "LOC-001"
```

### AC-002: Aplicación Correcta de Tarifas y Factores
**Description:** Asegura que las tarifas de incendio y los factores técnicos correspondientes se aplican de forma precisa en el cálculo de la prima neta.

```gherkin
Scenario: Aplicación precisa de tarifas y factores técnicos
  Dado que el sistema tiene acceso a las tarifas de incendio correctas según la suma asegurada y el tipo de riesgo (ej. para "INCENDIO", Suma Asegurada de 100000, Tarifa = 0.0010, Factor = 1.1)
  Cuando se calcula la prima neta para una ubicación con esos parámetros
  Entonces el valor de la prima neta resultante es consistente con la fórmula (100000 * 0.0010 * 1.1 = 110.00)
  Y el cálculo utiliza los valores obtenidos del servicio FT-010
```

### AC-003: Independencia de Cálculo para Múltiples Ubicaciones
**Description:** Confirma que el cálculo de la prima neta se realiza de forma independiente para cada ubicación, sin influir en las demás.

```gherkin
Scenario: Cálculo independiente para múltiples ubicaciones en una póliza
  Dado que una póliza contiene múltiples ubicaciones de riesgo con sus respectivos datos válidos (ej. "LOC-001" y "LOC-002")
  Y cada ubicación tiene parámetros de cálculo distintos
  Cuando se ejecuta el proceso de cálculo de primas netas para la póliza
  Entonces el sistema calcula la prima neta para "LOC-001" de forma independiente
  Y el sistema calcula la prima neta para "LOC-002" de forma independiente
  Y el resultado de la prima neta de "LOC-001" no afecta el cálculo ni el resultado de "LOC-002"
```

**BR-001: Fórmula de Cálculo de Prima Neta Básica**
- Description: Define la expresión matemática para calcular la prima neta de una ubicación de riesgo.
- Trigger: Al solicitar el cálculo de la prima neta para una ubicación.
- Logic: `Prima Neta = Suma Asegurada * Tarifa de Incendio * Factor Técnico` (Esta es la fórmula base; cualquier complejidad adicional debe ser especificada por el negocio).
- Implementation: Servicio de Cálculo de Primas.
- Exception: Si algún parámetro requerido para la fórmula es nulo o inválido, el cálculo debe fallar.

**BR-002: Obtención de Tarifas y Factores**
- Description: Establece que las tarifas y factores técnicos deben ser obtenidos del Servicio de Consulta de Parámetros (FT-010).
- Trigger: Antes de ejecutar la fórmula de cálculo de prima neta.
- Logic: El sistema debe invocar al servicio FT-010, pasando el `tipo_riesgo` y `suma_asegurada` de la ubicación para obtener la `tarifa_incendio` y el `factor_tecnico` aplicables.
- Implementation: Componente de integración con FT-010 dentro del Servicio de Cálculo de Primas.
- Exception: Si el servicio FT-010 no responde o no encuentra tarifas para los parámetros dados, el cálculo debe abortarse con un error.

## 13. Edge Cases and Exceptions
### Case 1: Datos de ubicación incompletos o inválidos
```gherkin
Scenario: Intento de cálculo con datos de ubicación faltantes
  Dado que una ubicación de riesgo (ID: "LOC-002") tiene la suma asegurada nula o cero
  Cuando se intenta calcular la prima neta para la ubicación "LOC-002"
  Entonces el sistema devuelve un error indicando que la suma asegurada es inválida
  Y no se calcula ni almacena ninguna prima neta para "LOC-002"
```

### Case 2: Tarifas o factores no encontrados en FT-010
```gherkin
Scenario: No se encuentran tarifas o factores para los parámetros de la ubicación
  Dado que una ubicación de riesgo (ID: "LOC-003") tiene datos válidos (suma asegurada = 50000.00, tipo de riesgo = "RIESGO_NUEVO")
  Y el servicio FT-010 no tiene tarifas ni factores definidos para el "RIESGO_NUEVO"
  Cuando se intenta calcular la prima neta para la ubicación "LOC-003"
  Entonces el sistema devuelve un error indicando que no se pudieron obtener las tarifas/factores necesarios
  Y no se calcula ni almacena ninguna prima neta para "LOC-003"
```

### Case 3: Fallo en la comunicación con el Servicio de Ubicaciones
```gherkin
Scenario: Error de conexión al intentar guardar la prima neta calculada
  Dado que la prima neta para una ubicación (ID: "LOC-004") ha sido calculada exitosamente
  Cuando el sistema intenta guardar el resultado de la prima neta en el Servicio de Ubicaciones
  Pero el Servicio de Ubicaciones no está disponible o responde con un error de red
  Entonces el sistema registra un error CRITICAL
  Y notifica al usuario que no se pudo guardar el resultado del cálculo
  Y la prima neta de "LOC-004" no se actualiza
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Precisión y Mantenimiento de la Lógica de Cálculo:**
    -   Description: La lógica de cálculo de la prima neta puede volverse compleja y estar sujeta a cambios regulatorios o de negocio, lo que aumenta el riesgo de errores en la implementación o dificultad para mantenerla.
    -   Impact: Cálculos incorrectos, ofertas de seguros erróneas, pérdidas financieras, insatisfacción del cliente.
    -   Probability: Media.
    -   Mitigation: Implementar la lógica de cálculo de forma modular y bien encapsulada, utilizando objetos de valor inmutables como se sugiere. Realizar extensas pruebas unitarias, de integración y de regresión. Validar la lógica con expertos de negocio (actuarios). Considerar un BRMS (Business Rule Management System) si la complejidad de las reglas de negocio escala.
2.  **Disponibilidad y Latencia del Servicio FT-010:**
    -   Description: La dependencia crítica del servicio FT-010 para obtener tarifas y factores podría causar fallos o retrasos en el cálculo de primas si este servicio no está disponible o tiene alta latencia.
    -   Impact: Incapacidad de calcular primas, retrasos en la generación de ofertas, impacto negativo en la experiencia del usuario.
    -   Probability: Media.
    -   Mitigation: Implementar Circuit Breaker y estrategias de reintento. Considerar caching de tarifas y factores (si la volatilidad lo permite) o una estrategia de fallback para escenarios de indisponibilidad. Monitoreo proactivo del rendimiento de FT-010.

**Technical Debt:** N/A (se llenará por el equipo operativo según el alcance y el MVP)

## 17. Criticality
**Criticality Level:** Alta
**Justification:** El cálculo de la prima neta es una funcionalidad fundamental y central para el negocio de seguros. Sin ella, no es posible determinar el costo base de las propiedades aseguradas, lo cual es imprescindible para tarificar, cotizar y emitir pólizas.
**Feature Impact:** La no implementación o un fallo en esta historia impactaría directamente la capacidad de tarificar y generar cualquier tipo de oferta o póliza de seguro, deteniendo el flujo principal del negocio.
**Critical Dependencies:** FT-010 (tarifas y factores técnicos) y FT-011 (datos de ubicación validados) son dependencias críticas que deben estar estables y disponibles.
**Recommended Priority:** Sprint actual (dada su alta prioridad y naturaleza crítica para el negocio).
