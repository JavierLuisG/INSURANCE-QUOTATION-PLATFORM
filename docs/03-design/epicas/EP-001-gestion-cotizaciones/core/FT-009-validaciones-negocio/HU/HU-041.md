## 3. User Story
Como un **desarrollador**,
quiero **que la lógica de cálculo de primas incorpore todas las reglas de negocio y factores técnicos definidos**,
para que **se asegure la precisión del precio**.

## 4. Functional Description
**Description:** Esta historia de usuario se centra en la implementación del motor de reglas de negocio para el cálculo de primas. El sistema debe ser capaz de procesar las características de una cotización o póliza y aplicar dinámicamente recargos, descuentos y factores especiales basados en reglas predefinidas. Esto incluye la consideración de características de ubicación, canales de venta y combinaciones específicas de coberturas o riesgos para determinar la prima final de manera precisa.
**Flow:** `FT-004: Ejecución y Persistencia del Cálculo de Primas` (inicio del cálculo) → `HU-041: Aplicar reglas de negocio para el cálculo de primas` (ejecución de la lógica de reglas) → `FT-004: Ejecución y Persistencia del Cálculo de Primas` (persistencia del resultado y finalización del cálculo).

## 6. Acceptance Criteria
### AC-001: Aplicación de recargo por característica de ubicación
**Description:** Valida que si una ubicación posee una característica específica que activa un recargo, este se sume correctamente a la prima.

```gherkin
Scenario: Aplicar recargo por característica específica de la ubicación
  Given una cotización con una ubicación que tiene la característica "Zona de Alto Riesgo"
  And la regla de negocio define un recargo del 10% para "Zona de Alto Riesgo"
  When se ejecuta el cálculo de primas
  Then el recargo del 10% se suma correctamente a la prima base
  And la prima final refleja este recargo
```

### AC-002: Aplicación de descuento por canal de venta
**Description:** Valida que si la cotización proviene de un canal de venta elegible para un descuento, este se aplique a la prima comercial.

```gherkin
Scenario: Aplicar descuento por canal de venta específico
  Given una cotización generada a través del "Canal Digital"
  And la regla de negocio define un descuento del 5% para el "Canal Digital"
  When se ejecuta el cálculo de primas
  Then el descuento del 5% se aplica a la prima comercial
  And la prima final refleja este descuento
```

### AC-003: Aplicación de factor especial por combinación de coberturas/riesgos
**Description:** Valida que si una combinación particular de coberturas o riesgos requiere un factor especial, este se aplique según la regla definida.

```gherkin
Scenario: Aplicar factor especial por combinación de coberturas y riesgos
  Given una cotización con las coberturas "Incendio" y "Robo" para un riesgo de "Comercio"
  And la regla de negocio define un factor multiplicador de 1.2 para la combinación "Incendio + Robo en Comercio"
  When se ejecuta el cálculo de primas
  Then el factor de 1.2 se aplica a la prima correspondiente
  And la prima final refleja la aplicación de este factor
```

**BR-001:** Recargo por Característica de Ubicación
- Description: Aplica un porcentaje de recargo a la prima base si la ubicación del riesgo cumple con ciertas características definidas.
- Trigger: Durante la fase de cálculo de la prima, después de obtener la prima base.
- Logic: `IF (ubicacion.caracteristica == 'Zona de Alto Riesgo') THEN prima_base = prima_base * (1 + recargo_porcentaje_alto_riesgo)`
- Implementation: Motor de reglas de negocio / Módulo de cálculo de primas.
- Exception: Si la característica de ubicación no está definida, no se aplica recargo.

**BR-002:** Descuento por Canal de Venta
- Description: Aplica un porcentaje de descuento a la prima comercial si la cotización se origina a través de un canal de venta específico.
- Trigger: Durante la fase de cálculo de la prima, después de calcular la prima comercial.
- Logic: `IF (cotizacion.canal_venta == 'Canal Digital') THEN prima_comercial = prima_comercial * (1 - descuento_porcentaje_canal_digital)`
- Implementation: Motor de reglas de negocio / Módulo de cálculo de primas.
- Exception: Si el canal de venta no está en la lista de canales con descuento, no se aplica.

**BR-003:** Factor Especial por Combinación de Coberturas/Riesgos
- Description: Multiplica la prima de una cobertura o el total de la prima por un factor específico si se cumplen ciertas combinaciones de coberturas y tipos de riesgo.
- Trigger: Durante la fase de cálculo de la prima, al evaluar las coberturas individuales o la prima total.
- Logic: `IF (coberturas_seleccionadas.contains('Incendio') AND coberturas_seleccionadas.contains('Robo') AND riesgo == 'Comercio') THEN prima_total = prima_total * factor_combinacion_inc_rob_comercio`
- Implementation: Motor de reglas de negocio / Módulo de cálculo de primas.
- Exception: Si la combinación no es exacta o no está definida, se usa el factor por defecto (1.0).

## 11. Architecture and Technical Dependencies
- **Motor de reglas de negocio (BRMS)**: Se utilizará un motor de reglas (ej. Drools, OpenL Tablets, o implementación custom) para gestionar y aplicar las reglas de forma dinámica.
- **Módulo de cálculo de primas**: Componente principal que orquesta la obtención de datos, la llamada al BRMS y la consolidación del resultado.
- **FT-007: Integración con Servicios de Referencia (Tarifas)**: Se integrará para obtener tarifas base, catálogos de características y otros datos necesarios para la evaluación de las reglas. Considerar timeouts (500ms), reintentos (3 veces con backoff exponencial) y circuit breaker para resiliencia.
- **Base de datos de reglas**: Almacenamiento persistente de las reglas de negocio, parametrizaciones y sus versiones.
- **Kafka Topic**: Posiblemente un topic `premium-calculated-events` para publicar resultados de cálculos.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad de las reglas:**
    -   Description: A medida que el número y la complejidad de las reglas aumentan, la lógica de cálculo puede volverse difícil de entender, mantener y depurar.
    -   Impact: Errores en el cálculo de primas, dificultad para incorporar nuevas reglas, lentitud en el desarrollo.
    -   Probability: Media.
    -   Mitigation: Implementar un BRMS robusto, documentar cada regla exhaustivamente, establecer un proceso claro de gestión de cambios de reglas, realizar revisiones de código y pruebas de regresión automáticas.
2.  **Rendimiento del Motor de Reglas:**
    -   Description: Un gran volumen de reglas o reglas computacionalmente intensivas pueden impactar negativamente el tiempo de respuesta del servicio de cálculo.
    -   Impact: Mala experiencia de usuario en el cotizador, sobrecarga del servicio.
    -   Probability: Media.
    -   Mitigation: Optimizar la estructura de las reglas, realizar pruebas de carga, monitorear el rendimiento en producción, considerar caching de resultados intermedios.
3.  **Coherencia y Conflictos de Reglas:**
    -   Description: Posibilidad de que existan reglas contradictorias o que la interacción entre múltiples reglas lleve a resultados inesperados.
    -   Impact: Cálculos de prima incorrectos, disputas comerciales, problemas de cumplimiento.
    -   Probability: Alta.
    -   Mitigation: Herramientas de validación de reglas en el BRMS, pruebas exhaustivas de combinaciones de reglas, definición clara de precedencia de reglas, revisiones manuales por expertos de negocio.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La precisión en el cálculo de primas es el core del negocio de seguros. Un cálculo incorrecto puede llevar a pérdidas financieras (sub-tarificación), pérdida de competitividad (sobre-tarificación) y problemas de cumplimiento regulatorio.
**Feature Impact:** Sin la implementación correcta de esta historia, la feature de "Cálculo de Primas" no sería funcional o produciría resultados erróneos, invalidando cualquier proceso que dependa de ella (cotización, emisión).
**Critical Dependencies:** Todas las historias de usuario relacionadas con la cotización, emisión y renovación de pólizas dependen críticamente de esta historia para obtener precios correctos.
**Recommended Priority:** Sprint actual / Próximo sprint (dada su dependencia con FT-004 y FT-007, debe ir inmediatamente después o en paralelo).

## 18. Identified Assumptions

    -   Description: Se asume que existe o se seleccionará y proveerá una tecnología o framework para implementar el motor de reglas de negocio que permita la parametrización y fácil mantenimiento.
