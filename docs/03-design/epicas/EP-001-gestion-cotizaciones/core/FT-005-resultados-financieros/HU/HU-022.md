## 1. Identificación General
**Feature:** Cálculo y Presentación de Cotizaciones
**Capability:** CAP-005 - Desglose de Precios Financieros
**Actor:** Usuario (cliente o agente que visualiza la cotización)
**Bounded Context:** Cotizaciones
**Story Points:** 3 puntos

## 2. Enabled Capability
**CAP-005:** Desglose de Precios Financieros
**Business Value:** Aumentar la transparencia en el cálculo de la cotización, permitiendo al usuario comprender la composición del costo final y generando mayor confianza en el proceso.
**Requires:** CAP-003 - Cálculo de Primas (derivado de HU-016), CAP-004 - Aplicación de Reglas de Negocio (derivado de HU-019)
**Enables:** CAP-006 - Confirmación y Contratación de Cotización (funcionalidad posterior)
**Orchestrates:** N/A

## 3. User Story
Como usuario,
quiero ver los componentes adicionales que afectan el precio final (impuestos, recargos, descuentos),
para que pueda comprender la composición del costo.

## 4. Functional Description
**Description:** Esta historia de usuario permite al actor visualizar un desglose detallado de todos los componentes adicionales que contribuyen al precio final de una cotización. Esto incluye impuestos, recargos aplicados y descuentos concedidos, con el objetivo de proporcionar transparencia completa sobre cómo se calcula el costo total.
**Flow:** HU-016 (Calcular prima neta y comercial) → HU-019 (Aplicar factores técnicos y reglas de negocio) → **HU-022 (Visualizar componentes adicionales del precio)** → HU-026 (Cambiar estado a "Aprobada" o "Rechazada" manualmente)

## 5. Expected Results


| element | description |
|---|---|
| Data | Lista de objetos que representan impuestos, recargos y descuentos. Cada objeto debe contener al menos el nombre/descripción del componente, su valor monetario y el tipo de componente (impuesto, recargo, descuento). Puede incluir un campo para la aplicación (total o por ubicación). |
| States | La cotización debe estar en un estado 'Calculada' o 'Lista para visualización'. La sección de desglose de precios en la interfaz de usuario cambia de un estado 'vacío' o 'cargando' a 'mostrando componentes'. |
| Notifications | No se esperan notificaciones directas al usuario por la visualización. Posibles mensajes de error si la carga de componentes falla. |
| Integrations | Consulta a la API de cotizaciones del backend para obtener el desglose de los componentes financieros asociados a la cotización calculada. |
| Kafka | No se espera la publicación ni el consumo de eventos Kafka directamente por esta historia (es una operación de lectura). |
| Logs | Logs de nivel INFO en el backend al procesar la consulta de componentes financieros y en el frontend al cargar y renderizar la sección. |
| UI | Una nueva sección o un panel expandible en la pantalla de resultados financieros de la cotización. Esta sección mostrará los componentes (impuestos, recargos, descuentos) de forma clara, posiblemente en una tabla o lista, con sus respectivos valores. |


## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización de componentes después del cálculo
**Description:** Valida que, una vez que la cotización ha sido calculada, los componentes adicionales del precio se muestran correctamente en la sección de resultados financieros.

```gherkin
Scenario: El usuario ve los componentes adicionales tras el cálculo
  Given que la cotización ha sido calculada y sus componentes financieros están disponibles
  When accedo a la sección de resultados financieros
  Then se muestran los impuestos, recargos y descuentos aplicados
```

### AC-002: Detalle de recargos específicos
**Description:** Asegura que cualquier recargo específico aplicado a la cotización se lista individualmente con su valor correspondiente en el desglose.

```gherkin
Scenario: Un recargo específico se lista con su valor
  Given que se aplica un recargo específico (ej. 'Recargo por Riesgo') a la cotización
  When se visualizan los resultados financieros en la sección de desglose
  Then el 'Recargo por Riesgo' se lista explícitamente con su valor monetario
```

### AC-003: Manejo de componentes no aplicados o con valor cero
**Description:** Confirma que si no se aplican impuestos, recargos o descuentos, o si su valor total es cero, las secciones correspondientes se manejan adecuadamente (no aparecen o muestran cero).

```gherkin
Scenario: Las secciones de componentes no aplicados no se muestran o indican cero
  Given que no se aplican impuestos o recargos a la cotización (o su suma es cero)
  When se visualizan los resultados financieros en la sección de desglose
  Then la sección de 'Impuestos' y/o 'Recargos' no aparece, o muestra un valor de cero
```

**BR-001:** Visualización condicional de secciones de componentes
- Description: Si un tipo de componente (impuesto, recargo, descuento) no tiene elementos aplicados o la suma de sus valores es cero, la sección correspondiente en la UI no debe ser visible, o debe indicar claramente un valor de cero.
- Trigger: Al renderizar la sección de desglose de precios.
- Logic: `IF (lista_componentes_por_tipo.isEmpty() OR sum(lista_componentes_por_tipo.valor) == 0) THEN ocultar_seccion_o_mostrar_cero()`
- Implementation: Frontend.
- Exception: N/A

**BR-002:** Desglose de componentes por ubicación (si aplica)
- Description: Los componentes adicionales pueden necesitar ser desglosados no solo a nivel total de la cotización, sino también por ubicaciones específicas (ej. por vehículo, por riesgo geográfico) si la lógica de negocio lo exige.
- Trigger: Al mostrar los componentes financieros en la UI.
- Logic: Si el campo `aplicacion` del componente es `POR_UBICACION`, se agrupará o presentará junto con la información de la ubicación relevante.
- Implementation: Backend (API de cotizaciones para proporcionar la estructura) y Frontend (para la presentación).
- Exception: Si no se especifica `aplicacion` o es `TOTAL`, se considera un componente global.

## 10. UX and Navigation Flow
**UX Flow:**
1.  **Pantalla de "Resultados de Cotización"**: El usuario llega a esta pantalla después de haber calculado una cotización.
2.  **Sección de "Desglose de Precios"**: Dentro de esta pantalla, se presenta una sección dedicada (ej. un panel expandible, una tarjeta) que muestra el detalle de impuestos, recargos y descuentos.
**Messages/Modals:**
*   Mensaje de error: "No se pudieron cargar los componentes adicionales del precio. Inténtelo de nuevo más tarde." (en caso de fallo de la API).
*   Mensaje informativo: Si no hay componentes aplicables, la sección podría mostrar "No se aplicaron impuestos, recargos o descuentos adicionales."
**Stepper/Breadcrumbs:** Podría ser parte de un paso "Revisión de Costos" dentro de un flujo de cotización más amplio.

## 11. Architecture and Technical Dependencies
-   **Backend Service:** `cotizaciones-service` (microservicio de cotizaciones).
    -   Proporciona un endpoint REST (ej. `/api/v1/cotizaciones/{id}/componentes`) para consultar los componentes financieros de una cotización específica.
    -   Debe asegurar la consistencia y la disponibilidad de los datos persistidos por las historias HU-016 y HU-019.
    -   Configuración de timeout: 500ms. Retries: 2, con estrategia de backoff exponencial.
-   **Frontend Component:** Componente de UI (ej. `PriceBreakdownComponent` ya sea en React/Angular/Vue) responsable de consumir la API del backend y renderizar el desglose de forma clara.
-   **Base de Datos:** Los componentes financieros deben estar persistidos en la base de datos de cotizaciones, asociados a la cotización principal.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad del desglose por ubicación**: La nota de implementación sugiere considerar el desglose por ubicación. Si esto se incluye en el alcance, la complejidad del modelo de datos, la lógica de negocio y la UI aumentará significativamente, lo que podría afectar la estimación y el tiempo de entrega.
    *   Impacto: Retrasos en la entrega, mayor esfuerzo de desarrollo, UI más compleja.
    *   Probabilidad: Media (si no se define claramente el alcance).
    *   Mitigación: Clarificar con el Product Owner si el desglose por ubicación es un requisito para el MVP o si puede ser una fase posterior. Priorizar el desglose total para la primera iteración.
2.  **Consistencia de datos**: Existe el riesgo de que los componentes calculados por HU-019 no se persistan correctamente o no estén disponibles de forma consistente para la consulta de HU-022.
    *   Impacto: Información incorrecta mostrada al usuario, inconsistencias en los precios.
    *   Probabilidad: Baja (si los procesos previos son robustos).
    *   Mitigación: Establecer pruebas de integración robustas entre el cálculo y la visualización de componentes.

**Technical Debt:** A ser rellenado por el equipo operativo según el alcance y el MVP.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Aunque no impide que el usuario obtenga un precio final, la falta de transparencia en la composición del costo puede generar desconfianza o confusión. Es importante para una buena experiencia de usuario y para la credibilidad del sistema de cotizaciones.
**Feature Impact:** La no implementación o el fallo de esta historia afectaría negativamente la transparencia de la característica de "Cálculo y Presentación de Cotizaciones", pudiendo llevar a una menor adopción o a un aumento en las consultas al soporte.
**Critical Dependencies:** Depende críticamente de que las HUs HU-016 y HU-019 funcionen correctamente y persistan los datos de componentes.
**Recommended Priority:** Sprint actual o siguiente, ya que complementa funcionalidades clave ya existentes y mejora la experiencia del usuario.
