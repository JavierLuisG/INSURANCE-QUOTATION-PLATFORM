## 3. User Story
Como usuario,
quiero que el sistema calcule la prima comercial total de la cotización, a partir de la suma de las primas netas y la aplicación de factores comerciales,
para conocer el costo final que se presentará al cliente.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso de consolidación de las primas calculadas previamente para obtener un valor comercial final. El sistema sumará las primas netas de todas las ubicaciones de la cotización y luego aplicará los factores comerciales definidos (como gastos de expedición e impuestos) para llegar a la prima comercial total. Este valor representa el costo final que se presentará al cliente.
**Flow:** HU-054 (Cálculo de Primas Netas por Ubicación) → HU-056 (Cálculo de Prima Comercial Total) → HU-020 (Visualizar Resumen de Prima Neta y Comercial Total)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Suma correcta de primas netas
**Description:** Valida que la suma de todas las primas netas de las ubicaciones sea el punto de partida correcto para el cálculo de la prima comercial.

```gherkin
Scenario: Suma de primas netas para el cálculo comercial
  Given que las primas netas de todas las ubicaciones de la cotización han sido calculadas y son [PrimaNetaUbicacion1], [PrimaNetaUbicacion2], etc.
  When se ejecuta el cálculo de prima comercial
  Then la base para la aplicación de factores comerciales es la suma de [PrimaNetaUbicacion1] + [PrimaNetaUbicacion2] + ...
```

### AC-002: Aplicación correcta de factores comerciales
**Description:** Valida que los factores comerciales (gastos de expedición, impuestos) se apliquen de manera correcta sobre la suma de las primas netas.

```gherkin
Scenario: Aplicación de factores comerciales sobre la suma de primas netas
  Given que la suma de las primas netas es [SumaPrimasNetas]
  And que existen factores comerciales definidos (ej. Gastos de Expedición: [PorcentajeGE]%, Impuestos: [PorcentajeImpuestos]%)
  When se calcula la prima comercial total
  Then la prima comercial total es igual a [SumaPrimasNetas] * (1 + [PorcentajeGE]/100) * (1 + [PorcentajeImpuestos]/100) (o según el orden y fórmula definidos)
```

### AC-003: Cálculo sin factores comerciales
**Description:** Valida que si no hay factores comerciales definidos o aplicables, la prima comercial total sea igual a la suma de las primas netas.

```gherkin
Scenario: Cálculo de prima comercial sin factores comerciales
  Given que la suma de las primas netas es [SumaPrimasNetas]
  And que no hay factores comerciales definidos o aplicables para la cotización
  When se calcula la prima comercial total
  Then la prima comercial total es igual a [SumaPrimasNetas]
```

**BR-001:** Cálculo de la Suma de Primas Netas
- Description: Antes de aplicar cualquier factor comercial, se debe obtener la suma de todas las primas netas calculadas para cada ubicación de la cotización.
- Trigger: Al iniciar el cálculo de la prima comercial total.
- Logic: `SumaPrimasNetas = SUM(cotizacion.primasNetasUbicaciones)`
- Implementation: Servicio de Cálculo de Primas Comerciales
- Exception: Si no hay primas netas calculadas, la suma es 0.

**BR-002:** Aplicación de Factores Comerciales
- Description: Los factores comerciales definidos deben aplicarse secuencialmente sobre la suma de las primas netas.
- Trigger: Después de obtener la suma de las primas netas.
- Logic:
  ```
  primaComercial = SumaPrimasNetas
  FOR EACH factor IN cotizacion.factoresComerciales:
    IF factor.tipo == "porcentaje":
      primaComercial = primaComercial * (1 + factor.valor)
    ELSE IF factor.tipo == "fijo":
      primaComercial = primaComercial + factor.valor
  ```
- Implementation: Servicio de Aplicación de Factores Comerciales
- Exception: El orden de aplicación de los factores debe ser configurable o predefinido (e.g., gastos de expedición antes de impuestos).

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad de los factores comerciales:**
    *   Descripción: La definición de "factores comerciales" y su "orden de aplicación" puede ser más compleja de lo anticipado (ej. factores condicionales, diferentes tipos de cálculo).
    *   Impacto: Retrasos en la implementación, cálculos incorrectos si no se define bien la lógica.
    *   Probabilidad: Media
    *   Mitigación: Realizar un spike o una reunión de refinamiento técnico para definir exhaustivamente los factores y su lógica de aplicación antes de la implementación.
2.  **Rendimiento:**
    *   Descripción: Si una cotización tiene un número muy elevado de ubicaciones o factores, el cálculo podría ser lento.
    *   Impacto: Mala experiencia de usuario, timeouts.
    *   Probabilidad: Baja (a menos que se anticipen cotizaciones de gran escala)
    *   Mitigación: Optimizar los algoritmos de suma y aplicación, considerar cacheo si aplica.

## 17. Criticality
