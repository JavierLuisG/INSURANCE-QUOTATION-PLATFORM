## 2. Enabled Capability
**CAP-005:** Cálculo de Prima Ajustada por Riesgo Catastrófico
**Business Value:** Asegurar que las primas reflejen con precisión los riesgos catastróficos específicos de la ubicación, garantizando la solvencia de la compañía y la competitividad de las pólizas ofrecidas.
**Requires:** CAP-003 (Cálculo de Prima Neta), CAP-001 (Consumo de Tarifas de Catástrofe (CAT)), CAP-002 (Consumo de Tarifa FHM)
**Enables:** CAP-006 (Cálculo de Prima Final para Emisión de Póliza)
**Orchestrates:** N/A

## 3. User Story
Como sistema,
Quiero aplicar los factores de Catástrofe (CAT) y FHM según la zona y condiciones de la ubicación,
Para que se pueda ajustar la prima neta por el riesgo específico de eventos catastróficos.

## 4. Functional Description
**Description:** El servicio de aplicación de factores en el Motor de Cálculo recibirá una prima neta calculada previamente junto con los detalles de la ubicación del riesgo. Utilizará la información de la ubicación para determinar la zona CAT y las condiciones FHM aplicables, consultando los catálogos de factores CAT y FHM (previamente consumidos por otras historias). Una vez identificados los factores y cuotas correspondientes, estos se aplicarán a la prima neta, generando una prima ajustada que incorpora el riesgo específico de eventos catastróficos.
**Flow:** HU-170 (Calcular Prima Neta por Ubicación) → HU-171 (Aplicar Factores de Catástrofe (CAT) y FHM) → [Siguiente historia: Cálculo de Prima Final / Cotización]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Aplicación del factor CAT
**Description:** Valida que, si una ubicación se encuentra en una zona CAT, el factor correspondiente se aplica correctamente a la prima neta.

```gherkin
Scenario: Aplicar factor CAT a una prima neta en zona de catástrofe
  Given una "prima_neta" de 1000 USD
  And una "ubicacion" identificada en "Zona CAT A"
  And el catálogo de factores CAT indica un "factor_cat" de 1.2 para "Zona CAT A"
  When el sistema calcula la prima ajustada
  Then la "prima_ajustada" resultante debe ser 1200 USD (1000 * 1.2)
  And se debe registrar la aplicación del "factor_cat" de 1.2
```

### AC-002: Aplicación de la cuota FHM
**Description:** Valida que, si una ubicación cumple con las condiciones FHM, la cuota correspondiente se aplica correctamente a la prima.

```gherkin
Scenario: Aplicar cuota FHM a una prima con condiciones específicas
  Given una "prima_neta" de 1000 USD
  And una "ubicacion" que cumple con las "condiciones_fhm_tipo_B"
  And el catálogo FHM indica una "cuota_fhm" de 50 USD para "condiciones_fhm_tipo_B"
  When el sistema calcula la prima ajustada
  Then la "prima_ajustada" resultante debe ser 1050 USD (1000 + 50)
  And se debe registrar la aplicación de la "cuota_fhm" de 50 USD
```

### AC-003: Resultado de cálculo con ajuste combinado CAT y FHM
**Description:** Valida que el resultado final de la prima ajustada refleja correctamente la aplicación combinada de los factores CAT y FHM cuando ambos son aplicables.

```gherkin
Scenario: Aplicar factores CAT y FHM combinados a la prima
  Given una "prima_neta" de 1000 USD
  And una "ubicacion" en "Zona CAT A" y que cumple "condiciones_fhm_tipo_B"
  And el catálogo CAT indica un "factor_cat" de 1.2 para "Zona CAT A"
  And el catálogo FHM indica una "cuota_fhm" de 50 USD para "condiciones_fhm_tipo_B"
  When el sistema calcula la prima ajustada
  Then la "prima_ajustada" resultante debe ser 1250 USD ((1000 * 1.2) + 50)
  And se debe registrar la aplicación de ambos factores
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| prima_neta | decimal | yes | N/A | Mayor que 0 | N/A | 1250.75 |
| ubicacion_id | UUID/string | yes | N/A | Formato UUID o identificador de ubicación válido | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| zona_cat | string | no | N/A | Debe coincidir con un valor en el catálogo CAT | Catálogo de Zonas CAT | Zona CAT A |
| factor_cat | decimal | no | 1.0 | Mayor o igual a 1.0 | Catálogo de Factores CAT | 1.2 |
| condiciones_fhm | array of strings | no | [] | Cada elemento debe coincidir con una condición en el catálogo FHM | Catálogo de Condiciones FHM | ["Tipo Construccion Madera", "Piso Bajo"] |
| cuota_fhm | decimal | no | 0.0 | Mayor o igual a 0.0 | Catálogo de Cuotas FHM | 50.00 |
| prima_ajustada | decimal | yes | N/A | Mayor que 0 | N/A | 1250.75 |


**BR-001: Determinación de Zona CAT**
- Description: Identifica la zona de catástrofe a la que pertenece una ubicación específica.
- Trigger: Al recibir una solicitud de cálculo de prima ajustada con una ubicación.
- Logic: Consultar el servicio/base de datos de geolocalización o catálogos internos para mapear la `ubicacion_id` a una `zona_cat` específica.
- Implementation: Servicio de Aplicación de Factores en el Motor de Cálculo.
- Exception: Si la ubicación no está mapeada a ninguna zona CAT, se considera que no aplica factor CAT (factor por defecto 1.0).

**BR-002: Aplicación del Factor CAT**
- Description: Aplica el factor de catástrofe a la prima neta.
- Trigger: Después de determinar la `zona_cat` y obtener el `factor_cat` correspondiente.
- Logic: `prima_intermedia = prima_neta * factor_cat`.
- Implementation: Servicio de Aplicación de Factores en el Motor de Cálculo.
- Exception: Si el `factor_cat` no se encuentra para la `zona_cat` identificada, se utiliza un factor de 1.0 (sin ajuste).

**BR-003: Determinación de Condiciones FHM**
- Description: Evalúa si una ubicación cumple con las condiciones para la aplicación de la cuota FHM.
- Trigger: Al recibir una solicitud de cálculo de prima ajustada con una ubicación.
- Logic: Consultar los atributos de la `ubicacion` (ej. tipo de construcción, piso, materiales) y compararlos con las reglas definidas en el catálogo FHM para determinar si aplican `condiciones_fhm`.
- Implementation: Servicio de Aplicación de Factores en el Motor de Cálculo.
- Exception: Si la ubicación no cumple ninguna condición FHM, la cuota FHM por defecto es 0.0.

**BR-004: Aplicación de Cuota FHM**
- Description: Aplica la cuota FHM a la prima (después de aplicar CAT, si aplica).
- Trigger: Después de determinar las `condiciones_fhm` y obtener la `cuota_fhm` correspondiente.
- Logic: `prima_ajustada = prima_intermedia + cuota_fhm`.
- Implementation: Servicio de Aplicación de Factores en el Motor de Cálculo.
- Exception: Si la `cuota_fhm` no se encuentra para las `condiciones_fhm` identificadas, se utiliza una cuota de 0.0 (sin ajuste).

**BR-005: Orden de Aplicación de Factores**
- Description: Define el orden en que se aplican los diferentes factores y cuotas.
- Trigger: Durante el cálculo de la prima ajustada.
- Logic: Primero se aplica el `factor_cat` a la `prima_neta`, y luego se añade la `cuota_fhm` al resultado intermedio.
- Implementation: Servicio de Aplicación de Factores en el Motor de Cálculo.

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia y Actualización de Catálogos:** Si los datos de los catálogos CAT y FHM (gestionados por HU-160 y HU-161) no son consistentes, están desactualizados o son inaccesibles, el cálculo de la prima ajustada podría ser incorrecto o fallar.
    -   Impact: Alto. Primas erróneas, pérdidas financieras, incumplimiento regulatorio.
    -   Probability: Media. Depende de la robustez de las historias de consumo.
    -   Mitigation: Implementar validaciones de datos en la ingesta, mecanismos de fallback (ej. usar valores por defecto), monitoreo de la frescura de los datos.
2.  **Complejidad de Lógica de Determinación de Ubicación:** La lógica para mapear una ubicación a una zona CAT o a condiciones FHM específicas podría ser compleja y propensa a errores si no está bien definida y probada.
    -   Impact: Medio. Cálculos incorrectos para ciertas ubicaciones.
    -   Probability: Media.
    -   Mitigation: Clarificar reglas de negocio con expertos, usar datos de prueba representativos, implementar pruebas unitarias y de integración exhaustivas para la lógica de mapeo.
3.  **Rendimiento del Servicio:** El cálculo de la prima ajustada es un paso crítico en el proceso de cotización. Un rendimiento lento podría afectar la experiencia del usuario.
    -   Impact: Medio. Degradación de la experiencia de usuario, posibles timeouts.
    -   Probability: Baja. El cálculo es matemático y los catálogos deberían estar en memoria/caché.
    -   Mitigation: Optimizar consultas a catálogos, asegurar índices adecuados, realizar pruebas de carga.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para la precisión del cálculo de primas, que es el core del negocio de seguros. Un cálculo incorrecto de los factores CAT y FHM puede llevar a primas insuficientes para cubrir riesgos (pérdidas financieras) o primas excesivas que afecten la competitividad.
**Feature Impact:** Sin la implementación de esta historia, la característica "Ajuste de Primas por Riesgo Catastrófico" no podría entregarse, resultando en una valoración incompleta y errónea del riesgo para las pólizas.
**Critical Dependencies:** Depende críticamente de las historias que calculan la prima neta (HU-170) y las que proveen los catálogos de factores (HU-160, HU-161).
**Recommended Priority:** Sprint actual, dada su prioridad "Alta" y su impacto directo en el valor de negocio.
