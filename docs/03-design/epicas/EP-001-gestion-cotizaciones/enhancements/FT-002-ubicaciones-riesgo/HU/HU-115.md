## 1. Identificación General
**Feature:** Gestión de Cotizaciones de Seguros
**Capability:** CAP-005 - Gestión de Ubicaciones de Riesgo
**Actor:** Usuario
**Bounded Context:** Cotizaciones
**Story Points:** 3

## 2. Enabled Capability
**CAP-005:** Gestión de Ubicaciones de Riesgo
**Business Value:** Permite al usuario especificar múltiples lugares de interés para el seguro con todos sus datos de dominio, lo que mejora la precisión y la personalización de la cotización.
**Requires:** CAP-001 - Gestión de Datos Generales de la Cotización (implica que una cotización ya existe y está abierta para edición).
**Enables:** CAP-006 - Validación de Datos Específicos de Ubicación de Riesgo.
**Orchestrates:** Catálogo de Códigos Postales (para `zonaCatastrofica`).

## 3. User Story
Como un usuario,
Quiero añadir una nueva ubicación de riesgo a mi cotización,
Para especificar múltiples lugares de interés para el seguro con todos sus datos del dominio.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario agregar una nueva ubicación de riesgo a una cotización de seguro existente. Al hacer clic en la opción correspondiente, se presenta un formulario donde el usuario puede ingresar los detalles específicos de la ubicación, como dirección, tipo constructivo y giro. El sistema gestiona las validaciones necesarias, incluyendo la aplicación de un límite configurable de ubicaciones y la persistencia de los datos junto con el cálculo automático de su estado de validación.
**Flow:** HU-112 (Editar Datos Generales de la Cotización - cotización abierta) → HU-115 (Agregar Ubicación de Riesgo) → HU-155 (Validar Datos Específicos de Ubicación de Riesgo)


**BR-001:** Límite Configurable de Ubicaciones
- Description: El número máximo de ubicaciones de riesgo que se pueden agregar a una cotización es un valor configurable a nivel de sistema.
- Trigger: Intento de agregar una nueva ubicación.
- Logic: `if (cotizacion.ubicaciones.length >= CONFIG.MAX_UBICACIONES) then REJECT_ADDITION`
- Implementation: Servicio de Cotizaciones (Backend) y Frontend para validación.
- Exception: N/A

**BR-002:** Cálculo Automático de Estado de Validación y Alertas Bloqueantes
- Description: Al guardar una nueva ubicación, el sistema debe calcular automáticamente su `estadoValidacion` y cualquier `alertasBloqueantes` asociada, basándose en reglas de negocio internas y la información de la ubicación.
- Trigger: Guardado de la cotización con una nueva ubicación.
- Logic: Pseudocódigo: `ubicacion.estadoValidacion = calcularEstadoValidacion(ubicacion); ubicacion.alertasBloqueantes = generarAlertas(ubicacion);`
- Implementation: Servicio de Cotizaciones (Backend).
- Exception: N/A

**BR-003:** Obtención Automática de Zona Catastrófica
- Description: El campo `zonaCatastrofica` para una ubicación se debe obtener automáticamente consultando el catálogo de Códigos Postales (CP) al validar el `codigoPostal` ingresado.
- Trigger: Entrada o validación del `codigoPostal`.
- Logic: Pseudocódigo: `ubicacion.zonaCatastrofica = consultarCatalogoCP(ubicacion.codigoPostal).esZonaCatastrofica;`
- Implementation: Servicio de Cotizaciones (Backend), integración con Catálogo CP.
- Exception: Si el código postal no se encuentra en el catálogo, se puede asumir un valor por defecto o generar una alerta.

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario navega a una cotización abierta.
2.  En la vista de detalle de la cotización, el usuario localiza y hace clic en el botón "Agregar Ubicación".
3.  Se abre un formulario modal o una nueva sección en la pantalla para ingresar los datos de la nueva ubicación.
4.  El usuario llena los campos del formulario.
5.  El usuario hace clic en un botón "Guardar Ubicación" o "Aceptar".
6.  Si se excede el límite de ubicaciones, se muestra un mensaje de error.
7.  Si la ubicación se guarda con éxito, el formulario se cierra y la nueva ubicación aparece listada en la cotización.
**Messages/Modals:**
*   Mensaje de éxito: "Ubicación agregada exitosamente a la cotización."
*   Mensaje de error: "No se pudo agregar la ubicación. Por favor, revise los datos."
*   Mensaje de advertencia: "Ha alcanzado el límite de X ubicaciones. No puede añadir más."
*   Modales: Formulario de adición de ubicación, modal de confirmación al guardar (opcional).
**Stepper/Breadcrumbs:** TBD - No especificado, pero la navegación dentro de la cotización podría incluir un 'stepper' si la cotización es un proceso multifase.

## 11. Architecture and Technical Dependencies
- **Backend API (Cotizaciones):** Expondrá un endpoint para `POST /cotizaciones/{id}/ubicaciones` que recibirá los datos de la ubicación y gestionará la lógica de negocio (validación de límite, cálculo de `estadoValidacion`, `alertasBloqueantes`, y consulta al catálogo CP).
- **Frontend:** Componentes UI para el botón "Agregar Ubicación", el formulario de entrada de datos de la ubicación y la visualización de notificaciones.
- **Servicio/API de Catálogo de Códigos Postales:** Un servicio externo o interno al que el backend de Cotizaciones consultará para obtener información del código postal, incluyendo el indicador `zonaCatastrofica`. Se espera que este servicio tenga alta disponibilidad y un tiempo de respuesta bajo.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad del Catálogo CP:**
    *   Descripción: Si el servicio del catálogo CP no está disponible o tiene alta latencia, la funcionalidad de agregar ubicación podría verse afectada, ya que `zonaCatastrofica` es un dato clave.
    *   Impacto: Retraso o imposibilidad de guardar ubicaciones con datos completos, afectando la calidad de la cotización.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breaker y retries, manejar errores de forma elegante en la UI, considerar un caché local para datos de CP o un valor por defecto en caso de falla crítica.
2.  **Complejidad del Cálculo de `estadoValidacion` y `alertasBloqueantes`:**
    *   Descripción: Las reglas para calcular `estadoValidacion` y `alertasBloqueantes` pueden ser complejas y requerir múltiples fuentes de datos.
    *   Impacto: Mayor tiempo de desarrollo, mayor riesgo de bugs, y dificultad para mantener.
    *   Probabilidad: Media.
    *   Mitigación: Definir claramente las reglas de negocio, usar un motor de reglas de negocio (BRMS) si la complejidad es muy alta, escribir pruebas exhaustivas.

**Technical Debt:** TBD (Será completado por el equipo de desarrollo/operaciones según el alcance del MVP).

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para el propósito principal del sistema de cotizaciones, ya que permite la especificación detallada de los bienes a asegurar. Sin la capacidad de agregar ubicaciones de riesgo, la mayoría de las cotizaciones serían incompletas o inexactas.
**Feature Impact:** Sin esta funcionalidad, la característica de "Gestión de Cotizaciones de Seguros" carecería de la capacidad esencial para detallar los activos asegurados, haciendo que las cotizaciones sean genéricas y posiblemente incorrectas.
**Critical Dependencies:** HU-112 (Editar Datos Generales de la Cotización) es crítica, ya que una cotización debe existir para poder agregar ubicaciones.
**Recommended Priority:** Sprint actual o el siguiente, dada su alta prioridad y su impacto directo en el valor de negocio.
