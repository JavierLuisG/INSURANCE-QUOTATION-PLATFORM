## 3. User Story
Como sistema,
Quiero que la lógica de cálculo de primas incorpore las reglas de negocio y factores técnicos definidos (ej., aplicación de recargos, descuentos),
Para que la prima final sea correcta y consistente con las políticas de suscripción.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad del sistema para aplicar la lógica de negocio y los factores técnicos definidos durante el proceso de cálculo de primas. Esto incluye la evaluación de condiciones específicas (como tipo de cliente o canal de venta) para aplicar recargos o descuentos, y la incorporación de factores técnicos según las especificaciones de las tarifas. El objetivo es asegurar que cada prima calculada refleje con precisión las políticas de suscripción y las reglas de negocio establecidas.
**Flow:** [HU-129: Aplicar Reglas de Negocio y Factores Técnicos en Cálculo (pre-procesamiento o definición de reglas)] → [HU-156: Aplicar Lógica de Negocio en Cálculo de Primas] → [HU-141: Presentar Cotización Final / Emitir Póliza]

## 6. Acceptance Criteria
### AC-001: Aplicación de Recargos o Descuentos
**Description:** Valida que el sistema aplica correctamente los recargos o descuentos a la prima cuando se cumplen las condiciones de negocio definidas.

```gherkin
Scenario: Aplicación de descuento por tipo de cliente
  Given un cliente de tipo "VIP" y un canal de venta "Web"
  And la prima base es de 1000
  When el sistema calcula la prima
  Then la prima final incluye el descuento del 10% para clientes "VIP", resultando en 900
```

### AC-002: Incorporación de Factores Técnicos
**Description:** Valida que los factores técnicos se utilizan en el cálculo de la prima según las especificaciones de las tarifas y las reglas de negocio.

```gherkin
Scenario: Aplicación de factor técnico por edad del asegurado
  Given una prima base de 500
  And un factor técnico de edad que indica un recargo del 5% para asegurados mayores de 60 años
  When el sistema calcula la prima para un asegurado de 65 años
  Then la prima final refleja el recargo del 5% por edad, resultando en 525
```

### AC-003: Reflejo de Reglas de Negocio en la Prima Final
**Description:** Valida que el resultado final de la prima refleja el impacto de todas las reglas de negocio ejecutadas durante el cálculo.

```gherkin
Scenario: El resultado de la prima final refleja múltiples reglas de negocio
  Given una prima base de 2000
  And una regla de negocio que aplica un recargo del 5% por "riesgo alto"
  And una regla de negocio que aplica un descuento del 2% por "pago anual"
  When el sistema calcula la prima
  Then la prima final es 2000 * (1 + 0.05) * (1 - 0.02) = 2058
```

**BR-001:** Aplicación de Recargos por Tipo de Cliente
- Description: Los clientes con ciertas características (ej. historial de siniestros) pueden incurrir en recargos adicionales sobre la prima base.
- Trigger: Al calcular la prima para un cliente.
- Logic: `IF cliente.historial_siniestros > X THEN prima_final = prima_final * (1 + recargo_riesgo)`
- Implementation: Módulo de Reglas de Negocio
- Exception: N/A

**BR-002:** Aplicación de Descuentos por Canal de Venta
- Description: Se pueden aplicar descuentos específicos basados en el canal a través del cual se realiza la venta (ej. canal digital).
- Trigger: Al calcular la prima para un canal de venta específico.
- Logic: `IF canal_venta == "Web" THEN prima_final = prima_final * (1 - descuento_web)`
- Implementation: Módulo de Reglas de Negocio
- Exception: N/A

**BR-003:** Cálculo de Factores Técnicos de Tarificación
- Description: El sistema debe incorporar factores técnicos definidos en las tablas de tarificación (ej. edad, tipo de vehículo, zona geográfica) para ajustar la prima.
- Trigger: Durante el cálculo inicial de la prima.
- Logic: `prima_base_ajustada = prima_base * factor_edad * factor_vehiculo * factor_zona`
- Implementation: Motor Central de Cálculo de Primas, Módulo de Reglas de Negocio
- Exception: N/A

```gherkin
Scenario: Conflicto entre reglas de recargo y descuento
  Given una configuración de reglas donde un recargo del 10% se aplica a "clientes con riesgo alto"
  And un descuento del 15% se aplica a "clientes VIP"
  And un cliente es clasificado como "VIP" y "riesgo alto"
  When el sistema calcula la prima
  Then el sistema aplica ambas reglas siguiendo la precedencia definida (ej. descuentos después de recargos)
  And la prima final refleja el resultado de la aplicación secuencial de ambas reglas
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad y Mantenimiento de las Reglas:**
    -   Description: A medida que el número y la complejidad de las reglas de negocio aumenten, la gestión, el mantenimiento y la depuración del Módulo de Reglas de Negocio pueden volverse desafiantes.
    -   Impact: Errores en el cálculo de primas, lentitud en la aplicación de reglas, dificultad para incorporar nuevos productos.
    -   Probability: Media
    -   Mitigation: Implementar un BRMS robusto, definir una estrategia clara de gestión de reglas (versionado, testing), documentar exhaustivamente cada regla.
2.  **Rendimiento del Motor de Cálculo:**
    -   Description: La aplicación de múltiples reglas y factores técnicos complejos podría impactar negativamente el rendimiento del Motor Central de Cálculo de Primas, especialmente bajo alta demanda.
    -   Impact: Latencia elevada, timeouts, mala experiencia de usuario en cotizaciones.
    -   Probability: Media
    -   Mitigation: Optimización del motor de reglas, caching de reglas frecuentes, pruebas de carga exhaustivas, escalabilidad horizontal del servicio.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** Esta historia es fundamental para el core del negocio de seguros. Un cálculo de primas incorrecto afecta directamente la rentabilidad de la compañía, la confianza del cliente, el cumplimiento normativo y puede generar problemas legales y financieros significativos.
**Feature Impact:** Sin esta historia, la funcionalidad de "Cálculo de Primas" no puede generar primas finales válidas y consistentes, invalidando todo el proceso de suscripción y emisión de pólizas.
**Critical Dependencies:** Todas las historias que dependen de un cálculo de prima correcto (ej. emisión de póliza, facturación, cotización final).
**Recommended Priority:** Sprint actual / Próximo sprint (dada su prioridad "Alta" y "Estimación: 4 puntos").

## 18. Identified Assumptions
1.  **Reglas de Negocio Definidas y Validables:**
    -   Description: Se asume que todas las reglas de negocio y factores técnicos que deben aplicarse en el cálculo de primas están claramente definidos, documentados y validados por el área de negocio.
    -   Impact if false: El sistema podría aplicar reglas incorrectas o incompletas, llevando a primas erróneas.
    -   - Requires validation from: Área de Suscripción, Producto
2.  **Disponibilidad y Consistencia de Datos de Entrada:**
    -   Description: Se asume que los datos de entrada necesarios para el cálculo (prima base, tipo de cliente, canal de venta, factores técnicos) estarán disponibles y serán consistentes en el momento de la invocación del cálculo.
    -   Impact if false: El cálculo podría fallar o producir resultados incorrectos debido a la falta o invalidez de datos.
    -   Requires validation from: Equipo de Integración, Servicios de Datos, Equipo de Producto
3.  **Rendimiento del Módulo de Reglas:**
    -   Description: Se asume que el Módulo de Reglas de Negocio (BRMS) o la implementación de la lógica de negocio tendrá un rendimiento aceptable para procesar las reglas sin latencia significativa.
    -   Impact if false: El tiempo de respuesta para el cálculo de primas podría ser inaceptablemente alto.
    -   Requires validation from: Equipo de Arquitectura, Equipo de Desarrollo
