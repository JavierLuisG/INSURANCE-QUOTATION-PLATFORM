## 2. Enabled Capability
**CAP-166:** Validación de Códigos Postales por Zonas de Riesgo
**Business Value:** Asegurar la integridad de los códigos postales de las ubicaciones, reducir errores en la clasificación de zonas de riesgo y garantizar la precisión de los datos para procesos posteriores (ej. cálculo de primas, logística).
**Requires:** CAP-119 (Validación de Formato de Código Postal), CAP-163 (Disponibilidad del Catálogo de Códigos Postales y Zonas)
**Enables:** TBD (Ej: Asignación automática de niveles de riesgo, generación de informes geográficos, cálculo de tarifas basadas en zona)
**Orchestrates:** Servicio de Consulta de Catálogos

## 3. User Story
Como sistema,
Quiero validar los códigos postales de las ubicaciones contra el `catalogo_cp_zonas` provisto,
Para asegurar que solo se usan códigos postales válidos y asociados a zonas de riesgo.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad por la cual el sistema debe verificar la existencia y validez de los códigos postales de las ubicaciones. La validación se realiza comparando el código postal de una ubicación con los registros presentes en el `catalogo_cp_zonas`. El objetivo es garantizar que cada código postal utilizado en el sistema no solo sea un código postal real, sino que también esté reconocido y asociado a una zona de riesgo según el catálogo oficial. Si un código postal no se encuentra en el catálogo, se considerará inválido para los propósitos de esta funcionalidad.
**Flow:** HU-163 (Consumir Catálogo de Códigos Postales y Zonas) → HU-119 (Validar Formato de Código Postal de Ubicación) → **HU-166 (Validar Códigos Postales Contra Catálogo)** → [Proceso de negocio que utiliza la ubicación validada, ej. asignación de riesgo].

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Verificación de existencia del código postal
**Description:** Valida que un código postal de una ubicación exista dentro del `catalogo_cp_zonas`.

```gherkin
Scenario: Código postal existe en el catálogo
  Given una ubicación con el código postal "28001"
  And el "28001" existe en el `catalogo_cp_zonas`
  When se valida el código postal de la ubicación
  Then la validación se realiza sin errores
```

### AC-002: Manejo de código postal no encontrado
**Description:** Asegura que el sistema genera un error de validación si el código postal no se encuentra en el catálogo.

```gherkin
Scenario: Código postal no existe en el catálogo
  Given una ubicación con el código postal "99999"
  And el "99999" NO existe en el `catalogo_cp_zonas`
  When se valida el código postal de la ubicación
  Then el sistema genera un error de validación
```

### AC-003: Validación exitosa de código postal válido
**Description:** Confirma que no se generan errores cuando un código postal es válido y está presente en el catálogo.

```gherkin
Scenario: Código postal válido y existente
  Given una ubicación con el código postal "08001"
  And el "08001" existe en el `catalogo_cp_zonas`
  When se valida el código postal de la ubicación
  Then no se genera ningún error de validación
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Rendimiento del Catálogo**:
    -   Description: Si el `catalogo_cp_zonas` es muy extenso y la consulta no está optimizada (ej. sin índices, carga en caliente), la latencia de la validación podría ser inaceptable.
    -   Impact: Demoras en la respuesta del sistema, posible impacto negativo en la experiencia del usuario o en procesos batch.
    -   Probability: Media
    -   Mitigation: Implementar índices adecuados en la base de datos del catálogo, considerar estrategias de caché (Redis, Memcached) para los códigos postales más consultados, o cargar el catálogo en memoria si su tamaño lo permite y la frecuencia de actualización es baja.
2.  **Desincronización del Catálogo**:
    -   Description: El `catalogo_cp_zonas` podría no estar actualizado o contener datos inconsistentes, llevando a validaciones incorrectas.
    -   Impact: Ubicaciones válidas rechazadas o ubicaciones inválidas aceptadas, afectando la integridad de los datos de riesgo.
    -   Probability: Baja (asumiendo que HU-163 maneja la actualización)
    -   Mitigation: Establecer un proceso claro de actualización y sincronización del catálogo (responsabilidad de HU-163), mecanismos de monitoreo de la frescura de los datos del catálogo.

**Technical Debt:** [To be filled by operating team per scope and MVP]
- Podría surgir deuda técnica si la integración con el catálogo no utiliza un servicio genérico y se acopla directamente a una implementación específica del catálogo.

## 17. Criticality
**Criticality Level:** Alta
**Justification:** La validación de códigos postales es fundamental para asegurar la integridad y la calidad de los datos de ubicación, que a su vez son críticos para la correcta evaluación de riesgos y para el funcionamiento de múltiples procesos de negocio. Un fallo en esta validación podría llevar a decisiones de negocio erróneas o a incumplimiento normativo.
**Feature Impact:** Sin esta validación, la funcionalidad de "Gestión de Ubicaciones y Zonas de Riesgo" sería incompleta y propensa a errores, comprometiendo la fiabilidad de todo el sistema que dependa de ubicaciones geográficamente correctas y clasificadas por riesgo.
**Critical Dependencies:** HU-119 y HU-163 son críticas, ya que sin ellas, esta historia no puede funcionar correctamente.
**Recommended Priority:** Sprint actual (considerando su alta prioridad y baja estimación).

## 18. Identified Assumptions
1.  **Disponibilidad y Actualización del `catalogo_cp_zonas`**
    -   Description: Se asume que el `catalogo_cp_zonas` estará siempre disponible para consulta y que su contenido será la versión más reciente y precisa de los códigos postales y sus zonas de riesgo.
    -   Impact if false: La validación fallaría por indisponibilidad o produciría resultados incorrectos debido a datos obsoletos/erróneos.
    -   Requires validation from: Equipo de Datos, Dueño del Catálogo, Equipo responsable de HU-163.
2.  **Consistencia de Formato del Código Postal**
    -   Description: Se asume que el formato del código postal de entrada (de la ubicación) y el formato de los códigos postales en el `catalogo_cp_zonas` serán idénticos y compatibles.
    -   Impact if false: La validación podría fallar incluso para códigos postales lógicamente correctos debido a diferencias de formato (ej. con/sin guiones, espacios).
    -   Requires validation from: Equipo de Datos, Arquitectos.
