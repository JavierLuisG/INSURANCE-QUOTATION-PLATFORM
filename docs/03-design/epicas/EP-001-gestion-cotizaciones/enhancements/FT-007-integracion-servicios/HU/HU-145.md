## 2. Enabled Capability
**CAP-001:** Gestión de Datos Geográficos para Evaluación de Riesgo
**Business Value:** Asegurar la correcta evaluación del riesgo por ubicación, lo que impacta directamente en la precisión del cálculo de primas y la toma de decisiones.
**Requires:** HU-092 (Configurar Mock Server Base, FT-020)
**Enables:** Lógica de Cálculo de Primas (ej. US-YYY)
**Orchestrates:** Plataforma-core-ohs (o su simulación)

## 3. User Story
Como sistema,
Quiero consultar y validar información de códigos postales y sus zonas de riesgo desde `Plataforma-core-ohs` (o su simulación),
Para asegurar la correcta evaluación del riesgo por ubicación.

## 4. Functional Description
**Description:** El sistema debe integrar la capacidad de consultar un servicio externo (`Plataforma-core-ohs`) para obtener información detallada sobre códigos postales. Esta información incluye datos de zona como la Clasificación de Áreas de Riesgo (CAT) y el nivel técnico asociado, los cuales son fundamentales para la lógica interna de cálculo de primas y la evaluación de riesgos basada en la geolocalización. La funcionalidad debe manejar tanto las respuestas exitosas, donde se obtienen los datos esperados, como los escenarios de error, como cuando un código postal es inválido o no se encuentra en el catálogo externo. Se debe considerar la optimización para manejar un alto volumen de consultas.
**Flow:** [Solicitud de Cálculo de Prima (ej. US-XXX)] → [HU-145: Consumir Datos de Códigos Postales y Zonas de Riesgo] → [Lógica de Cálculo de Primas (ej. US-YYY)]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Consulta Exitosa de Código Postal
**Description:** Valida que el sistema puede consultar un código postal válido y obtener la información de zona asociada desde `Plataforma-core-ohs`.

```gherkin
Scenario: Obtener información de zona para un código postal válido
  Given el sistema requiere validar un código postal válido "28001"
  When realiza la consulta a Plataforma-core-ohs
  Then obtiene la información de zona (CAT, nivel técnico) asociada al CP "28001"
  And los datos de zona incluyen un 'CAT' y un 'nivel_tecnico' válidos
```

### AC-002: Manejo de Código Postal Inválido o No Encontrado
**Description:** Valida que el sistema gestiona adecuadamente los códigos postales que son inválidos o no se encuentran en el catálogo de `Plataforma-core-ohs`.

```gherkin
Scenario: El código postal es inválido o no encontrado
  Given el sistema requiere validar un código postal "99999" que es inválido o no encontrado en Plataforma-core-ohs
  When se realiza la consulta a Plataforma-core-ohs
  Then el servicio devuelve una indicación de error clara
  And el sistema registra el evento como un WARN o ERROR
```

### AC-003: Disponibilidad de Datos para Cálculo de Primas
**Description:** Asegura que, una vez obtenidos, los datos de zona de riesgo están correctamente procesados y disponibles para ser utilizados por la lógica de cálculo de primas.

```gherkin
Scenario: Los datos de zona se procesan y están disponibles para la lógica de cálculo
  Given que los datos de zona (CAT 'A', nivel técnico '3') para un CP válido se han recibido de Plataforma-core-ohs
  When se procesan internamente por el sistema
  Then los datos de zona están accesibles para la lógica de cálculo de primas
  And la lógica de cálculo de primas puede utilizar 'CAT' y 'nivel_tecnico' en sus operaciones
```

- Logic: `IF NOT regex_match(codigo_postal, '^\d{5}$') THEN return ERROR_INVALID_CP_FORMAT`
- Implementation: Servicio de Validación de CP.
- Exception: N/A

- Trigger: Después de recibir una respuesta exitosa de `Plataforma-core-ohs`.
- Logic: `IF response.status == 'SUCCESS' THEN map_to_internal_format(response.zona, response.nivel_tecnico) AND store_for_access_by_pricing_logic`

## 11. Architecture and Technical Dependencies
- **`Plataforma-core-ohs` (API REST):** Servicio externo para la consulta de códigos postales y sus zonas de riesgo.
    -   **Timeout:** 5 segundos.
    -   **Retries:** 2 reintentos con estrategia de backoff exponencial.
- **Clientes API REST:** Implementación de un cliente HTTP robusto (ej. Feign, WebClient) para interactuar con `Plataforma-core-ohs`.
- **Servicio de Validación de CP:** Componente interno responsable de orquestar la llamada al cliente API, validar el CP, procesar la respuesta y manejar errores.
- **Circuit Breaker:** Implementar un patrón de Circuit Breaker (ej. Resilience4j, Hystrix) para aislar fallos de `Plataforma-core-ohs` y mejorar la resiliencia del sistema.
- **Estrategia de Caching (Opcional/Futuro):** Considerando la nota de "optimizar la consulta de CP para grandes volúmenes", podría considerarse una capa de caché local para códigos postales frecuentemente consultados.

## 13. Edge Cases and Exceptions
### Case 1: `Plataforma-core-ohs` no disponible o con alta latencia
```gherkin
Scenario: El servicio externo Plataforma-core-ohs está caído o responde muy lento
  Given el sistema intenta consultar un código postal "28001"
  When Plataforma-core-ohs no responde o supera el tiempo de espera configurado (5 segundos)
  Then el sistema activa el Circuit Breaker y aplica la política de fallback (ej. devuelve un error controlado, usa un valor por defecto seguro o reintenta según configuración)

```

```gherkin
Scenario: Plataforma-core-ohs devuelve una respuesta exitosa pero con datos de zona incompletos o incorrectos

```

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Rendimiento de `Plataforma-core-ohs`:**
    -   Description: `Plataforma-core-ohs` es un servicio externo. Su disponibilidad, latencia y capacidad de respuesta están fuera de nuestro control directo y pueden impactar la funcionalidad crítica de cálculo de primas.
    -   Impact: Retrasos en la evaluación del riesgo, cálculos de primas incorrectos o imposibilidad de cotizar.
    -   Probability: Media.
    -   Mitigation: Implementación de Circuit Breaker, políticas de reintento con backoff, monitoreo proactivo de la integración, y consideración de una estrategia de caching para datos de CP si el volumen y la frecuencia de cambio lo justifican.
2.  **Volumen de Consultas y Límite de Tasa (Rate Limiting):**
    -   Description: La nota "Optimizar la consulta de CP para grandes volúmenes" sugiere que el sistema podría generar un alto número de solicitudes, lo que podría exceder los límites de tasa impuestos por `Plataforma-core-ohs` o causar una degradación del rendimiento.
    -   Impact: Errores de "Too Many Requests", bloqueo temporal de la integración, o alto consumo de recursos.
    -   Probability: Alta si no se gestiona.
    -   Mitigation: Negociación de límites de tasa con el equipo de `Plataforma-core-ohs`, implementación de caching de resultados para códigos postales comunes, procesamiento por lotes si es aplicable, o uso de un sistema de colas.
**Technical Debt:** N/A (Se llenará por el equipo operativo según el alcance y el MVP)
