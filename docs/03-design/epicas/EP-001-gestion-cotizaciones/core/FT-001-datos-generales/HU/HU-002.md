## 3. User Story
As a usuario,
I want buscar y cargar una cotización existente por su folio,
So that puedo continuar con su edición o revisión.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario localizar y cargar una cotización previamente creada utilizando su número de folio único. Una vez cargada, el sistema presentará los datos generales de la cotización, permitiendo al usuario modificar y guardar estos datos. También incluye el manejo de casos donde el folio no existe y la validación de permisos de usuario.
**Flow:** [HU-001: Crear Cotización] → [HU-002: Cargar y editar cotización existente por folio] → [HU-003: Guardar Cotización Editada/Revisar Cotización]

## 16. Technical Notes and Risks
**Risks:**
1.  **Rendimiento de búsqueda:**
    -   Description: La búsqueda de cotizaciones por folio podría ser ineficiente si el volumen de datos es muy grande y la base de datos no está correctamente indexada.
    -   Impact: Demoras en la carga de cotizaciones, afectando la experiencia de usuario y la productividad.
    -   Probability: Media.
    -   Mitigation: Asegurar la existencia de índices eficientes en el campo `folioCotizacion` en la base de datos.
2.  **Problemas de concurrencia:**
    -   Description: Múltiples usuarios podrían intentar editar la misma cotización simultáneamente, lo que podría llevar a la pérdida de datos o inconsistencias.
    -   Impact: Datos desactualizados o corruptos, frustración del usuario.
    -   Probability: Baja a Media (dependiendo del uso).
    -   Mitigation: Implementar un mecanismo de bloqueo optimista (ej. campo de versión en la entidad de cotización) o notificaciones de que la cotización ha sido modificada por otro usuario.
3.  **Fallo de autorización:**
    -   Description: Un error en la lógica de autorización podría permitir que usuarios no autorizados editen cotizaciones.
    -   Impact: Brecha de seguridad, compromiso de la integridad de los datos de negocio.
    -   Probability: Baja (con buenas prácticas de seguridad y pruebas), Alta (si se descuida).
    -   Mitigation: Revisión exhaustiva del código de seguridad, pruebas de penetración, validación estricta de RBAC.

**Technical Debt:** La implementación de la "búsqueda eficiente y tolerante a errores de entrada parcial" se menciona como opcional. Si no se aborda en esta iteración, se registrará como deuda técnica para una futura mejora de UX.
