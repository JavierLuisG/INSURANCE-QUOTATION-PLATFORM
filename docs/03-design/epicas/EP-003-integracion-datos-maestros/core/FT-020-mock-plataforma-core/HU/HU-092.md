## 3. User Story
Como desarrollador,
Quiero un mock server operativo y accesible para el cotizador,
Para que pueda simular las respuestas del servicio `Plataforma-core-ohs` y desarrollar de forma independiente.

## 4. Functional Description
**Description:** Esta historia de usuario se centra en la configuración y despliegue de un mock server base que permita a los desarrolladores simular las respuestas del servicio `Plataforma-core-ohs`. El objetivo es proporcionar un entorno de desarrollo aislado para el módulo Cotizador, facilitando el desarrollo y las pruebas sin depender de la disponibilidad o estado real del servicio externo.
**Flow:** [Inicio del desarrollo del Cotizador] → [Configurar Mock Server Base (esta historia)] → [Desarrollo independiente de funcionalidades del Cotizador]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Verificación de actividad del Mock Server
**Description:** Valida que el mock server se inicia correctamente y responde a peticiones a su URL base, indicando su estado activo.

```gherkin
Scenario: El mock server está activo y responde
  Given que he iniciado el mock server
  When accedo a la URL base del mock server (ej. http://localhost:8080)
  Then recibo una respuesta HTTP 200 OK con un mensaje indicando que el servidor está activo (ej. "Mock Server - Activo")
```

### AC-002: Conexión exitosa del Cotizador
**Description:** Asegura que el módulo Cotizador puede establecer una conexión y comunicarse correctamente con el mock server.

```gherkin
Scenario: El cotizador se conecta al mock server
  Given que el mock server está configurado y activo
  And que el Cotizador está configurado para apuntar al mock server
  When el Cotizador intenta realizar una petición al servicio `Plataforma-core-ohs`
  Then la conexión se establece correctamente y el Cotizador recibe una respuesta simulada del mock server
```

### AC-003: Flexibilidad en la configuración del Mock Server
**Description:** Permite la fácil modificación de parámetros de configuración como puertos y URLs para el mock server.

```gherkin
Scenario: La configuración del mock server es modificable
  Given que el mock server está configurado con un puerto y una URL base
  When modifico el archivo de configuración o las variables de entorno para cambiar el puerto o la URL base
  Then el mock server se inicia con la nueva configuración aplicada y es accesible en el nuevo puerto/URL
```

**BR-001:** Configuración de puerto y URL
- Description: El mock server debe permitir la configuración de su puerto de escucha y su URL base a través de parámetros externos (ej. variables de entorno, archivo de configuración).
- Trigger: Al iniciar el mock server.
- Logic: Cargar `mock_server_port` y `mock_server_base_url` de la configuración.
- Implementation: Componente de configuración del framework de mock server.
- Exception: Si el puerto está en uso, el servidor debe notificar y no iniciar.

## 16. Technical Notes and Risks
**Risks:**
1.  **Mantenimiento de Mocks**:
    *   Descripción: Los mocks pueden desactualizarse si el contrato de `Plataforma-core-ohs` cambia con frecuencia.
    *   Impacto: Errores en el desarrollo del Cotizador debido a expectativas incorrectas de la API.
    *   Probabilidad: Media.
    *   Mitigación: Establecer un proceso para la actualización de mocks en sincronía con los cambios de `Plataforma-core-ohs` (ej. CI/CD que valide mocks).
2.  **Complejidad del Framework**:
    *   Descripción: Elegir un framework de mock server demasiado complejo puede dificultar su uso y mantenimiento.
    *   Impacto: Mayor curva de aprendizaje, desarrollo más lento.
    *   Probabilidad: Baja a media.
    *   Mitigación: Seleccionar un framework ligero y bien documentado (ej. WireMock es robusto y popular).

## 18. Identified Assumptions
1.  **Contrato de `Plataforma-core-ohs` Estable**:
    *   Description: Se asume que el contrato (endpoints, formatos de request/response) del servicio `Plataforma-core-ohs` es lo suficientemente estable como para crear mocks representativos.
    *   Impact if false: Los mocks se volverían obsoletos rápidamente, requiriendo actualizaciones constantes y potencialmente introduciendo errores en el Cotizador.
    *   Requires validation from: Equipo de `Plataforma-core-ohs` / Arquitectura.
2.  **Uso Exclusivo en Desarrollo/CI**:
    *   Description: Se asume que este mock server será utilizado únicamente en entornos de desarrollo local y CI/CD, y no en entornos de staging o producción.
    *   Impact if false: Riesgos de seguridad, rendimiento y confusión si se despliega en entornos equivocados.
    *   Requires validation from: Arquitectura / DevOps.
