## 3. User Story
Como un administrador de parámetros,
Quiero que el sistema ingeste o simule la consulta de tarifas de catástrofe (CAT) desde el servicio `Plataforma-core-ohs`,
Para que el motor de cálculo aplique los factores de catástrofe correctos según la zona.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema obtiene y almacena los factores de catástrofe (CAT) desde el servicio externo `Plataforma-core-ohs`. El sistema debe ser capaz de consumir estos factores, considerando sus fechas de vigencia, y hacerlos disponibles para el motor de cálculo. Se contempla la posibilidad de una simulación de la consulta en caso de que el servicio real no esté disponible.
**Flow:** [Inicio de la configuración de parámetros] → [HU-045: Ingestión de Tarifas CAT] → [HU-XXX: Aplicación de factores CAT por el motor de cálculo]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Obtención exitosa de factores CAT
**Description:** Valida que el sistema puede obtener los factores de catástrofe del servicio `Plataforma-core-ohs` o su simulación cuando se solicita la carga.

```gherkin
Scenario: Obtención de factores CAT desde Plataforma-core-ohs
  Given el servicio `Plataforma-core-ohs` está disponible y contiene factores CAT válidos
  When se solicita la carga de tarifas CAT
  Then el sistema obtiene los factores correctamente
  And los factores son almacenados en el repositorio de parámetros de cálculo
```

### AC-002: Consulta de tarifas CAT por el motor de cálculo
**Description:** Valida que el motor de cálculo puede acceder y utilizar las tarifas CAT cargadas para una zona específica.

```gherkin
Scenario: Consulta de tarifas CAT por el motor de cálculo
  Given las tarifas CAT han sido cargadas y están disponibles en el sistema
  And el motor de cálculo solicita las tarifas para una zona específica (ej. 'Zona A')
  When el motor de cálculo consulta las tarifas CAT
  Then recibe los valores actualizados y correctos para la 'Zona A'
```

### AC-003: Consideración de fechas de vigencia
**Description:** Valida que el sistema considera las fechas de vigencia de los factores CAT al cargarlos y al ponerlos a disposición.

```gherkin
Scenario: Aplicación de fechas de vigencia de factores CAT
  Given el servicio `Plataforma-core-ohs` proporciona factores CAT con fechas de vigencia (ej. '01/01/2026 - 31/12/2026')
  When el sistema carga estos factores
  Then los factores se marcan como vigentes solo dentro de su periodo especificado
  And el motor de cálculo solo aplica los factores que están vigentes en la fecha de la consulta
```

### AC-004: Mapeo consistente de zonas CAT
**Description:** Valida que el mapeo de zonas CAT es consistente con el catálogo interno de códigos postales y zonas.

```gherkin
Scenario: Consistencia en el mapeo de zonas CAT
  Given el sistema ha cargado factores CAT para diversas zonas
  And existe un `catalogo_cp_zonas` en el sistema
  When el sistema procesa los factores CAT
  Then asegura que el mapeo de zonas CAT es consistente con el `catalogo_cp_zonas`
  And no se generan errores por zonas no reconocidas o mal mapeadas
```

| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| id_tarifa_cat | UUID | yes | N/A | Formato UUID | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| zona_cat | String | yes | N/A | Debe coincidir con `catalogo_cp_zonas` | catalogo_cp_zonas | ZONA_NORTE_MEX |
| factor_cat | Decimal | yes | 1.0 | Valor numérico positivo | N/A | 1.25 |

| fecha_vigencia_fin | Date | yes | 9999-12-31 | Formato YYYY-MM-DD, debe ser posterior o igual a `fecha_vigencia_inicio` | N/A | 2026-12-31 |
| origen | String | yes | Plataforma-core-ohs | Valores permitidos: 'Plataforma-core-ohs', 'Simulación' | N/A | Plataforma-core-ohs |
| fecha_carga | DateTime | yes | Fecha y hora actual | Formato ISO 8601 | N/A | 2026-04-21T10:30:00Z |


**BR-001:** Consistencia de Mapeo de Zonas CAT
- Description: Los códigos de zona CAT recibidos del servicio `Plataforma-core-ohs` deben ser válidos y corresponder a las zonas definidas en el `catalogo_cp_zonas` interno del sistema.
- Trigger: Al recibir datos de tarifas CAT del servicio externo.
- Logic:
  ```pseudocode
  PARA CADA tarifa_cat EN datos_recibidos:
    SI tarifa_cat.zona_cat NO ESTÁ EN catalogo_cp_zonas:
      REGISTRAR ERROR: "Zona CAT no reconocida"
      DESCARTAR tarifa_cat O MARCAR COMO INVÁLIDA
    FIN SI
  FIN PARA
  ```
- Implementation: Adaptador de integración `Plataforma-core-ohs`, Repositorio de parámetros de cálculo.
- Exception: Si una zona no se mapea, la tarifa asociada no se carga y se registra un error.

**BR-002:** Aplicación de Fechas de Vigencia
- Description: Las tarifas CAT solo deben ser consideradas válidas y aplicables por el motor de cálculo dentro de su rango de fechas de vigencia (`fecha_vigencia_inicio` y `fecha_vigencia_fin`).
- Trigger: Al cargar las tarifas CAT y al consultarlas por el motor de cálculo.
- Logic:
  ```pseudocode
  AL CARGAR:
    SI fecha_vigencia_inicio > fecha_vigencia_fin:
      REGISTRAR ADVERTENCIA: "Rango de vigencia inválido"
      AJUSTAR A VIGENCIA INDEFINIDA O DESCARTAR
  AL CONSULTAR (por motor de cálculo):
    FECHA_ACTUAL = HOY
    SI FECHA_ACTUAL >= tarifa_cat.fecha_vigencia_inicio AND FECHA_ACTUAL <= tarifa_cat.fecha_vigencia_fin:
      RETORNAR tarifa_cat
    SINO:
      IGNORAR tarifa_cat O RETORNAR VALOR POR DEFECTO
    FIN SI
  ```
- Implementation: Repositorio de parámetros de cálculo.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Latencia de `Plataforma-core-ohs`:**
    - Descripción: El sistema depende de la disponibilidad y el rendimiento del servicio externo.
    - Impacto: Retrasos en la actualización de tarifas, cálculos incorrectos o desactualizados.
    - Probabilidad: Media.
    - Mitigación: Implementar Circuit Breaker, reintentos con backoff, monitoreo constante, plan de contingencia con simulación o valores por defecto.
2.  **Inconsistencia de Mapeo de Zonas:**
    - Descripción: Desalineación entre los códigos de zona de `Plataforma-core-ohs` y `catalogo_cp_zonas`.
    - Impacto: Tarifas CAT no aplicadas correctamente a las zonas, errores en los cálculos.
    - Probabilidad: Media.
    - Mitigación: Validaciones estrictas en la ingestión (BR-001), proceso de conciliación manual o automático, comunicación con el equipo de `Plataforma-core-ohs`.
3.  **Gestión de Fechas de Vigencia:**
    - Descripción: Errores en la interpretación o aplicación de las fechas de vigencia de las tarifas.
    - Impacto: Aplicación de factores CAT incorrectos o desactualizados.
    - Probabilidad: Baja.
    - Mitigación: Pruebas unitarias y de integración exhaustivas sobre la lógica de vigencia (BR-002), validación de rangos.

## 17. Criticality
**Criticality Level:** High
**Justification:** Esta historia es fundamental para la precisión de los cálculos del motor, ya que asegura que los factores de catástrofe, que son variables críticas, se apliquen correctamente. Un cálculo erróneo puede tener un impacto significativo en el negocio (ej. tarificación incorrecta de seguros).
**Feature Impact:** La no implementación o el fallo de esta historia resultaría en que el motor de cálculo no podría aplicar los factores de catástrofe correctos, llevando a resultados inexactos o inválidos en las tarifas, afectando directamente la funcionalidad principal del motor de cálculo.
**Critical Dependencies:** El "Motor de Cálculo" es críticamente dependiente de esta historia para obtener datos precisos.
**Recommended Priority:** Sprint actual o próximo.
