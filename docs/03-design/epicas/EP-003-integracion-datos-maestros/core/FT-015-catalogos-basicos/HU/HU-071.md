## 1. Identificación General
**Feature:** Gestión de Cotizaciones
**Capability:** CAP-005 - Gestión de Catálogos Externos
**Actor:** Sistema (cotizador)
**Bounded Context:** Módulo de Cotización
**Story Points:** 2

## 2. Enabled Capability
**CAP-005:** Gestión de Catálogos Externos
**Business Value:** Asegura que el formulario de cotización siempre presente información actualizada y precisa, lo que mejora la experiencia del usuario y la validez de las cotizaciones.
**Requires:** CAP-001 (Configuración de Conectividad con Servicios Externos)
**Enables:** CAP-006 (Selección de Giros en Cotización)
**Orchestrates:** Servicio `Plataforma-core-ohs`

## 3. User Story
Como sistema,
Quiero recuperar el catálogo de giros desde el servicio `Plataforma-core-ohs` (o su mock),
Para ofrecer una lista actualizada en el formulario de cotización.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad del sistema de cotización para obtener y mantener actualizado el catálogo de giros. El cotizador realizará una llamada a un servicio externo (`Plataforma-core-ohs` o su mock) para obtener una lista de giros, que incluye sus identificadores y descripciones. Esta lista será utilizada para poblar un campo de selección en el formulario de cotización, asegurando que los usuarios siempre elijan de un catálogo vigente. En caso de fallo en la recuperación, el sistema debe informar al usuario y registrar el error.
**Flow:** HU-068 (Inicio de Formulario de Cotización) → HU-071 (Recuperación de Catálogo de Giros) → HU-072 (Selección de Giro por el Usuario)

## 5. Expected Results


| element | description |
|---|---|
| Data | Se recupera una lista de objetos 'Giro', cada uno con un ID y una descripción. |

| Notifications | En caso de fallo, se muestra un mensaje de error genérico en la UI al usuario. |

## 6. Acceptance Criteria
### AC-001: Recuperación exitosa del catálogo de giros
**Description:** Valida que el sistema pueda obtener el catálogo de giros del servicio externo y que la lista contenga los IDs y descripciones esperados.

```gherkin
Scenario: El cotizador recupera exitosamente el catálogo de giros
  Given que el cotizador necesita el catálogo de giros
  When realiza una solicitud al servicio `Plataforma-core-ohs`

  And el formulario de cotización muestra la lista de giros actualizada
```

### AC-002: Reflejo de actualizaciones en el catálogo
**Description:** Asegura que los cambios en el catálogo de origen se reflejen cuando el cotizador lo consulta nuevamente.

```gherkin
Scenario: El cotizador refleja las actualizaciones del catálogo de giros
  Given que el catálogo de giros ha sido actualizado en el servicio `Plataforma-core-ohs`
  When el cotizador consulta nuevamente el catálogo de giros
  Then los cambios se reflejan en la lista mostrada en el formulario de cotización
```

### AC-003: Manejo de errores en la recuperación del catálogo
**Description:** Verifica que el sistema maneje adecuadamente los fallos en la recuperación del catálogo, informando al usuario y registrando el incidente.


## 11. Architecture and Technical Dependencies
-   **`Plataforma-core-ohs` (Servicio Externo)**: Fuente del catálogo de giros.
    -   Propósito: Proporcionar la lista de giros con ID y descripción.
    -   Timeout: 5 segundos.
    -   Retries: 2 reintentos con backoff exponencial.
-   **Cliente API REST (Interno)**: Componente del cotizador encargado de realizar las llamadas HTTP a `Plataforma-core-ohs`.
-   **Capa de Mapeo de Datos (Interno)**: Transforma la respuesta del servicio externo a un modelo de datos interno (`Giro`).
-   **Repositorio de Catálogos (Interno)**: Abstracción para el acceso a datos de catálogos, incluyendo el de giros.
-   **Circuit Breaker**: Implementado en el cliente API REST para `Plataforma-core-ohs` para prevenir fallos en cascada.
    -   Configuración: Umbral de error del 50%, ventana de tiempo de 1 minuto, tiempo de apertura de 30 segundos.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad del Servicio `Plataforma-core-ohs`**:
    -   Descripción: Si `Plataforma-core-ohs` está inactivo o experimenta alta latencia, el cotizador no podrá cargar el catálogo de giros.
    -   Impacto: Los usuarios no podrán completar el formulario de cotización o tendrán una mala experiencia.
    -   Probabilidad: Media
    -   Mitigación: Implementación de Circuit Breaker, reintentos, cacheo del catálogo (considerar como deuda técnica), monitoreo proactivo del servicio dependiente.
2.  **Cambios en la Interfaz del Servicio `Plataforma-core-ohs`**:
    -   Descripción: Si la API de `Plataforma-core-ohs` cambia (ej. nombres de campos, formato de respuesta), la integración actual podría romperse.
    -   Impacto: Fallo en la recuperación del catálogo.
    -   Probabilidad: Baja (con buena comunicación entre equipos)
    -   Mitigación: Comunicación constante con el equipo de `Plataforma-core-ohs`, uso de versiones de API, pruebas de integración automatizadas.

**Technical Debt:**
-   Considerar la implementación de un mecanismo de cacheo para el catálogo de giros para reducir la dependencia directa y la carga sobre `Plataforma-core-ohs`, mejorando el rendimiento y la resiliencia. (A evaluar en futuras iteraciones).

## 17. Criticality
**Criticality Level:** Medium
**Justification:** Sin el catálogo de giros, el formulario de cotización no puede ser completado correctamente por el usuario, afectando directamente la capacidad principal del sistema. Sin embargo, no es un fallo que impida el acceso total al sistema o cause pérdida de datos críticos.
**Feature Impact:** La no implementación o fallo de esta historia impide que la funcionalidad de "Gestión de Cotizaciones" opere de manera completa y útil, ya que no se podrá especificar un giro para la cotización.
**Critical Dependencies:** El formulario de cotización es críticamente dependiente de esta historia para funcionar correctamente.
**Recommended Priority:** Sprint actual (dado que es una dependencia clave para el flujo de cotización).
