## 3. User Story
Como un **usuario**,
Quiero que el sistema valide que las sumas aseguradas de cada ubicación estén dentro de los rangos predefinidos,
Para **evitar errores en la cotización y asegurar que los montos sean coherentes con las políticas de suscripción**.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para asegurar que las sumas aseguradas ingresadas por el usuario para cada ubicación dentro de una cotización cumplan con los rangos mínimos y máximos establecidos por las políticas de suscripción. El sistema debe ejecutar una validación contra estos rangos configurables y, en caso de incumplimiento, reportar un error específico.
**Flow:** Ingreso de Suma Asegurada (HU-XXX TBD) → **Validación de Rangos de Suma Asegurada (HU-049)** → Continuación de Cotización (HU-XXX TBD) / Reporte de Errores.

## 6. Acceptance Criteria
### AC-001: Validación exitosa de suma asegurada dentro del rango
**Description:** Valida que una suma asegurada ingresada dentro de los límites permitidos sea considerada válida por el sistema.

```gherkin
Scenario: Suma asegurada dentro del rango permitido
  Given que los rangos de suma asegurada para la ubicación son [1000, 100000]
  And que he ingresado una suma asegurada de 50000 para la ubicación
  When se ejecuta la validación de la suma asegurada
  Then la suma asegurada se considera válida
  And el sistema no reporta errores para esa suma asegurada
```

### AC-002: Error por suma asegurada por debajo del mínimo
**Description:** Valida que el sistema reporte un error específico cuando la suma asegurada ingresada es inferior al mínimo permitido.


## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| suma_asegurada_ubicacion | Decimal | yes | N/A | Mayor que 0 | N/A | 75000.50 |
| rango_minimo_suma_asegurada | Decimal | yes | N/A | Mayor o igual a 0 | Configurable por tipo de riesgo, zona, etc. | 1000.00 |
| rango_maximo_suma_asegurada | Decimal | yes | N/A | Mayor que rango_minimo_suma_asegurada | Configurable por tipo de riesgo, zona, etc. | 100000.00 |
| tipo_de_riesgo | String | yes | N/A | N/A | CAT_TIPO_RIESGO | Incendio |
| zona_geografica | String | no | N/A | N/A | CAT_ZONA_GEOGRAFICA | Zona A |


**BR-001:** Validación de Rango de Suma Asegurada
- Description: La suma asegurada ingresada para una ubicación debe estar entre el rango mínimo y máximo definido para las condiciones de la póliza (ej. tipo de riesgo, zona).
- Trigger: Al ingresar o modificar una suma asegurada para una ubicación en el proceso de cotización.
- Logic: `IF suma_asegurada_ubicacion < rango_minimo_suma_asegurada THEN ERROR("Suma asegurada por debajo del mínimo")`
  `ELSE IF suma_asegurada_ubicacion > rango_maximo_suma_asegurada THEN ERROR("Suma asegurada por encima del máximo")`
  `ELSE VALID`
- Implementation: Módulo de reglas de validación.
- Exception: N/A

## 13. Edge Cases and Exceptions
### Case 1: Rangos no definidos
```gherkin
Scenario: Rangos de suma asegurada no configurados para un tipo de riesgo/zona
  Given que no existen rangos de suma asegurada definidos para el 'Tipo de Riesgo: Robo' y 'Zona B'
  When intento cotizar una suma asegurada para 'Tipo de Riesgo: Robo' en 'Zona B'
  Then el sistema reporta un error indicando que los rangos no están configurados
  And la cotización no puede proceder hasta que los rangos sean definidos
```

### Case 2: Suma asegurada igual al mínimo o máximo
```gherkin
Scenario: Suma asegurada exactamente en el límite
  Given que los rangos de suma asegurada son [1000, 100000]
  When ingreso una suma asegurada de 1000
  Then la suma asegurada se considera válida
  And cuando ingreso una suma asegurada de 100000
  Then la suma asegurada se considera válida
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Dependencia de rangos dinámicos:**
    *   Descripción: Si los rangos son obtenidos de FT-010 y este servicio no está disponible o falla, la validación no podrá completarse.
    *   Impacto: No se pueden realizar cotizaciones o se realizan con valores no validados, llevando a errores de suscripción.
    *   Probabilidad: Media.
    *   Mitigación: Implementar Circuit Breaker y mecanismos de reintento. Considerar rangos por defecto o un "fail-safe" que permita continuar la cotización con una advertencia si el servicio de rangos falla temporalmente, pero no si es crítico.
2.  **Complejidad de la configuración de rangos:**
    *   Descripción: La nota menciona que los rangos pueden depender de "otros factores como el tipo de riesgo o la zona", lo que podría llevar a una configuración de reglas compleja.
    *   Impacto: Mayor tiempo de desarrollo, mayor probabilidad de errores en la lógica de validación, dificultad en el mantenimiento.
    *   Probabilidad: Media.
    *   Mitigación: Priorizar los factores más críticos inicialmente (MVP). Utilizar un BRMS (Business Rule Management System) si la complejidad justifica la inversión. Documentar claramente la lógica de configuración.
