**Feature:** Gestión de Ubicaciones de Riesgo y Coberturas

## 2. Enabled Capability
**CAP-031:** Obtener Catálogos de Clasificación de Riesgo y Garantías
**Business Value:** Permite asociar clasificaciones de riesgo y garantías estandarizadas a ubicaciones y coberturas, asegurando consistencia y facilitando la cotización precisa.
**Requires:** CAP-XXX (Disponibilidad del servicio `Plataforma-core-ohs` o un mecanismo de simulación)
**Enables:** FT-002: Gestión Dinámica de Ubicaciones de Riesgo, FT-003: Configuración y Selección de Coberturas por Ubicación
**Orchestrates:** `Plataforma-core-ohs` (servicio externo)

## 3. User Story
Como usuario,
quiero que el sistema obtenga catálogos de clasificación de riesgo y garantías desde el servicio de referencia,
para asociarlos a las ubicaciones y coberturas.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para recuperar listados de valores predefinidos (catálogos) para la clasificación de riesgo de ubicaciones y para la selección de garantías. Estos catálogos serán obtenidos de un servicio externo (`Plataforma-core-ohs`) y se utilizarán para poblar las opciones disponibles en la interfaz de usuario al configurar ubicaciones y coberturas. En caso de indisponibilidad del servicio externo, se utilizará un mecanismo de simulación o datos predefinidos para permitir el desarrollo y pruebas.
**Flow:** [Inicio de configuración de ubicación/cobertura] → [HU-031: Obtención de catálogos] → [FT-002: Gestión Dinámica de Ubicaciones de Riesgo / FT-003: Configuración y Selección de Coberturas por Ubicación]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Carga de catálogos desde el servicio de referencia
**Description:** Valida que las opciones de clasificación de riesgo y garantías se cargan correctamente desde el servicio `Plataforma-core-ohs` cuando el usuario accede a la funcionalidad de configuración.

```gherkin
Scenario: Carga exitosa de catálogos desde Plataforma-core-ohs
  Given que el usuario necesita clasificar el riesgo de una ubicación o seleccionar una garantía
  And el servicio 'Plataforma-core-ohs' está disponible y responde correctamente
  When el usuario accede a la opción correspondiente para seleccionar riesgo o garantía
  Then las opciones se cargan desde 'Plataforma-core-ohs'
  And el usuario puede ver las opciones disponibles en la interfaz
```

### AC-002: Consistencia de los datos de los catálogos
**Description:** Asegura que los datos cargados desde los catálogos sean consistentes y correctos según la información de referencia proporcionada por `Plataforma-core-ohs`.

```gherkin
Scenario: Datos de catálogos consistentes
  Given que los catálogos de clasificación de riesgo y garantías se han cargado correctamente
  When un usuario selecciona una opción de riesgo o garantía
  Then los datos asociados a esa opción son consistentes con la información de referencia de 'Plataforma-core-ohs'
  And la información utilizada en la lógica de negocio es la esperada
```

### AC-003: Mecanismo de simulación o datos predefinidos
**Description:** Verifica que, si el servicio `Plataforma-core-ohs` no está disponible o no proporciona los catálogos, el sistema utiliza un mecanismo alternativo (simulación o datos predefinidos) para permitir la funcionalidad.

```gherkin
Scenario: Fallback a simulación/datos predefinidos
  Given que el usuario necesita clasificar el riesgo de una ubicación o seleccionar una garantía
  And el servicio 'Plataforma-core-ohs' no está disponible o no responde
  When el usuario accede a la opción correspondiente para seleccionar riesgo o garantía
  Then el sistema utiliza un mecanismo de simulación o datos predefinidos para cargar las opciones
  And el usuario puede ver las opciones simuladas/predefinidas en la interfaz
```

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| idClasificacionRiesgo | UUID/String | yes | N/A | Formato UUID o alfanumérico | ClasificacionRiesgo | RISK-001 |
| nombreClasificacionRiesgo | String | yes | N/A | Texto libre | ClasificacionRiesgo | Riesgo Bajo |
| idGarantia | UUID/String | yes | N/A | Formato UUID o alfanumérico | Garantias | GAR-FIRE |
| nombreGarantia | String | yes | N/A | Texto libre | Garantias | Incendio |


**BR-001:** Consistencia de Datos de Catálogo
- Description: Los datos de clasificación de riesgo y garantías obtenidos del servicio `Plataforma-core-ohs` deben ser utilizados tal cual, sin modificaciones, para asegurar la consistencia con la fuente de referencia.
- Trigger: Al recibir la respuesta de la API de `Plataforma-core-ohs`.
- Logic: Los valores de `id` y `nombre` para cada elemento del catálogo deben mapearse directamente a los campos de la interfaz de usuario y el modelo de datos interno.
- Implementation: Servicio de cliente API y capa de mapeo de datos.
- Exception: Si los datos son inválidos o incompletos, se debe registrar un error y activar el mecanismo de fallback.

**BR-002:** Mecanismo de Fallback para Catálogos
- Description: Si la llamada al servicio `Plataforma-core-ohs` falla o no retorna datos, el sistema debe utilizar un conjunto de datos predefinidos o un stub para permitir el desarrollo y, potencialmente, una operación limitada.
- Trigger: Fallo en la invocación o respuesta de `Plataforma-core-ohs`.
- Logic: Si `Plataforma-core-ohs` no responde o retorna un error HTTP (ej. 4xx, 5xx) o un cuerpo vacío, se cargan los datos de un archivo de configuración local o un objeto mock.
- Implementation: Cliente API con lógica de reintento y fallback.
- Exception: Si el mecanismo de fallback también falla, se debe mostrar un mensaje de error al usuario y loguear el incidente.

## 11. Architecture and Technical Dependencies
- **Plataforma-core-ohs API**:
    - Propósito: Proveer los catálogos de clasificación de riesgo y garantías.
    - Timeout: 5 segundos.
    - Retries: 2 reintentos con backoff exponencial.
- **Backend Service (Cliente API)**: Un módulo o servicio en el backend que encapsula la lógica de llamada a `Plataforma-core-ohs`, manejo de errores, reintentos y el mecanismo de fallback.
- **Cache (opcional)**: Considerar un mecanismo de caché para los catálogos si la frecuencia de actualización es baja y se desea reducir la carga en `Plataforma-core-ohs`.

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Rendimiento de `Plataforma-core-ohs`**:
    - Descripción: La indisponibilidad o baja latencia de `Plataforma-core-ohs` impactará directamente la capacidad de clasificar riesgos y seleccionar garantías.
    - Impacto: Imposibilidad de configurar ubicaciones/coberturas o experiencia de usuario degradada.
    - Probabilidad: Media (depende de la estabilidad del servicio externo).
    - Mitigación: Implementar reintentos, circuit breaker, caching y el mecanismo de fallback con datos predefinidos/simulados.
2.  **Compatibilidad de la Estructura de Datos**:
    - Descripción: Cambios en la estructura de datos de los catálogos de `Plataforma-core-ohs` podrían romper la integración.
    - Impacto: Fallos en la carga de catálogos, inconsistencia de datos.
    - Probabilidad: Baja a Media (depende de la gobernanza de APIs en `Plataforma-core-ohs`).
    - Mitigación: Contratos de API bien definidos, pruebas de integración automatizadas, comunicación con el equipo de `Plataforma-core-ohs`.

**Technical Debt:**
- La implementación del mecanismo de simulación o stubs para `Plataforma-core-ohs` podría convertirse en deuda técnica si no se reemplaza por la integración real una vez que el servicio esté disponible y estable. Se debe priorizar la remoción de los stubs una vez que la dependencia externa sea estable.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es fundamental para habilitar la funcionalidad de clasificación de riesgo y selección de garantías, que son pilares de la configuración de ubicaciones y coberturas. Sin estos catálogos, las funcionalidades dependientes no pueden operar con datos de referencia.
**Feature Impact:** La no implementación o fallo de esta historia impide la correcta clasificación y asociación de información clave en las ubicaciones y coberturas, afectando la integridad y validez del proceso de cotización.
**Critical Dependencies:** FT-002: Gestión Dinámica de Ubicaciones de Riesgo y FT-003: Configuración y Selección de Coberturas por Ubicación dependen directamente de esta historia.
**Recommended Priority:** Media (según lo indicado en la historia original).
