## 3. User Story
Como un usuario,
quiero iniciar una nueva cotización,
para que el sistema me asigne un folio único de forma idempotente.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso inicial para crear una nueva cotización. Al seleccionar la opción correspondiente, el sistema debe comunicarse con un servicio de folios para obtener y asignar automáticamente un identificador único (folio) a la nueva cotización. Este folio debe ser visible para el usuario, pero no editable, y el proceso de asignación debe ser idempotente, garantizando que reintentos por errores temporales no generen folios duplicados o diferentes.
**Flow:** [Acceso a la pantalla principal del cotizador] → [HU-001: Iniciar nueva cotización con folio automático] → [HU-XXX: Cargar interfaz de edición de cotización con folio]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Generación de folio al iniciar cotización
**Description:** Valida que al seleccionar la opción de crear una nueva cotización, el sistema genere y asigne un folio único.

```gherkin
Scenario: El sistema genera un nuevo folio al iniciar una cotización
  Given estoy en la pantalla principal del cotizador
  When selecciono la opción para crear una nueva cotización
  Then se genera un nuevo folio de cotización
```

### AC-002: Idempotencia en la asignación del folio
**Description:** Valida que, ante errores temporales y reintentos, el folio asignado a la cotización se mantenga el mismo.

```gherkin
Scenario: El folio se mantiene el mismo ante reintentos por errores temporales
  Given se ha intentado generar un folio para una nueva cotización y se produjo un error temporal
  When se reintenta la creación de la misma cotización
  Then se mantiene el mismo folio generado inicialmente para esa cotización
```

### AC-003: Visualización y no editabilidad del folio
**Description:** Valida que el campo del folio en la interfaz de la nueva cotización se muestre prellenado y no sea editable por el usuario.

```gherkin

  When se carga la interfaz de la nueva cotización
  Then el campo "Folio" se muestra prellenado con el folio asignado
  And el campo "Folio" no es editable por el usuario
```

**BR-001:** Generación de Folio Único
- Description: Cada nueva cotización debe tener un folio único asignado por el sistema.
- Trigger: Al iniciar una nueva cotización.
- Logic: El sistema debe solicitar un folio al Servicio de Folios (`Plataforma-core-ohs`).
- Implementation: API de cotizaciones (backend)
- Exception: Si el Servicio de Folios no puede generar un folio único, se debe manejar el error.

**BR-002:** Idempotencia en la Asignación de Folio
- Description: Si la creación de una cotización falla temporalmente después de que un folio ha sido asignado por el Servicio de Folios, los reintentos posteriores para la *misma* operación de creación deben resultar en la asignación del *mismo* folio.
- Trigger: Reintentos de creación de cotización después de un fallo temporal.
- Logic: El sistema debe tener un mecanismo para reusar o verificar la asignación previa del folio en caso de reintentos. Esto implica que el Servicio de Folios debe soportar la idempotencia o la API de cotizaciones debe gestionar la reusabilidad del folio ya asignado.
- Implementation: API de cotizaciones (backend) y/o Servicio de Folios (`Plataforma-core-ohs`).
- Exception: Si no se puede garantizar la idempotencia, se podría generar un folio duplicado o un error persistente.

**BR-003:** Folio No Editable
- Description: Una vez asignado, el folio de la cotización no puede ser modificado por el usuario.
- Trigger: Carga de la interfaz de edición de cotización.
- Logic: El campo de visualización del folio en la interfaz de usuario debe estar deshabilitado o en modo solo lectura.
- Implementation: Frontend del cotizador.

## 11. Architecture and Technical Dependencies
- **API de cotizaciones (backend):** Endpoint de creación de cotizaciones. Responsable de orquestar la llamada al Servicio de Folios y persistir la cotización.
- **Servicio de Folios (`Plataforma-core-ohs`):** Servicio externo o microservicio encargado de generar folios únicos e idempotentes.
    - Propósito: Generación y gestión de identificadores únicos.
    - Timeout: A definir (ej. 5 segundos)
    - Retries: A definir (ej. 3 reintentos con backoff exponencial)
- **Frontend del cotizador:** Componente que muestra el botón "Nueva Cotización" y el campo de visualización del Folio.
- **Circuit Breaker:** Se recomienda implementar un Circuit Breaker para la integración con `Plataforma-core-ohs` para manejar fallos del servicio de folios de forma resiliente.

## 13. Edge Cases and Exceptions

**Description:** El `Plataforma-core-ohs` (Servicio de Folios) no responde o devuelve un error.

```gherkin

  Then el sistema muestra un mensaje de error al usuario (ej. "No se pudo iniciar la cotización. Inténtelo de nuevo más tarde.")

```

### Case 2: Fallo de red o timeout durante la creación
**Description:** La llamada a la API de backend o al Servicio de Folios experimenta un timeout o fallo de red después de que el folio ha sido generado pero antes de que la cotización se persista o se muestre al usuario.

```gherkin
Scenario: Manejo de fallos de red/timeout después de la generación del folio
  Given estoy en la pantalla principal del cotizador
  And el Servicio de Folios ha generado un folio exitosamente
  And ocurre un fallo de red o timeout antes de que la cotización se persista o la interfaz se cargue
  When el sistema intenta recuperarse (ej. mediante reintentos)
  Then se aplica la lógica de idempotencia para mantener el folio original
  And el sistema intenta persistir la cotización con el folio generado
  And si la persistencia falla después de reintentos, se notifica al usuario del error
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Fiabilidad del Servicio de Folios:**
    -   Descripción: Si `Plataforma-core-ohs` no es altamente disponible o falla frecuentemente, impactará directamente la capacidad de iniciar nuevas cotizaciones.
    -   Impacto: Interrupción del flujo de negocio, frustración del usuario.
    -   Probabilidad: Media.
    -   Mitigación: Implementar Circuit Breaker, reintentos con backoff, monitoreo robusto del servicio de folios, definir SLA.
2.  **Complejidad de la Idempotencia:**
    -   Descripción: Asegurar la idempotencia en la generación y asignación del folio puede ser complejo si requiere coordinación entre el frontend, la API de cotizaciones y el Servicio de Folios.
    -   Impacto: Posible generación de folios duplicados o cotizaciones incompletas.
    -   Probabilidad: Media.
    -   Mitigación: Diseño cuidadoso del flujo de idempotencia, pruebas exhaustivas, utilizar capacidades de idempotencia del Servicio de Folios si existen.
3.  **Rendimiento del Servicio de Folios:**
    -   Descripción: Una alta latencia en la respuesta del Servicio de Folios puede ralentizar el inicio de cotizaciones.
    -   Impacto: Mala experiencia de usuario.
    -   Probabilidad: Baja a Media.
    -   Mitigación: Monitoreo de rendimiento, optimización de la llamada, caching si es aplicable (con cuidado por la unicidad).

**Technical Debt:** [To be filled by operating team per scope and MVP]
- Considerar un mecanismo de fallback para la generación de folios si el servicio principal no está disponible por períodos prolongados (ej. folios temporales, aunque esto podría ir en contra de la unicidad deseada).

## 17. Criticality
**Criticality Level:** High
**Justification:** Esta historia es fundamental para iniciar cualquier proceso de cotización. Sin ella, los usuarios no pueden crear nuevas cotizaciones, lo que detiene el flujo de negocio principal del cotizador.
**Feature Impact:** La no implementación o fallo de esta historia impide el uso completo de la funcionalidad de "Cotizador de Productos".
**Critical Dependencies:** Todas las historias de usuario relacionadas con la edición, guardado o gestión de cotizaciones dependen directamente de que se pueda iniciar una cotización y se le asigne un folio.
**Recommended Priority:** Sprint actual / Próximo sprint (dada la prioridad Alta y estimación de 2 puntos).

## 18. Identified Assumptions
1.  **Disponibilidad del Servicio de Folios:**
    -   Description: Se asume que el `Plataforma-core-ohs` (Servicio de Folios) estará disponible y responderá de manera consistente y eficiente.
    -   Impact if false: El usuario no podrá iniciar cotizaciones, generando errores y frustración.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` / Arquitectura.
2.  **Capacidad de Idempotencia del Servicio de Folios:**
    -   Description: Se asume que el Servicio de Folios (`Plataforma-core-ohs`) o la API de cotizaciones tienen un mecanismo robusto para garantizar la idempotencia en la asignación de folios, es decir, que un reintento de creación resulte en el mismo folio.
    -   Impact if false: Folios duplicados, inconsistencia de datos, problemas de trazabilidad.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` / Equipo de Backend.
3.  **Formato y Unicidad del Folio:**
    -   Description: Se asume que el folio generado por el Servicio de Folios cumplirá con los requisitos de formato y garantizará la unicidad a nivel de sistema.
    -   Impact if false: Problemas de identificación, colisiones de folios.
    -   Requires validation from: Equipo de `Plataforma-core-ohs` / Negocio.
