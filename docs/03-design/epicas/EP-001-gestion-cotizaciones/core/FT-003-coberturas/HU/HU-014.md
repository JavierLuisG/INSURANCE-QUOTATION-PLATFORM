## 1. Identificación General / General Identification
**Feature:** Gestión de Coberturas por Ubicación
**Capability:** CAP-014 - Visualizar Resumen de Coberturas por Ubicación
**Actor:** Usuario
**Bounded Context:** Gestión de Pólizas y Coberturas
**Story Points:** 2 puntos de historia

## 2. Enabled Capability
**CAP-014:** Visualizar Resumen de Coberturas por Ubicación
**Business Value:** Permite una revisión rápida y eficiente del estado y parámetros de las coberturas activas para una ubicación específica, mejorando la agilidad en la gestión y validación de pólizas.
**Requires:** CAP-012: Seleccionar y deseleccionar coberturas para una ubicación; CAP-013: Configurar parámetros específicos de cobertura (Sumas Aseguradas, Deducibles)
**Enables:** N/A
**Orchestrates:** N/A

## 3. User Story
Como un **usuario**,
quiero **ver un resumen claro de las coberturas activas y sus parámetros para cada ubicación**,
para **una revisión rápida**.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario visualizar una vista consolidada y concisa de todas las coberturas que han sido activadas para una ubicación específica. El resumen incluirá el nombre de cada cobertura, su suma asegurada y el deducible correspondiente. El sistema garantizará que la información mostrada esté siempre actualizada, reflejando cualquier cambio reciente en las configuraciones de las coberturas. En el caso de que una ubicación no tenga coberturas seleccionadas, se presentará un mensaje informativo al usuario.
**Flow:** HU-013 (Configurar parámetros específicos de cobertura) → HU-014 (Visualizar resumen de coberturas activas)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualizar Coberturas Activas con Parámetros
**Description:** Valida que, al acceder al resumen de una ubicación que tiene coberturas configuradas, se muestren todas las coberturas activas junto con sus sumas aseguradas y deducibles correspondientes.

```gherkin
Scenario: Visualizar coberturas activas y sus parámetros configurados
  Given que he configurado coberturas para la "Ubicación A"
  When accedo a la vista de resumen de la "Ubicación A"
  Then se lista cada cobertura activa con su suma asegurada y deducible
  And la lista incluye "Cobertura de Incendio" con Suma Asegurada de $150,000 y Deducible de $1,500
  And la lista incluye "Cobertura de Robo" con Suma Asegurada de $75,000 y Deducible de $750
```

### AC-002: Mostrar Mensaje para Ubicaciones sin Coberturas
**Description:** Valida que si una ubicación no tiene ninguna cobertura seleccionada o configurada, el sistema muestra un mensaje informativo en lugar de una lista vacía.

```gherkin
Scenario: Ubicación sin coberturas seleccionadas
  Given que la "Ubicación B" no tiene coberturas seleccionadas
  When accedo a la vista de resumen de la "Ubicación B"
  Then se muestra un mensaje indicando que no hay coberturas
  And el mensaje es "No hay coberturas activas configuradas para esta ubicación."
```

### AC-003: Actualización Automática del Resumen
**Description:** Valida que cualquier cambio realizado en las coberturas o sus parámetros (a través de HU-012 o HU-013) se refleja de forma inmediata y precisa en el resumen al acceder o refrescar la vista.

```gherkin
Scenario: Actualización de información de coberturas tras un cambio
  Given que la "Ubicación C" tiene "Cobertura de Daños por Agua" con Suma Asegurada de $100,000
  And se ha modificado la Suma Asegurada de "Cobertura de Daños por Agua" a $120,000 en la configuración
  When accedo al resumen de la "Ubicación C"
  Then la información de la "Cobertura de Daños por Agua" se actualiza automáticamente
  And la Suma Asegurada de "Cobertura de Daños por Agua" mostrada es $120,000
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Riesgo: Rendimiento de carga del resumen con muchas coberturas.**
    - Descripción: Si una ubicación tiene un número extremadamente alto de coberturas configuradas (ej. cientos o miles), la consulta al backend y la renderización en el frontend podrían afectar el rendimiento y la experiencia del usuario.
    - Impacto: Tiempos de carga lentos, posible UI congelada, frustración del usuario.
    - Probabilidad: Media, si no se prevé un límite en el número de coberturas por ubicación.
    - Mitigación: Implementar paginación, virtualización de listas o carga diferida (lazy loading) si se identifica este escenario. Optimizar las consultas de base de datos en el backend.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es crucial para la usabilidad y la eficiencia en la gestión de pólizas, ya que proporciona una visión consolidada esencial. Sin embargo, su fallo no impide la configuración o selección de coberturas (HU-012, HU-013), solo dificulta su verificación rápida.
**Feature Impact:** La no implementación o el fallo de esta historia impediría una revisión eficiente de las configuraciones de cobertura por ubicación, forzando a los usuarios a inspeccionar cada cobertura individualmente, lo que ralentizaría drásticamente los procesos de validación y gestión.
**Critical Dependencies:** Depende críticamente de que las coberturas puedan ser previamente seleccionadas y configuradas.
**Recommended Priority:** Sprint actual o inmediatamente después de la finalización de HU-012 y HU-013.

1.  **Asunción: Existencia de una interfaz de gestión de ubicaciones.**
    - Description: Se asume que el usuario tiene un punto de entrada o una interfaz que le permite seleccionar una ubicación específica antes de acceder a la vista de resumen de sus coberturas.
    - Impact if false: El usuario no podría navegar para ver el resumen de coberturas.
    - Requires validation from: Equipo de UX/Producto.
2.  **Asunción: El término "actualización automática" implica recarga al acceder/refrescar la vista.**
    - Description: Se interpreta que la "información se actualiza automáticamente" significa que los datos se recuperan frescos cada vez que el usuario accede a la vista de resumen o realiza una acción de refresco, y no necesariamente implica una suscripción en tiempo real a cambios (ej. vía WebSockets).
    - Impact if false: Si se espera una actualización en tiempo real y solo se implementa una recarga bajo demanda, la experiencia del usuario podría no cumplir con las expectativas.
    - Requires validation from: Equipo de UX/Producto.
3.  **Asunción: Los parámetros "suma asegurada" y "deducible" son los únicos relevantes para el resumen.**
    - Description: La historia especifica estos dos parámetros. Se asume que no hay otros parámetros críticos que deban mostrarse en este resumen conciso.
    - Impact if false: El resumen podría estar incompleto para las necesidades del usuario, requiriendo una revisión de la historia.
    - Requires validation from: Usuario/Product Owner.
