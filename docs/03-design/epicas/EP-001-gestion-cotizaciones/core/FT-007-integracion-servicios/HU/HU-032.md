**Feature:** Cálculo de Primas

## 2. Enabled Capability
**CAP-001:** Gestión de Tarifas y Factores Técnicos para Cálculo de Primas
**Business Value:** Asegurar la precisión y exactitud en el cálculo de las primas, lo cual es fundamental para la operatividad del negocio y la satisfacción del cliente.
**Requires:** Inicio de Cálculo de Primas (HU-015)
**Enables:** CAP-002 - Ejecución de Cálculo de Primas (derivado de FT-004)
**Orchestrates:** Plataforma-core-ohs (Servicio de Referencia de Tarifas)

## 3. User Story
Como un **usuario** (del sistema de cálculo de primas),
Quiero que el sistema **consulte tarifas y factores técnicos desde el servicio de referencia**,
Para **realizar cálculos de prima precisos**.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso mediante el cual el sistema de cálculo de primas interactúa con el servicio externo `Plataforma-core-ohs` para obtener las tarifas y factores técnicos necesarios. El objetivo principal es asegurar que todos los cálculos de primas se realicen utilizando la información más actualizada y precisa disponible. Se deben manejar diferentes tipos de tarifas (ej. `tarifas_incendio`, `tarifas_cat`, `tarifa_fhm`) y sus parámetros de consulta, así como la gestión de errores si el servicio de referencia no está disponible.
**Flow:** [Inicio de Cálculo de Prima] → [HU-032: Consultar tarifas y factores técnicos] → [FT-004: Ejecución y Persistencia del Cálculo de Primas]

## 6. Acceptance Criteria
### AC-001: Consulta de tarifas y factores técnicos
**Description:** Valida que el sistema consulta correctamente las tarifas y factores técnicos desde el servicio de referencia cuando se requiere para un cálculo de prima.

```gherkin
Scenario: Consulta exitosa de tarifas y factores técnicos
  Given se inicia un cálculo de prima
  When el motor de cálculo requiere tarifas y factores técnicos
  Then el sistema consulta las tarifas (e.g., `tarifas_incendio`, `tarifas_cat`, `tarifa_fhm`) y factores técnicos de `Plataforma-core-ohs`
  And el sistema recibe una respuesta válida con los datos requeridos
```

### AC-002: Aplicación de tarifas en el cálculo
**Description:** Valida que las tarifas y factores obtenidos se aplican correctamente según las reglas de negocio en el cálculo de la prima.

```gherkin
Scenario: Aplicación correcta de tarifas en el cálculo
  Given las tarifas y factores técnicos han sido obtenidos exitosamente de `Plataforma-core-ohs`
  When el motor de cálculo utiliza estos datos para calcular la prima
  Then las tarifas y factores se aplican según las reglas de negocio definidas (e.g., FT-009)
  And el resultado del cálculo de prima es preciso
```

### AC-003: Manejo de errores en la consulta de tarifas
**Description:** Valida que el sistema gestiona adecuadamente los errores cuando el servicio de tarifas no responde o falla, impidiendo el cálculo o utilizando valores por defecto si es aceptable.

```gherkin
Scenario: Manejo de error cuando el servicio de tarifas no responde
  Given se inicia un cálculo de prima
  When el motor de cálculo intenta consultar tarifas y factores técnicos de `Plataforma-core-ohs`
  And el servicio `Plataforma-core-ohs` no responde o devuelve un error
  Then el sistema gestiona el error (ej. registra el fallo)
  And el sistema no permite el cálculo de la prima
  (Optional) Or el sistema utiliza valores por defecto predefinidos para las tarifas y factores (si es una opción aceptable y configurada)
```

**BR-001:** Aplicación de Tarifas y Factores
- Description: Todas las tarifas y factores técnicos obtenidos deben ser aplicados en el cálculo de la prima según las fórmulas y condiciones definidas en las reglas de negocio.
- Trigger: Después de la consulta exitosa de tarifas y factores, al iniciar el proceso de cálculo de prima.
- Logic: `prima_calculada = f(tarifas, factores, datos_riesgo, reglas_negocio)`
- Implementation: Motor de cálculo de primas (FT-004, FT-009).
- Exception: N/A

**BR-002:** Gestión de Fallos en la Consulta de Tarifas
- Description: Si la consulta al servicio `Plataforma-core-ohs` falla (timeout, error de servicio, etc.), el sistema debe impedir la continuación del cálculo de la prima. Opcionalmente, si se define, puede usar valores por defecto preestablecidos.
- Trigger: Error en la llamada al cliente API de `Plataforma-core-ohs`.
- Logic: `IF (respuesta_servicio_tarifas == ERROR) THEN { abortar_calculo() OR usar_valores_defecto() }`
- Implementation: Cliente API para `Plataforma-core-ohs`, Motor de cálculo.
- Exception: Si se configuran valores por defecto y son aceptables para el negocio, el cálculo puede proceder con una advertencia.

## 11. Architecture and Technical Dependencies
- **Backend:**
    - **Cliente API para `Plataforma-core-ohs`:** Responsable de la comunicación con el servicio externo. Debe manejar reintentos, timeouts y mapeo de datos.
    - **Motor de cálculo:** Orquesta la consulta de tarifas y factores, y los utiliza en el cálculo de la prima.
- **`Plataforma-core-ohs` (Servicio Externo):**
    - **Propósito:** Proporcionar tarifas y factores técnicos actualizados.
    - **Timeout:** Configurar un timeout razonable (ej. 5-10 segundos) para la respuesta.
    - **Retries:** Implementar una política de reintentos con backoff exponencial para fallos transitorios.
- **Circuit Breaker:** Considerar la implementación de un Circuit Breaker para `Plataforma-core-ohs` para prevenir fallos en cascada y permitir la recuperación del servicio.

## 16. Technical Notes and Risks
**Risks:**
1.  **Dependencia Externa Crítica:**
    -   Description: La disponibilidad y el rendimiento de `Plataforma-core-ohs` son críticos para la funcionalidad de cálculo de primas. Un fallo en este servicio detendrá los cálculos.
    -   Impact: Alta. Impacto directo en la capacidad de negocio para generar primas.
    -   Probability: Media (depende de la estabilidad del servicio externo).
    -   Mitigation: Implementar Circuit Breaker, reintentos con backoff, monitoreo proactivo del servicio externo, y considerar una estrategia de caché o valores por defecto para contingencias si el negocio lo permite.
2.  **Complejidad en el Manejo de Tarifas:**
    -   Description: La historia menciona "diferentes tipos de tarifas y sus parámetros de consulta". Esto implica una lógica compleja para seleccionar y aplicar la tarifa correcta.
    -   Impact: Media. Puede llevar a errores de cálculo si no se maneja correctamente.
    -   Probability: Media.
    -   Mitigation: Diseño cuidadoso de la interfaz del cliente API, modelado claro de los datos de tarifas, y pruebas exhaustivas para cada tipo de tarifa y sus parámetros.

**Technical Debt:** [To be filled by operating team per scope and MVP]
- Si se utiliza una solución provisional para el manejo de la diversidad de tarifas, documentar como deuda técnica para refactorizar hacia un motor de reglas más genérico.
