## 3. User Story
Como un **usuario**,
quiero **eliminar una ubicación de riesgo que ya no es necesaria**,
para que **la cotización se mantenga actualizada y precisa**.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario eliminar una ubicación de riesgo específica de una cotización existente. El proceso incluye la selección de la ubicación, una confirmación explícita para prevenir eliminaciones accidentales y la actualización de la cotización para reflejar el cambio. Se debe manejar el caso donde se intenta eliminar la única ubicación de una cotización, ya sea permitiéndolo o advirtiendo sobre la necesidad de mantener al menos una ubicación.
**Flow:** HU-006 (Agregar ubicación) → HU-008 (Eliminar ubicación) → HU-XXX (Consultar cotización actualizada)

## 6. Acceptance Criteria
### AC-001: Eliminación exitosa de una ubicación de riesgo
**Description:** Valida que el usuario puede eliminar una ubicación de riesgo cuando hay múltiples ubicaciones en la cotización, y esta desaparece de la vista.

```gherkin
Scenario: Eliminación exitosa de una ubicación cuando existen múltiples
  Given una cotización con múltiples ubicaciones de riesgo (ej. 'Ubicación A', 'Ubicación B')
  When el usuario selecciona 'Ubicación A' y confirma su eliminación
  Then 'Ubicación A' ya no aparece en la lista de ubicaciones de la cotización
  And la cotización se actualiza correctamente
```

### AC-002: Manejo de la eliminación de la única ubicación de riesgo
**Description:** Valida el comportamiento del sistema cuando el usuario intenta eliminar la última ubicación de riesgo de una cotización.

```gherkin
Scenario: Intento de eliminar la única ubicación de riesgo
  Given una cotización con una única ubicación de riesgo (ej. 'Ubicación Única')
  When el usuario selecciona 'Ubicación Única' y confirma su eliminación
  Then el sistema permite la eliminación de la ubicación
  And la cotización se actualiza correctamente y queda sin ubicaciones
  Or el sistema muestra una advertencia indicando que 'se requiere al menos una ubicación'
```

### AC-003: Persistencia de la eliminación de la ubicación
**Description:** Valida que una ubicación eliminada no reaparece al consultar la cotización nuevamente.

```gherkin
Scenario: La ubicación eliminada no aparece al consultar la cotización
  Given una cotización donde se ha eliminado previamente la 'Ubicación C'
  When el usuario consulta la cotización
  Then 'Ubicación C' no aparece en la lista de ubicaciones de riesgo de la cotización
```

**BR-001:** Confirmación de Eliminación
- Description: Antes de eliminar una ubicación de riesgo, el sistema debe solicitar una confirmación al usuario para evitar borrados accidentales.
- Trigger: Cuando el usuario intenta eliminar una ubicación.
- Logic: Mostrar un diálogo de confirmación con opciones 'Confirmar' y 'Cancelar'.
- Implementation: Frontend.
- Exception: N/A

**BR-002:** Implicaciones en Cálculos de Cotización
- Description: La eliminación de una ubicación de riesgo podría impactar los cálculos de la prima total o de otras características de la cotización.
- Trigger: Tras la eliminación exitosa de una ubicación de riesgo.
- Logic: El sistema debe recalcular automáticamente la cotización o marcarla como pendiente de recálculo si la lógica de negocio lo requiere.
- Implementation: Servicio de Cálculo de Cotizaciones (Backend).
- Exception: N/A

**BR-003:** Requisito de Mínimo de Ubicaciones
- Description: Si la lógica de negocio requiere que una cotización tenga al menos una ubicación de riesgo, el sistema debe advertir al usuario si intenta eliminar la única ubicación.
- Trigger: Cuando el usuario intenta eliminar la única ubicación de una cotización.
- Logic:
    IF (cantidad de ubicaciones en cotización == 1) THEN
        IF (negocio_requiere_minimo_una_ubicacion == TRUE) THEN
            Mostrar advertencia "Se requiere al menos una ubicación."
            Bloquear eliminación.
        ELSE
            Permitir eliminación.
        END IF
    END IF
- Implementation: Backend (API de cotizaciones), Frontend (Mensaje de advertencia).
- Exception: N/A (depende de la regla de negocio específica).

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario visualiza una cotización con una lista de ubicaciones de riesgo.
2.  El usuario hace clic en el botón "Eliminar Ubicación" junto a la ubicación deseada.
3.  Aparece un diálogo de confirmación.
4.  El usuario hace clic en "Confirmar" o "Cancelar".
5.  Si confirma, la ubicación desaparece de la lista y se muestra un mensaje de éxito. Si cancela, el diálogo se cierra y la ubicación permanece.
6.  Si se intenta eliminar la única ubicación y hay una restricción, se muestra un mensaje de advertencia.
**Messages/Modals:**
*   Diálogo de confirmación: "¿Está seguro de que desea eliminar esta ubicación de riesgo? Esta acción no se puede deshacer." [Confirmar] [Cancelar]
*   Mensaje de éxito: "Ubicación de riesgo eliminada correctamente."
*   Mensaje de advertencia (si aplica): "No se puede eliminar la única ubicación de riesgo. Una cotización debe tener al menos una ubicación."
**Stepper/Breadcrumbs:** N/A

## 11. Architecture and Technical Dependencies
- **API de Cotizaciones (Backend):** Endpoint `/api/quotes/{quoteId}/locations/{locationId}` (DELETE) para eliminar la ubicación de riesgo.
    *   Propósito: Eliminar lógicamente o físicamente una ubicación de riesgo de una cotización.
    *   Timeout: 5000 ms
    *   Retries: 0 (la eliminación es idempotente, pero un reintento podría indicar un problema mayor)
- **Servicio de Cálculo de Cotizaciones:** Podría ser invocado por el servicio de cotizaciones después de la eliminación para recalcular la prima.
- **Frontend (Componente de Cotizaciones):** Botón "Eliminar Ubicación", componente de diálogo de confirmación.

## 16. Technical Notes and Risks
**Risks:**
1.  **Impacto en Cálculos de Prima:**
    -   Descripción: La eliminación de una ubicación de riesgo puede tener un impacto complejo en el cálculo de la prima total de la cotización, especialmente si existen dependencias entre ubicaciones o descuentos/recargos multifactoriales.
    -   Impacto: Cálculos incorrectos, cotizaciones erróneas, posibles pérdidas financieras o problemas de cumplimiento.
    -   Probabilidad: Media
    -   Mitigación: Asegurar que el servicio de cálculo de cotizaciones sea invocado y que maneje correctamente la ausencia de una ubicación eliminada. Implementar pruebas exhaustivas para diferentes escenarios de cálculo.
2.  **Pérdida Accidental de Datos:**
    -   Descripción: A pesar de la confirmación, un usuario podría eliminar una ubicación por error, resultando en la pérdida de información relevante si no hay un mecanismo de recuperación.
    -   Impacto: Frustración del usuario, necesidad de reingreso de datos, cotizaciones incompletas.
    -   Probabilidad: Baja (con confirmación)
    -   Mitigación: Implementar una eliminación lógica (soft delete) en lugar de física, permitiendo una recuperación si es necesario. Asegurar registros de auditoría detallados.

## 18. Identified Assumptions
1.  **Existencia de una Cotización y Ubicaciones:**
    -   Description: Se asume que el usuario ya tiene una cotización existente y que esta contiene al menos una ubicación de riesgo que puede ser eliminada.
    -   Impact if false: Si no hay cotizaciones o ubicaciones, la funcionalidad de eliminación no es aplicable o la UI no mostrará el botón.
    -   Requires validation from: Equipo de Producto/UX.
2.  **Identificación Única de Ubicaciones:**
    -   Description: Se asume que cada ubicación de riesgo dentro de una cotización tiene un identificador único que permite su selección y eliminación precisa.
    -   Impact if false: Podría haber ambigüedad al seleccionar qué ubicación eliminar, llevando a errores.
    -   Requires validation from: Arquitectura/Equipo Técnico.
3.  **Impacto de la Eliminación en la UI:**
    -   Description: Se asume que la eliminación de una ubicación de riesgo de la cotización se reflejará instantáneamente en la interfaz de usuario sin necesidad de recargar la página completa.
    -   Impact if false: Experiencia de usuario deficiente, percepción de lentitud o errores.
    -   Requires validation from: Equipo de Frontend/UX.
