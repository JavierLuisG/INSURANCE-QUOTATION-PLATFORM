**Business Value:** Ajustar la protección a las necesidades específicas del cliente, mejorando la personalización de las cotizaciones y la satisfacción del cliente.
**Requires:** CAP-012 (Seleccionar y deseleccionar coberturas para una ubicación), FT-009 (Implementación de Reglas de Negocio y Validaciones)

## 3. User Story
Como un **usuario**,
quiero **configurar sumas aseguradas y deducibles específicos para cada cobertura y ubicación**,
para **ajustar la protección a las necesidades del cliente**.

## 4. Functional Description
**Description:** Esta historia permite al usuario, después de seleccionar una cobertura para una ubicación específica, acceder a los detalles de dicha cobertura. Dentro de estos detalles, el usuario podrá introducir y modificar los valores de la suma asegurada y el deducible. El sistema validará estos valores contra reglas de negocio (rangos mínimos, máximos o pasos) y los persistirá. Una vez guardados, estos parámetros se reflejarán correctamente en la cotización final.
**Flow:** HU-012 (Seleccionar y deseleccionar coberturas) → HU-013 (Configurar parámetros específicos de cobertura) → HU-XXX (Consultar Cotización con parámetros configurados)

## 7. Data and Business Rules


| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| coberturaId | string | yes | N/A | Debe existir en el catálogo de coberturas | Coberturas | COB_INCENDIO |
| ubicacionId | string | yes | N/A | Debe existir en el catálogo de ubicaciones de la cotización | Ubicaciones | UBI_PRINCIPAL |
| sumaAsegurada | number | yes | N/A | Debe ser un valor numérico positivo. Rango mínimo y máximo definido por la regla de negocio BR-001. | N/A | 150000.00 |
| deducible | number | yes | N/A | Debe ser un valor numérico positivo. Rango mínimo, máximo y/o pasos definidos por la regla de negocio BR-002. | N/A | 500.00 |


**BR-001:** Validación de Rango de Suma Asegurada
- Description: La suma asegurada introducida debe estar dentro de un rango predefinido (mínimo y máximo) que es específico para cada tipo de cobertura.
- Trigger: Al intentar guardar los parámetros de cobertura.
- Logic: `sumaAsegurada >= cobertura.minSumaAsegurada && sumaAsegurada <= cobertura.maxSumaAsegurada`
- Implementation: Backend (API de cotizaciones)
- Exception: Si el valor está fuera de rango, se muestra un mensaje de error.

**BR-002:** Validación de Rango y Pasos de Deducible
- Description: El deducible introducido debe estar dentro de un rango predefinido (mínimo y máximo) y, opcionalmente, ser un múltiplo de un "paso" específico para la cobertura.
- Trigger: Al intentar guardar los parámetros de cobertura.
- Logic: `deducible >= cobertura.minDeducible && deducible <= cobertura.maxDeducible && (cobertura.pasoDeducible == null || deducible % cobertura.pasoDeducible == 0)`
- Implementation: Backend (API de cotizaciones)
- Exception: Si el valor está fuera de rango o no cumple con los pasos, se muestra un mensaje de error.

**BR-003:** Cobertura Configurable
- Description: Solo las coberturas que tienen una propiedad explícita de ser configurables permitirán la edición de sus parámetros de suma asegurada y deducible.
- Trigger: Al acceder al detalle de una cobertura.
- Logic: `cobertura.esConfigurable == true`
- Implementation: Frontend (para habilitar/deshabilitar campos) y Backend (para validar la posibilidad de persistencia).

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad en la gestión de reglas de validación:** La variedad de rangos y pasos por cobertura y ubicación puede hacer que la lógica de validación sea compleja de mantener y escalar.
    -   **Impact:** Mayor riesgo de errores, dificultad en el mantenimiento, lentitud en la adición de nuevas coberturas.
    -   **Probability:** Media.
    -   **Mitigation:** Utilizar un motor de reglas de negocio (BRMS) si la complejidad lo justifica, o diseñar una estructura de datos flexible para las reglas.
2.  **Rendimiento de la API de cotizaciones:** Si la validación de parámetros implica consultas complejas o un alto número de reglas, podría afectar el rendimiento de la API al guardar.
    -   **Impact:** Latencia en la experiencia del usuario.
    -   **Probability:** Baja a Media.
    -   **Mitigation:** Optimización de la base de datos, caching de reglas, pruebas de carga exhaustivas.

## 18. Identified Assumptions
1.  **Coberturas Configurables Definidas:**
    -   Description: Se asume que el sistema ya tiene un catálogo de coberturas y que algunas de ellas están explícitamente marcadas como "configurables" (permitiendo la edición de Suma Asegurada y Deducible).
    -   Impact if false: Si no existen coberturas configurables o no están correctamente identificadas, la funcionalidad de esta HU no tendría dónde aplicarse, haciendo el esfuerzo de desarrollo inútil.
    -   Requires validation from: Equipo de Producto / Negocio (definición y propiedades del catálogo de coberturas).
2.  **Reglas de Negocio para Rangos y Pasos Disponibles:**
    -   Description: Se asume que el negocio proporcionará los rangos mínimos, máximos y los pasos permitidos para las sumas aseguradas y deducibles para cada cobertura configurable.
    -   Impact if false: Sin estas reglas, no se podrán implementar las validaciones críticas, lo que podría llevar a la configuración de parámetros erróneos o inconsistentes en las cotizaciones.
    -   Requires validation from: Equipo de Producto / Negocio.
