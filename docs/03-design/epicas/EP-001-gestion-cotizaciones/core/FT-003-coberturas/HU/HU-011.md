## 1. Identificación General
**Feature:** Gestión de Cotizaciones de Seguros
**Capability:** CAP-011 - Visualizar Catálogo de Coberturas por Tipo de Seguro
**Actor:** Usuario
**Bounded Context:** Cotizaciones de Seguros / Coberturas
**Story Points:** 2

## 2. Enabled Capability
**CAP-011:** Visualizar Catálogo de Coberturas por Tipo de Seguro
**Business Value:** Permite al usuario elegir las protecciones adecuadas para su cotización.
**Requires:** CAP-004 - Selección de Tipo de Seguro, Moneda y Canal de Venta
**Enables:** Selección y Configuración de Coberturas por Ubicación
**Orchestrates:** FT-007 - Integración con Servicios de Referencia (Catálogos de Coberturas)

## 3. User Story
Como un **usuario**,
quiero **ver un catálogo de coberturas disponibles para el tipo de seguro seleccionado**,
para que **pueda elegir las protecciones adecuadas**.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario, después de haber seleccionado un tipo de seguro, acceder a una sección donde se le presentará un listado dinámico de coberturas que son aplicables específicamente a ese tipo de seguro. El sistema debe asegurar que si el tipo de seguro se cambia, el catálogo de coberturas se actualice en consecuencia. En caso de que no existan coberturas para el tipo de seguro seleccionado, se mostrará un mensaje informativo.
**Flow:** HU-004: Seleccionar tipo de seguro → HU-011: Visualizar catálogo de coberturas → [Seleccionar Coberturas / Configurar Coberturas]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Visualización de coberturas aplicables al tipo de seguro
**Description:** Valida que al acceder a la sección de coberturas, se muestre la lista correcta basada en el tipo de seguro previamente seleccionado.

```gherkin
Scenario: Mostrar lista de coberturas aplicables
  Given que he seleccionado un "Tipo de Seguro A" para la cotización
  When accedo a la sección de coberturas de una ubicación
  Then se muestra la lista de coberturas aplicables al "Tipo de Seguro A"
```

### AC-002: Actualización de coberturas al cambiar el tipo de seguro
**Description:** Asegura que la lista de coberturas se actualice dinámicamente si el tipo de seguro de la cotización es modificado.

```gherkin
Scenario: Actualizar coberturas al cambiar tipo de seguro
  Given que he seleccionado un "Tipo de Seguro A" y he visto sus coberturas
  And cambio el tipo de seguro de la cotización a "Tipo de Seguro B"
  When vuelvo a la sección de coberturas
  Then la lista de coberturas se actualiza mostrando las aplicables al "Tipo de Seguro B"
```

### AC-003: Manejo de ausencia de coberturas
**Description:** Verifica que se muestre un mensaje adecuado cuando no hay coberturas disponibles para un tipo de seguro específico.

```gherkin
Scenario: Mostrar mensaje cuando no hay coberturas disponibles
  Given que he seleccionado un "Tipo de Seguro C" para el cual no hay coberturas disponibles
  When accedo a la sección de coberturas
  Then se muestra un mensaje informativo indicando la ausencia de coberturas
```

## 7. Data and Business Rules

**Tabla de campos de datos**:
*(Nota: La historia no especifica los campos individuales de una cobertura, solo el concepto de "catálogo de coberturas". Se requeriría más detalle del usuario para definir los campos específicos de cada cobertura.)*

| field | type | required | default | validation | catalog | example |
|---|---|---|---|---|---|---|
| idCobertura | UUID | yes | N/A | Formato UUID válido | N/A | a1b2c3d4-e5f6-7890-1234-567890abcdef |
| nombreCobertura | String | yes | N/A | No vacío, max 100 caracteres | N/A | Responsabilidad Civil |
| descripcionCobertura | String | no | N/A | Max 500 caracteres | N/A | Cubre daños a terceros en caso de accidente. |
| tipoSeguro | String | yes | N/A | Debe existir en el catálogo de tipos de seguro (ej. 'Auto', 'Hogar') | Catálogo de Tipos de Seguro | AUTO |


**BR-001:** Carga Dinámica de Coberturas
- Description: La lista de coberturas mostradas debe cargarse en tiempo real y adaptarse al tipo de seguro seleccionado en la cotización.
- Trigger: Acceso a la sección de coberturas o cambio del tipo de seguro de la cotización.
- Logic: `IF tipo_seguro_seleccionado IS NOT NULL THEN obtener_coberturas_por_tipo(tipo_seguro_seleccionado) ELSE mostrar_mensaje_error_o_vacio()`
- Implementation: Backend API de cotizaciones y Frontend.
- Exception: Si no se puede obtener el tipo de seguro, se muestra un error.

**BR-002:** Filtrado de Coberturas
- Description: Las coberturas listadas deben corresponder exclusivamente al tipo de seguro actualmente asociado a la cotización.
- Trigger: Carga inicial de la sección de coberturas o actualización del tipo de seguro.
- Logic: `coberturas_disponibles = filtrar_catalogo_global(tipo_seguro_actual)`
- Implementation: Backend API de cotizaciones.

**BR-003:** Paginación/Búsqueda de Catálogo (si aplica)
- Description: Si el volumen de coberturas para un tipo de seguro es extenso, la interfaz debe ofrecer mecanismos de paginación o búsqueda para facilitar la navegación.
- Trigger: Presentación de la lista de coberturas.
- Logic: `IF numero_coberturas > UMBRAL_PAGINACION THEN habilitar_paginacion_o_busqueda()`
- Implementation: Frontend.

## 11. Architecture and Technical Dependencies
- **Backend API de Cotizaciones:** Responsable de consultar y filtrar las coberturas por tipo de seguro.
- **`Plataforma-core-ohs` (Servicio de Catálogos de Coberturas):** Servicio externo que provee el catálogo maestro de coberturas.
  - Propósito: Obtener el listado completo de coberturas.
  - Timeout: 5000 ms (sugerido)
  - Retries: 3 reintentos con backoff exponencial (sugerido)
- **Frontend:** Interfaz de usuario para mostrar el listado de coberturas, con lógica para manejar la paginación/búsqueda y los mensajes informativos.
- **Kafka Topic:** No especificado en la historia.
- **Circuit Breaker:** Implementar un Circuit Breaker para la integración con `Plataforma-core-ohs` para manejar fallos del servicio externo.

## 16. Technical Notes and Risks
**Risks:**
1.  **Dependencia de servicio externo (`Plataforma-core-ohs`):**
    -   Descripción: Si el servicio de catálogos externo falla o tiene alta latencia, afectará directamente la capacidad de visualizar coberturas.
    -   Impacto: El usuario no podrá ver o seleccionar coberturas, deteniendo el flujo de cotización.
    -   Probabilidad: Media
    -   Mitigación: Implementar Circuit Breaker, reintentos, cacheo de catálogos (si es posible y los datos no cambian frecuentemente), y mensajes de error claros al usuario.
2.  **Volumen de datos del catálogo:**
    -   Descripción: Si el catálogo de coberturas es muy extenso, el rendimiento de la carga inicial y la experiencia de usuario podrían verse afectados sin paginación/búsqueda adecuada.
    -   Impacto: Lentitud en la interfaz, dificultad para el usuario encontrar coberturas.
    -   Probabilidad: Media
    -   Mitigación: Asegurar la implementación de paginación, filtros o búsqueda en el frontend y optimización de las consultas en el backend.

**Technical Debt:**
-   Definición formal y centralizada de la estructura de datos de Coberturas si no existe.
-   Considerar un mecanismo de cacheo para el catálogo de coberturas si el servicio externo es lento o propenso a fallas, y los datos no requieren ser en tiempo real.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es fundamental para que el usuario pueda personalizar su cotización y elegir las protecciones deseadas. Sin ella, el proceso de cotización estaría incompleto o sería ineficiente. Sin embargo, no es un punto de fallo crítico que impida iniciar una cotización (ya que HU-004 es el inicio).
**Feature Impact:** La no implementación o fallo de esta historia impide al usuario seleccionar las coberturas, lo que afecta directamente la capacidad de generar una cotización completa y relevante, impactando la propuesta de valor del producto.
**Critical Dependencies:** Depende críticamente de que HU-004 haya seleccionado un tipo de seguro y de que FT-007 provea los datos del catálogo.
**Recommended Priority:** Sprint actual o próximo, ya que es una pieza clave en el flujo de cotización.

    -   Impact if false: El filtrado de coberturas no funcionará correctamente, mostrando coberturas incorrectas o ninguna.
    -   Requires validation from: Equipo de Producto y Dueño de la HU-004.
