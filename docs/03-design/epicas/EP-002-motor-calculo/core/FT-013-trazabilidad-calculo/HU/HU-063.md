## 2. Enabled Capability
**CAP-003:** Registro de Trazabilidad de Cálculos
**Business Value:** Permite a los auditores verificar la exactitud de los cálculos históricos, asegurando el cumplimiento normativo y la transparencia. Reduce el riesgo de errores y facilita la resolución de disputas.
**Requires:** CAP-001 (Cálculo de Prima), CAP-002 (Persistencia de Cotizaciones)
**Enables:** CAP-004 (Análisis de Discrepancias de Cálculos)
**Orchestrates:** N/A

## 3. User Story
Como **auditor**,
Quiero que el sistema registre los parámetros clave y las tarifas utilizadas para un cálculo específico,
Para que pueda auditar y entender cómo se llegó a un resultado específico en cualquier momento.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad para registrar los parámetros de entrada y las tarifas utilizadas en el momento exacto de un cálculo de prima. Cuando se realiza un cálculo y sus resultados son persistidos (como parte de la HU-060), el sistema debe capturar y almacenar una "instantánea" de los valores específicos de las tarifas (incendio, CAT, FHM) y otros parámetros (rangos, CP-zona) que influyeron en ese cálculo. Esta información se asociará directamente con la cotización resultante, permitiendo a los auditores consultar posteriormente la cotización y visualizar exactamente qué valores de parámetros se usaron, incluso si esos parámetros han cambiado en el sistema con el tiempo. El objetivo es proporcionar una trazabilidad completa y precisa de cada cálculo.
**Flow:** HU-060 (Cálculo y persistencia de cotización) → **HU-063 (Registro de parámetros de trazabilidad)** → HU-028 (Consulta de cotización histórica con trazabilidad)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Registro de Parámetros Clave al Persistir Cálculo
**Description:** Valida que los valores clave de tarifas y otros parámetros se registren de forma inmutable junto con la cotización cuando esta se persiste.

```gherkin
Scenario: Los parámetros clave se registran junto con la cotización
  Given se ha completado un cálculo de prima con valores específicos de tarifas (incendio: 0.05, CAT: 0.02, FHM: 0.01) y parámetros (rango_edad: 18-30, cp_zona: 'A')
  When los resultados del cálculo se persisten en el sistema
  Then la cotización se guarda con un registro inmutable que incluye los valores exactos de tarifa (incendio: 0.05, CAT: 0.02, FHM: 0.01) y parámetros (rango_edad: 18-30, cp_zona: 'A')
  And estos parámetros son recuperables para futuras auditorías.
```

### AC-002: Visualización de Parámetros Exactos en Consulta Histórica
**Description:** Asegura que, al consultar una cotización histórica, se muestren los parámetros que se usaron en el momento de su cálculo.

```gherkin
Scenario: La consulta de una cotización histórica muestra los parámetros usados
  Given existe una cotización persistida con un registro de trazabilidad de parámetros (incendio: 0.05, CAT: 0.02, FHM: 0.01)
  And un auditor consulta esta cotización histórica
  When se visualiza la sección de trazabilidad del cálculo
  Then se muestran los valores exactos de los parámetros (incendio: 0.05, CAT: 0.02, FHM: 0.01) que se registraron al momento del cálculo.
```

### AC-003: Preservación de Valores de Parámetros Históricos
**Description:** Confirma que los valores de los parámetros registrados para un cálculo anterior no se ven afectados por cambios futuros en esos parámetros en el sistema.

```gherkin
Scenario: Los valores de parámetros históricos no cambian si el parámetro actual es modificado
  Given existe una cotización persistida con un registro de trazabilidad donde la tarifa de incendio era 0.05
  And la tarifa de incendio actual en el sistema se actualiza a 0.06
  When un auditor consulta la cotización histórica original
  Then la sección de trazabilidad sigue mostrando la tarifa de incendio como 0.05.
```

**BR-001:** Inmutabilidad de Parámetros Registrados
- Description: Una vez que los parámetros de cálculo se registran para una cotización, no deben ser modificables.
- Trigger: Al intentar actualizar los parámetros de trazabilidad de una cotización ya persistida.
- Logic: El sistema debe prevenir cualquier operación de actualización o eliminación sobre los registros de `TrazabilidadCalculo` asociados a una `Cotizacion` existente. Solo se permite la creación inicial.
- Implementation: Capa de persistencia del servicio de cotizaciones/cálculos.
- Exception: N/A

**BR-002:** Vinculación Obligatoria con Cotización
- Description: Cada registro de trazabilidad de cálculo debe estar asociado a una cotización existente.
- Trigger: Al intentar registrar parámetros de trazabilidad.
- Logic: El campo `cotizacion_id` debe ser un ID válido de una cotización ya persistida.
- Implementation: Servicio de registro de trazabilidad.
- Exception: N/A


## 16. Technical Notes and Risks
**Risks:**
1.  **Nombre:** Sobrecarga de Almacenamiento
    - Descripción: Almacenar un gran volumen de parámetros detallados para cada cotización podría aumentar significativamente el tamaño de la base de datos y los costos de almacenamiento.
    - Impacto: Mayor uso de recursos, menor rendimiento de la base de datos, mayores costos.
    - Probabilidad: Media
    - Mitigación: Evaluar el nivel de detalle necesario. Considerar almacenar solo IDs de versiones de catálogos o un hash de los parámetros cuando sea posible, en lugar de todos los valores crudos. Utilizar un formato de almacenamiento eficiente (ej. JSONB en PostgreSQL).
2.  **Nombre:** Acoplamiento Fuerte con el Esquema de Parámetros
    - Descripción: Si el esquema de los parámetros de cálculo cambia frecuentemente, el modelo de datos de trazabilidad podría volverse obsoleto o requerir migraciones complejas.
    - Impacto: Dificultad para mantener la trazabilidad, errores en la interpretación de datos históricos.
    - Probabilidad: Media
    - Mitigación: Utilizar un esquema flexible (ej. JSON/JSONB) para los parámetros variables o definir una estructura genérica `clave-valor`. Asegurar que los campos críticos (tarifas principales) sean explícitamente tipados y estables.
3.  **Nombre:** Impacto en el Rendimiento de Persistencia
    - Descripción: La adición de un paso de registro de trazabilidad podría aumentar el tiempo de persistencia de una cotización.
    - Impacto: Latencia percibida por el usuario, degradación del rendimiento del sistema.
    - Probabilidad: Baja (si se optimiza la persistencia)
    - Mitigación: Optimizar las consultas de inserción, monitorear la latencia.
**Technical Debt:** N/A (Se llenará por el equipo operativo según el alcance y MVP)

## 17. Criticality
**Criticality Level:** Media
**Justification:** La historia es fundamental para el cumplimiento regulatorio y la capacidad de auditoría, lo cual es un valor de negocio importante. Sin embargo, no afecta directamente la funcionalidad principal del cálculo o la venta de primas en tiempo real.
**Feature Impact:** Sin esta funcionalidad, la característica de "Trazabilidad de Cálculos de Prima" sería inútil, ya que no habría datos históricos para auditar. Esto podría llevar a incumplimientos regulatorios y a la imposibilidad de resolver disputas sobre cálculos.
**Critical Dependencies:** HU-060 (Persistencia de la cotización) es una dependencia crítica. Si HU-060 falla, esta historia no puede ejecutarse.
**Recommended Priority:** Sprint actual o siguiente, dada su prioridad "Media" y su importancia para la auditoría.

## 18. Identified Assumptions
1.  **Disponibilidad de Parámetros de Cálculo:**
    - Description: Se asume que al momento de ejecutar y persistir un cálculo, todos los parámetros y tarifas clave relevantes están disponibles y son accesibles para ser registrados.
    - Impact if false: Si los parámetros no están disponibles, el registro de trazabilidad será incompleto o fallará, invalidando la capacidad de auditoría.
    - Requires validation from: Equipo de Desarrollo del Módulo de Cálculos.
2.  **Nivel de Detalle Adecuado:**
    - Description: Se asume que el equipo ha decidido un nivel de detalle apropiado para los parámetros a registrar (ej., solo IDs de versiones, hash, o valores específicos).
    - Impact if false: Podría llevar a una sobrecarga de datos innecesaria o a una falta de información crítica para la auditoría.
    - Requires validation from: Stakeholders de Auditoría, Arquitectura, Equipo de Desarrollo.
3.  **Inmutabilidad del Registro:**
    - Description: Se asume que una vez que un registro de trazabilidad de cálculo se crea, es inmutable y no puede ser modificado.
    - Impact if false: La integridad de la auditoría podría verse comprometida si los datos históricos pueden ser alterados.
    - Requires validation from: Seguridad, Auditoría, Arquitectura.
