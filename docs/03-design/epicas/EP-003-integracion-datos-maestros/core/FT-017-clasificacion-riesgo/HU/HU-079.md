## 2. Enabled Capability
**CAP-007:** Integración de Datos Externos de Riesgo y Garantías
**Business Value:** Asegurar que la lógica de negocio y la interfaz de usuario operen con datos de riesgo y garantías estandarizados y actualizados, mejorando la precisión en la evaluación financiera y la toma de decisiones.
**Requires:** CAP-005 (Adquisición de Datos Externos de Clasificación de Riesgo), CAP-006 (Adquisición de Datos Externos de Garantías) - (Asumiendo estas capacidades se relacionan con HU-077 y HU-078)

**Orchestrates:** Servicio Externo de Clasificación de Riesgo, Servicio Externo de Garantías

## 3. User Story
Como **sistema**,
Quiero **mapear los datos de clasificación de riesgo y garantías del servicio externo a mi modelo interno**,
Para que **su correcta utilización en la lógica de negocio y la interfaz de usuario**.

## 4. Functional Description
**Description:** Esta historia de usuario describe el proceso por el cual el sistema toma los datos crudos de clasificación de riesgo y garantías obtenidos de servicios externos y los transforma para que se ajusten a la estructura y los estándares del modelo de datos interno de la aplicación. Esto asegura que los datos sean coherentes, validados y listos para ser consumidos por la lógica de negocio (cálculos, validaciones) y presentados de manera uniforme en la interfaz de usuario. El mapeo incluye la transformación de formatos, la normalización de valores y la asignación de identificadores únicos y estables.
**Flow:** [HU-077: Adquirir Datos de Clasificación de Riesgo] → [HU-079: Mapear Datos de Clasificación de Riesgo y Garantías] → [HU-080: Almacenar Datos Mapeados]

## 6. Acceptance Criteria
### AC-001: Mapeo de Clasificación de Riesgo
**Description:** Valida que los datos de clasificación de riesgo recibidos de un servicio externo se transforman correctamente al formato del modelo de datos interno.

```gherkin
Scenario: El sistema mapea correctamente los datos de clasificación de riesgo externos
  Given que el sistema recibe datos de clasificación de riesgo de un servicio externo
    And el modelo de datos interno para clasificación de riesgo está definido con campos como ID, nombre y nivel
  When el sistema mapea los datos de clasificación de riesgo
  Then los datos se transforman al formato del modelo de datos interno
    And se asigna un ID único y estable a cada clasificación de riesgo
```

### AC-002: Mapeo de Garantías
**Description:** Valida que los datos de garantías recibidos de un servicio externo se transforman correctamente al formato del modelo de datos interno, incluyendo atributos clave.

```gherkin
Scenario: El sistema mapea correctamente los datos de garantías externos
  Given que el sistema recibe datos de garantías de un servicio externo
    And el modelo de datos interno para garantías está definido con campos como ID, nombre, descripción y tipo
  When el sistema mapea los datos de garantías
  Then los datos se transforman al formato del modelo de datos interno
    And se asigna un ID único y estable a cada garantía
    And los atributos como ID, nombre y descripción son consistentes con el modelo interno
```

### AC-003: Consistencia de Datos Mapeados
**Description:** Valida que los datos mapeados son consistentes y utilizables por la lógica de negocio, reflejando las expectativas funcionales.

```gherkin
Scenario: Los datos mapeados son consistentes para la lógica de negocio
  Given que el mapeo de datos de riesgo y garantías ha sido exitoso
  When la lógica de negocio intenta utilizar los datos mapeados (ej. para cálculos de riesgo)
  Then los valores de los datos son consistentes y válidos según las reglas de negocio
    And no se producen errores debido a inconsistencias de formato o tipo de datos
```

**BR-001:** Unicidad y Estabilidad de Identificadores
- Description: Los identificadores internos asignados a la clasificación de riesgo y a las garantías deben ser únicos dentro del sistema y estables, es decir, una vez asignados a un elemento, no deben cambiar para ese mismo elemento en futuras actualizaciones. Esto es crucial para mantener la integridad referencial.
- Trigger: Al realizar el mapeo de cualquier dato de clasificación de riesgo o garantía por primera vez o al actualizar un registro existente.
- Logic:
    - Si `idRiesgoExterno` ya existe en el mapeo, se utiliza el `idRiesgoInterno` existente.
    - Si `idRiesgoExterno` es nuevo, se genera un nuevo `idRiesgoInterno` (UUID).
    - Mismo principio aplica para `idGarantiaExterna` e `idGarantiaInterna`.
- Implementation: Capa de Mapeo de Datos / Servicio de Identificadores.
- Exception: Si no se puede generar un ID único (muy improbable con UUID) o si hay conflicto de ID.

**BR-002:** Normalización de Nivel de Riesgo
- Description: El nivel de riesgo externo debe ser mapeado a un catálogo interno estandarizado (ej. 'ALTO', 'MEDIO', 'BAJO').
- Trigger: Durante el mapeo de datos de clasificación de riesgo.
- Logic: Convertir valores externos (ej. 'High', 'Medium', 'Low', '1', '2', '3') a los valores internos definidos.
- Implementation: Capa de Mapeo de Datos.
- Exception: Si el valor externo no corresponde a ningún valor interno conocido, se registra un error y el mapeo podría fallar o asignar un valor por defecto.

## 16. Technical Notes and Risks
**Risks:**
1.  **Inconsistencia de Identificadores Externos**:
    -   Description: Si el servicio externo cambia la forma en que genera o presenta los identificadores de riesgo/garantía, podría romperse la lógica de estabilidad de IDs internos.
    -   Impact: Duplicidad de registros, pérdida de historial o referencias cruzadas incorrectas.
    -   Probability: Media
    -   Mitigation: Monitoreo de cambios en la API externa. Implementar un mecanismo robusto de reconciliación de IDs basado en múltiples atributos si el ID principal externo es volátil.
2.  **Complejidad del Mapeo**:
    -   Description: Los datos externos pueden ser más complejos o tener más variaciones de lo anticipado, lo que podría aumentar la complejidad de la capa de mapeo y el tiempo de desarrollo.
    -   Impact: Retrasos en la implementación, mayor probabilidad de errores de mapeo.
    -   Probability: Media
    -   Mitigation: Realizar un análisis exhaustivo de los esquemas de datos externos. Implementar un sistema de mapeo configurable o basado en reglas.
**Technical Debt:** [To be filled by operating team per scope and MVP]
- Considerar un motor de reglas o una herramienta de ETL para mapeos complejos o cambiantes, en lugar de lógica hardcodeada.

## 17. Criticality
**Criticality Level:** Media
**Justification:** Esta historia es crucial para la integración de datos externos, pero no afecta directamente al usuario final ni a funcionalidades críticas de negocio hasta que los datos sean consumidos. Un fallo en el mapeo afectaría la calidad de los datos, pero no el funcionamiento inmediato del sistema.
**Feature Impact:** Sin un mapeo adecuado, la funcionalidad de "Gestión de Clasificación de Riesgo y Garantías" no podría utilizar los datos externos de manera efectiva, lo que llevaría a cálculos incorrectos o información errónea en la UI.
**Critical Dependencies:** Las historias que consumen los datos de riesgo y garantías mapeados (ej. cálculo de riesgo, visualización en UI) dependen directamente de esta historia.
**Recommended Priority:** Sprint actual o siguiente, después de la adquisición de datos.
