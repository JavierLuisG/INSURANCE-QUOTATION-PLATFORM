## 4. Functional Description
**Description:** Esta historia de usuario habilita la funcionalidad para que el sistema obtenga la Tarifa FHM (Factor Horas Máquina) y los factores de equipo electrónico desde el servicio externo `Plataforma-core-ohs`. La ingestión puede realizarse a través de una integración real o mediante una simulación, garantizando que los datos críticos para cálculos específicos de coberturas estén disponibles y actualizados. Se debe implementar un mecanismo robusto para el manejo de errores, especialmente para valores nulos o inválidos.
**Flow:** (Proceso de inicio de cálculo/actualización de parámetros) → [HU-046: Ingestión de Tarifa FHM y Factores de Equipo Electrónico] → (Cálculo de Coberturas FHM y Equipo Electrónico)

**BR-001: Manejo de Valores de Parámetros Nulos/Inválidos**
- Description: Cuando un parámetro (tarifa FHM o factor de equipo electrónico) obtenido de `Plataforma-core-ohs` es nulo, no numérico, o se encuentra fuera de un rango de valores aceptable, el sistema debe registrar el error y, si está configurado, utilizar un valor por defecto predefinido para ese parámetro. En caso de no haber un valor por defecto o si el error es crítico, el sistema debe notificar al 'Administrador de parámetros'.
- Trigger: Durante el proceso de ingestión y validación de parámetros desde `Plataforma-core-ohs`.
- Logic:
    ```
    SI (valor_obtenido ES NULO O NO_NUMERICO O valor_obtenido < MIN_VAL_PERMITIDO) ENTONCES
        REGISTRAR_ERROR("Valor inválido para parámetro X: " + valor_obtenido)
        SI (EXISTE_VALOR_POR_DEFECTO_CONFIGURADO_PARA_X) ENTONCES
            UTILIZAR_VALOR_POR_DEFECTO_PARA_X
        SINO
            NOTIFICAR_ADMINISTRADOR("Error crítico: Parámetro X sin valor válido ni por defecto.")
            // Opcional: Detener la ingestión de este parámetro o de todo el lote
        FIN_SI
    FIN_SI
    ```
- Implementation: Adaptador de integración `Plataforma-core-ohs` y/o Servicio de ingestión de parámetros.
- Exception: Si el valor por defecto no es configurable o el impacto de un valor inválido es demasiado alto, la ingestión de todo el lote de parámetros podría ser rechazada.

## 11. Architecture and Technical Dependencies
- **`Plataforma-core-ohs`:** Servicio externo, fuente de verdad para la tarifa FHM y los factores de equipo electrónico.
    - Propósito: Proveer los valores actualizados de los parámetros.
    - Timeout: 5 segundos.
    - Retries: 3 reintentos con estrategia de backoff exponencial.
- **Adaptador de integración `Plataforma-core-ohs`:** Componente encargado de la comunicación (API REST/SOAP) con el servicio externo y la transformación de los datos recibidos al formato interno del sistema.
- **Repositorio de parámetros de cálculo:** Componente de persistencia (base de datos, caché distribuida) donde se almacenan los parámetros ingestados para su rápido acceso por el motor de cálculo.
- **Circuit Breaker:** Implementado en el adaptador de integración para `Plataforma-core-ohs` para manejar la indisponibilidad o latencia excesiva del servicio externo y prevenir fallos en cascada.

## 16. Technical Notes and Risks
**Risks:**
1.  **Fiabilidad y Latencia de `Plataforma-core-ohs`:**
    - Descripción: La disponibilidad y el rendimiento del servicio `Plataforma-core-ohs` son críticos. Fallos o alta latencia pueden afectar directamente la actualización de los parámetros y, por ende, la precisión de los cálculos.
    - Impacto: Cálculos de coberturas imprecisos o desactualizados, degradación del servicio, impacto financiero.
    - Probabilidad: Media.
    - Mitigación: Implementación de Circuit Breaker, políticas de reintento, monitoreo proactivo de la API de `Plataforma-core-ohs`, definición robusta de valores por defecto y mecanismos de notificación de errores.
2.  **Cambios en el Contrato de la API de `Plataforma-core-ohs`:**
    - Descripción: Si el contrato de la API externa (estructura de datos, endpoints) cambia sin previo aviso o de forma no compatible, el adaptador de integración puede fallar.
    - Impacto: Ingestión de parámetros fallida, necesidad de refactorización urgente, interrupción del servicio.
    - Probabilidad: Baja a Media.
    - Mitigación: Comunicación constante con el equipo de `Plataforma-core-ohs`, pruebas de integración automatizadas, diseño flexible del adaptador, versionado de API.

## 17. Criticality
**Criticality Level:** Media
**Justification:** La ingestión de estos parámetros es fundamental para la precisión de cálculos específicos de coberturas. **Critical Dependencies:** El motor de cálculo de coberturas FHM y Equipo Electrónico depende directamente de la disponibilidad de estos parámetros.
