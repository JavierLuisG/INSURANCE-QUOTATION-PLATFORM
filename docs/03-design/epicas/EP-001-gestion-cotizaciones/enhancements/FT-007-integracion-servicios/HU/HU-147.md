## 2. Enabled Capability
**CAP-005:** Gestión y Consulta de Tarifas y Factores Técnicos
**Business Value:** Permite el cálculo preciso y actualizado de las primas de seguro, asegurando la correcta tarificación de los productos y la competitividad en el mercado.
**Requires:** HU-092 (Configurar Mock Server Base, FT-020)
**Enables:** CAP-006 (Cálculo de Primas de Incendio), CAP-007 (Cálculo de Primas de CAT), CAP-008 (Cálculo de Primas de FHM), CAP-009 (Cálculo de Primas de Equipo Electrónico)
**Orchestrates:** `Plataforma-core-ohs` (Servicio Externo)

## 3. User Story
Como sistema,
Quiero consultar las tarifas (incendio, CAT, FHM) y factores técnicos (equipo electrónico) desde `Plataforma-core-ohs` (o su simulación),
Para utilizarlos en el cálculo preciso de las primas.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad del sistema para interactuar con el servicio externo `Plataforma-core-ohs` con el fin de obtener las tarifas de seguro (como incendio, CAT, FHM) y los factores técnicos (como los aplicables a equipo electrónico). Una vez recibidos, estos datos serán procesados y mapeados a la estructura interna del sistema, asegurando que estén disponibles y sean correctos para el módulo de cálculo de primas. Se implementará un mecanismo robusto de manejo de errores para situaciones donde el servicio externo no responda o devuelva datos inconsistentes, incluyendo notificaciones adecuadas.
**Flow:** Solicitud de Cálculo de Prima → [**HU-147: Consumir Tarifas y Factores Técnicos**] → Lógica de Cálculo de Prima → Resultado de Cálculo.

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Consulta Exitosa de Tarifas y Factores
**Description:** Valida que el sistema pueda obtener correctamente las tarifas y factores técnicos del servicio externo `Plataforma-core-ohs`.

```gherkin
Scenario: Consulta y recepción exitosa de tarifas y factores
  Given el sistema requiere tarifas o factores para un cálculo de prima
  When realiza una consulta al servicio `Plataforma-core-ohs`
  Then obtiene los datos de tarifas y factores necesarios del servicio externo con un código de respuesta exitoso (ej. 200 OK).
```

### AC-002: Mapeo y Procesamiento Correcto de Datos Recibidos
**Description:** Asegura que los datos recibidos del servicio externo se transformen y validen adecuadamente para su uso en el módulo de cálculo.

```gherkin
Scenario: Mapeo y validación de datos recibidos
  Given los datos de tarifas y factores son recibidos exitosamente de `Plataforma-core-ohs`
  When el sistema procesa y mapea estos datos a su estructura interna
  Then los datos se transforman correctamente y se validan según las reglas de negocio, quedando listos para la lógica de cálculo.
```

### AC-003: Manejo de Errores por Fallo o Inconsistencia del Servicio Externo
**Description:** Define cómo el sistema reacciona ante la falta de disponibilidad del servicio externo o la recepción de datos inválidos.

```gherkin
Scenario: Manejo de errores en la consulta externa
  Given el sistema intenta consultar tarifas o factores
  When el servicio `Plataforma-core-ohs` no responde (ej. timeout, error 5xx) o devuelve datos inconsistentes/inválidos
  Then el sistema registra el error, notifica a los equipos de soporte y aplica una estrategia de resiliencia (ej. Circuit Breaker, valores por defecto si aplica) en lugar de fallar la operación completa.
```

**BR-001:** Validación de Valores Positivos para Tarifas/Factores
- Description: Todos los valores de tarifas y factores técnicos recibidos del servicio externo deben ser números positivos.
- Trigger: Después de recibir y parsear la respuesta de `Plataforma-core-ohs`.
- Logic: `valorTarifaFactor > 0`
- Implementation: Módulo de Adaptación de Tarifas.
- Exception: Si un valor no es positivo, se registra un error, se descarta el dato o se notifica para revisión.

**BR-002:** Mapeo de Estructuras de Datos
- Description: La estructura de datos de tarifas y factores de `Plataforma-core-ohs` debe ser mapeada a un modelo de datos interno consistente y bien definido para el módulo de cálculo de primas.
- Trigger: Al procesar la respuesta exitosa de `Plataforma-core-ohs`.
- Logic: Implementación de un adaptador o mapper que transforme el DTO externo al DTO interno.
- Implementation: Módulo de Adaptación de Tarifas.

## 11. Architecture and Technical Dependencies
- `Plataforma-core-ohs` (API REST): Servicio externo para obtener tarifas y factores. Se debe configurar un `HttpClient` con timeouts adecuados (ej. 5 segundos) y una estrategia de reintentos (ej. 3 reintentos con backoff exponencial).
- Módulo de Adaptación de Tarifas: Componente interno responsable de la validación, transformación y mapeo de los datos recibidos de `Plataforma-core-ohs` a la estructura de datos interna.
- Circuit Breaker: Implementación de un patrón Circuit Breaker (ej. Resilience4j, Hystrix) para aislar fallos del servicio `Plataforma-core-ohs` y evitar la propagación de errores.
- Caché Distribuida (opcional): Considerar la implementación de un mecanismo de caché para almacenar tarifas y factores consultados frecuentemente, reduciendo la dependencia y latencia de `Plataforma-core-ohs`.

## 13. Edge Cases and Exceptions
### Case 1: Servicio `Plataforma-core-ohs` Inaccesible
```gherkin
Scenario: Servicio externo no disponible
  Given el sistema intenta consultar tarifas y factores
  When `Plataforma-core-ohs` no está disponible o no responde (ej. error de red, timeout)
  Then el sistema activa el Circuit Breaker, registra el error y notifica a los sistemas de monitoreo, y opcionalmente utiliza un valor por defecto o datos en caché si la política lo permite.
```

### Case 2: Datos Incompletos o Vacíos Recibidos
```gherkin
Scenario: Datos incompletos o inválidos de `Plataforma-core-ohs`
  Given el sistema recibe una respuesta de `Plataforma-core-ohs`
  When la respuesta contiene datos de tarifas o factores que son nulos, vacíos o no cumplen con las validaciones de formato/valor
  Then el sistema registra un log de advertencia/error detallado, descarta los datos inválidos y notifica, y el cálculo de prima podría proceder con valores por defecto o fallar si los datos son críticos.
```

### Case 3: No hay Tarifas/Factores para un Criterio Específico
```gherkin
Scenario: Ausencia de datos para un criterio de consulta
  Given el sistema consulta tarifas/factores para un producto o criterio específico
  When `Plataforma-core-ohs` devuelve una respuesta indicando que no hay datos para ese criterio (ej. lista vacía, código 404)
  Then el sistema registra un log informativo y procede según la lógica de negocio (ej. usar valores por defecto, solicitar intervención manual, marcar el cálculo como no viable).
```

## 16. Technical Notes and Risks
**Risks:**
1.  **Disponibilidad y Latencia de `Plataforma-core-ohs`**:
    - Description: El servicio externo `Plataforma-core-ohs` podría experimentar interrupciones o alta latencia, impactando directamente el rendimiento y la disponibilidad del cálculo de primas.
    - Impact: Retrasos en el cálculo, fallos en la cotización de pólizas, experiencia de usuario degradada.
    - Probability: Media.
    - Mitigation: Implementación de Circuit Breaker, política de reintentos con backoff, monitoreo proactivo de la latencia de la integración, posible implementación de caché para datos de tarifas.
2.  **Complejidad y Estabilidad del Contrato de `Plataforma-core-ohs`**:
    - Description: La estructura de datos de tarifas y factores de `Plataforma-core-ohs` puede ser compleja y susceptible a cambios, lo que podría requerir ajustes constantes en el módulo de adaptación.
    - Impact: Errores en el mapeo de datos, cálculos de primas incorrectos, alto costo de mantenimiento.
    - Probability: Media.
    - Mitigation: Mantener una comunicación fluida con el equipo de `Plataforma-core-ohs`, diseño flexible y desacoplado del Módulo de Adaptación de Tarifas, pruebas de integración automatizadas para detectar cambios en el contrato, versionado de la API.
