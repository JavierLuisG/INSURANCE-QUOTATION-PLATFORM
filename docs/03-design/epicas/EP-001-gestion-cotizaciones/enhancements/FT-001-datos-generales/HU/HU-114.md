## 2. Enabled Capability
**CAP-001:** Gestión de Layout de Ubicaciones
**Business Value:** Permite al usuario definir la estructura de campos que se capturarán para cada ubicación en un folio de cotización, asegurando la recolección de información relevante y personalizada. Esto mejora la flexibilidad y la precisión en la captura de datos de ubicaciones.
**Requires:** CAP-XXX (Creación de Cotización, relacionada con HU-110)
**Enables:** CAP-XXX (Captura de Datos de Ubicación)
**Orchestrates:** N/A

## 3. User Story
Como usuario,
Quiero poder consultar y configurar el layout de ubicaciones de mi cotización,
Para definir la estructura de campos que se capturarán en cada ubicación del folio.

## 4. Functional Description
**Description:** Esta historia de usuario permite a un usuario consultar la configuración actual del layout de ubicaciones de una cotización y modificarlo para definir qué campos se mostrarán y capturarán para cada ubicación dentro de un folio. Cuando se accede por primera vez a una cotización que no tiene un layout definido, el sistema carga una configuración por defecto con los campos obligatorios del dominio de Ubicación. Los cambios realizados en el layout son persistidos y afectan cómo se renderiza el formulario de captura de ubicaciones.
**Flow:** HU-110 (Crear Nueva Cotización) → HU-114 (Gestión de Layout de Ubicaciones) → HU-XXX (Captura de Datos de Ubicación)

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Consulta de Layout Existente
**Description:** Valida que el sistema devuelve la configuración de layout actual de una cotización si esta ya existe.

```gherkin
Scenario: Consulta de la configuración de layout de una cotización con layout existente
  Given que tengo una cotización abierta con folio "Q-001" y una configuracionLayout existente
  When accedo a la sección de layout (`GET /v1/quotes/Q-001/locations/layout`)
  Then el sistema devuelve la configuración actual de configuracionLayout asociada al folio
```

### AC-002: Persistencia de Cambios en el Layout
**Description:** Valida que el sistema guarda correctamente las modificaciones o la nueva configuración del layout.

```gherkin
Scenario: Guardar una nueva configuración o modificación del layout
  Given que el usuario está configurando o modificando el layout de la cotización con folio "Q-001"
  When guarda los cambios (`PUT /v1/quotes/Q-001/locations/layout` con la nueva configuración)
  Then el sistema persiste la nueva configuración de configuracionLayout en la cotización
```

### AC-003: Renderizado Dinámico del Formulario
**Description:** Valida que la interfaz de captura de ubicaciones se adapta a la configuración de layout guardada.

```gherkin
Scenario: La interfaz de captura de ubicaciones se actualiza según el layout
  Given que el layout de la cotización con folio "Q-001" ha sido actualizado y guardado
  When el usuario accede al formulario de captura de ubicaciones de esa cotización
  Then la interfaz renderiza los campos conforme a la configuración guardada en configuracionLayout
```

### AC-004: Carga de Layout por Defecto
**Description:** Valida que, si no hay un layout previo, se carga una configuración por defecto.

```gherkin
Scenario: Consulta de layout para una cotización nueva sin configuración previa
  Given que es la primera vez que se abre la cotización con folio "Q-002" y no tiene una configuracionLayout previa
  When se consulta el layout (`GET /v1/quotes/Q-002/locations/layout`)
  Then el sistema devuelve una configuración por defecto que incluye nombreUbicacion, direccion, codigoPostal, tipoConstructivo, nivel, anioConstruccion, giro, garantías[]
```

**BR-001: Layout por Defecto de Ubicaciones**
- Description: Cuando se consulta el layout de una cotización por primera vez y no existe una `configuracionLayout` asociada, el sistema debe devolver una configuración estándar que incluya los campos obligatorios del dominio de Ubicación.
- Trigger: Solicitud `GET /v1/quotes/{folio}/locations/layout` para una cotización sin `configuracionLayout` persistida.
- Logic: Si la `configuracionLayout` para el `folio` es nula o no existe, el servicio de backend construirá y retornará un objeto `configuracionLayout` con los siguientes campos marcados como visibles y obligatorios: `nombreUbicacion`, `direccion`, `codigoPostal`, `tipoConstructivo`, `nivel`, `anioConstruccion`, `giro`, `garantías[]`.
- Implementation: Servicio de Backend (Quotes Service).
- Exception: N/A.

## 10. UX and Navigation Flow
**UX Flow:**
1.  El usuario navega a la pantalla "Detalle de Cotización" (previamente creada o seleccionada).
2.  En la sección de ubicaciones, el usuario hace clic en un botón o enlace "Configurar Layout de Ubicaciones".
3.  El sistema presenta la "Pantalla de Configuración de Layout", mostrando una interfaz donde el usuario puede añadir, eliminar, reordenar y configurar las propiedades (visible, obligatorio, tipo) de los campos de ubicación.
4.  El usuario realiza las configuraciones deseadas.
5.  El usuario hace clic en "Guardar" o "Cancelar".
6.  Si guarda, el sistema persiste los cambios y regresa a la "Pantalla Detalle de Cotización" con un mensaje de éxito.
7.  Si cancela, el sistema descarta los cambios y regresa a la "Pantalla Detalle de Cotización".
8.  Posteriormente, al acceder al formulario de captura de ubicaciones, este se renderizará con los campos definidos en el layout.
**Messages/Modals:**
*   **Mensaje de éxito:** "Configuración de layout de ubicaciones guardada exitosamente."
*   **Mensaje de error:** "Error al guardar la configuración de layout. Por favor, intente de nuevo."
*   **Modal de confirmación:** "¿Desea guardar los cambios antes de salir?" (Si el usuario intenta navegar sin guardar).
**Stepper/Breadcrumbs:** `Cotizaciones > [Folio de Cotización] > Configuración de Layout de Ubicaciones`

## 11. Architecture and Technical Dependencies
- **Backend Service:** Quotes Service (Microservicio encargado de la gestión de cotizaciones).
    - Expone los endpoints `GET /v1/quotes/{folio}/locations/layout` y `PUT /v1/quotes/{folio}/locations/layout`.
    - Es responsable de la persistencia de `configuracionLayout` en la base de datos.
    - Implementa la lógica para generar el layout por defecto (BR-001).
- **Frontend Application:** Aplicación web de cotizaciones.
    - Componente de UI para la configuración del layout de ubicaciones (permite edición visual).
    - Componente de UI para el renderizado dinámico de formularios de ubicaciones basado en la `configuracionLayout`.
- **Database:** Base de datos relacional (ej. PostgreSQL) para almacenar el objeto `configuracionLayout` dentro de la entidad de Cotización.

## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad del Renderizado Dinámico en Frontend:**
    - Description: La implementación de un componente de UI que renderice dinámicamente formularios basados en la estructura de `configuracionLayout` puede ser compleja, especialmente si se requieren validaciones personalizadas o interacciones complejas entre campos.
    - Impact: Retrasos en el desarrollo del frontend, introducción de bugs en la interfaz de usuario, experiencia de usuario deficiente.
    - Probability: Media
    - Mitigation: Utilizar una librería o framework de formularios dinámicos maduro, dedicar tiempo a la planificación detallada del componente de UI, realizar pruebas exhaustivas de la interfaz y sus interacciones.
2.  **Validación y Consistencia de `configuracionLayout`:**
    - Description: Asegurar que la estructura del objeto `configuracionLayout` sea siempre consistente y válida tanto al ser guardada por el backend como al ser interpretada por el frontend, evitando la corrupción de datos o errores en tiempo de ejecución.
    - Impact: Fallos en la aplicación, datos inconsistentes, imposibilidad de renderizar formularios correctamente.
    - Probability: Media
    - Mitigation: Definir un esquema JSON estricto para `configuracionLayout`, implementar validación exhaustiva en el backend para el endpoint `PUT`, realizar pruebas unitarias y de integración sobre la serialización/deserialización del objeto.

## 18. Identified Assumptions
1.  **Estructura del Objeto `configuracionLayout`:**
    - Description: Se asume que `configuracionLayout` será un objeto JSON que contendrá un array de objetos, donde cada objeto representa un campo configurable con propiedades como `nombreCampo`, `tipo`, `obligatorio`, `visible`, `orden`, y `catalogo` (si aplica).

    - Impact if false: No se podría generar el layout por defecto de manera consistente o los campos configurables no tendrían un origen claro.
    - Requires validation from: Equipo de Negocio / Arquitectura.
3.  **Roles y Permisos de Usuario:**
    - Description: Se asume que ya existen roles de usuario (`Asegurador`, `Administrador de Cotizaciones`) y que estos tienen los permisos adecuados para realizar las acciones de consultar y configurar el layout.
    - Impact if false: La funcionalidad no sería accesible para los usuarios previstos o se presentaría un riesgo de seguridad por acceso no autorizado.
    - Requires validation from: Equipo de Seguridad / Negocio.
