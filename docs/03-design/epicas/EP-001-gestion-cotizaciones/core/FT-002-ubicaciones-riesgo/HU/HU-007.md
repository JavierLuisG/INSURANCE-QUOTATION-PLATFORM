## 2. Enabled Capability
**CAP-007:** Edición de Ubicación de Riesgo
**Business Value:** Permite la corrección y actualización precisa de la información de las ubicaciones de riesgo, asegurando la validez y completitud de los datos para la cotización, lo que reduce errores en la emisión de pólizas y mejora la experiencia del usuario.
**Requires:** CAP-006 - Agregar Ubicación de Riesgo
**Enables:** CAP-008 - Visualización de Detalles de Cotización, CAP-009 - Cálculo de Prima
**Orchestrates:** N/A

## 3. User Story
Como usuario,
Quiero modificar los datos de una ubicación de riesgo existente,
Para poder corregir o actualizar su información con todos los campos de dominio requeridos.

## 4. Functional Description
**Description:** Esta historia de usuario describe la funcionalidad que permite a un usuario seleccionar una ubicación de riesgo previamente creada dentro de una cotización y editar sus detalles. El sistema debe presentar un formulario pre-llenado con la información actual de la ubicación, permitiendo al usuario modificar cualquier campo del dominio como `nombreUbicacion`, `direccion`, `codigoPostal`, `estado`, `municipio`, `colonia`, `ciudad`, `tipoConstructivo`, `nivel`, `anioConstruccion`, `giro` (incluyendo `claveIncendio`), `garantías[]` y `zonaCatastrofica`. Tras guardar, los cambios deben persistir y el sistema debe recalcular automáticamente `alertasBloqueantes` y `estadoValidacion`. Se deben manejar validaciones para campos obligatorios y la determinación automática de `zonaCatastrofica` basada en el `codigoPostal` contra el catálogo correspondiente.
**Flow:** HU-006 (Agregar una nueva ubicación) → HU-007 (Editar detalles específicos de una ubicación de riesgo) → HU-XXX (Continuar con la cotización / Revisar cotización)

**Description:** Confirmar que el campo `zonaCatastrofica` se determina automáticamente al validar el código postal.


**BR-001: Recalculo de Alertas Bloqueantes y Estado de Validación**
- Description: Tras cada operación de guardado de una ubicación, el sistema debe recalcular automáticamente las `alertasBloqueantes` y el `estadoValidacion` de la ubicación.
- Trigger: Después de una operación `PATCH` exitosa en `/v1/quotes/{folio}/locations/{índice}`.
- Logic:
    1.  Evaluar todos los campos obligatorios de la ubicación. Si alguno está vacío o inválido, `estadoValidacion` = `INCOMPLETA`. De lo contrario, `COMPLETA`.
    2.  Evaluar reglas de negocio específicas para determinar `alertasBloqueantes` (ej. si `zonaCatastrofica` es `true` y no se selecciona una garantía específica).
- Implementation: Servicio de Backend de Cotizaciones.
- Exception: N/A

**BR-002: Determinación de Zona Catastrófica por Código Postal**
- Description: El campo `zonaCatastrofica` se debe determinar automáticamente al validar el `codigoPostal` contra el catálogo de Códigos Postales y Zonas Catastróficas.
- Trigger: Cuando se actualiza o valida el campo `codigoPostal`.
- Logic:
    1.  Consultar el catálogo de Códigos Postales para el `codigoPostal` proporcionado.
    2.  Si el `codigoPostal` se encuentra y está marcado como zona catastrófica, `zonaCatastrofica` será `true`. En caso contrario, `false`.
- Implementation: Servicio de Backend de Cotizaciones (interactuando con el Servicio de Catálogos).
- Exception: Si el `codigoPostal` no es válido o no se encuentra en el catálogo, `zonaCatastrofica` podría ser `false` por defecto o generar una alerta.

## 11. Architecture and Technical Dependencies
- **Backend API (Cotizaciones):** `PATCH /v1/quotes/{folio}/locations/{índice}`. Propósito: Actualizar parcialmente los datos de una ubicación específica. Timeout: 5000 ms. Retries: 0 (para evitar efectos duplicados en operaciones PATCH no idempotentes por diseño).
- **Servicio de Catálogos:** Para la validación del `codigoPostal` y la determinación de `zonaCatastrofica`, así como para proveer los catálogos de `estado`, `municipio`, `colonia`, `ciudad`, `tipoConstructivo`, `giro`.
- **Base de Datos:** Persistencia de los datos de la ubicación y la cotización.
- **Frontend (Aplicación Web):** Componente de formulario para la edición de ubicaciones, con lógica de validación front-end.

## 16. Technical Notes and Risks
**Risks:**
1.  **Consistencia de datos con catálogos externos:**
    *   Descripción: Cambios en los catálogos de CP, estados, municipios o giros podrían generar inconsistencias en los datos de la ubicación o afectar la determinación de `zonaCatastrofica` si no se gestionan adecuadamente.
    *   Impacto: Datos incorrectos en la cotización, errores en la prima, validaciones fallidas.
    *   Probabilidad: Media.
    *   Mitigación: Implementar un proceso de actualización o sincronización periódica con los servicios de catálogos. Manejo robusto de errores de integración.
2.  **Complejidad del formulario de edición y experiencia de usuario:**
    *   Descripción: La cantidad de campos y reglas de validación podría hacer que el formulario sea complejo de usar, lo que podría llevar a errores de entrada de datos y frustración del usuario.
    *   Impacto: Baja usabilidad, alta tasa de errores de usuario, retrabajo.
    *   Probabilidad: Media.
    *   Mitigación: Priorizar un diseño de UI/UX claro y sencillo, implementar validaciones en tiempo real y mensajes de ayuda contextualmente relevantes.
3.  **Rendimiento del recalculo de `alertasBloqueantes` y `estadoValidacion`:**
    *   Descripción: Si la lógica de recalculo es muy compleja o intensiva en recursos, podría impactar negativamente el tiempo de respuesta del guardado de la ubicación.
    *   Impacto: Alta latencia en la operación de guardado, percepción de lentitud del sistema.
    *   Probabilidad: Baja a Media.
    *   Mitigación: Optimizar la lógica de recalculo, realizar pruebas de rendimiento, considerar un procesamiento asíncrono si el impacto es significativo (aunque para una única ubicación, síncrono suele ser aceptable).

## 17. Criticality
**Criticality Level:** High
**Justification:** La capacidad de corregir o actualizar la información de una ubicación de riesgo es fundamental para asegurar la precisión de la cotización y la correcta emisión de pólizas. Datos incorrectos pueden llevar a errores en la prima, rechazos de pólizas o problemas legales.
**Feature Impact:** Sin esta funcionalidad, cualquier error en la entrada de datos de una ubicación requeriría que el usuario la eliminara y recreara, lo cual es ineficiente, propenso a errores y genera una mala experiencia de usuario. Impacta directamente la calidad y validez de las cotizaciones.
**Critical Dependencies:** El cálculo de la prima, la emisión de la póliza y la visualización correcta de la cotización dependen directamente de que los datos de la ubicación sean precisos y completos.
**Recommended Priority:** Sprint actual (dada la prioridad Alta).

## 18. Identified Assumptions
1.  **Acceso y Permisos del Usuario:**
    *   Description: Se asume que el usuario que intenta editar una ubicación tiene los permisos necesarios para modificar esa cotización y ubicación específica.
    *   Impact if false: El usuario no podrá editar la ubicación, resultando en un error de autorización (403 Forbidden) y frustración.
    *   Requires validation from: Equipo de Seguridad / Product Owner.
2.  **Disponibilidad y Confiabilidad del Servicio de Catálogos:**
    *   Description: Se asume que el Servicio de Catálogos (para CP, giros, estados, etc.) está disponible, es accesible y responde de manera consistente y correcta para las validaciones y determinaciones automáticas.
    *   Impact if false: Errores en la validación de datos, imposibilidad de determinar `zonaCatastrofica`, o imposibilidad de guardar ubicaciones completas.
    *   Requires validation from: Equipo de Integraciones / Arquitectura.
3.  **Idempotencia del Endpoint PATCH:**
    *   Description: Se asume que la operación `PATCH` sobre `/v1/quotes/{folio}/locations/{índice}` es idempotente, es decir, que aplicar la misma solicitud varias veces produce el mismo resultado que aplicarla una sola vez, sin efectos secundarios no deseados.
    *   Impact if false: Podría haber efectos secundarios no deseados o inconsistencias en los datos si la solicitud se reintenta incorrectamente por algún fallo transitorio.
    *   Requires validation from: Equipo de Desarrollo Backend.
