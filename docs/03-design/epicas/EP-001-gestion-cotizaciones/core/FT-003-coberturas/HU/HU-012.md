## 3. User Story
Como usuario,
quiero poder seleccionar o deseleccionar coberturas individuales para cada ubicación de riesgo,
para personalizar la protección.

## 4. Functional Description
**Description:** Esta historia de usuario permite al usuario activar o desactivar coberturas específicas de un catálogo para una ubicación de riesgo particular dentro de una cotización. La interfaz debe proporcionar un mecanismo claro (como checkboxes o switches) para realizar estas selecciones y reflejar el estado actual de cada cobertura. Las selecciones realizadas deben persistir al guardar y consultar la cotización nuevamente. Se debe considerar la posibilidad de que existan coberturas obligatorias que no puedan ser deseleccionadas.
**Flow:** HU-006 (Agregar ubicación) → HU-011 (Visualizar catálogo de coberturas) → HU-012 (Seleccionar/Deseleccionar coberturas) → [Guardar Cotización]

## 6. Acceptance Criteria (3-5 criteria)
### AC-001: Seleccionar una cobertura para una ubicación
**Description:** Valida que una cobertura puede ser marcada como activa para una ubicación específica.

```gherkin
Scenario: Un usuario selecciona una cobertura individual para una ubicación
  Given estoy en la sección de coberturas de la "Ubicación A"
  And existe un "Catálogo de Coberturas" disponible para el tipo de seguro
  When selecciono la "Cobertura X" del catálogo
  Then la "Cobertura X" se marca como activa para la "Ubicación A" en la interfaz
```

### AC-002: Deseleccionar una cobertura para una ubicación
**Description:** Valida que una cobertura previamente seleccionada puede ser marcada como inactiva.

```gherkin
Scenario: Un usuario deselecciona una cobertura individual para una ubicación
  Given estoy en la sección de coberturas de la "Ubicación A"
  And la "Cobertura Y" está actualmente seleccionada y activa para la "Ubicación A"
  When deselecciono la "Cobertura Y"
  Then la "Cobertura Y" deja de estar activa para la "Ubicación A" en la interfaz
```

### AC-003: Persistencia de las selecciones de coberturas por ubicación
**Description:** Valida que las selecciones de coberturas realizadas para cada ubicación se guardan correctamente y se recuperan al consultar la cotización.

```gherkin
Scenario: Las selecciones de coberturas persisten al guardar y consultar la cotización
  Given he seleccionado la "Cobertura P" para la "Ubicación 1"
  And he deseleccionado la "Cobertura Q" para la "Ubicación 1"
  When guardo la cotización
  And luego consulto la misma cotización
  Then la "Cobertura P" se muestra como activa para la "Ubicación 1"
  And la "Cobertura Q" se muestra como inactiva para la "Ubicación 1"
```

**BR-001:** Coberturas Obligatorias
- Description: Algunas coberturas pueden ser obligatorias por tipo de seguro o por políticas internas y no pueden ser deseleccionadas por el usuario.
- Trigger: Al cargar el catálogo de coberturas para una ubicación.
- Logic: Si `cobertura.esObligatoria` es `true`, el control de selección (checkbox/switch) debe estar deshabilitado y marcado como seleccionado.
- Implementation: Servicio de Coberturas, Lógica de Negocio en Backend/Frontend.

## 10. UX and Navigation Flow
**UX Flow:**
1.  Navegar a la pantalla de detalle de una cotización.
2.  Seleccionar una ubicación de riesgo específica.
3.  Acceder a la sección de "Coberturas" para esa ubicación.

## 13. Edge Cases and Exceptions
### Case 1: Intento de deseleccionar una cobertura obligatoria
```gherkin
Scenario: El usuario intenta deseleccionar una cobertura obligatoria
  Given estoy en la sección de coberturas de la "Ubicación B"
  And la "Cobertura Z" está marcada como obligatoria y activa
  When intento deseleccionar la "Cobertura Z" (ej. haciendo clic en el checkbox deshabilitado)
  Then la "Cobertura Z" permanece seleccionada y activa
  And la interfaz no permite la deselección (ej. el checkbox está deshabilitado)
```


## 16. Technical Notes and Risks
**Risks:**
1.  **Complejidad en reglas de negocio de coberturas:**
    - Descripción: La lógica para determinar qué coberturas son obligatorias, incompatibles o tienen dependencias podría volverse compleja, afectando la UI y el backend.
    - Impacto: Retrasos en el desarrollo, errores en la cotización, mala experiencia de usuario.
    - Probabilidad: Media.
    - Mitigación: Definir claramente las reglas de negocio antes de la implementación, usar un BRMS si la complejidad es muy alta, implementar pruebas exhaustivas para las reglas.
2.  **Rendimiento de la persistencia:**
    - Descripción: Si una cotización tiene muchas ubicaciones y cada una muchas coberturas, la operación de guardar podría ser lenta.
    - Impacto: Mala experiencia de usuario, timeouts.
    - Probabilidad: Baja (para un MVP inicial).
    - Mitigación: Optimizar el endpoint de guardado, considerar estrategias de guardado parcial o asíncrono si el volumen de datos crece.

## 18. Identified Assumptions
1.  **Catálogo de Coberturas Establecido:**
    *   Description: Se asume que existe un catálogo de coberturas bien definido, con metadatos como el nombre, descripción y si es obligatoria o no.
    *   Impact if false: La UI no podría mostrar las opciones correctamente o el backend no sabría qué reglas aplicar.
    *   Requires validation from: Equipo de Producto, Dueño de Negocio.
2.  **Mecanismo de Guardado de Cotización:**
    *   Description: Se asume que ya existe un flujo y un mecanismo para "guardar la cotización" en general, y esta historia integrará la persistencia de las selecciones de coberturas dentro de ese flujo.
    *   Impact if false: Se necesitaría una historia adicional para implementar la funcionalidad de guardado principal, retrasando esta historia.
    *   Requires validation from: Equipo de Desarrollo, Arquitecto.
3.  **Identificación Única de Ubicaciones y Coberturas:**
    *   Description: Se asume que tanto las ubicaciones de riesgo como las coberturas tienen identificadores únicos (UUIDs) que permiten su correcta asociación y persistencia.
    *   Impact if false: Problemas de integridad de datos y dificultad para asociar las selecciones correctamente.
    *   Requires validation from: Equipo de Desarrollo, Arquitecto.
